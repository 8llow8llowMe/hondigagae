# 일정 만들기 두 화면 — 입력 밀도 · 달력 팝오버 설계

> 대상: `/plans/new` (직접 만들기) · `/ai-plans/new` (AI 일정 조건 입력)
> 작성: 2026-09-09
> 상태: 설계 확정 · 계획 `docs/superpowers/plans/2026-09-09-plan-create-layout.md` — 착수 이슈 미생성

**Goal:** 두 만들기 화면에서 **"할 일이 많아 보이는" 거부감**을 없앤다. 화면을 쪼개지 않고,
(1) 달력이 화면을 밀어내지 않게 하고 (2) 기본값이 있는 선택 항목을 접어 rest 상태를 가볍게 한다.

**Non-goal:** 단계별 위저드 · 프로그레스바 (§2 에서 기각). 새 API. 입력 항목의 추가/삭제.

---

## 1. 진단

### 1-1. 실제 필드 수는 적다

| 화면 | 필수 | 선택 | 비고 |
| --- | --- | --- | --- |
| `/plans/new` | 반려견 · 제목 · 시작일 · 종료일 | 예산 | 반려견 1마리면 자동 선택 → 실질 3개 |
| `/ai-plans/new` | **기간 · 반려견** | 자유요청 · 지역 · 예산 · 저장한곳우선 · 꼭넣을장소 | 선택 5개 **전부 기본값이 있다** |

`/ai-plans/new` 는 **반려견 1마리 사용자 기준 날짜 두 개만 고르면 제출된다.** 길어 보이는 것과
실제로 해야 하는 일의 양이 어긋나 있다.

### 1-2. 밀도의 원인은 "필드 수"가 아니라 "동시에 말하는 것의 수"

`/ai-plans/new` 의 rest 상태에서 컨트롤은 7개인데 텍스트 요소는 20개 가까이 동시에 서 있다.

| 종류 | 개수 |
| --- | --- |
| 회색 설명·힌트 줄 | **7** (`createDescription` · `fieldNoteHint` · `fieldRegionHint` · `fieldPetHint` · `fieldBudgetHint` · `preferFavoritesHint` · `createSubmitHint`) |
| 헤딩 | **4** (`page.tsx` 의 `h1` + 폼 안 `h2` + `h3` 2개) |
| 반려견별 설명 (`describePet`) | 마리당 1줄 |
| 칩 | **9** (지역 4 + 예산 5) |

모든 필드가 **쉬지 않고 자기 설명을 하고 있다.** 간격도 `gap-5`(20) / `gap-6`(24) 뿐이라
덩어리 경계가 안 읽히고 균질한 회색 벽으로 보인다.

### 1-3. 달력이 열릴 때 화면이 튄다

`DateField` 는 달력을 **문서 흐름 안에서** 펼친다. 날짜를 누르면 아래 내용 전부가 약 300px
밀린다. 코드가 이미 그 부작용을 보정하고 있다 — `panelRef.current?.scrollIntoView()` (#162).
**보정이 필요하다는 것 자체가 신호다.**

## 2. 기각 — 단계별 위저드 + 프로그레스바

최초 제안은 "한 화면에 하나씩 작성 + 프로그레스바" 였다. 아래 이유로 채택하지 않는다.
**같은 제안이 다시 올라올 때 이 절을 먼저 읽는다.**

| # | 이유 |
| --- | --- |
| 1 | **비용/편익 역전.** 위저드가 이기는 조건(필수 필드 다수 · 분기 · 높은 단건 인지부하 · 이탈률)이 하나도 성립하지 않는다. 필수 2개짜리 흐름이 "다음 5번"이 된다 |
| 2 | **필드끼리 서로 봐야 한다.** 기간↔예산, 기간↔반려견, 지역↔고정장소. 위저드는 이 관계를 자른다 (`DESIGN.md` §7-1 "세로축이 곧 우선순위다") |
| 3 | **진행 표시가 한 흐름에서 두 번, 다른 뜻으로 나온다.** `/ai-plans/jobs/[jobId]` 가 이미 서버가 주는 `n / m` 단계를 그린다 (#250). 입력 진행률을 얹으면 정보량이 진짜 있는 쪽의 의미가 희석된다 |
| 4 | **디자인 시스템에 어휘가 없다.** `src/components/` 에 Stepper/Progress 가 없고, `DESIGN.md` §10 이 게이지류를 배제하며 진척을 문장으로 표현한다 |
| 5 | **폼 아키텍처 재결정을 부른다.** `docs/form-guide.md` §1 이 "단계별 위저드가 필요해지면 이 결정을 다시 본다" 를 명시. 실제로 깨지는 것: `useForm` 의 전체 스키마 일괄 검증, form-guide §4 서버 400 → **단계 라우팅** 신설, §7 이탈 경고 불가(App Router 한계)에 이탈 지점 5배, `?from={jobId}` 복원의 착지 단계 결정 |
| 6 | **AI 화면에서 특히 역효과.** "AI 가 알아서 짜준다" 의 가치는 입력이 적다는 것이다. 5단계는 첫 화면부터 "오래 걸리겠네" 를 말한다 |

**재검토 조건:** 필수 필드가 크게 늘거나(숙소 유형·이동수단·동행 인원 등), **계측으로 폼 중도
이탈이 확인되면** 다시 본다. 지금은 둘 다 없다.

## 3. 설계 — `DateField` 팝오버화 (두 화면 공통 선행)

### 3-1. 왜 지금까지 흐름 안이었나

docstring 에 두 대안의 기각 기록이 있고 **제약은 실재한다.**

| 기각된 안 | 이유 | 근거 |
| --- | --- | --- |
| `BottomSheet` | `PlanCreateForm` 이 담기 시트 안에서도 렌더된다 → 시트 위 시트 | `place-add-to-plan-sheet.tsx:298` |
| `absolute` 팝오버 | 시트 패널이 `overflow-hidden`, 본문이 `overflow-y-auto` → 잘린다 | `bottom-sheet.tsx:69` · `:92` |

### 3-2. 채택 — `createPortal(document.body)` + `position: fixed`

body 에 붙은 `fixed` 요소는 **조상 `overflow` 가 없어 두 clip 을 모두 빠져나간다.**
세 사용처(`/plans/new` · 담기 시트 · `/ai-plans/new`)가 여전히 코드 한 벌로 성립한다 —
지금 구조가 지키려던 조건 그대로다.

| 항목 | 결정 |
| --- | --- |
| 위치 | 입력의 `getBoundingClientRect()` → `top: rect.bottom + 8`, `left: rect.left` |
| 폭 | 달력의 **자연 폭**(내용이 정한다)을 쓰되 `rect.width` 보다 좁아지지 않는다. 좌우는 뷰포트 여백 8px 를 남기고 clamp — 375px 에서 잘리지 않아야 한다 |
| 뒤집기 | 아래 공간이 부족하면 입력 **위로** |
| 스크롤 | **닫는다.** 재배치보다 단순하고 날짜 피커에서 표준. 중첩 스크롤러(담기 시트) 때문에 `capture: true` 로 듣는다 |
| z | `z-[60]` — 담기 시트(`z-50`) 위 |
| 그림자 | **생긴다.** 이제 진짜로 떠 있으므로 `DESIGN.md` §6 에 부합 (기존 "그림자 없음" 은 흐름 안이라서였다) |
| 삭제 | `scrollIntoView` 보정(#162) — 밀리지 않으니 보정 대상이 없다 |

### 3-3. 건드리지 않는 것

- **`useOverlay` 는 그대로.** ref 기반이라 포털 노드에서도 Esc·초기 포커스·트리거 복귀가 성립한다.
- **바깥 클릭 핸들러도 그대로.** `contains` 는 DOM 트리 기반이라 포털 노드를 정상 판정한다.
- **폼 제출 사고 없음.** `Calendar` 의 날짜 버튼이 이미 `type="button"` 이다 (`calendar.tsx:178`).
  포털은 이벤트를 **React 트리**로 버블링하므로 이 확인이 필수였다.
- **SSR 안전.** `open` 이 `false` 로 시작하므로 서버 렌더에서 포털이 돌지 않는다.

### 3-4. 함정

**초기 포커스가 스크롤을 유발하면 방금 건 스크롤 리스너가 즉시 닫는다.**
`useOverlay` 가 패널로 포커스를 넣으므로, 스크롤 리스너는 **다음 프레임에** 붙인다.

### 3-5. 부수 결정 — z 스케일 문서화

이 저장소의 **첫 포털**이다. 그리고 `z-40` / `z-50` 이 지금 관례로만 존재한다(토큰 없음).

| 층 | 값 | 예 |
| --- | --- | --- |
| 흐름 내 컨트롤에 붙은 팝오버 | `z-40` | `Menu` · `InfoTip` · 탭바 |
| 오버레이 | `z-50` | `Modal` · `BottomSheet` · `Toast` |
| **오버레이 위의 팝오버** | `z-[60]` | 날짜 달력 |

이 3단을 `DESIGN.md` §7 에 적는다. **안 적으면 다음 사람이 또 추측한다.**
CSS 변수화(`--z-*`)는 별건으로 미룬다.

### 3-6. 기존 기록

docstring 의 기각 기록은 **지우지 않는다.** "포털+fixed 가 세 번째 답이었다" 를 덧붙인다.

## 4. 설계 — `/ai-plans/new` 밀도

### 4-1. 접기 (progressive disclosure)

기본값이 있는 선택 항목을 **「더 자세히 정할게요」** 한 덩어리로 접는다.

| 접는 것 | 기본값 |
| --- | --- |
| 지역 (칩) | 제주 전체 |
| 예산 (칩 + 입력) | 상관없음 |
| 생성 옵션 (저장한 곳 우선 · 꼭 넣을 장소) | 없음 |

접힌 상태에는 한 줄 요약을 붙인다 — `제주 전체 · 예산 상관없음`. 값이 있으면 그 값으로.

### 4-2. 펼침 판정 — **마운트 시 1회만**

```
sigunguCode !== null || budgetManwon !== '' || preferFavorites || pinnedPlaces.length > 0
```

**지연 `useState` 로 1회 계산한다. 반응형으로 두지 않는다.**
반응형이면 마지막 값을 지우는 순간 **입력 중인 섹션이 접혀버린다.**
`restoreValues` 가 `sessionStorage` 를 지연 초기화로 읽는 것과 같은 이유다.

이 판정이 중요한 자리는 **`?from={jobId}` 복원**이다. 실패 후 「조건 바꾸기」로 온 사람에게
자기가 넣었던 예산이 접혀 있으면 **사라진 것처럼 보인다.**

### 4-3. 자유 요청(`requestNote`) 위치

**필수 뒤 · 접기 앞으로 옮긴다.** (아트보드 01 은 맨 위로 지정)

- 아트보드가 이 필드를 **선택**으로 둔 의도(*"필수로 두면 뭘 써야 하지에서 막힌다"*)는 그대로 지킨다.
  바꾸는 것은 **위치뿐**이다.
- 맨 위에 두면 **화면의 첫 요소가 가장 답하기 어려운 빈칸**이 된다 (빈 종이 문제).
- **접기 안으로 넣지 않는다.** AI 품질에 가장 크게 기여하는 입력이라, 묻는 것은 레이아웃 개선이
  아니라 제품 손해다.

### 4-4. 함께 걷어낼 것

| 대상 | 처리 | 이유 |
| --- | --- | --- |
| 폼 안 `h2`(`createHeading`) + `p`(`createDescription`) | **제거** | `page.tsx` 의 `h1` 바로 아래에서 같은 말을 반복 |
| `fieldRegionHint` · `fieldBudgetHint` · `preferFavoritesHint` | **`InfoTip` 으로** | 부연이지 행동을 바꾸는 문장이 아니다 |
| `fieldPetHint` · `createSubmitHint` | **유지** | 행동·기대를 바꾼다 |

`InfoTip` 도입 사유(#313)가 정확히 이 경우다 — *"상시 노출로 다 세우면 밀도만 키우고 행동은
하나도 바꾸지 않는다. 필수 표시가 아니라 원할 때 여는 채널이다."*

### 4-5. 밴드는 넣지 않는다

`Band` 는 콘텐츠 뷰(홈·일정 상세·장소 상세·마이페이지)에만 쓰이고 **이 저장소의 어떤 폼에도
없다.** 접기로 3덩어리가 되면 `gap` 으로 충분하다. **접고도 빽빽하면 그때 다시 본다** —
지금 넣으면 근거 없이 새 패턴을 만드는 셈이다.

### 4-6. rest 상태 결과

```
AI 일정 만들기

여행 기간
[시작일]  [종료일]
2박 3일

함께 갈 아이
□ 보리   □ 콩이
같이 가는 아이를 모두 골라요

어떤 여행이면 좋겠어요? (선택)
[                              ]

▸ 더 자세히 정할게요        제주 전체 · 예산 상관없음

[ AI 일정 만들기 ]
약 1분 걸려요
```

## 6. 검증

`date-field` 는 테스트가 없고 패널이 `open` 뒤에 있어 `renderToStaticMarkup` 으로 잡히지 않는다.
`testing-guide.md` §1 대로 **브라우저 실측**이다. (FE dev 서버는 **포트 5174** 고정)

- [ ] **세 사용처 × 375px / 1440px** — `/plans/new` · `/ai-plans/new` · **담기 시트 안**
      (담기 시트가 핵심 회귀 지점이다)
- [ ] 달력을 열어도 **아래 내용이 밀리지 않는다**
- [ ] 화면 하단 필드에서 **위로 뒤집힌다**
- [ ] 스크롤하면 닫힌다 (페이지 스크롤 · 시트 내부 스크롤 **둘 다**)
- [ ] Esc · 바깥 클릭 · 닫은 뒤 포커스가 입력으로 복귀
- [ ] 날짜 선택이 **폼을 제출하지 않는다**
- [ ] `?from={jobId}` 진입 시 접기 섹션이 **펼쳐진 채**로 뜬다
- [ ] 접기 섹션에서 마지막 값을 지워도 **접히지 않는다**
- [ ] `pnpm verify` · `pnpm format:check`
