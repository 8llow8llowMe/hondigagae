# 일정 상세 — 정보 계층 재설계 · 근거 토글 전면 제거

> 대상: `/plans/[planId]` (좌 레일 개요 카드 · 준비물 절 · 일차 카드) + 근거 토글을 쓰는 전 화면
> 작성: 2026-09-22
> 상태: 설계 확정 (구현 계획 미작성)

**Goal:** 일정 상세의 세 자리가 **"값을 나열한 것"에서 "계층을 가진 것"으로** 바뀐다.
좌 레일은 탐색을 하고, 준비물 빈 칸은 미완성으로 읽히지 않고, 일차 카드는 판정이 자기
영역을 갖는다. 그리고 **근거를 접는 토글을 저장소에서 없앤다.**

**Non-goal:** 새 API. 동선 지도 카드(`동선지도-세부명세.md`). 일차 편집·담기 흐름.
장소 개요 본문 접기(`place.detailOverviewMore`)와 목록 페이지네이션(`plan.loadMore`) —
근거가 아니라 다른 것이다.

## 1. 진단

### 1-1. 좌 레일 개요 카드 — 층이 7개인데 신호가 1개

`plan-overview-panel.tsx:109` 의 카드 안은 `flex flex-col gap-2` 로 7줄이 **균등하게**
쌓여 있다. 유일한 간격 차이는 동행견 앞의 `gap-5` 하나다.

| 줄                                             | 성격              | 현재 무게                     |
| ---------------------------------------------- | ----------------- | ----------------------------- |
| 제목 + `초안` + `⋯`                            | 신원              | `lg:text-display` / extrabold |
| `2026년 9월 25일 (금) – 9월 27일 (일)`         | 사실              | `text-body-2` muted           |
| `총 3일 · 예산 미정`                           | 사실              | `text-caption` muted          |
| `D-3`                                          | **상태**          | `text-body-2` bold            |
| `1일차 [적합도 여행 적합] 2일차 [적합도 보통]` | **목차 + 판정**   | caption + 배지                |
| `3일차 [적합도 보통]`                          | 〃 (wrap 고아 행) | 〃                            |
| 동행견                                         | 신원              | `text-body-1`                 |

결함 여섯:

1. **`D-3` 이 고아다.** 이 카드가 매번 답해야 하는 질문("언제 떠나지")의 답이, 바로 위
   날짜 줄과 거의 같은 무게로 네 번째 줄에 있다.
2. **성격이 다른 둘이 한 flex 줄에 있다.** `PlanPhaseVerdictStrip`(`:253`)이 `D-N`(상태)과
   일자 배지(목차)를 같은 `flex-wrap` 에 넣어, wrap 되면 `3일차 보통` 만 다음 줄에 떨어진다.
3. **목차라는 신호가 0 이다.** 각 칸은 `#day1` 앵커인데(`:262`) `›` 도 밑줄도 hover
   affordance 도 없다. #732 가 데스크톱 전용 목차 카드를 걷으면서 **"목차"라는 성격까지**
   같이 잃었다.
4. **축 라벨이 반복된다.** 배지 셋 중 둘이 `적합도 보통` 이라 한 카드에서 `적합도` 가
   세 번 선다.
5. **`예산 미정` 은 사실이 아니라 빈 상태다.** 액션으로 이어지지 않는 빈 상태를 사실처럼
   적으면 잡음만 남는다.
6. **동행견이 신원에서 가장 멀다.** `:24` 주석이 "누구와 가는가는 신원의 일부"라고 적어
   두고서, 그 값을 판정 스트립 **뒤**에 둬 신원이 둘로 쪼개져 있다.

### 1-2. 준비물 빈 상태 — 분량이 아니라 "보여 줄 것을 안 보여 준다"

`plan-packing-list.tsx` 의 `Intro`(`:284`)는 안내 2문장(63자) + CTA + 맨텍스트 `직접 추가`
다. 문제는 분량이 아니다.

- **AI 가 무엇을 골라 주는지 짐작할 단서가 0 이다.** 전부 문장으로만 있다.
- `packingSavedNote`("이 일정에 저장돼요")는 **CTA 를 누를지 정하는 데 기여하지 않는다** —
  눌러 보면 안다. 결과 화면의 캡션이 그 말을 할 자리다.
- `직접 추가`(`AddSection`)가 버튼 **아래** 맨텍스트라 두 진입점의 위계가 안 보이고,
  그 모양 자체가 미완성으로 읽힌다.

### 1-3. 일차 카드 — 판정이 자기 영역을 갖지 않는다

`plan-day-section.tsx:174` → `plan-day-verdict.tsx:89` 의 순서는 헤더 → 판정 줄 → 근거
문단 → 접기 버튼 → 1px 선 → 항목들이다.

1. **판정 덩어리가 헤더와 같은 인셋·같은 바닥이라 경계가 없다.** 근거 문장이 "1일차의
   설명"인지 "첫 항목의 설명"인지 시각적으로 안 갈린다. 1px 선은 항목 목록 앞에만 있다.
2. **결론과 입력값이 동급으로 나란하다.** `여행 적합`(결론)과 `27.9℃`(재료)가 같은 줄
   같은 무게다.
3. **액션이 두 자리로 흩어졌다.** `이 날 산책` 은 판정 줄의 `ml-auto`(`plan-day-verdict.tsx:112`)
   인데 `장소 추가`·`순서 편집` 은 카드 맨 아래다. #653 이 도구를 판정 아래로 내리기로 한
   결정이 **한 버튼에만 적용되지 않았다.**
4. **라벨이 목적지를 말하지 않는다.** `이 날 산책` 이 실제로 여는 것은 `representativePlaceId`
   의 장소 상세다.
5. **썸네일 회색이 예외가 아니라 기본이다.** `plan-item-row.tsx:130` 은 `firstImage` 만 보고
   없으면 아이콘으로 떨어지는데, dev 실측으로 이미지 없는 장소가 70% 다
   (`lib/place/illustration.ts` 머리주석).
6. **날짜 형식이 좌 레일과 다르다.** 좌 레일 `2026년 9월 25일 (금)` / 일차 카드
   `9월 25일 (금)`.

### 1-4. 횡단 — 근거 토글은 수지가 안 맞는다

`ReasonList`(`components/reason-list.tsx`)는 기본 2개(장소 패널은 3개)만 보이고 나머지를
접는다. **접어서 아끼는 것은 문장 한 줄(약 22px)이고, 접는 버튼은 44px 다**(DESIGN.md §7
최소 터치 영역). 근거가 3개인 흔한 경우 접기가 순손실이다.

더 나쁜 것은 **같은 화면에서 근거를 두 번 숨긴다**는 점이다. 장소 상세는 `ReasonList` 의
접기(`place-walk-safety-panel.tsx:176`)와 `계산 근거 보기/접기`(`:233`)를 함께 갖는다.

## 2. 기각한 안

**좌 레일 개요 카드를 둘로 쪼개기** (신원 카드 + 판정 목차 카드).
§0 의 카드 판정에는 걸리지만, 이미 레일에 개요 → 확정 버튼 → 준비물 → 병원 넷이 서 있어
다섯째 카드를 더하면 모바일에서 일차 카드까지 스크롤이 한 화면 더 늘어난다. #732 가
목차 카드를 없앤 이유가 그대로 되살아난다. **카드 안 1px 선으로 같은 구획을 만든다.**

**일자 판정 스트립을 가로 칩으로 유지하고 테두리만 주기.**
칩에 테두리를 주면 앵커임은 읽히지만, 등급을 점 하나로 줄이면 색만으로 정보를 전달하게
되어 §2-3 마지막 규칙에 걸린다. 낱말을 넣으면 폭이 세로 목록과 같아져 얻는 것이 없다.

**근거 토글을 "긴 근거에만" 남기기.**
접는 조건을 개수로 가르면 같은 컴포넌트가 화면마다 다르게 굴고, 사용자는 "왜 여기만
접히지"를 묻는다. 전부 없애는 쪽이 규칙이 하나다.

## 3. 설계 — 좌 레일 개요 카드

카드 안을 **1px 선으로 세 구획**으로 나눈다. 카드는 하나 그대로다.

```
초안                                              ⋯     ← eyebrow 줄 (제목에서 분리)
몽과 제주 2박 3일                                        ← h1
(아바타) 몽 · 폼스키 중형견                               ← 신원 완성
──────────────────────────────────────────────────
D-3   출발까지 3일                                       ← 상태 (이 카드의 헤드라인)
9.25 (금) – 9.27 (일) · 3일
──────────────────────────────────────────────────
일자별 적합도                                            ← 목차임을 라벨이 말한다
1일차                      [여행 적합]   ›
2일차                      [보통]       ›
3일차                      [보통]       ›
```

### 3-1. `초안` 배지를 제목 줄에서 뺀다

제목 위 eyebrow 줄로 올리고 `⋯` 메뉴가 그 줄의 오른쪽 끝에 선다. 제목이 2~3줄로 접힐 때
배지 위치가 제목 길이를 따라 흔들리던 것이 사라지고, `h1` 이 자기 줄을 온전히 쓴다.

### 3-2. `D-day` 가 헤드라인이다

`phaseText`(`D-3` · `D-DAY` · `오늘 3일차`)를 `text-title-1` 이상으로 올리고, 오른쪽에
보조 문구를 붙인다. 날짜 범위는 그 아래 `text-caption` 으로 내린다.

- **올해 일정이면 연도를 뗀다.** `lib/plan/date.ts` 에
  `formatPlanDateRangeCompact(startDate, endDate, today)` 를 더한다 — **시작일과 종료일이
  모두 `today` 의 해**면 `formatPlanDay` 형식(`9월 25일 (금) – 9월 27일 (일)`)이고, 한쪽이라도
  다른 해면 기존 `formatPlanDateRange` 를 그대로 돌려준다. 내년 일정에서 연도를 떼면 언제인지
  알 수 없어진다. `formatPlanDateRange` 자체는 건드리지 않는다 — 다른 화면이 쓴다.
- **`예산 미정` 을 걷는다.** 예산이 있을 때만 `· 예산 30만원` 으로 이 줄에 붙는다.
  `messages.plan.budgetEmpty` 는 이 화면에서 쓰이지 않는다.
- `phaseText` 가 `null`(지난 일정)이면 이 구획은 날짜 줄만 남는다.

### 3-3. 판정 스트립을 세로 목차로 되돌린다

**카드를 새로 만들지 않는다** — #732 가 걷어낸 것은 `hidden lg:block` 카드였지, 세로
레이아웃 자체가 아니었다. 카드 안에 두면 모든 폭에서 서므로 그 결정이 지켜진다.

- 섹션 라벨 `일자별 적합도` 를 `text-caption text-fg-muted` 로 한 번만 둔다.
  **배지에서 축 라벨을 뗀다** — `MetricBadge` 의 `axis` 를 주지 않는다. #652 의 요구
  (혼잡도의 `보통` 과 구분)는 섹션 라벨이 충족한다. `sr-only` 축 이름은 `nav` 의
  `aria-label` 이 계속 갖는다.

  > **마지막 문장은 #841 구현 중 뒤집혔다.** `nav` 의 이름은 `aria-label` 이 아니라 보이는
  > 섹션 머리를 가리키는 **`aria-labelledby`** 다 — `aria-label` 이면 같은 문구가 이름으로
  > 한 번 · 문단으로 또 한 번 읽힌다. 그리고 **`sr-only` 축은 서지 않는다**: 줄 단위 탐색
  > (NVDA `Insert+F7`)에서 축을 되살려야 한다면 배지가 아니라 `sr-only` 자리라는 것까지만
  > 정하고 유예했다. 정본은 `일정상세-세부명세.md` **D18-2** 다.

- 각 줄은 `min-h-11` 앵커이고 오른쪽 끝에 `ChevronRightIcon`(16) 이 선다. 줄 사이는 1px.
- `PLAN_VERDICT_STRIP_MAX_DAYS` 를 **4 → 7** 로 올린다. 세로 한 줄이 44px 이므로 7일이면
  308px 이고, 그 이상은 요약이 아니라 목록이 된다. 넘치는 일자는 지금처럼
  `verdictStripMore` 한 줄로 말한다.

  > **308 은 #841 실측으로 갈아 끼웠다.** 줄만 센 값이라 구획선 · 섹션 머리 · `mb-1` 이
  > 빠져 있었다 — `nav` 실측은 3줄 **173px** · 7줄 **353px** 이다 (1024 폭 2026-09-22).
  > 상한 7 자체는 그대로다. **예산을 잴 때는 353 쪽을 쓴다.** 정본은 **D18-2** 다.

### 3-4. 동행견을 제목 바로 아래로 올린다

- **1마리면 한 줄이다** — `(아바타 sm) 몽 · 폼스키 중형견`.
- **2마리 이상이면 지금 형태(전원 세로 나열)를 유지한다.** #218 이 전원 나열을 요구한
  근거는 "일자 판정이 `verdictBasisPet` 으로 부르는 이름이 반드시 이 카드 안에 있어야
  한다" 이고, 그 요구는 여러 마리일 때만 생긴다(한 마리면 `basisPetName` 이 `null` 이라
  일자 카드가 이름을 부르지 않는다 — `plan-day-verdict.tsx` 의 `basisPetName` JSDoc).
- 조회 실패·`companions.length === 0` 이면 줄 자체가 사라진다 (D5, 지금과 같다).

## 4. 설계 — 준비물 빈 상태

```
여행 준비물  [AI]
┌────────────────────────────────┐
│        ( 가방 일러스트 )          │
│  날짜 · 장소 · 예보 · 몽의 특성을   │
│      읽고 챙길 것을 골라요.        │
└────────────────────────────────┘
[ AI로 준비물 챙기기 ]  [ + 직접 추가 ]
```

- **일러스트 1종을 새로 그린다** (§7). 면은 `bg-band`, 일러스트는 `place-*.svg` 와 같은
  플랫 라인 스타일이다. **장식이 아니라 빈 칸을 메우는 것**이므로 `alt=""` 다.
- **문구를 한 문장으로 줄인다.** `packingIntro` 를
  `날짜 · 장소 · 예보 · {petName}의 특성을 읽고 챙길 것을 골라요.` 로 바꾼다.
  `{petName}` 은 대표 동행견 이름이고, **동행견을 못 찾으면 `반려견` 으로 떨어진다** —
  이름을 지어내지 않는다.

  > **치환자는 #841 구현 중 통째로 걷혔다 — 이 문단이 틀렸다.** `대표 동행견` 은 계약에
  > 없는 **FE 발명**이다: #179 로 서버는 동행 반려견 **전체**를 근거로 삼고, 특성 조회가
  > 일부만 성공하면 그 아이를 빼고 WARN 만 남기는데 `PackingListResponse` 에는 그 사실을
  > 알려 주는 필드가 없다 — 화면은 몇 마리가 들어갔는지 모른다. 두 마리 일정에서 한 아이
  > 이름만 말하면 `packingSinglePetNote`('대표 반려견 기준이에요')가 지워진 이유가 그대로
  > 되살아난다. 실제 문구에는 치환자가 없다 —
  > `AI가 날짜 · 장소 · 예보 · 반려견 특성을 읽고 챙길 것을 골라요.`
  >
  > **다시 이름을 넣으려 할 때 위 문장을 근거로 들지 말 것.** `messages/plan.ts` 의
  > `packingIntro` 주석과 테스트가 함께 막고 있다. 정본은 **D18-4-1** 이다.

- **`packingSavedNote` 를 빈 상태에서 뺀다.** 그 문장은 생성 결과(`Result`)의 캡션으로
  옮긴다 — 저장 여부가 실제로 궁금해지는 것은 목록이 생긴 뒤다. 메시지 키는 유지한다.

  > **옮기지 않았다.** `Result` 가 #586 으로 **이미** 그 자리를 갖고 있어서, #841 이 한 것은
  > 빈 상태에서 **뺀 것뿐**이다. `Result` 의 캡션을 다시 정하려면 #586 을 다시 여는 판단이
  > 따로 필요하고, 이 이슈는 그것을 하지 않았다. 정본은 **D18-4-1** 이다.

- **`직접 추가` 를 `Button variant="secondary"` 로 승격**해 CTA 와 같은 줄에 둔다.
  `AddSection`(`:548`)은 **이미 접힘 상태를 갖고 있다** — `!open` 이면
  `Button variant="ghost" size="sm"` 하나를 그린다. 바꾸는 것은 **variant 와 자리**뿐이고
  열림 동작은 그대로다. `ghost` 가 테두리도 채움도 없어 맨텍스트로 읽히던 것이 원인이다.
- 생성 실패(`generateFailed`)면 지금처럼 `ErrorState` 가 CTA 자리를 대신하고, 일러스트
  면과 안내 문장은 **남는다** — 다시 눌렀을 때 무엇이 만들어지는지가 화면에 있어야 한다
  (`Intro` 주석의 기존 판단 그대로).

**고스트 칩 미리보기는 기각했다.** 결과의 모양을 칩으로 보여 주면 설명이 가장 짧아지지만,
칩 문구가 실제 AI 응답과 어긋나면 **화면이 하지 않은 약속을 한 것**이 된다. 이 저장소가
일러스트에 "우리가 아는 것만 말한다"를 요구한 것(`lib/place/illustration.ts`)과 같은 규율이다.

## 5. 설계 — 일차 카드

```
1일차  9월 25일 (금)                                  ⋯
┌─ 등급 tint 면 + -500 실선 ────────────────────────┐
│  [여행 적합]                          27.9 ℃       │
│                                   최고 체감온도     │
│  · 반려견 출입이 확인된 장소입니다                    │
│  · 최고기온 27도, 강수확률 30% 로 …                 │
│  · (세 번째 근거 — 접지 않는다)                      │
└──────────────────────────────────────────────────┘
──────────────────────────────────────────────────
1 [일러스트] 이동                            [이동] ✓
2 [일러스트] 그디글라 게스트하우스             [숙박] ✓
──────────────────────────────────────────────────
[장소 추가] [순서 편집]              [이 날 산책 코스 →]
```

### 5-1. 판정을 tint 밴드로 감싼다

- 면은 `METRIC_TINT_TONE[tone]`, 테두리는 `METRIC_TINT_EDGE_TONE[tone]` 이다
  (`components/metric.tsx:306` · `:334`). **면만 깔지 않는다** — DESIGN.md §2-3 이
  #709 에서 못박은 규칙이고, tint 는 바닥과 밝기로 갈리지 않아 면만으로는 적록색약에게
  칠하지 않은 것과 같다.
- **판정 배지는 `surface="tint"` 다** (`BADGE_TONE_ON_TINT`, `metric.tsx:88`). 같은 톤의
  tint 위에 tint 배지를 얹으면 1.00:1 이라 배지가 사라진다.
- **`axis` 는 그대로 둔다.** 좌 레일 목차와 달리 여기는 섹션 라벨이 없어, 축 이름을 떼면
  `보통` 이 혼잡도와 구분되지 않는다.
- **판정을 못 낸 날도 밴드가 선다.** `METRIC_TINT_TONE` 에서 `unknown` 은 중립 면(`--band`)
  이라 카드 모양이 일자마다 달라지지 않는다. 그 안에는 배지 대신
  `unavailableSentence()` 의 문장만 든다.
- **`unavailableSentence()` 가 `null` 이면 밴드를 그리지 않는다.** 지금의 "말할 것이
  없으면 자리도 만들지 않는다" 판단(`plan-day-verdict.tsx:80`)을 밴드에 그대로 적용한다.
  `planDayVerdictIsBlank()` 는 손대지 않는다.
- 온도는 밴드 오른쪽 끝에 선다. **값에 등급 색을 쓰지 않는다** — §2-3 은 등급 색 숫자를
  22px 이상 + weight 900 에만 허용하고, 체감온도는 중립 수치다. tint 면 위의 텍스트 색
  (`-700`)을 그대로 쓴다.

### 5-2. 근거를 불릿 목록으로, 전부 노출한다

밴드 안 `<ul>` 이다. 순서는 서버 순서를 유지하고, 정보성(`scoreDelta === 0`)은 한 단계
흐리게 내린다 — 지금 규칙 그대로다. 접기는 없다(§6).

### 5-3. 액션을 한 자리로 모은다

`이 날 산책` 을 판정 줄에서 떼어 카드 바닥 액션 줄로 옮기고, 라벨을
`이 날 산책 코스` + `ArrowRightIcon` 으로 바꿔 목적지를 말하게 한다. `representativePlaceId`
가 `null` 이면 지금처럼 버튼이 없다. #653 이 "읽는 순서와 탭 순서를 맞춘다"로 도구를
아래로 내린 결정이 이로써 완결된다.

### 5-4. 날짜 형식

일차 카드의 `formatPlanDay` 를 정본으로 삼고 좌 레일이 거기 맞춘다(§3-2). 일차 카드는
바뀌지 않는다.

### 5-5. 썸네일 폴백 — 키는 `contentType` 이 아니라 `itemType` 이다

**`PlanItemPlace` 에는 `contentType` 이 없다** (`types/plan.ts:671` — `addr1` · `indoor` ·
`firstImage` · `lat` · `lng` 뿐). 그래서 `/places` 목록과 홈이 쓰는
`placeIllustration(contentTypeCode)` 를 이 행에서 그대로 부를 수 없다.

대신 `item.itemType.code` 가 다섯 값 중 하나로 늘 온다 (`PLAN_ITEM_TYPES`, `:563`).

| `itemType` | 일러스트                 | 상태     |
| ---------- | ------------------------ | -------- |
| `LODGING`  | `place-lodging.svg`      | 있음     |
| `MEAL`     | `place-restaurant.svg`   | 있음     |
| `PLACE`    | `place-tourist_spot.svg` | 있음     |
| `WALK`     | `plan-item-walk.svg`     | **신규** |
| `MOVE`     | `plan-item-move.svg`     | **신규** |

- 새 함수 `planItemIllustration(itemTypeCode)` 를 `lib/plan/illustration.ts` 에 둔다.
  **`lib/place/illustration.ts` 를 고치지 않는다** — 그쪽은 `contentType` 이 키이고 장소
  도메인의 것이다. 두 표가 같은 파일 몇 개를 가리키는 것은 중복이 아니라 **키가 다른 두
  매핑**이다.
- 모르는 코드는 `null` 이고 지금의 회색 아이콘 타일로 떨어진다. **카테고리를 지어내지
  않는다** (`place/illustration.ts` 의 판단 그대로).
- `firstImage` 가 있으면 사진이 이긴다. 순서는 사진 → 일러스트 → 회색 타일.
- 순번 칩(`plan-item-row.tsx:190`)은 일러스트 위에도 그대로 선다.

**실측 결과.** dev 게이트웨이 응답과 백엔드 소스 분기 추적을 함께 봤다.

**일자 판정은 실측하지 못했다** — 인증이 필요해 이번 실측에서 빠졌다. 정적 상한 13 을 가진
