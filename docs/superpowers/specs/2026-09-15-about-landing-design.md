# 서비스 소개 페이지 — `/about` 확장 설계

> 대상: `app/(main)/about/page.tsx` · `features/about/about-view.tsx` · `lib/messages/about.ts` · `DESIGN.md`(표면 예외 1절 추가)
> 이슈: **미발행** — 구현 착수 전 `[FE] feat:` 이슈로 발행한다 (`docs/git-workflow.md`)
> 작성: 2026-09-15
> 상태: 설계 확정 (구현 계획 미작성)
> 목업: `frontend/docs/features/about/소개페이지-목업.html` (정적 HTML 1장, 브라우저로 연다)

**Goal:** 로그인 없이 열리는 `/about` 을 **서비스 소개 페이지**로 확장한다. 첫 방문 보호자가
"이 서비스가 내 질문에 답하는가" 를 한 화면에서 판단하고 홈으로 넘어가게 하고, 공모전
심사자가 마지막 절에서 데이터 활용의 근거를 확인하게 한다.

**Non-goal:** 홈(`/`)의 역할 변경 — 홈은 이미 미로그인 방문자에게 실제 판정을 먼저 보여 주는
화면이다(홈-세부명세 D5-3). 새 라우트. 백엔드 호출. 회원가입·소셜 로그인·마이페이지 소개.
산책 코스(올레 29) 소개 — BE 진행 중이라 화면이 없다(screen-inventory §6-1). AI 후보 기능
10종 중 미선정 기능의 소개.

## 1. 진단

### 1-1. 서비스를 설명하는 화면이 없다

`/about` 은 #611 에서 **모바일 푸터가 빠지며 출처 표기가 갈 곳**으로 생겼다. 소개 문단 3줄 ·
데이터 출처 5개 · 면책 1줄, 정적 카드 셋이다. 서비스가 무엇을 판단하고 왜 믿을 수 있는지는
어디에도 없다.

홈은 반대로 **설명 없이 판정부터** 보여 준다. 그 설계는 옳다 — 첫 방문자가 데이터 판정을
먼저 보고 가입하게 한다(D5-3). 다만 홈은 "오늘 제주시" 라는 한 시점의 답이라 서비스의
범위(장소 필터 · 일정 · AI · 긴급)를 말하지 못한다.

### 1-2. 두 청중이 같은 문을 쓴다

| 청중 | 들어오는 길 | 알고 싶은 것 |
| --- | --- | --- |
| 첫 방문 보호자 | 검색 · 공유 링크 · 홈 하단 "서비스 소개" | 내 개를 데려가도 되는지, 지금 나가도 되는지 |
| 공모전 심사자 · 관광 담당자 | 출품 자료의 URL, 모바일 비로그인 | 어떤 공공데이터를 어떻게 판단으로 바꿨나 |

**두 청중은 순서가 다르다.** 보호자는 자기 질문의 답이 보이면 읽고, 심사자는 데이터가
보이면 읽는다. 한 화면에서 둘을 다 잡으려면 **앞은 보호자, 뒤는 심사자**로 갈라야 하고,
사용자가 정한 우선순위는 **보호자 우선**이다.

### 1-3. 소개 페이지가 홈과 경쟁하면 진다

소개가 홈의 판정 카드를 그대로 다시 그리면 같은 사실을 두 화면이 말한다(DESIGN.md §1
"같은 사실을 두 번 말하지 않는다"). 소개는 **홈으로 보내는 화면**이다 — 실데이터를 부르지
않고 **고정 예시**로 "이런 판정을 한다" 만 보여 주고, 실제 값은 홈이 답한다.

## 3. 무엇을 강조하고 무엇을 뺐나

### 3-1. 강조 — 이 서비스만 하는 말부터

| 순위 | 기능 | 왜 이 자리인가 |
| --- | --- | --- |
| 1 | **산책 안전 판정** (추정 노면 온도 · 체감온도 · 골든타임) | 기온이 아니라 **발바닥이 닿는 온도**로 판정한다. 브랜드 심볼(발바닥)의 존재 이유이고, 다른 여행 서비스에 없다. 히어로 예시가 이것이다 |
| 2 | **내 반려견 기준 필터** (크기 · 체중, 315곳) | "데려가도 되나" 가 P1 의 첫 질문. 정보 없음을 배제하지 않는 규칙까지 신뢰 요소다 |
| 3 | **적합도 + 근거** · **한산한 날** | 점수만 주지 않고 이유를 붙인다(XAI). 30일 혼잡도에서 서버가 하루를 고른다 |
| 4 | **AI 일정 · 비 오면 실내 대안** | 실제 있는 장소 목록 안에서만 고른다(환각 차단). 하루만 다시 짜기 · 준비물까지 이어진다 |
| 5 | **긴급 시설 214곳** | P2 의 가장 급한 질문. 짧게, 그러나 빠지지 않게 |
| 6 | **데이터 원천 5곳 · 근거 원칙** | P3 몫. 기존 출처 카드가 이 절로 흡수된다 |

### 3-2. 뺀 것

| 뺀 것 | 이유 |
| --- | --- |
| 회원가입 · 소셜 로그인 · 마이페이지 · 저장한 장소 | 있어야 하는 기능이지 고를 이유가 아니다. CTA 가 "가입 없이 홈부터" 라 소개하면 모순이다 |
| 산책 코스(올레 29) | BE 진행 중, FE 화면 없음. 없는 것을 소개하지 않는다 |

## 4. 구조 — 질문 3개

### 4-1. 채택: 보호자의 질문 순서로 절을 나눈다

```text
데려가도 돼요?  →  지금 나가도 돼요?  →  오늘 어디 가요?  →  위급하면?  →  무엇을 보고 판단하나요
```

기능 이름이 아니라 **사용자의 불안**이 절 제목이다. DESIGN.md §1 이 이 서비스를 "정보
서비스가 아니라 의사결정 지원" 이라 못박았고, 이 구조는 그 정의를 화면 순서로 옮긴 것이다.
P1 은 앞 셋에서, P2 는 둘째~넷째에서, P3 는 마지막에서 자기 것을 찾는다.

### 4-2. 기각

| 안 | 모양 | 기각 이유 |
| --- | --- | --- |
| A. 여행의 하루 | 출발 전 → 아침 → 낮 → 비 오는 오후 → 위급 | 따뜻하지만 길다. 심사자가 기능 범위를 빨리 잡지 못하고, "하루" 프레임에 출발 전 준비(필터·일정)가 잘 안 들어간다 |
| C. 기능 카드 그리드 | 6기능 카드 + 숫자 밴드 | 훑기는 빠르나 템플릿 랜딩으로 읽힌다. 판정과 근거가 다른 카드와 **같은 무게**가 되어 차별점이 사라진다 |

## 5. 절별 설계

문구는 **여기서 확정**한다(feature 인덱스 규칙). 전부 해요체, 용어표(DESIGN.md §1) 준수,
"최고의 · 완벽한" 류 금지. 아래 문구는 구현 시 `messages.about` 으로 옮기고, 이미 있는
`footer.tagline` · `footer.sources` · `footer.disclaimer` · `footer.contest` 는 **다시 적지 않고
그대로 읽는다**(about-view 머리 주석의 원칙 유지).

### 5-1. 히어로 (P1)

| 요소 | 내용 |
| --- | --- |
| 표지어 | `반려견과 함께하는 제주 여행` |
| `h1` (보임) | `동반 가능한 곳만 골라서, 지금 가도 되는지까지 봐요` |
| 부제 | `날씨·노면 온도·혼잡도를 공공데이터로 확인하고, 반려견의 크기와 성향에 맞는 장소로 하루 일정을 짜요. 회원가입 없이도 오늘 판정부터 볼 수 있어요.` |
| CTA 1 (채움) | `오늘 판정 보러 가기` → `/` |
| CTA 2 (윤곽) | `장소 찾기` → `/places` |
| 예시 카드 | 아래 |

**예시 카드는 고정값이다.** 백엔드를 부르지 않는다. 내용은 홈 판정 카드와 같은 어휘를 쓰되
값은 코드 상수다.

```text
오늘 산책 · 제주시 기준                    [위험]  ← --metric-critical
기온 29℃ · 추정 노면(아스팔트) 온도 56.0℃ · 체감온도 31℃
· 노면 온도가 52℃ 를 넘어 발바닥 화상 위험이 있어요
· 오늘 산책하기 좋은 시간은 06:00–08:00 이에요
화면 예시예요. 실제 값은 기상청 실시간 관측으로 계산해요.
```

- 등급어 `위험` 은 `--metric-critical-*` 로 칠한다 — 예시라도 **실제 등급 자리**다(§6-2).
- 숫자 `56.0℃` 는 홈 문구 주석의 실제 제보 사례(기온 29℃ · 노면 56℃)에서 가져왔다. "온도가
  잘못됐다" 는 제보가 나온 바로 그 장면이라 **이 서비스의 요점을 한 줄로 보여 준다.**
- 마지막 줄 캡션은 필수다. 빠지면 방문자가 지금 제주 날씨로 읽는다.

### 5-2. 데려가도 돼요? (P1)

| 요소 | 내용 |
| --- | --- |
| `h2` | `데려가도 돼요?` |
| 리드 | `장소마다 갈리는 동반 조건을 내 반려견 기준으로 걸러요.` |
| 항목 | `크기와 체중을 등록하면 그 조건으로 제주 315곳을 걸러요` / `동반 정보가 없는 곳은 '불가'로 단정하지 않고 정보 없음으로 따로 보여 줘요` / `실내인지, 지금 운영 중인지도 함께 봐요` |
| 예시 | 필터 칩(`내 반려견 기준 · 소형 · 7kg`) + 장소 행 3개(이름 · 동반 조건 태그 · 실내/실외) — 그중 하나는 `정보 없음` 점선 태그 |
| 링크 | `장소 찾기` → `/places` |

`정보 없음` 을 예시에 넣는 이유: `UNKNOWN` 을 배제하지 않는 규칙(feature 인덱스 —
`AllowedPetSize#allows`)이 이 서비스의 신뢰 요소라서다. 감추면 "다 안다" 로 읽힌다.

### 5-3. 지금 나가도 돼요? (P1 · P2)

| 요소 | 내용 |
| --- | --- |
| `h2` | `지금 나가도 돼요?` |
| 리드 | `기온이 괜찮아도 아스팔트는 뜨거워요. 발바닥이 닿는 온도로 판정해요.` |
| 항목 | `기상청 실시간 관측으로 노면(아스팔트) 온도를 추정해요` / `체감온도와 함께 안전·주의·위험으로 판정하고 이유를 붙여요` / `하루 중 산책하기 좋은 시간을 골라 줘요` / `기상특보가 발효되면 그것부터 알려요` |
| 예시 | 골든타임 곡선 — 시간축 24칸, 기온·노면 두 선, 추천 구간(06–08)을 면으로. 홈 D4-1-c 와 같은 표현(세로 막대 없음) |
| 링크 | `오늘 판정 보기` → `/` |

곡선의 색: 기온 `--fg-muted`, 노면 `--metric-critical-500`, 추천 구간 면 `--metric-high-100`.
등급 색이 **데이터 자리**에만 있다는 것을 목업에서도 지킨다.

### 5-4. 오늘 어디 가요? (P1 · P2)

| 요소 | 내용 |
| --- | --- |
| `h2` | `오늘 어디 가요?` |
| 리드 | `점수만 주지 않아요. 왜 그런지 이유를 함께 보여 줘요.` |

네 개의 하위 카드(2×2, 모바일 1단).

| 카드 | 제목 | 본문 | 예시 |
| --- | --- | --- | --- |
| a | `여행 적합도` | `날씨·동반 조건·혼잡도를 묶어 등급으로 답하고, 근거를 접어 둬요.` | 배지 `적합도 높음` + 근거 2줄 |
| b | `한산한 날` | `앞으로 30일 혼잡도 예측에서 가장 한산한 날을 골라요.` | 막대 7개, 하나만 `--congestion-best` |
| c | `AI 일정` | `반려견 조건과 여행 기간을 넣으면 하루 단위 초안을 만들어요. 실제 있는 장소만 후보로 써서 없는 곳을 지어내지 않아요.` | 일자 탭 + 항목 3개 + `하루만 다시 짜기` |
| d | `비가 오면 실내로` | `일자별 날씨를 미리 브리핑하고, 비 오는 날은 가까운 실내 대안을 함께 보여 줘요.` | 날씨 아이콘 + 실내 대안 행 |

- 카드 a 의 등급어는 **서버 `name` 과 같은 어휘**(`적합도 높음`)를 쓴다. 숫자 점수는 쓰지 않는다(§3-2).
- 카드 b 의 막대는 `--congestion-bar` / `--congestion-best` 다. 등급 스케일을 쓰지 않는다
  (DESIGN.md §2-3 #603). 목업도 같다.
- 카드 c 의 마지막 문장은 환각 차단을 사용자 언어로 옮긴 것이다. "환각" · "LLM" 은 쓰지 않는다.
- 링크: `AI 일정 만들기` → `/ai-plans/new` (보호 경로 — 미로그인이면 기존 `toLoginHref` 흐름을 탄다).

### 5-5. 위급하면? (P2)

| 요소 | 내용 |
| --- | --- |
| `h2` | `위급하면?` |
| 리드 | `여행 중 가장 급한 질문에는 가장 짧게 답해요.` |
| 항목 | `현재 위치 기준으로 동물병원·동물약국 214곳을 거리순으로 찾아요` / `지금 진료 중인지 함께 보여 줘요` / `여행 일정 안에서도 한 번에 들어가요` |

## 6. 시각 톤 — "소개 페이지 표면" 예외

사용자 결정: **브랜드 그린을 넓게 쓰는 마케팅형 룩.** 이것은 DESIGN.md §0·§1 의 두 규칙과
부딪히므로 **예외를 문서로 연다.**

### 6-1. 무엇을 여는가

| 기존 규칙 | 이 화면에서 | 근거 |
| --- | --- | --- |
| 인터페이스 안은 무채색, 채도는 데이터에만 (§1) | 히어로 · 절 구분 밴드 · 마무리 CTA 에 브랜드 그린 **면**을 쓴다 | 브랜드 에셋 규칙 "인터페이스 안은 무채색, **밖**은 브랜드 컬러". 소개 페이지는 제품을 쓰는 화면이 아니라 **제품을 소개하는 화면**이라 락업의 "스플래시·외부 노출" 자리와 같은 쪽이다 |
| 헤더 심볼 24px, 로고 자리에만 (§1) | 히어로에 락업(심볼 + 워드마크)을 `(auth)` 셸 크기(48 / 40×148)로 둔다 | 히어로에는 데이터가 없다 — §1 이 `(auth)` 셸에 2배를 허용한 근거와 같다. 헤더의 24px 은 그대로다 |
| 마케팅 톤 금지 (§1) | **열지 않는다.** 룩만 열고 카피는 그대로다 | 과장은 데이터 신뢰형 컨셉을 스스로 깎는다. 심사자가 가장 먼저 보는 것이 이 어긋남이다 |

### 6-2. 지키는 것

- **등급 색(`--metric-*`)은 예시 카드의 실제 등급 자리에만.** 절 제목 · 아이콘 · 장식에 쓰지 않는다.
- **혼잡도 막대는 `--congestion-*`**, 영업 상태는 `--status-open-*`. 목업도 제품과 같은 토큰을 쓴다.
- **브랜드 그린 위에 글자를 얹는 면은 `--brand-600` 이상**(흰 글자 5.27:1 · 700 은 6.91:1). `--brand-500` 위에 글자 금지는 그대로다(§2-4).
- **새 색을 만들지 않는다.** 연한 그린 두 단은 팔레트에 이미 있는 값을 **이름만 새로** 부른다.

| 새 토큰 | 값 | 같은 값의 기존 토큰 | 용도 |
| --- | --- | --- | --- |
| `--brand-50` | `#F0F7F3` | `--row-selected` | 절 배경 밴드 |
| `--brand-100` | `#E4F0EA` | `--metric-high-100` | 규모 타일 · 아이콘 배경 |

값이 같아도 이름을 분리하는 것은 §2-3 #598 의 원칙(다른 축은 자기 토큰을 낸다)이다.
`--metric-high-100` 을 절 배경에 그대로 쓰면 "적합도 높음" 의 tint 가 브랜드 면이 된다.

- **타이포 스케일 7단 안에서만.** 히어로 `h1` 은 `page`(34/44/800), 절 `h2` 는 `display`(28/36/800), 카드 제목 `title-2`, 본문 `body-2`, 캡션 `caption`. 스케일 밖 값을 만들지 않는다.
- **spacing · radius · shadow 는 기존 스케일.** 카드는 radius 12 + 1px 테두리, 그림자 없음. 히어로 예시 카드만 `--shadow-md` — 그린 면 위에 **떠 있는** 것이라 §6 규칙 안이다.
- **모바일 <768 에서 카드는 전폭**(§0). 그린 밴드는 원래 전폭이다.

### 6-3. DESIGN.md 갱신

§0 뒤에 **"0-2. 소개 페이지 표면"** 절을 추가한다. 내용은 §6-1 표와 §6-2 토큰 표. 이 절이
없으면 다음 화면이 "소개도 그린을 썼으니" 로 예외를 넘겨받는다 — **적용 범위를 `/about`
하나로 명시한다.**

## 7. 레이아웃 · 반응형

| 폭 | 히어로 | 절 본문 | 하위 카드 |
| --- | --- | --- | --- |
| 375 (기준) | 1단. 카피 → CTA → 예시 카드 | 1단, 좌우 16 | 1단 |

## 8. 접근성

- **`h1` 은 보인다.** 지금의 `sr-only` `h1` 을 걷는다 — 히어로가 곧 화면 제목이다.
  `h2` 상향은 `h1` 이 보이는 화면 규칙(`lg:`)을 따른다(§3-1 #358).
- 랜드마크는 셸의 것(`header` · `nav`×2 · `main` · `footer`)만. 절은 `section` +
  `aria-labelledby`.
- 등급 · 상태는 **글자가 먼저** — `위험` · `적합도 높음` · `진료중` 을 색 없이도 읽는다.
- 예시 그래프(곡선 · 막대)는 `role="img"` + `aria-label` 한 문장. 값이 데이터가 아니라 예시라
  세부 표를 붙이지 않는다.
- 그린 면 위 글자는 흰색, 면은 `--brand-700`(6.91:1). 링크는 `--link` 그대로.
- 터치 영역 44×44. CTA 버튼 높이 44 이상.

## 9. 구현 메모

이 절은 구현 계획의 입력이다. 구현 자체는 `writing-plans` 뒤에 한다.

- **서버 컴포넌트 · 프리페치 없음 · 세션 조회 없음** — 지금과 같다. 예시 값은 `features/about/`

- `messages.about` 에 §5 문구를 추가한다. `footer.*` 는 재사용. `message-tone.test.ts` 가 해요체를 감시한다.
- 보호 경로 링크(`/ai-plans/new` · `/pets/new`)는 `nav/menu-items.ts` 의 `toLoginHref` 흐름과 같게 — 미로그인이면 `returnTo` 를 붙인다. 링크가 실제로 가는 곳인지는 `site-footer.test.ts` 의 "갈 곳 있는 링크만" 패턴으로 잠근다.
- 그린 밴드는 `Canvas` 에 배경을 바꿀 수 있는 최소 변경으로 — `Canvas` 에 톤 prop 을 여는지, 소개 전용 래퍼를 두는지는 구현 계획에서 정한다. **`Surface` 안에서 배경을 덮지 않는다**(§0 "면은 카드가 소유한다").
- 골든타임 곡선 · 혼잡 막대 예시는 홈 · 장소 상세의 실제 컴포넌트를 **재사용하지 않는다** — 그 컴포넌트는 서버 타입에 묶여 있고, 여기는 고정 그림이다. 순수 SVG 로 그린다.
- 이미지는 없다. 사진을 넣으면 출처 표기가 또 필요하고(`사진 출처: 한국관광공사`), 소개가 갤러리로 읽힌다.
