## 3. A · 스크롤 무대 (#914)

### 3-1. 모양

**1024 이상.** 질문 1 · 2 · 위급 세 절에서 왼쪽 항목(`points`) 하나가 최소 뷰포트 58% 높이를 차지하고, 오른쪽 예시 열은 **헤더 아래 화면 높이의 sticky 틀**이다. 예시는 그 틀 안에서 세로 가운데에 선다(최대 560). 항목의 **중심**이 기준선(헤더 아래 화면의 가운데 = 카드 중심, 질문 2 는 개 + 카드 덩어리 중심)을 지나면 그 항목이 켜지고(지금 항목 번호 칸 채움 · 지나온 항목 브랜드 테두리 · 아직 안 온 항목은 회색 테두리와 `--fg-muted` 문장), 예시가 그 단계 상태가 된다. 고정 카드 위에는 맥락 줄(`표지어 · 제목` + 바로가기)이 붙는다. 마지막 항목이 켜지는 바로 그 순간 무대 끝이 화면 바닥에 닿아, 다음 스크롤부터 문장과 예시가 함께 올라간다. 세부는 §3-5(#940).

**1024 미만.** 쌓기 흐름은 지금 그대로다. 항목 높이를 늘리지 않고 **항목을 흐리지 않는다**(#940 — 예시가 아래에 있어 흐린 문장이 가리킬 그림이 없다). 예시의 해당 부분은 단계대로 바뀐다.

**질문 3 · 데이터 절은 무대가 아니다.** 질문 3 은 네 항목 목록 + 예시 하나다(§3-5). 데이터 절은 심사자 몫이라 훑기가 우선이다.

### 3-2. 단계표

단계 `0` 은 "무대에 들어오기 전", 마지막 단계는 "전부 보임" 이다. **정적 렌더 · 감속 모션 · JS 실패는 전부 마지막 단계다.**

| 절 | 단계 1 | 단계 2 | 단계 3 | 단계 4 |
| --- | --- | --- | --- | --- |
| 질문 1 데려가도 돼요? | 필터 칩 등장 · 행 정렬 | `정보 없음` 행이 강조되고 점선 태그가 브랜드 테두리 | 실내 · 실외 · `운영 중` 태그만 남고 나머지 태그가 흐려진다 | — |
| 질문 2 지금 나가도 돼요? | 두 선이 그려진다(800ms, 기존 곡선 그리기) | 봉우리 라벨 + 판정 배지 `위험` | 추천 구간 면 | 기상특보 띠 |
| 위급하면? | 현재 위치 점이 한 번 울리고 거리순으로 정렬된다 | `진료중` 태그 | 일정 안 진입 행 | — |

- **등급 배지는 단계 2 에서 처음 나타나고 그 뒤로 색이 바뀌지 않는다.** 단계 0 · 1 에서는 배지 자리를 비운다(투명). 다른 등급 색을 거치지 않는다.
- **기상특보 띠는 질문 2 예시에 새로 들어가는 요소다.** 항목 4("기상특보가 발효되면 그것부터 알려요")가 가리킬 그림이 지금은 없다. 색은 기존 `--metric-mid-*`(주의 계열) — 특보는 판정 등급과 같은 축의 **데이터**라 등급 색 자리다. 문구는 `messages.about.specimen.curveAlert`.
- **거리순 정렬은 `transform` 만 쓴다.** 행 순서를 DOM 에서 바꾸지 않는다 — 스크린리더가 읽는 순서는 처음부터 끝 상태(거리순)다.

### 3-3. 단계를 흘려보내는 길

장소 · 긴급 예시는 **서버 컴포넌트**이고, 곡선 예시는 클라이언트다. 둘에 같은 단계를 흘려야 한다.

| 받는 쪽 | 방법 |
| --- | --- |
| 서버 예시(장소 · 긴급) | `ScrollStage` 가 무대 래퍼에 **단계 플래그 클래스**를 붙인다(`about-stage` + `is-step-1` … ). 예시 안 요소는 `about-stage-*` 이름 클래스를 갖고, 단계별 모양은 `globals.css` 가 준다 |
| 클라이언트 예시(곡선) | `ScrollStage` 가 여는 React 컨텍스트 `useStageStep()` 을 읽는다. 무대 밖에서 쓰이면 `null` 이고, 그때는 지금처럼 스스로 1회 재생한다 |

**왜 Tailwind 변형(`group-data-[step=2]:`)이 아닌가:** 대괄호 변형은 eslint `noComplexArbitrary` 가 막고(`surface-list-2col.test.ts` 가 같은 이유로 CSS 로 나갔다), 단계마다 조합이 늘어 클래스 문자열이 읽히지 않는다. **이름 클래스 + `globals.css` 한 블록**이 이 저장소의 선례다.

**정적 렌더의 플래그는 "마지막 단계" 다.** 서버가 렌더한 마크업에는 `is-step-1 … is-step-N` 이 전부 붙어 있다. 마운트 뒤 한 번 재서 실제 위치로 맞춘다 — 아직 안 온 무대는 `0` 으로 되감기고 지나온 무대는 끝 상태로 남는다.

**`useRevealOnce` 와 다른 점 하나 — 화면 안에 걸린 무대도 되감긴다.** `useRevealOnce` 는 "로드 시 보이는 요소는 숨기지 않는다" 인데, 무대는 스크롤 위치의 함수라 첫 항목이 가운데선 아래면 화면 안에 있어도 0 이다(1280×900 에서 질문 1 예시 윗부분이 첫 화면 아래쪽에 걸린다). 대신 **첫 맞춤은 전환 없이** 적용한다 — 마운트 직후 두 프레임 동안 래퍼에 `is-settling` 이 붙어 전환을 끈다. 켜 둔 채로 되감으면 칩이 200ms 에 걸쳐 사라지는 "지우기" 가 재생된다(`useRevealOnce` 의 `armed` 가 전환을 끄는 것과 같은 이유).

**강조는 `is-live` 아래에서만 칠한다.** 래퍼에는 누적 플래그 말고 둘이 더 붙는다 — 지금 단계 하나(`is-current-N`)와 재기가 실제로 걸렸다는 표시(`is-live`). "지금 단계만 칠하는" 강조(정보 없음 행 면 · 태그 테두리 · 항목 흐림)는 `.is-live.is-current-N` 에서만 켠다. 정적 렌더와 감속 모션에는 `is-live` 가 없어, 마지막 단계의 강조가 끝 상태에 눌어붙지 않는다.

### 3-4. 트리거

- `useActiveStep`: **중심이 기준선을 지난 마지막 항목의 번호**를 돌려준다(#940 개정 — 처음에는 "윗변이 뷰포트 가운데선을 지난" 이었다, §3-5). 기준선이 두 항목 중심 사이에 있으면 위 항목, 무대를 지나왔으면 N, 아직 안 왔으면 0. **뒤로 스크롤하면 단계가 내려간다** — 무대는 1회 재생이 아니라 스크롤 위치의 함수다. 1회 재생 규칙(선행 명세 §6-4)은 무대 밖 요소(등장 · 카운트업)에만 남는다.
- **스크롤마다 한 프레임에 한 번 잰다**(passive `scroll` · `resize` + `requestAnimationFrame`). cleanup 에서 리스너 둘을 떼고 남은 프레임을 취소한다.
- **`IntersectionObserver` 를 쓰지 않는다** (구현 중 개정, #914 실측). 처음 안은 항목마다 가운데 띠(`rootMargin: '-45% 0px -45% 0px'`)를 관측해 "들어온 항목 = 현재 단계" 로 읽었다. 1280×900 에서 50px 씩 스크롤하며 기록하니 **단계를 건너뛰고(질문 1 이 0 → 3), 맨 위로 돌아와도 0 이 아닌 1 에 멈췄다.** 사건은 띠를 넘는 순간에만 오고 한 묶음 안의 순서가 일정하지 않으며, 빠른 스크롤에서는 늦게 도착한다. 사건을 "다시 잴 신호" 로만 쓰고 기하로 재는 안도 해 봤지만, 사건이 늦게 오면 그 사이 위치를 여전히 놓쳤다. 무대 셋의 항목 열 개를 한 프레임에 재는 비용은 무시할 만하고, `setStep` 은 값이 같으면 다시 그리지 않는다. 바꾼 뒤 같은 기록에서 세 무대 모두 내려갈 때 `0→1→2→3(→4)`, 올라올 때 정확히 거꾸로 `0` 까지 돌아왔다.
- **감속 모션이면 재지 않고 마지막 단계에 고정한다.** 스크롤과 함께 모양이 바뀌는 것 자체가 움직임이다.

### 3-5. 가독성 · 시선 · 질문 3 개정 (#940)

구현 뒤 화면을 다시 보고 다섯을 고쳤다. 방향은 비교 모형(현재 · 1차 · 2차 · 3차) 중 **3차**다.

| 증상 | 원인 | 결정 |
| --- | --- | --- |
| 항목 문장이 작고 얇다 | 14px · 400 이 58vh 칸 안에서 각주처럼 읽힌다. 꺼진 항목 `opacity .3` 은 대비가 약 2:1 | 문장 `text-body-1` → `lg:text-title-2`(600, 행 제목 등급). 점 → **단계 번호** + 번호 잇는 선(지나온 구간 채움). 번호 칸 기본 모양은 채움(끝 상태)이고, `is-live` 아래에서 지나온 칸은 브랜드 테두리 · 아직 안 온 칸은 회색 테두리다(그림자 고리 없음). 흐림은 `--fg-muted` 글자색, 1024 이상만 — `--fg-subtle` 은 읽는 텍스트에 쓰지 않는다(DESIGN.md §2-2, 연녹 밴드 위 3.07:1) |
| 고정 예시가 위로 치우친다 | `sticky` 헤더 아래 24 · 위 정렬인데 켜지는 항목은 화면 가운데 — 시선이 대각선으로 오간다 | 예시 열 = 헤더 아래 화면 높이의 sticky 틀, 예시 덩어리는 `margin: auto` 로 세로 가운데(넘치면 아래로). 덩어리 폭 최대 560 |
| 켜지는 항목이 가운데가 아니다 | 윗변으로 쟀다 — 문장이 기준선보다 29vh 아래일 때 켜졌다. 기준선도 뷰포트 가운데라 카드 중심보다 헤더/2 위였다 | **중심**을 **헤더 아래 화면의 가운데**(`activeStepLine`)와 비교한다. 틀의 위아래 여백이 같아(52 · 52) 카드 중심과 같은 선이다 — 질문 2 는 아래 여백을 걷어 개 + 카드 덩어리 중심이 그 선이다 |

| 바로가기가 작고 멀다 · 제목이 사라진다 | 14px, 마지막 항목보다 화면 30% 아래. 제목은 항목 2 부터 화면 밖 | 바로가기 `text-body-1`(절의 액션이라 인라인 링크 등급 `body-2` 의 예외 — DESIGN.md §3-1). 1024 이상은 **맥락 줄**로 올린다 — 고정 카드 윗변 기준 `absolute`, 제목은 절 `h2` 가 헤더 밑으로 사라진 뒤에만 드러나고(`is-heading-gone`, `aria-hidden`) 바로가기는 늘 보인다. 항목 아래 바로가기는 `lg:hidden` |
| 질문 3 카드 넷이 많다 | 1280×800 에서도 한 화면에 다 안 들어오고, 넷이 저마다 인터랙션을 가져 초점이 넷 | **네 항목 목록(탭) + 예시 하나**(`FeatureTabs`). 1024 미만은 가로 칩(`Chip` sm 모양) + 카드 머리에 제목 · 설명. 1024 이상에서 절 높이 `min(100dvh − 헤더)` · 내용 세로 가운데(`.about-q3-fill`) |

- **질문 2 캐릭터 자리.** 자세 자리(`about-pose-room`)는 예시 열이 아니라 예시 덩어리(`.about-stage-frame`)에 붙는다 — 개와 카드가 함께 가운데 선다. 맥락 줄은 그 자리 안 왼쪽에 두 줄로 쌓인다(오른쪽 여백 = 개 폭 + 인셋). 예전 카피 열 꼬리(`about-pose-tail`)는 지웠다 — 틀이 화면 높이라 예시 높이와 상관없이 무대 끝에서 풀리고, 덩어리가 가운데라 개 머리가 헤더 밑으로 들어가지 않는다. 창 높이 720 미만은 개를 모바일 크기로 줄인다(덩어리 653 → 613, 1024×700 에서 가용 636).
- **질문 3 패널은 겹치지 않는다.** 처음에는 패널 넷을 한 칸에 겹쳐 카드 높이를 가장 긴 패널에 묶었는데, 짧은 패널(여행 적합도)에서 카드 아래 절반이 비었다. 고른 패널만 서고(`display: none`) 200 동안 떠오른다. 1024 이상은 카드가 왼쪽 열과 세로 가운데라 높이가 바뀌어도 절 높이는 그대로다. **1024 미만은 탭을 바꾸면 문서 높이가 바뀐다**(§10 "문서 높이 불변" 의 예외) — 그래서 `useActiveStep` 이 본문 크기 변화(`ResizeObserver`)에도 다시 잰다. 아래 위급 무대가 밀린 채 다음 스크롤까지 단계가 어긋나지 않게.
- **탭 방향.** `aria-orientation` 은 보이는 방향을 따른다 — 정적 렌더는 가로, 마운트 뒤 1024 이상이면 세로. 화살표는 네 방향을 다 받는다.
- **질문 3 을 URL 에 두지 않는다.** 필터 · 탭 URL 규칙은 데이터를 고르는 탭 몫이고, 이것은 고정값 예시를 넘겨 보는 시연이다(`PlanSpecimen` 일자 탭과 같다). 자동으로 넘기지 않는다(WCAG 2.2.2).

**기각한 안.**

| 안 | 이유 |
| --- | --- |
| 2차 — 제목 + 예시를 왼쪽에 고정, 항목을 오른쪽에서 올린다 | 고정 덩어리가 헤더 아래 화면의 86% 라 빡빡했다(사용자 검토). 1280 이상은 절 내비가 이미 지금 절을 알려 줘 큰 제목을 붙잡을 필요가 작다 — 3차 맥락 줄이 같은 이득을 52px 로 얻는다 |
| 글 왼쪽 그대로 제목만 고정 | 항목이 제목 밑으로 들어가며 가려지고, 제목(위)과 카드(가운데) 높이가 다시 어긋난다 |
| 질문 3 을 스크롤 무대로 | 58vh × 4 로 가장 긴 절이 되고, 무대가 네 번 이어져 단조롭고, 예시 안 조작과 스크롤 전환이 부딪힌다 |

| 바로가기를 버튼으로 | 절마다 버튼이 서면 히어로 · 마무리 CTA 와 겨뤄 주 버튼이 다섯이 된다 |

## 4. B · 첫 화면 리듬 (#915)

| 요소 | 모양 | 구현 |
| --- | --- | --- |
| 제목 어절 등장 | `h1` 을 어절(공백) 단위 `span` 으로 나누고 60ms 씩 지연해 200ms 로 올라온다 | 서버 컴포넌트 `SplitHeading` + `globals.css` `@keyframes`. **JS 없음** |
| 첫 화면 높이 | 1024 이상에서 히어로가 `100dvh - --header-h` 를 채운다 | `globals.css` 이름 클래스 `about-hero-fill` — `app/globals.css` 가 이미 같은 식(`calc(100dvh - var(--header-h))`)을 쓴다 |
| 카드 패럴랙스 | 1024 이상에서 판정 카드가 스크롤의 0.12배로 거슬러 올라간다(최대 108px) | `HeroParallax` + `useScrollFrame` — 상태가 아니라 ref 로 `transform` 을 고친다 |
| 스크롤 힌트 | 1024 이상 히어로 카피 아래 "내려가며 질문 다섯 개에 답해요" 한 줄, 질문 1 절로 가는 앵커. 스크롤 40px 이후 사라지고 맨 위로 돌아오면 다시 선다. 반복 애니메이션은 없다 | `ScrollCue` + `useScrollFrame`. 사라진 동안 `tabIndex=-1` · `aria-hidden` |
| 절 내비 | 1280 이상 왼쪽 고정: 처음 · 데려가도 돼요? · 지금 나가도 돼요? · 오늘 어디 가요? · 위급하면? · 무엇을 보고 판단하나요. 현재 절이 강조되고 누르면 이동한다. **1280–1535 는 점만, 1536 이상은 라벨까지** | `SectionNav` + `useScrollFrame` · `stepAt`(기준선 뷰포트 40%) |
| 모바일 진행선 | 1024 미만에서 헤더 바로 아래 2px `--brand-500` 선이 문서 진행률만큼 찬다 | `ScrollProgressBar` + `useScrollFrame`. `transform: scaleX` 만 쓴다 · 위치는 `globals.css` `.about-progress` |
| 규모 카운트업 | 315 · 214 · 5 가 화면에 들어올 때 600ms 로 한 번 센다 | `verdict-specimen.tsx` 의 `useCountUp` 을 `use-count-up.ts` 로 빼서 공유 |

- **어절 등장은 스크린리더에 한 문장으로 읽혀야 한다.** 원문은 `h1` 안 `sr-only` 텍스트로, 조각 `span` 은 `aria-hidden` 이다. `aria-label` 로 두지 않는 이유는 브라우저 번역이 `aria-label` 을 옮기지 않아서다(판정 카드 · 규모 숫자와 같은 계약).
- **감속 모션이면 어절이 한꺼번에 끝 상태로 선다.** 전역 감속 규칙이 `animation-delay` 도 0 으로 끈다 — 길이만 줄이면 `both` 채우기 때문에 지연 동안 투명하게 머물러 어절이 60ms 간격으로 하나씩 튀어나왔다(#915 검토, Playwright `reducedMotion` 재현).
- **절 내비는 랜드마크를 늘리지 않는다.** `nav` 가 아니라 `div` + 링크 목록이다 — 셸의 랜드마크(`header` · `nav`×2 · `main` · `footer`)만 둔다는 선행 명세 §8 을 지킨다. 링크는 `aria-current="true"` 로 현재 절을 알린다.
- 진행선 · 패럴랙스 · 절 내비는 **장식**이라 감속 모션이면 멈춘다(진행선은 남되 전환 없음).
- **절 내비 라벨은 각 절의 제목(`q1.heading` …)을 그대로 읽는다** — 같은 절을 두 이름으로 부르지 않게. 처음 안은 표지어(`질문 1` · `그리고`)였는데, 1280–1535 에서는 라벨이 링크의 유일한 이름이라 `그리고` 가 가는 곳을 말하지 못했다(WCAG 2.4.4, #915 검토). 새 문구는 `nav.top`(처음) · `nav.label`(목록 이름) 둘뿐이다.
- **절 내비는 자기 면(흰 면 + 1px 테두리)을 갖는다.** 고정이라 그린 밴드(히어로 · 마무리) 위도 지나가는데, 면이 없으면 회색 점이 그린 위에서 사라진다. 그림자는 없다.
- **1280 에서 라벨을 숨기는 이유:** 콘텐츠 왼쪽 끝이 104px(좌우 여백 64 + 밴드 안쪽 40)이라 라벨까지 두면 본문에 닿는다. 점만일 때 레일 오른쪽 끝은 약 68px 이다. 링크 이름은 `sr-only` 라벨이 준다.
- **절 내비는 본문(`main`)이 끝나면 숨는다**(`opacity` 0 · `inert`). 푸터 글자는 왼쪽 40px 에서 시작해 1280×800 · 1366×768 · 1536×864 에서 맨 아래까지 내리면 흰 면이 푸터 문구를 가렸다(#915 검토 재현).
- **절 앵커는 헤더 높이만큼 스크롤 여백(`scroll-margin-top: var(--header-h)`)을 둔다** — 없으면 `처음` 이 `scrollY = 64` 에 멈춰 스크롤 힌트가 다시 서지 않고, 다른 절도 표지어가 헤더 경계에 붙는다.
- **규모 숫자는 셀 준비 중에 0 을 보인다.** 타일 등장은 타일 윗변이, 세기는 숫자가 선을 지날 때 시작해 약 17px 동안 끝 값(315)이 먼저 보였다가 44 로 떨어져 다시 셌다(#915 검토 재현).

**구현 중 개정 (#915).** 계획은 `useScrollProgress`(y · 진행률 상태) · `useActiveSection`(`IntersectionObserver`) 두 훅이었다. 둘 다 **`useScrollFrame` 하나**로 바꿨다 — 스크롤 무대(§3-4)가 관측 사건으로는 빠른 스크롤의 위치를 놓쳐 스크롤마다 재기로 옮긴 것과 같은 이유이고, 패럴랙스 · 진행선은 상태를 두면 스크롤 한 프레임마다 다시 그리게 된다. 현재 절은 스크롤 무대의 `stepAt` 을 그대로 쓴다.

## 5. C · 만져 보는 예시 (#916)

선행 명세 §6-4 가 보류한 "3단" 을 연다. **계산하는 척을 하지 않는다**는 기각 사유(기온 슬라이더)는 그대로 지킨다.

| 예시 | 조작 | 지키는 것 |
| --- | --- | --- |
| 질문 1 필터 칩 | `실내` · `운영 중` 칩이 `aria-pressed` 토글이다. 켜면 조건에 안 맞는 행이 흐려진다(`opacity` 0.3) | **행을 지우지 않는다** — 카드 높이가 바뀌면 무대 기준(항목 위치)이 밀린다. 거르는 값은 라벨 문자열이 아니라 데이터의 `indoor` 불리언이다(`isPlaceDimmed`). 칩은 28 높이 그대로 누르는 자리만 46 으로 넓힌다(`before:`, 1px 테두리 뺀 패딩 상자 기준). **무대 단계 0 에서는 칩이 `visibility: hidden` · `pointer-events: none`** — 투명하기만 하면 눌려, 켠 줄 모르는 필터가 단계 1 에 적용된 채 나타났다(#916 검토) |
| 질문 2 시각 핸들 | 곡선 아래 `input type="range"`(0–23시, 시작 12시). 끌거나 화살표로 옮기면 세로 점선 · 점이 노면 선을 따라가고, 그 시각의 기온 · 노면 · 판정을 한 줄로 보인다 | **값은 미리 적은 24점 표다**(`GOLDEN_CURVE_HOURLY`). 06–08시는 안전, 12시는 판정 카드와 같은 56.0℃ 위험이다(테스트가 잠근다). **등급 경계는 서버 기본값과 같다**(`HOURLY_GRADE_EDGES` — 노면 42 이상 주의 · 52 이상 위험, tour-service `WalkSafetyEvaluator`). 처음 안(40 · 52 초과)은 14시 52℃ 를 주의로 보여, 서버 어휘와 배지를 그대로 쓰는 예시가 실서비스와 다른 판정을 가르쳤다(#916 검토). 판정은 서버 code 를 돌려주고 톤은 `walkSafetyTone` 이 준다. **만지기 전에는 점 · 읽기 줄이 없다** — 카드 배지가 이미 위험을 말한다. **읽기는 range 의 `aria-valuetext` 하나다** — `aria-live` 를 더하면 range 가 스스로 읽는 값과 겹쳐 두 번 읽혔다. 곡선은 12시에서 접선이 수평이고 23시(x 357)까지 간다 — 예전 path 는 13시 반께 더 올라가 점이 봉우리보다 높은데 값은 낮게 읽혔다. 캡션 `화면 예시예요` 유지 |
| 질문 3 혼잡도 | 막대 hover · tap · 포커스에 날짜와 수준 툴팁 | 막대가 버튼이 되고(`aria-label` 에 같은 문장, 툴팁은 `aria-hidden`), 묶음은 `role="img"` 에서 이름 있는 `role="group"` 이 된다 — `img` 안의 버튼은 접근성 트리에서 사라진다. 수준 낱말은 서버 `CongestionLevel` 어휘(`한산` · `보통` · `혼잡`). **탭은 열기만 하고 닫기는 blur 가 맡는다** — 토글이면 안드로이드 Chrome 에서 포커스가 연 툴팁을 클릭이 바로 닫았다(#916 검토, Pixel 7). hover(`group-hover:`)는 Tailwind v4 가 `@media (hover: hover)` 안에 넣어 터치에서는 받쳐 주지 않는다. 툴팁 숨김은 `opacity-0` 이 아니라 `invisible` 이다. 첫 · 마지막 막대 툴팁은 가장자리에 붙인다 |
| 질문 3 다시 짜기 | `하루만 다시 짜기` 가 버튼이 된다. 누르면 진행 단계 셋(500ms 씩)을 지나 **지금 고른 일자**가 대체 세트로 바뀌고, 끝 문장("N일차를 다시 짰어요")이 남는다. 다시 누르면 원래 세트 | 진행 단계는 DESIGN.md §8 "무한 스피너 대신 진행 단계" 를 그대로 보여 준다. **예시 캡션을 붙인다** — "화면 예시예요. 실제로는 서버가 다시 짜요." 진행 · 끝 문장은 `aria-live`. 진행 중에는 `disabled` 가 아니라 `aria-disabled` 다(키보드로 누르면 포커스가 body 로 떨어졌다). **진행 중에 일자를 바꾸면 취소한다**(보고 있지 않은 일자가 바뀌었다). 감속 모션이면 진행 단계를 건너뛰고 끝 문장만 남긴다. 새 항목이 올라오는 등장은 넣지 않았다(새 keyframes 가 필요하고 진행 · 끝 문장이 바뀜을 알린다) |

**다시 짜기 시연의 위험.** "가짜 AI" 로 읽힐 수 있다. 그래서 두 가지를 못박는다. ① 대체 세트도 `PLAN_SPECIMEN` 과 같은 파일의 고정값이고, ② 캡션이 예시임을 밝힌다. 이것이 거슬리면 이 줄만 걷어도 나머지 C 는 선다(§12).

**판정 읽기 줄의 등급어는 서버 `name` 어휘다** — `안전` · `주의` · `위험`. 배지는 기존 `MetricBadge` 를 쓴다(색 매핑을 새로 만들지 않는다).

## 6. E · 캐릭터 (#917)

### 6-1. 원칙

선행 명세 §9 의 "이미지는 없다" 는 **사진** 금지였다(출처 표기 · 갤러리화). 자체 일러스트는 둘 다 해당하지 않아 이 문서가 개정한다. 대신 셋을 지킨다.

- **세 자리에만, 그 절의 문장을 연기하는 자세로.** 빈 곳을 채우는 장식이 아니다. 캐릭터가 화면마다 있으면 마케팅 배너가 된다(DESIGN.md §1 "마케팅 톤 금지" 와 같은 축).
- **캐릭터에 등급 색을 칠하지 않는다.** 뜨거운 노면 장면에서도 개는 크림색이고, 빨강은 열기 선에만 간다. 초록(`--brand-700`)은 귀 · 코 · 목줄 · 발바닥 패드에만 있다 — 패드는 심볼의 초록 발바닥을 받는다(#930 에서 규칙 문장에 더했다. 시안 v5 부터 패드가 초록이었다)(브랜드 에셋 규칙 "심볼을 등급 색으로 칠하지 않는다" 와 같은 축).
- **등장은 1회, 무한 반복 없음.** 자세 전환은 스크롤 단계와 시각 핸들에 묶는다.

**박스 안에 넣지 않는다.** 카드 안에 작은 개를 두는 안은 시안 검토에서 기각했다(사용자 판단, 2026-09-25). 캐릭터는 카드 **밖**, 카드 윗변이나 절 끝선 위에 발을 대고 선다.

## 7. 모션 규칙 (선행 명세 §6-4 개정)

- **새 duration 은 0개다.** 쓰는 값은 전부 DESIGN.md §8 과 선행 명세의 것이다 — 등장 200 · 형제 지연 60 · 색 · 투명도 150 · 카운트업 600 · 곡선 800 · 막대 400. 무대 전환은 200, 색 전환은 150, 위치 점 울림은 800, 자세 전환은 150, 열기 선은 200.
- **무대는 1회 재생이 아니다.** 스크롤 위치의 함수라 되돌리면 되돌아간다. 1회 규칙은 등장 · 카운트업 · 캐릭터 첫 등장에 남는다.
- **움직이는 속성은 `transform` · `opacity` · SVG `stroke-*` · 색(배경 · 테두리)뿐이다.** 레이아웃을 움직이지 않는다 — 문서 높이가 바뀌면 스크롤 위치로 재는 단계가 연쇄로 어긋난다.
- **위치 점 울림(위급 절 단계 1)은 곡선 그리기 길이 800 을 다시 쓴다.** 새 길이가 아니라 기존 값의 재사용이고, 단계 1 에 들어올 때마다 1회다.
- **감속 모션이면** 무대는 마지막 단계에 고정, 패럴랙스 · 어절 등장 · 캐릭터 등장은 끝 상태, 카운트업은 즉시 끝 값이다. 전역 규칙(`app/globals.css` — 한 프레임으로 줄임)이 CSS 쪽을, 각 훅의 `matchMedia` 가 JS 쪽을 맡는다.

## 8. 접근성

- 무대 단계는 **시각 강조**다. 모든 항목 문장과 예시의 끝 상태 내용은 처음부터 DOM 에 있고 순서도 끝 상태 그대로다. 단계가 바뀌어도 스크린리더에 알리지 않는다(`aria-live` 없음) — 스크롤할 때마다 읽으면 소음이다.
- 필터 칩: `button` + `aria-pressed`. 시각 핸들: `input type="range"` + `<label>` + 읽기 줄 `aria-live="polite"`. 혼잡도 막대: `button` + `aria-label`. 다시 짜기: `button`, 진행 단계 줄 `aria-live="polite"`.
- 캐릭터는 `alt=""` + 부모 `aria-hidden` — 내용을 더하지 않는 그림이다.
- 터치 영역 44 이상(칩 · 막대 · 다시 짜기 · 핸들 손잡이 줄).
- 절 내비 링크는 `aria-current`. 포커스 링은 기존 `focus-visible:ring-brand-500`.

### 9-2. 훅

```ts
// 중심이 기준선을 지난 마지막 항목 번호(0..N). 첫 렌더 · 감속 모션이면 N (#940 — 윗변 → 중심).
// live 는 재기가 걸렸는지 — 강조의 훅. copy 를 주면 그 안 h2 가 헤더 밑으로 들어갔는지(headingGone).
useActiveStep(count: number, copy?: RefObject<Element | null>): {
  step: number
  live: boolean
  settling: boolean
  headingGone: boolean
  register: (index: number) => (node: Element | null) => void
}

// 기준선 — 헤더 아래 화면의 가운데 (#940). 헤더 높이는 --header-h 토큰에서 읽는다.
activeStepLine(viewportHeight: number, headerHeight: number): number

// 중심들(무대) · 윗변들(절 내비) → 번호. null 은 건너뛰되 번호는 원래 자리로 센다.
stepAt(positions: readonly (number | null)[], line: number): number

// 스크롤 · 리사이즈마다 한 프레임에 한 번 onFrame (마운트 때 한 번 먼저). passive + rAF.
// 패럴랙스 · 스크롤 힌트 · 진행선 · 절 내비가 쓴다 (#915 개정 — 계획의 두 훅을 대신한다).
useScrollFrame(onFrame: () => void): void

// 기존 verdict-specimen 의 것을 옮긴다. 시그니처 그대로.
useCountUp(target: number, play: boolean): number
```
