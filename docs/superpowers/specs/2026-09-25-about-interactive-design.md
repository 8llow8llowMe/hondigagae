## 3. A · 스크롤 무대 (#914)

### 3-1. 모양

**1024 이상.** 질문 1 · 2 · 위급 세 절에서 왼쪽 항목(`points`) 하나가 최소 뷰포트 58% 높이를 차지하고, 오른쪽 예시는 `position: sticky`(헤더 아래 24)로 붙는다. 항목의 윗변이 화면 세로 가운데선을 지나면 그 항목이 켜지고(`opacity` 0.3 → 1, 표지 칸 채움), 예시가 그 단계 상태가 된다.

**1024 미만.** 쌓기 흐름은 지금 그대로다. 항목 높이를 늘리지 않고, 켜진 항목만 강조되며 예시의 해당 부분이 같이 바뀐다.

**질문 3 · 데이터 절은 무대가 아니다.** 질문 3 은 하위 카드 넷이 한 항목씩이라 무대로 만들 항목 목록이 없고, 데이터 절은 심사자 몫이라 훑기가 우선이다.

### 3-2. 단계표

단계 `0` 은 "무대에 들어오기 전", 마지막 단계는 "전부 보임" 이다. **정적 렌더 · 감속 모션 · JS 실패는 전부 마지막 단계다.**

| 절 | 단계 1 | 단계 2 | 단계 3 | 단계 4 |
| --- | --- | --- | --- | --- |
| 질문 1 데려가도 돼요? | 필터 칩 등장 · 행 정렬 | `정보 없음` 행이 강조되고 점선 태그가 브랜드 테두리 | 실내 · 실외 · `운영 중` 태그만 남고 나머지 태그가 흐려진다 | — |
| 질문 2 지금 나가도 돼요? | 두 선이 그려진다(800ms, 기존 곡선 그리기) | 봉우리 라벨 + 판정 배지 `위험` | 추천 구간 면 | 기상특보 띠 |
| 위급하면? | 현재 위치 점이 한 번 울리고 거리순으로 정렬된다 | `진료중` 태그 | 일정 안 진입 행 | — |

- **등급 배지는 단계 2 에서 처음 나타나고 그 뒤로 색이 바뀌지 않는다.** 단계 0 · 1 에서는 배지 자리를 비운다(투명). 다른 등급 색을 거치지 않는다.
- **기상특보 띠는 질문 2 예시에 새로 들어가는 요소다.** 항목 4("기상특보가 발효되면 그것부터 알려요")가 가리킬 그림이 지금은 없다. 색은 기존 `--metric-mid-*`(주의 계열) — 특보는 판정 등급과 같은 축의 **데이터**라 등급 색 자리다. 문구는 `messages.about.specimen.curveAlert`.
- **거리순 정렬은 `transform` 만 쓴다.** 행 순서를 DOM 에서 바꾸지 않는다 — 스크린리더가 읽는 순서는 처음부터 끝 상태(거리순)다.

### 3-3. 단계를 흘려보내는 길

장소 · 긴급 예시는 **서버 컴포넌트**이고, 곡선 예시는 클라이언트다. 둘에 같은 단계를 흘려야 한다.

| 받는 쪽 | 방법 |
| --- | --- |
| 서버 예시(장소 · 긴급) | `ScrollStage` 가 무대 래퍼에 **단계 플래그 클래스**를 붙인다(`about-stage` + `is-step-1` … ). 예시 안 요소는 `about-stage-*` 이름 클래스를 갖고, 단계별 모양은 `globals.css` 가 준다 |
| 클라이언트 예시(곡선) | `ScrollStage` 가 여는 React 컨텍스트 `useStageStep()` 을 읽는다. 무대 밖에서 쓰이면 `null` 이고, 그때는 지금처럼 스스로 1회 재생한다 |

**왜 Tailwind 변형(`group-data-[step=2]:`)이 아닌가:** 대괄호 변형은 eslint `noComplexArbitrary` 가 막고(`surface-list-2col.test.ts` 가 같은 이유로 CSS 로 나갔다), 단계마다 조합이 늘어 클래스 문자열이 읽히지 않는다. **이름 클래스 + `globals.css` 한 블록**이 이 저장소의 선례다.

**정적 렌더의 플래그는 "마지막 단계" 다.** 서버가 렌더한 마크업에는 `is-step-1 … is-step-N` 이 전부 붙어 있다. 마운트 뒤 한 번 재서 실제 위치로 맞춘다 — 아직 안 온 무대는 `0` 으로 되감기고 지나온 무대는 끝 상태로 남는다.

**`useRevealOnce` 와 다른 점 하나 — 화면 안에 걸린 무대도 되감긴다.** `useRevealOnce` 는 "로드 시 보이는 요소는 숨기지 않는다" 인데, 무대는 스크롤 위치의 함수라 첫 항목이 가운데선 아래면 화면 안에 있어도 0 이다(1280×900 에서 질문 1 예시 윗부분이 첫 화면 아래쪽에 걸린다). 대신 **첫 맞춤은 전환 없이** 적용한다 — 마운트 직후 두 프레임 동안 래퍼에 `is-settling` 이 붙어 전환을 끈다. 켜 둔 채로 되감으면 칩이 200ms 에 걸쳐 사라지는 "지우기" 가 재생된다(`useRevealOnce` 의 `armed` 가 전환을 끄는 것과 같은 이유).

**강조는 `is-live` 아래에서만 칠한다.** 래퍼에는 누적 플래그 말고 둘이 더 붙는다 — 지금 단계 하나(`is-current-N`)와 재기가 실제로 걸렸다는 표시(`is-live`). "지금 단계만 칠하는" 강조(정보 없음 행 면 · 태그 테두리 · 항목 흐림)는 `.is-live.is-current-N` 에서만 켠다. 정적 렌더와 감속 모션에는 `is-live` 가 없어, 마지막 단계의 강조가 끝 상태에 눌어붙지 않는다.

### 3-4. 트리거

- `useActiveStep`: **윗변이 화면 가운데선을 지난 마지막 항목의 번호**를 돌려준다. 가운데선이 항목 사이 틈에 있으면 위 항목, 무대를 지나왔으면 N, 아직 안 왔으면 0. **뒤로 스크롤하면 단계가 내려간다** — 무대는 1회 재생이 아니라 스크롤 위치의 함수다. 1회 재생 규칙(선행 명세 §6-4)은 무대 밖 요소(등장 · 카운트업)에만 남는다.
- **스크롤마다 한 프레임에 한 번 잰다**(passive `scroll` · `resize` + `requestAnimationFrame`). cleanup 에서 리스너 둘을 떼고 남은 프레임을 취소한다.
- **`IntersectionObserver` 를 쓰지 않는다** (구현 중 개정, #914 실측). 처음 안은 항목마다 가운데 띠(`rootMargin: '-45% 0px -45% 0px'`)를 관측해 "들어온 항목 = 현재 단계" 로 읽었다. 1280×900 에서 50px 씩 스크롤하며 기록하니 **단계를 건너뛰고(질문 1 이 0 → 3), 맨 위로 돌아와도 0 이 아닌 1 에 멈췄다.** 사건은 띠를 넘는 순간에만 오고 한 묶음 안의 순서가 일정하지 않으며, 빠른 스크롤에서는 늦게 도착한다. 사건을 "다시 잴 신호" 로만 쓰고 기하로 재는 안도 해 봤지만, 사건이 늦게 오면 그 사이 위치를 여전히 놓쳤다. 무대 셋의 항목 열 개를 한 프레임에 재는 비용은 무시할 만하고, `setStep` 은 값이 같으면 다시 그리지 않는다. 바꾼 뒤 같은 기록에서 세 무대 모두 내려갈 때 `0→1→2→3(→4)`, 올라올 때 정확히 거꾸로 `0` 까지 돌아왔다.
- **감속 모션이면 재지 않고 마지막 단계에 고정한다.** 스크롤과 함께 모양이 바뀌는 것 자체가 움직임이다.

## 4. B · 첫 화면 리듬 (#915)

| 요소 | 모양 | 구현 |
| --- | --- | --- |
| 제목 어절 등장 | `h1` 을 어절(공백) 단위 `span` 으로 나누고 60ms 씩 지연해 200ms 로 올라온다 | 서버 컴포넌트 `SplitHeading` + `globals.css` `@keyframes`. **JS 없음** |
| 첫 화면 높이 | 1024 이상에서 히어로가 `100dvh - --header-h` 를 채운다 | `globals.css` 이름 클래스 `about-hero-fill` — `app/globals.css` 가 이미 같은 식(`calc(100dvh - var(--header-h))`)을 쓴다 |
| 카드 패럴랙스 | 1024 이상에서 판정 카드가 스크롤의 0.12배로 거슬러 올라간다(최대 108px) | `useScrollProgress` — passive scroll + rAF 한 번 |
| 스크롤 힌트 | 히어로 하단에 "내려가며 질문 다섯 개에 답해요" 한 줄, 스크롤 40px 이후 사라진다. 반복하지 않는다 | 같은 훅 |
| 절 내비 | 1280 이상 왼쪽 고정: 처음 · 질문 1 · 질문 2 · 질문 3 · 그리고 · 데이터. 현재 절이 강조되고 누르면 이동한다 | 클라이언트 `SectionNav` + `useActiveSection`(`rootMargin: '-40% 0px -55% 0px'`) |
| 모바일 진행선 | 1024 미만에서 헤더 바로 아래 2px `--brand-500` 선이 문서 진행률만큼 찬다 | 같은 `useScrollProgress`. `transform: scaleX` 만 쓴다 |
| 규모 카운트업 | 315 · 214 · 5 가 화면에 들어올 때 600ms 로 한 번 센다 | `verdict-specimen.tsx` 의 `useCountUp` 을 `use-count-up.ts` 로 빼서 공유 |

- **어절 등장은 스크린리더에 한 문장으로 읽혀야 한다.** `h1` 에 `aria-label` 로 원문을 두고 조각 `span` 은 `aria-hidden` 이다.
- **절 내비는 랜드마크를 늘리지 않는다.** `nav` 가 아니라 `div` + 링크 목록이다 — 셸의 랜드마크(`header` · `nav`×2 · `main` · `footer`)만 둔다는 선행 명세 §8 을 지킨다. 링크는 `aria-current="true"` 로 현재 절을 알린다.
- 진행선 · 패럴랙스 · 절 내비는 **장식**이라 감속 모션이면 멈춘다(진행선은 남되 전환 없음).

| 예시 | 조작 | 지키는 것 |
| --- | --- | --- |

## 6. E · 캐릭터 (#917)

### 6-1. 원칙

선행 명세 §9 의 "이미지는 없다" 는 **사진** 금지였다(출처 표기 · 갤러리화). 자체 일러스트는 둘 다 해당하지 않아 이 문서가 개정한다. 대신 셋을 지킨다.

- **세 자리에만, 그 절의 문장을 연기하는 자세로.** 빈 곳을 채우는 장식이 아니다. 캐릭터가 화면마다 있으면 마케팅 배너가 된다(DESIGN.md §1 "마케팅 톤 금지" 와 같은 축).
- **캐릭터에 등급 색을 칠하지 않는다.** 뜨거운 노면 장면에서도 개는 크림색이고, 빨강은 열기 선에만 간다. 초록은 귀 · 코 · 목줄에만 있다(브랜드 에셋 규칙 "심볼을 등급 색으로 칠하지 않는다" 와 같은 축).
- **등장은 1회, 무한 반복 없음.** 자세 전환은 스크롤 단계와 시각 핸들에 묶는다.

**박스 안에 넣지 않는다.** 카드 안에 작은 개를 두는 안은 시안 검토에서 기각했다(사용자 판단, 2026-09-25). 캐릭터는 카드 **밖**, 카드 윗변이나 절 끝선 위에 발을 대고 선다.

## 7. 모션 규칙 (선행 명세 §6-4 개정)

- **새 duration 은 0개다.** 쓰는 값은 전부 DESIGN.md §8 과 선행 명세의 것이다 — 등장 200 · 형제 지연 60 · 색 · 투명도 150 · 카운트업 600 · 곡선 800 · 막대 400. 무대 전환은 200, 색 전환은 150, 위치 점 울림은 800, 자세 전환은 150, 열기 선은 200.
- **무대는 1회 재생이 아니다.** 스크롤 위치의 함수라 되돌리면 되돌아간다. 1회 규칙은 등장 · 카운트업 · 캐릭터 첫 등장에 남는다.
- **움직이는 속성은 `transform` · `opacity` · SVG `stroke-*` · 색(배경 · 테두리)뿐이다.** 레이아웃을 움직이지 않는다 — 문서 높이가 바뀌면 스크롤 위치로 재는 단계가 연쇄로 어긋난다.
- **위치 점 울림(위급 절 단계 1)은 곡선 그리기 길이 800 을 다시 쓴다.** 새 길이가 아니라 기존 값의 재사용이고, 단계 1 에 들어올 때마다 1회다.
- **감속 모션이면** 무대는 마지막 단계에 고정, 패럴랙스 · 어절 등장 · 캐릭터 등장은 끝 상태, 카운트업은 즉시 끝 값이다. 전역 규칙(`app/globals.css` — 한 프레임으로 줄임)이 CSS 쪽을, 각 훅의 `matchMedia` 가 JS 쪽을 맡는다.

## 8. 접근성

- 무대 단계는 **시각 강조**다. 모든 항목 문장과 예시의 끝 상태 내용은 처음부터 DOM 에 있고 순서도 끝 상태 그대로다. 단계가 바뀌어도 스크린리더에 알리지 않는다(`aria-live` 없음) — 스크롤할 때마다 읽으면 소음이다.
- 필터 칩: `button` + `aria-pressed`. 시각 핸들: `input type="range"` + `<label>` + 읽기 줄 `aria-live="polite"`. 혼잡도 막대: `button` + `aria-label`. 다시 짜기: `button`, 진행 단계 줄 `aria-live="polite"`.
- 캐릭터는 `alt=""` + 부모 `aria-hidden` — 내용을 더하지 않는 그림이다.
- 터치 영역 44 이상(칩 · 막대 · 다시 짜기 · 핸들 손잡이 줄).
- 절 내비 링크는 `aria-current`. 포커스 링은 기존 `focus-visible:ring-brand-500`.

## 12. 후속 · 미결

- **캐릭터 SVG 벡터화.** PNG 로 먼저 싣는다. 벡터화 도구로 옮기고 색을 토큰 값에 맞춘 뒤 기존 일러스트와 같은 그레인 필터를 얹는다. 별도 이슈.
- **다시 짜기 시연.** "가짜 AI" 로 읽힌다는 판단이 나오면 이 줄만 걷는다. 나머지 C 는 독립이다.
- **D 모바일 고정 무대.** 채택하지 않았다. 모바일 체류 시간 데이터가 생기면 다시 본다.
- **`animation-timeline`.** Firefox 지원 뒤 `useScrollProgress` 내부를 CSS 로 바꿀 수 있다. 훅 시그니처는 그대로 둔다.
