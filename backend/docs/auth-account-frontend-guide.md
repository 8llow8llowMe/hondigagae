# Auth Account Frontend Guide — 비밀번호 재설정 · 계정 연결/전환

## Purpose

이 문서는 프론트엔드에서 **비밀번호 재설정**과 **일반↔소셜 계정 연결/전환** UX를 구현할 때
auth-service API를 어떻게 쓰는지 정리한다. 로그인/회원가입 기본 흐름은 기존 명세를 따르고,
여기서는 계정 복구·연결 시나리오만 다룬다.

## 계정 모델 이해 (전제)

계정의 식별자는 **이메일**이며 DB unique 키다. 이메일 변경 기능은 의도적으로 제공하지 않는다.
한 계정은 두 로그인 수단을 가질 수 있다.

| 계정 상태 | password | provider | 가능한 로그인 |
| --- | --- | --- | --- |
| 일반 계정 | 있음 | null | 이메일 로그인 |
| 소셜 전용 계정 | null | KAKAO/NAVER | 소셜 로그인 |
| **연결된 계정** | 있음 | KAKAO/NAVER | **둘 다** |

`GET /api/v1/members/me` 응답의 `provider` + `hasPassword` 조합으로 FE가 상태를 구분한다:
`hasPassword=true, provider=null` → 일반 / `hasPassword=false, provider=KAKAO` → 소셜 전용 /
`hasPassword=true, provider=KAKAO` → 연결됨. **사용자 정보 화면의 비밀번호 메뉴는 이 조합으로 분기한다**
(소셜 전용 → "비밀번호 설정" 노출, 비밀번호 변경 숨김 / 연결됨 → "비밀번호 변경" + "소셜 전용으로 전환").

## 1. 비밀번호 재설정 (비밀번호를 잊은 사용자)

로그인 화면의 "비밀번호를 잊으셨나요?" 진입점에 연결한다. **일반/연결 계정 전용** —
소셜 전용 계정은 비밀번호가 없으므로 재설정 대상이 아니다(아래 응답 정책 참고).

| API | 인증 | 용도 |
| --- | --- | --- |
| `POST /api/v1/auth/password/reset/send-code` | 불필요 | `{email}` — 재설정 인증코드 메일 발송 |
| `POST /api/v1/auth/password/reset` | 불필요 | `{email, code, newPassword}` — 재설정 |

```
[화면 흐름]
이메일 입력 → send-code (항상 성공 응답)
→ "메일을 확인해주세요" 안내 (가입 여부를 화면에서 노출하지 않는다!)
→ 코드 + 새 비밀번호 입력 → reset → 성공 시 로그인 화면으로
```

- **send-code는 항상 200**이다. 미가입 이메일/소셜 전용 계정 여부는 **메일 내용**으로만 안내된다
  (계정 존재 여부를 응답으로 노출하지 않는 보안 정책). FE는 성공/실패 분기 없이
  "입력하신 주소로 안내 메일을 보냈습니다"로 통일해 표시한다.
- 소셜 전용 계정 사용자는 "카카오/네이버 로그인 이용" 안내 메일을 받는다. FE가 미리 걸러줄
  필요 없다 (걸러주는 것 자체가 계정 정보 노출이다).
- 재설정 성공 시 **전 기기 세션이 무효화**된다. "비밀번호가 변경되었습니다. 다시 로그인해주세요"로 안내.
- 새 비밀번호 규칙은 회원가입과 동일 (8~20자, 영문+숫자+특수문자, 공백 불가).

**에러 처리**

| 상황 | HTTP | resultCode | 프론트 처리 |
| --- | --- | --- | --- |
| 60초 내 재발송 | 429 | `AUTH_003` | "잠시 후 다시 요청해주세요" + 재요청 버튼 비활성 카운트다운 |
| IP 발송 상한 초과 | 429 | `AUTH_016` | "요청이 너무 많습니다" 안내 |
| 코드 불일치 | 400 | `AUTH_004` | 코드 입력란 오류 표시 (남은 시도 기회 있음) |
| 코드 만료/미발급 | 400 | `AUTH_005` | "코드가 만료되었습니다" + 재발송 유도 |
| 코드 5회 오입력 | 400 | `AUTH_017` | 코드 무효화됨 — 처음(발송)부터 다시 |
| 필드 검증 | 400 | `AUTH_101/102/104/106~108` | 필드별 오류 표시 |

## 2. 계정 연결 — 일반 계정 사용자가 같은 이메일로 소셜 로그인

**FE가 할 일은 없다. 자동으로 연결된다.** 일반 계정(비밀번호 있음)이 있는 이메일로
소셜 로그인하면 백엔드가 그 계정에 provider를 연결하고 그대로 로그인시킨다.
이후 이메일 로그인과 소셜 로그인 **둘 다** 사용 가능하다.

- 자동 연결이 안전한 이유: 소셜 쪽은 provider가 검증한 이메일만 허용(`AUTH_012`로 미검증 거부),
  일반 가입도 이메일 인증 필수 — 양쪽 다 메일함 소유가 증명된 상태다.
- 연결되는 순간 사용자에게 **"소셜 로그인이 연결되었습니다" 통보 메일**이 발송된다
  (본인이 아니면 비밀번호 변경을 유도하는 탈취 감지 수단).
- 반대 provider로 이미 연결된 계정이면 `409 AUTH_008` ("이미 카카오로 가입된 계정입니다") —
  resultMessage를 그대로 표시하면 된다.

## 3. 계정 전환/추가 — 소셜 전용 사용자가 이메일 로그인도 쓰고 싶을 때

소셜 전용 계정이 같은 이메일로 회원가입을 시도하면 `409 MEMBER_001`로 막힌다.
이때 "소셜 로그인 후 비밀번호를 설정하세요"로 유도하는 것이 정석 UX다.

| API | 인증 | 용도 |
| --- | --- | --- |
| `POST /api/v1/members/me/password/setup` | 필수 | `{newPassword}` — 비밀번호 최초 설정 |

```
[화면 흐름]
회원가입 시도 → 409 MEMBER_001 → "카카오로 가입된 이메일입니다. 카카오 로그인 후
설정에서 비밀번호를 만들 수 있어요" 안내 → 소셜 로그인 → 마이페이지 "비밀번호 설정"
→ setup 성공 → 이후 이메일 로그인도 가능
```

- 진입점: 마이페이지/설정에서 `hasPassword == false` 인 계정에 "비밀번호 설정" 메뉴를 노출한다.
- 이미 비밀번호가 있는 계정이 호출하면 `400 MEMBER_008` — "비밀번호 변경을 이용해주세요".
- 설정 후 세션은 유지된다 (로그아웃되지 않음).

## 4. 소셜 전용으로 전환 — 연결된 계정의 비밀번호 제거

연결된 계정(`hasPassword=true && provider != null`)이 이메일 로그인을 버리고
소셜 전용으로 전환한다. 비밀번호가 **완전히 제거(null)** 되어 이후 이메일 로그인이 불가하다.

| API | 인증 | 용도 |
| --- | --- | --- |
| `DELETE /api/v1/members/me/password` | 필수 | 비밀번호 제거 → 소셜 전용 계정으로 전환 |

```
[화면 흐름]
설정 → "소셜 전용으로 전환" → 확인 팝업
"카카오 전용 계정으로 전환할까요? 이메일 로그인을 더 이상 사용할 수 없고,
 모든 기기에서 로그아웃됩니다." [전환] [취소]
→ DELETE 성공 → 로그인 화면으로 (소셜 로그인 유도)
```

- **되돌릴 수 있는 결정이지만**(다시 "비밀번호 설정"으로 이메일 로그인 복구 가능) 전 기기
  로그아웃이 동반되므로 반드시 확인 팝업을 거친다.
- 성공 시 **전 기기 세션 무효화** + refresh 쿠키 제거 + "소셜 전용 계정으로 전환되었습니다"
  통보 메일 발송. FE는 로컬 토큰을 지우고 로그인 화면으로 보낸다.
- 전환 후에는 사용자 정보 화면에서 "비밀번호 변경" 메뉴를 숨긴다 (`hasPassword=false`).

**에러 처리**

| 상황 | HTTP | resultCode | 프론트 처리 |
| --- | --- | --- | --- |
| 소셜 미연결(일반 전용) 계정 | 400 | `MEMBER_009` | 메뉴 자체를 노출하지 않아야 함 — 방어적 안내 |
| 이미 소셜 전용 계정 | 400 | `MEMBER_007` | 메뉴 자체를 노출하지 않아야 함 |

## 흐름 요약

```
[비밀번호 재설정]
로그인 화면 → "비밀번호를 잊으셨나요?" → 이메일 입력 → 메일의 코드 + 새 비밀번호
→ 성공 → 전 기기 로그아웃됨 → 재로그인

[일반 → +소셜 (연결)]
소셜 로그인 버튼만 누르면 끝 (자동 연결 + 통보 메일). 이후 두 방법 모두 로그인 가능.

[소셜 → +이메일 (비밀번호 설정)]
소셜 로그인 → 마이페이지 "비밀번호 설정" → 이후 두 방법 모두 로그인 가능.

[연결됨 → 소셜 전용 (전환)]
설정 "소셜 전용으로 전환" → 확인 팝업 → 비밀번호 제거 + 전 기기 로그아웃
→ 이후 소셜 로그인만 가능 (필요하면 "비밀번호 설정"으로 복구).
```
