## 1. 정본 계층 (확정)

```text
혼디가개 디자인 가이드.dc.html  ← 상위 정본 (Claude Design 산출물)
        ↓ 값을 옮겨 적는다

        ↓ CSS 변수로 선언

        ↓ @theme inline 으로 매핑
frontend/app/globals.css
```

- **가이드에 없는 값을 DESIGN.md 에서 만들지 않는다.** 필요하면 가이드를 먼저 고친다.
- 가이드 문서 자신이 이 관계를 명시한다 — "퍼블리싱 시 코드베이스의 `frontend/DESIGN.md`

  등급 색이라 의미가 충돌하고, 0px 라운드·엔터프라이즈 밀도가 제품 톤과 맞지 않는다.

## 2. 검증 방법 — 가이드 요약을 그대로 믿지 않았다

가이드 산문에는 내부 모순이 있었다(예: "등급 색을 브랜드로 전용하지 않는다" 면서
링크와 등급 마크에 같은 hex 를 씀). 그래서 **아트보드 8종의 실제 값을 전수 집계**해
교차검증한 뒤 토큰을 정했다.

| 집계 대상       | 방법                                           | 쓰임                                  |
| --------------- | ---------------------------------------------- | ------------------------------------- |
| hex 빈도        | 아트보드 8종에서 `#RRGGBB` 전수 카운트         | 실제 팔레트 확정 · 미사용 토큰 색출   |
| `font-size`     | 빈도 + 앞뒤 문맥 샘플링                        | 스케일 밖 값이 화면인지 주석인지 판별 |
| `border-radius` | 빈도 + `role=radio\|checkbox` 요소만 따로 집계 | 칩 radius 확정                        |
| 대비비          | 30개 조합 재계산                               | DESIGN.md 표의 실측값                 |

**이 방법이 실제로 잡아낸 것들**

- `#237A54`(당시 DESIGN.md 의 링크색) — 아트보드 **0회**. 실제 링크는 `#1F7A55` **112회**.
- `--warn-*` · `--info-*` · `--success-*` — 전부 **0회**.
- `#F5F6F8`(당시 `--bg-subtle`) — 화면 안 **0회**. 가이드가 "모형 밖 자료만" 이라 못박은 값.
- `#EEF0F3` — **328회**로 3번째로 많이 쓰였는데 **토큰이 없었다** → `--band` 신설.
- 필터 컨트롤 radius — 전부 **8**. `rounded-full` 은 아바타·그래버·도트에만 쓰인다.
- `15px`(50회)는 화면이 아니라 **아트보드 옆 주석 열**, `11·13px` 은 **아바타 이니셜**.
  → 7단 스케일은 유지하고 예외 2개만 문서에 명시했다.

## 3. 발견한 결함

### 3-1. `tokens.css` 가 한 세대 뒤처져 있었다

DESIGN.md 는 2차 세트(커밋 `cf74f3c`)로 갱신됐는데 `tokens.css` 는 1차 값 그대로였다.
**문서와 화면이 다른 색이었다.**

| 토큰               | 코드(1차)       | 문서(2차)        |
| ------------------ | --------------- | ---------------- |
| `--fg`             | `#1A1D1B`       | `#15181D`        |
| `--fg-muted`       | `#5F6762`       | `#596069`        |
| `--fg-subtle`      | `#8A928C`       | `#878D96`        |
| `--border`         | `#E3E6E4`       | `#E3E5EA`        |
| `--border-strong`  | `#C8CDC9`       | `#C4C8D0`        |
| `--bg-subtle`      | `#F7F8F7`       | `#F5F6F8`        |
| radius sm/md/lg/xl | 6/10/16/24      | 4/8/12/16        |
| shadow 기준색      | `rgb(26 29 27)` | `rgba(21,24,29)` |
| `--metric-*` 12개  | **없음**        | 정의됨           |

> **교훈**: `tokens.css` 는 DESIGN.md 의 **수동** 동기다. 두 파일을 함께 고치지 않으면
> 조용히 갈라지고, 화면을 봐도 알아채기 어렵다. 두 파일 헤더에 서로를 명시해 뒀다.

### 3-2. `@theme` 자기참조로 radius 가 무효였다

`globals.css` 가 `@theme { --radius-sm: var(--radius-sm); }` 형태였다.
Tailwind v4 의 일반 `@theme` 은 이것을 `:root` 에 그대로 내보내므로, `tokens.css` 의
정의를 덮으면서 **자기 자신을 참조**하게 된다 → 값이 무효가 된다.

**`@theme inline` 으로 바꿨다.** `inline` 은 `:root` 선언을 만들지 않고 사용처에 값을
꽂으므로 `tokens.css` 의 정의를 그대로 가리킨다.

검증: 브라우저에서 `--radius-md` → `8px`, `.rounded-md` → `border-radius: 8px` 확인.

### 3-3. 가이드가 금지한 형태를 쓰는 코드 3건

작업 범위 밖이었지만 같은 규칙을 어기는 것이라 함께 고쳤다.

| 위치               | 무엇이 문제였나                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------- |
| 장소 필터 2축      | **배타 선택인데 `aria-pressed` 토글** — "배타적 축도 다중 선택으로 읽힌다" 며 가이드가 금지 |
| 장소 상세          | **전폭 히어로 + 본문 아래 "사진" 섹션** — 같은 자료를 두 번 크롭                            |
| `Chip`             | `rounded-full` — 원형은 사진·아바타 전용                                                    |
| `pet-trait-badges` | `accent`(AI 표시 전용)를 장식으로 사용 — DESIGN.md 가 이미 지적해 둔 항목                   |

## 4. 결정 기록 (2026-08-28 확정)

### D1. 링크 색 — 전용 토큰 신설, 값은 공유

`--link: #1F7A55` / `--link-hover: #16563C` 를 만들었다. **값은 `--metric-high-*` 과 같다.**

- 아트보드가 그렇다(링크 112회 · hover 54회). 값을 바꾸면 디자인과 어긋난다.
- 그러나 "등급 색과 상호작용 색을 분리한다" 는 원칙은 살려야 한다.
- **토큰명을 분리하면 나중에 갈라야 할 때 한 줄만 고치면 된다.** 값이 같아도 이름을 지킨다 —
  링크에 `--metric-high-*` 을, 등급에 `--link` 를 쓰지 않는다.
- `--brand-600 #237A54` 는 주요 버튼 hover 로 남겼다. 주요 버튼(`--brand-500`)과
  링크(`--link`)는 값이 다르다 — "누를 것" 의 두 단계다.

### D2. 위험 등급 — `--metric-critical-*` 신설

가이드가 "미해결" 로 남긴 항목이다. 값은 `--danger-*` 와 같게 두고 **이름만 분리했다.**

- 장애(5xx)와 산책 위험 판정이 같은 붉은색이면 사용자가 둘을 구분할 수 없다.
- 등급 스케일이 4단(HIGH/MID/LOW/UNKNOWN)에서 **5단**이 됐다.
- 붉은 톤을 실제로 갈라야 할 때 이 토큰의 값만 바꾸면 화면 코드는 건드리지 않는다.

### D3. `Card` 폐기 → `Band` / `Section` / `Row` / `RowList`

표면 방향 **2a** 확정에 따른다.

- 회색 배경 위에 둥근 흰 카드를 띄우면 대시보드처럼 읽힌다.
- 목록은 전폭 행 + 1px 구분선(인셋 16/40)이고, 묶음 경계만 8px 밴드로 끊는다.
- `PlaceCard` → `PlaceRow`, `PetCard` → `PetRow` 로 옮겼다.
- `--shadow-sm` 도 함께 폐기했다 — "평면 카드를 살짝 띄우는" 용도였는데 평면 카드
  자체를 없앴다.

### D4. 폐기한 토큰과 대체

| 폐기                                     | 대체                                            | 근거                              |
| ---------------------------------------- | ----------------------------------------------- | --------------------------------- |
| `--warn-*`                               | `--metric-mid-*`                                | 사용 0회. 측정값은 경고가 아니다  |
| `--info-*`                               | `--band` + `--fg-muted`                         | 사용 0회. 파랑은 팔레트에 없다    |
| `--success-500`                          | `--brand-500`                                   | 값이 동일했다                     |
| `--bg-subtle`                            | `--band`(화면 안) / `--bg-sunken`(밖)           | 한 토큰이 두 역할을 겸해 오용됐다 |
| `--brand-50/100/300`, `--accent-500/600` | `--metric-high-100` · `--band` · `--accent-700` | 사용 0회                          |
| `--shadow-sm`                            | 없음                                            | D3 참고                           |
| `--radius-lg`(카드 용도)                 | 라운드 없음                                     | 목록·섹션에 라운드가 없다         |

### D5. 동반 가능 여부에서 등급 색을 걷어냈다

`pet-tone.ts` 를 삭제하고 전부 중립 태그로 바꿨다.

- 동반 가능/불가는 **적합도 등급이 아니라 장소의 속성**이다.
- 등급 색을 다른 축에 전용하면 사용자가 "색 = 적합도" 라는 단서를 잃는다.
- 구분은 서버 `name` 문구가 맡는다 — 가이드의 "색은 유일한 채널이 아니다" 와 같은 방향.

### D6. 스케일 밖 예외는 2개만 명시

가이드 산문과 아트보드가 어긋난 지점이라 문서에 못박았다.

| 예외        | 어디에서만                 | 근거                                             |
| ----------- | -------------------------- | ------------------------------------------------ |
| **20/800**  | `ProfileCard` 등급어 한 곳 | 18은 라벨(16/600)과 안 갈리고 22는 이름과 겹친다 |
| **11·13px** | 아바타 이니셜(원형 안)     | 텍스트가 아니라 도형 내부 요소다                 |

spacing 은 가이드대로 **6** 을 스케일에 넣었다(태그 사이). Tailwind `1.5` 로 표현된다.

## 5-4. 회귀 방어 (이슈 #50 마무리)

토큰은 사람이 손으로 대조해야 지켜지는 규칙이 많았다. 그 대조를 테스트로 옮겼다 —
전부 `pnpm verify` 에서 돌아가므로 CI 가 막는다.

| 파일                             | 무엇을 막나                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------- |
| `src/styles/contrast.test.ts`    | **값** — 토큰 대비를 실제로 계산해 AA 기준을 단언한다 (33건)                  |
| `src/styles/token-usage.test.ts` | **쓰임** — 소스 전역에서 tint 위 `-500`, 폐기 토큰 부활, 평면 그림자를 찾는다 |
| `src/styles/token-sync.test.ts`  | **동기** — `DESIGN.md` ↔ `tokens.css` ↔ `globals.css` 를 대조한다             |

**이 테스트들이 실제로 잡은 것**

| 대상             | 무엇이었나                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `form-alert.tsx` | `bg-danger-100` 위에 `text-danger-500` — **3.97:1 로 AA 미달**. 폼 오류 메시지라 놓치면 안 되는 자리였다. `-700`(4.55:1)으로 고쳤다 |
| `DESIGN.md`      | 등급·소셜·레이아웃 표가 hex 만 적고 **토큰 이름을 안 적고 있었다**                                                                  |

**`token-sync.test.ts` 가 지키는 것** — 값(hex) 양방향 대조, 토큰 이름이 문서에 등장하는지,
`globals.css` 에 `@theme` 매핑이 있는지, `@theme inline` 을 쓰는지, 폐기 토큰이 되살아나지 않았는지.

### 실렌더 감사 (7화면 × 375 / 768 / 1280)

브라우저에서 각 화면을 열어 가로 오버플로 · 44px 히트 영역 · **실제 계산된 대비**를 쟀다.

| 발견                                | 처리                                                           |
| ----------------------------------- | -------------------------------------------------------------- |
| 장소 상세 전화·홈페이지 링크 17px   | 44px 히트 영역 부여. 상세에서 전화는 주요 행동이다             |
| 반려견 등록·수정 "목록으로" 22px    | 44px 히트 영역 부여                                            |
| `PlaceBackLink` 가 `brand-600` 사용 | 링크이므로 `--link` 로 교정                                    |
| **주요 버튼 흰 글자 3.49:1**        | **미해결 — DESIGN.md §2-4 참고.** 브랜드 색 결정이라 남겨 뒀다 |

오탐이었던 것 — 라디오·체크박스의 bare `<input>` 이 16~20px 로 잡혔으나 실제 타깃은
이를 감싼 `<label>`(60px)이다. 감사 스크립트의 한계였고 코드는 정상이다.
