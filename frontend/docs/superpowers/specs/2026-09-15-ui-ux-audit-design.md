## 0. 한 장 요약

혼디가개의 디자인 시스템(`DESIGN.md` 3a 표면 · 5톤 등급 · 해요체)은 이미 성숙하다. 시각적 결함은 적다.
**부족한 것은 "표현력"이 아니라 "판정의 도달률"이다.** 서비스가 약속한 세 질문 — _지금 가도 되나 · 어디로 가나 · 위급하면 어디로_ — 의 답이 화면에 **있지만, 사용자가 만나는 순서·위치·어휘가 그 약속과 어긋난다.**

| 축      | 진단                                | 대표 발견                                                                             |
| ------- | ----------------------------------- | ------------------------------------------------------------------------------------- |
| 첫 만남 | **첫 방문자는 핵심 판정을 못 본다** | 홈 "지금 산책 안전" 이 최근 본 장소가 있을 때만 렌더 (H-1)                            |
| 위계    | 답보다 도구·드문 액션이 먼저 선다   | 장소 상세 판정이 4~5 스크롤 아래 (D-1), 일정 상세 최상단이 "초안으로 되돌리기" (PL-2) |
| 어휘    | 같은 말이 다른 축을 가리킨다        | "보통" 이 혼잡도·적합도 둘 다 (G-1), 라벨 없는 "100" (H-3)                            |
| 응급    | 가장 급한 화면이 가장 느리다        | 지도 클러스터 겹침 · 위치 재요청이 작은 링크 · 영업시간 4줄 (E-1~E-4)                 |
| 전환    | 가입→반려견 등록 퍼널이 약하다      | 모바일 미로그인 헤더에 진입점 없음 (H-4), 등록 폼 2.5 스크린 (PT-1)                   |

**P0 3건 · P1 16건 · P2 21건.** P0 와 P1 상위 8건을 시안으로 그렸다 (§5).

## 2. 화면별 발견

형식: `ID [등급] 현상 → 근거 → 제안 → 성공 기준`. 시안이 있는 항목은 `시안 §n` 을 붙였다.

### 2-1. 홈 `/`

**H-1 [P0] 첫 방문자에게 "지금 산책 안전" 판정이 렌더되지 않는다.** — 시안 §1

- 현상: 5174 브라우저(최근 본 장소 있음)에서는 `오늘 산책 안전 · 25.5℃ · 수월봉 기준` 이 보이지만, 새 컨텍스트(Playwright, 위치 권한 허용 포함)에서는 섹션 자체가 없다. 모바일·데스크톱 동일.
- 근거: `src/features/home/use-home-insight.ts:24` "placeId 가 null 이면 조회하지 않는다 — 첫 방문자에게는 기준이 없고, 그때는 판정 섹션 자체를 렌더하지 않는다". 기준 장소는 `lib/insight/recent-place.ts` 의 localStorage 최근 본 장소다. 즉 **첫 방문 · 새 기기 · 시크릿 모드 · 공모전 심사용 새 브라우저** 전부 핵심 판정이 없는 홈을 본다.
- 제안: 기준 장소가 없을 때 **FE 고정 대표 지점(제주시 중심 1곳)** 으로 판정을 그리고, 기준 줄을 `제주시 기준 · 장소를 보면 그곳 기준으로 바뀌어요` 로 쓴다. 위치 권한이 있으면 가까운 장소로 승격. BE 홈 요약 API(S6-1) 전까지의 FE 범위 해법이다.
- 성공 기준: 시크릿 모드 첫 진입 390px 첫 화면(스크롤 0)에 등급어 + 체감온도 + 기준 줄이 보인다.

**H-2 [P1] 골든타임 헤드라인 `11:00 – 23:00 주의` 가 자기모순으로 읽힌다.** — 시안 §1

- 현상: "산책하기 좋은 시간" 제목 아래 창(11–23시)과 등급 배지(주의)가 한 줄. 표를 보면 주의는 14·15시 두 칸이다.
- 제안: 창은 창대로 두고, 배지 대신 **문장** `14–15시는 노면이 46℃까지 올라요. 그 전후가 좋아요`. 창 안에 주의 구간이 있으면 창을 `11–13시 · 16–23시` 로 쪼개 표기하는 안도 검토.
- 성공 기준: 사용자 테스트 5명 중 5명이 "나가기 좋은 시간" 을 창으로 답한다.

**H-3 [P1] 권역 카드의 `100` · 실내 카드의 `56` 에 라벨이 없다.** — 시안 §1

- 현상: 5권역 모두 `100` 인데 헤드라인은 "제주시권이 가장 나아요". 숫자가 무엇인지, 동점인데 왜 제주시권인지 설명이 없다.
- 제안: 카드 위 캡션 `반려견 활동 적합도 /100`, 숫자는 `100` 대신 배지 `적합 100`. **동점 분기 문구**: `오늘은 어디든 좋아요 · 한라산권만 18℃로 쌀쌀해요`.
- 성공 기준: 동점일 때 1위 권역을 단정하는 문장이 나오지 않는다.

**H-4 [P1] 모바일 미로그인 헤더에 로그인·가입 진입점이 없다.** — 시안 §1

- 현상: 헤더는 로고 + 응급 아이콘. 가입은 하단 탭 "내 정보" 를 눌러야 발견된다. "반려견을 등록해 주세요" 스트립은 링크 톤(`반려견 등록 ›`)이라 눌리는 것으로 안 보인다.
- 제안: 미로그인 홈 상단에 **온보딩 밴드 1개** — `우리 아이 기준으로 보려면` + `[반려견 등록하기]` 주 버튼. 로그인 후 반려견 0마리도 같은 자리. 등록이 끝나면 밴드가 프로필 카드로 바뀐다(이미 구현된 갈래).
- 성공 기준: 미로그인 홈 첫 화면에 주 버튼(`Button primary`)이 1개 있다.

**H-5 [P2] 장소 행에서 부정 정보 칩(`혼잡도 정보 없음` · `혼잡`)이 이름보다 먼저 선다.** — 시안 §1

- 제안: 이름 → 주소 → 칩 순서. `정보 없음` 계열은 §2-3 UNKNOWN 처방(점선·muted)으로 이름 아래.

**H-6 [P2] `동반 가능 여부가 원천에 없어 방문 전 확인이 필요합니다` 가 목록 위에 떠 있어 어느 장소 얘기인지 모른다.**

- 제안: 행 단위 칩 `동반 확인 필요` 로 내린다. 목록 위 문장은 지운다.

**H-7 [P2] 헤더 응급 아이콘(빨간 십자)에 라벨이 없다.** 초회에 의미가 안 읽힌다. → G-3 에서 하단 탭으로 함께 다룬다.

### 2-2. 장소 목록 `/places`

**P-1 [P1] 목록 행에 이 서비스만의 정보가 없다.** — 시안 §6

- 현상: 사진 · `관광지` 카테고리 칩 · 이름 · 주소 · `상세` 버튼. 관광 앱 어디에나 있는 행이다. 홈에서는 `여행 적합 90/100` 을 주는데 목록에는 동반 가능 여부조차 없다.
- 제안: 카테고리 칩을 **동반 상태 칩**(`동반 가능` / `동반 확인 필요` / `실내`)으로 바꾼다. 적합도는 개별 API 호출 비용이 있으니 **보이는 행 10개만 지연 조회**해 `오늘 적합 90` 을 오른쪽에 둔다(홈 `PlaceInsightRow` 재사용).
- 성공 기준: 행마다 반려견 관련 상태가 최소 1개 보인다.

**P-2 [P2] `상세` 버튼이 모든 행에 반복된다.** 행 전체가 링크이면 중복. → 행 전체 탭 + chevron, 버튼 자리에 저장(북마크).

**P-3 [P2] `반려견 동반 가능만` 필터가 기본 OFF 다.** 원천에 동반 정보가 없는 곳이 많아 ON 이면 결과가 줄어드는 딜레마 → 필터를 `동반 가능` · `확인 필요` 두 값으로 갈라 둘 다 기본 포함, `동반 불가` 만 제외.

**P-4 [P2] 검색 placeholder 가 폭에 따라 다르다.** 데스크톱 `이름이나 주소로 찾기` / 모바일 `이름·주소 검색`. 하나로.

### 2-3. 장소 상세 `/places/[placeId]`

**D-1 [P1] 핵심 답(동반 정보 · 지금 산책 판정)이 모바일에서 4~5 스크롤 아래다.** — 시안 §2

- 현상 순서: 갤러리 → 이름 → 혼잡도 차트 → 기본 정보 → 지도 → 오늘 이 지역 → 산책 판정 → **반려견 동반 정보** → 소개. 데스크톱은 좌측 레일이 판정을 위로 올려 주지만 모바일은 레일이 본문 뒤로 흐른다.
- 제안: 이름 바로 아래 **판정 요약 3줄** — `동반 · 정보 없음(방문 전 확인)` / `지금 산책 · 안전 25.5℃` / `덜 붐비는 날 · 9월 21일(월)`. 각 줄이 아래 세부 섹션의 앵커. 갤러리는 모바일에서 높이 200으로 줄인다.
- 성공 기준: 390px 스크롤 0 에서 세 답이 모두 보인다.

**D-2 [P1] 이름 옆 `보통` 배지가 무엇의 보통인지 알 수 없다.** → G-1.

**D-3 [P1] 혼잡도 차트의 `집중률 57.77` 은 해석 불가능한 숫자다.** — 시안 §2

- 현상: 소수 둘째 자리 · 단위 없음 · y축 없음 · 막대 위 회색 영역이 100 대비 잔여인지 불명.
- 제안: `집중률 58 · 30일 중 가장 한산` 정수 + **상대 표현** (`이 장소 30일 평균보다 22 낮아요`). 회색 잔여 영역은 지우고 막대 높이만. 이미 잘 된 것: `점선은 아직 모르는 날이에요` 범례, `7일만 보기` 토글.
- **구현 결과 (#651)**: 정수 · 상대 표현은 반영했다. 다만 **문구는 `30일 평균` 이 아니라 `이 기간 평균`** 이다 — 이 카드에는 `7일만 보기` 토글이 있어 7일에서는 같은 날이 `평균 70보다 12 낮아요` 로 바뀐다(실측). **`30일 중 가장 한산` 도 쓰지 않는다** — 전부 붐비는 주라면 가장 덜 붐비는 날도 `혼잡` 이다. **회색 잔여 영역은 지우지 않았다** — 그것이 0~100 축이고, 지우면 `UNKNOWN` 점선 칸이 유일한 전체 높이 요소가 되어 가장 붐비는 날처럼 읽힌다. 근거 셋은 [혼잡도-집중률-표현-세부명세](../../features/place/혼잡도-집중률-표현-세부명세.md) D8.

**D-4 [P2] 액션 `로그인 | 일정에 담기` 가 본문 중간에 떠 있고, 미로그인인데 `일정에 담기` 가 활성으로 보인다.** — 시안 §2

- 제안: 모바일 **하단 고정 액션 바**(`저장` · `일정에 담기`). 미로그인은 라벨을 `로그인하고 일정에 담기` 로.

**D-5 [P2] `장소 소개: 관광지` 한 단어 섹션.** 소개가 없으면 `소개가 등록되지 않았어요` 로 말하거나 섹션을 지운다.

### 2-4. 긴급 시설 `/emergency`

**E-1 [P0] 모바일 지도 클러스터 라벨이 겹쳐 읽히지 않는다.** — 시안 §3

- 현상: `이 지역 42곳` `14곳` `21곳` `8곳` `4곳` `7곳` `5곳` 라벨 알약이 서로 겹친다(390 캡처). 응급 화면에서 지도가 소음이다.
- 제안: 응급 화면은 **목록 뷰가 기본**, 지도는 토글. 클러스터는 라벨 알약 대신 숫자 원형 마커(지름 32).

**E-2 [P0] 위치 권한이 없을 때의 1순위 행동이 작은 텍스트 링크다.** — 시안 §3

- 현상: `위치 권한이 없어 거리를 계산할 수 없어요 · 현재 위치로 다시 찾기(링크)`.
- 제안: 상단에 **큰 주 버튼** `내 위치로 가까운 병원 찾기`. 거부 시 폴백 세그먼트 `제주시 · 서귀포 · 동부 · 서부` 로 기준점 선택. 캡션 `제주 중심 기준` 은 유지.
- 성공 기준: 권한 거부 상태에서도 2탭 안에 "내 지역" 순 정렬이 나온다.

**E-3 [P1] 필터 우선순위가 응급 맥락과 반대다.** — 시안 §3

- 현상: `전체 135 · 병원 50 · 약국 85` / `반경 10.0km · 24시간 1 · 지금 진료중 100`. 급할 때 필요한 건 "지금 진료중" 인데 여섯 번째.
- 제안: 첫 줄을 `지금 진료중(기본 ON) · 24시간 · 전체` 로, 둘째 줄 `병원 · 약국 · 반경`. `24시간 1` 은 데이터 한계이므로 `24시간 진료 확인된 곳 1곳` 으로 정직하게.

**E-4 [P1] 영업시간이 요일별 전문(4줄)으로 펼쳐진다.** — 시안 §3

- 제안: **오늘 한 줄** `진료중 · 24:00까지` (닫힘이면 `영업 종료 · 내일 10:00`), 전문은 펼치기. 전화 버튼(우측 44px)은 유지 — 이 화면에서 가장 잘 된 요소다.

### 2-5. 로그인 · 회원가입 · 비밀번호 찾기

**A-1 [P2] 소셜 로그인이 이메일 폼 아래다.** — 시안 §8. 실사용·공모전 시연 모두 카카오가 1순위. 소셜을 위로, 이메일은 `이메일로 로그인` 접기.

**A-2 [P2] 로그인 화면에 "왜 로그인하나" 가 없다.** 보호 라우트에서 튕겨온 경우 `returnTo` 로 갈라 `반려견 정보를 저장하려면 로그인이 필요해요` 한 줄.

**A-3 [P2] 가입 `3단계 중 1단계` 가 텍스트뿐.** 3점 인디케이터.

### 2-6. 마이페이지 `/mypage`

**M-1 [P2] `로그아웃` 이 섹션 제목 위계로 보인다.** 버튼인데 h2 크기. `버전 1.0.0` 행은 계정 섹션 밖(푸터)으로. 잘 된 것: `내 반려견 · 2/5마리`, `저장한 장소 · 3/100곳` 요약, 탈퇴를 작은 텍스트로 낮춘 것.

### 2-7. 반려견 `/pets` · `/pets/new` · `/pets/[petId]`

**PT-1 [P1] 등록 폼이 모바일 2.5 스크린이고 필드가 판정에 어떻게 쓰이는지 말하지 않는다.** — 시안 §5

- 현상: 이름·품종·생년월·체중·크기·활동량·사회성·산책 선호·민감도 3종. 하단 고정 `등록하기` 가 아래 필드 존재를 가린다.
- 제안: **2단계** — 1단계 필수(이름 · 크기)만으로 등록 완료, 2단계 `판정을 더 정확하게`(민감도 · 성향)는 선택이며 `나중에` 가능. 각 필드에 **효과 힌트** 1줄: `더위 민감 → 노면온도 기준이 5℃ 낮아져요`. 체중 힌트(`입장 체중 제한이 있는 곳을 걸러 줄 때 써요`)가 이미 좋은 선례다.
- 성공 기준: 1단계 완료율 측정 가능, 필수 2필드로 홈 판정이 반려견 기준으로 바뀐다.

**PT-2 [P2] 목록 카드에 성향 칩 7개가 나열된다.** 판정에 영향 주는 것(크기·민감도)만 앞에, 나머지는 `+3`.

**PT-3 [P2] 상세 하단 `삭제하기` 가 `저장하기` 와 같은 폭·위계다.** 텍스트 링크로 낮춘다.

### 2-8. 여행 일정 `/plans` · `/plans/new` · `/plans/[planId]`

**PL-1 [P1] 일정 목록 카드에 내용이 없다.** — 시안 §7 (목록 행)

- 현상: 이름 · 날짜 · 상태 배지 · D-18. 장소 몇 곳, 어느 권역, 판정이 어떤지 없다.
- 제안: 요약 줄 `2일 · 장소 3곳 · 서귀포` + 1일차 판정 배지. 함께 가는 반려견 아바타.

**PL-2 [P1] 상세 모바일 최상단 전폭 버튼이 `초안으로 되돌리기` 다.** — 시안 §4

- 현상: 드물고 되돌리기 어려운 상태 변경이 화면에서 가장 강한 자리. 핵심(1일차 판정 · 장소)은 그 아래 준비물 카드 다음이다.
- 제안: 상태 변경은 `⋯` 메뉴 안으로. 헤더는 `제목 · 날짜 · D-18 · 반려견` 만.

**PL-3 [P1] `여행 준비물 AI` 카드가 일차보다 위다.** — 시안 §4. 준비물은 출발 전날 과업. 일차 아래로 내리고 D-1 이하일 때만 위로 올린다(시간 기반 승격).

**PL-4 [P2] 일차 카드에서 액션 3개(`장소 추가 · 다시 만들기 · 순서 편집`)가 판정 위에 있다.** 판정 → 장소 → 액션 순. `다시 만들기` 는 오버플로.

**PL-5 [P2] 장소 행 우측 `✓` 아이콘의 뜻이 없다.** 방문 완료인지 동반 확인인지. 라벨 또는 제거.

**PL-6 [P2] 일정 만들기 `예산(선택)` 에 통화 접미(원)가 입력칸 안에 없다.** 체중 `kg` 처럼 접미 표시.

잘 된 것(유지·강조): `직선 13.6km 이동`, `비가 오면 갈 만한 실내 · 담기`, `중기예보 기준이라 대략적인 값이에요`, `여행 기간 밖 항목` 섹션.

### 2-9. AI 일정 `/ai-plans/new` · `/ai-plans/jobs/[jobId]`

**AI-1 [P1] 폼이 AI 가 무엇을 고려하는지 말하지 않는다.** — 시안 §7

- 현상: 날짜 · 반려견 · 자유 텍스트 · 접힌 상세 · `일정 만들기`. 신뢰 신호가 `만드는 데 1~2분쯤 걸려요` 한 줄.
- 제안: 제목 아래 **`AI 가 보는 것` 칩 4개** — `날씨·특보` `혼잡도 예측` `동반 가능 여부` `하루 이동량`. 반려견 선택 시 `소형견 · 더위 민감 → 오후 실내 위주` 처럼 조건이 결과에 어떻게 반영되는지 즉시 미리보기 1줄.

**AI-2 [P2] 진행 화면(미확인).** 명세상 단계(`CONDITIONS` 등)가 있다. 1~2분 대기에서 이탈을 막으려면 단계 3개 진행 표시 + `취소` + `끝나면 일정 목록에서 볼 수 있어요` 이탈 허용 문구가 있어야 한다. 실화면 확인 후 등급 재산정.

**AI-3 [P2] 반려견 선택이 AI 는 체크박스, 일반 일정은 라디오다.** 의도(다견/단견)라면 `여러 마리 가능해요` 힌트로 차이를 말한다.

### 2-10. 저장한 장소 `/favorites`

**F-1 [P1] 사라진 장소가 `이름을 불러오지 못했어요 · 장소 번호 212481712381923999` 로 첫 행에 선다.**

- 현상: 목 데이터지만 실서비스도 배치가 장소를 내리면 발생한다(`recent-place.ts:52` 가 같은 사례를 기록). 18자리 ID 는 사용자 언어가 아니다.
- 제안: `이 장소는 더 이상 제공되지 않아요` + `저장 해제` 버튼. 목록 맨 아래로.

**F-2 [P2] `97곳 더 저장할 수 있어요` 가 항상 우상단에 있다.** 한도 안내는 90곳 이상일 때만.

### 2-11. 서비스 소개 `/about`

**AB-1 [P2] 텍스트 3단락 + 출처 목록.** 심사자가 보는 화면인데 "어떻게" 가 없다. 세 질문(지금 가도 되나 → 어디로 → 위급하면) 각각에 **실화면 캡처 1장 + 데이터 출처 1줄**. 출처 로고는 쓰지 않는다(`DESIGN.md` §10 브랜드 색 예외 규칙).

### 2-12. 전역

**G-1 [P1] 등급 어휘가 축을 밝히지 않는다.** — 시안 §2·§6

- 현상: `안전/주의`(산책) · `여행 적합/보통`(적합도) · `보통`(혼잡도) · `확정/초안/완료`(일정). `보통` 이 두 축에 쓰여 장소 상세 이름 옆 `보통` 이 무엇인지 모른다.
- 제안: 배지 어휘를 축별로 가른다 — 혼잡도는 `한산 · 보통 · 붐빔`, 적합도는 `적합 · 무난 · 부적합`(서버 enum `description` 을 그대로 렌더하는 규칙과 충돌하면 배지 **앞에 축 라벨** `혼잡 보통` 로 해결). `DESIGN.md` §2-3 등급 토큰은 그대로 쓴다.
- **구현 결과 (#652)**: **축 라벨만 붙였다** — `적합도 보통` · `혼잡도 보통`. **어휘를 축별로 다시 짓는 1안은 쓰지 않았다**(§6 결정표가 이미 "1차는 축 라벨" 로 갈라 두었다). enum `name` 변경은 BE 결정이라 [등급배지-축라벨-세부명세](../../features/공통/등급배지-축라벨-세부명세.md) D9-2 로 넘겼다. **접두어는 `혼잡` 이 아니라 `혼잡도`·`적합도` 다** — 두 글자 형은 실제 서버 값에 붙이면 무너진다(`혼잡 한산` 은 모순, `적합 여행 적합` 은 중복). 이 저장소가 이미 두 곳에서 같은 접두어를 쓰고 있었다는 것이 근거다: `messages.home.congestionUnknown` 이 `혼잡도 정보 없음` 이었고, `DESIGN.md` §2-3 표의 "대표 문구" 열이 `적합도 높음/보통/낮음` 이다. 호출부 17곳 중 **9곳에 붙이고 8곳은 붙이지 않았으며** 그 이유는 세부명세 D5 표가 한 줄씩 갖는다. 산책 안전·기상특보·일정 상태는 충돌 어휘가 없어 손대지 않았다.

**G-2 [P2] 숫자 표기가 데이터 냄새를 낸다.** `최고 26.0℃` `최저 22.0℃` `집중률 57.77`. 일기예보 관습대로 기온은 정수, 점수는 정수. 체감온도만 소수 1자리 유지 가능.

**G-3 [P2] 응급 진입점이 헤더 아이콘 하나다.** 하단 탭을 `홈 · 장소 · 응급 · 일정 · 내 정보` 5탭으로. 반려견 보호자의 불안을 다루는 서비스에서 응급은 탭 자격이 있다.

**G-4 [P2] 문장 톤 혼재.** 서버 근거 문장(`~조건입니다`)과 UI 문구(`~예요`)가 한 카드 안에 섞인다. `DESIGN.md` §1 해요체 규칙과 충돌. 서버 문장을 못 바꾸면 인용 스타일(`ReasonList` 3px 바)로 "이건 데이터가 말하는 것" 임을 시각적으로 가른다 — 이미 그 장치가 있다.

**G-5 [P2] 로딩·빈 상태의 톤.** 캡처에서 빈 상태는 잘 쓰여 있다(`반경 안에 등록된 시설이 없어요`). 유지.
