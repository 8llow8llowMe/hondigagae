## 1. 진단 방법 — 다른 PC 에서 그대로 재현하기

스크린샷 눈대중이 아니라 **실행 중인 dev 서버에서 DOM 을 직접 측정**했다. 같은 숫자를 다시 얻으려면 아래를 따른다.

### 1-1. 워크트리 dev 서버 띄우기

워크트리에는 `node_modules` 도 `.env.local` 도 없다. 둘 다 gitignore 대상이라 **PC 를 옮기면 다시 만들어야 한다.**

```bash
cd <worktree>/frontend
cp <메인체크아웃>/frontend/.env.local .env.local
ln -s <메인체크아웃>/frontend/node_modules node_modules
./node_modules/.bin/next dev -p 5180 --webpack
```

- **`--webpack` 이 필요하다.** 심링크된 `node_modules` 에서 Turbopack 이 죽는다.
- **포트는 비어 있는 것을 쓴다.** 진단 시점에 `3000` · `5174` · `5176` 은 다른 워크트리 세션이 물고 있었다. `lsof -nP -iTCP:<port> -sTCP:LISTEN` 로 먼저 확인한다.
- `npx next dev` 는 쓰지 않는다 — 워크트리에 `node_modules` 가 없으면 npm 이 typescript 설치를 시도하다 실패한다.
- 백엔드는 dev 게이트웨이를 그대로 탄다. 코스 29개와 `/insights/walk-times` 모두 실응답을 받았다.

### 1-2. 측정 방법

브라우저 패널에서 뷰포트를 고정하고 `javascript_tool` 로 `getBoundingClientRect()` · `scrollWidth` 를 읽었다.

- **스크린샷으로 잘림·클리핑을 판정하지 않았다.** 패널 스크린샷은 뷰포트보다 좁게 잘려 돌아온다(1440×900 요청에 800×602 반환). 실제로 이 함정 때문에 "시간대 표가 잘린다" 고 한 번 오진했다가 `scrollWidth === clientWidth` 로 뒤집었다.
- **로딩 중 샘플링을 조심한다.** 골든타임은 클라이언트 조회라 네비게이션 직후 재면 비어 있다. 2.5초 대기 후 다시 재서 "골든타임이 안 뜬다" 는 오진을 뒤집었다.

### W-2. 이름과 URL 이 데이터와 맞지 않는다 · P0 — **닫혔다 (#810 · #811)**

`산책 코스` / `/walk-courses` 인데, 실제 내용은 **중앙값 15.7km · 5시간 이상이 23/29** 인 제주올레 종주 코스다. 반려견 동반 기준으로 이것을 "산책" 이라 부르는 것은 **29개 중 28개에 대해 사실과 다르다.**

### W-10. 코스 화면인데 지도가 없다 · P2

시종점이 글자뿐이고, **좌표가 있는 4개조차 지도를 안 띄운다** (`document.querySelector('[id*=map]')` → `null`). 경로 폴리라인은 응답에 없지만(공통명세 S0 제외 항목) **시작점 마커는 좌표만으로 가능하다.** 지도가 핵심인 서비스에서 코스 상세에 지도가 없는 것은 눈에 띈다.

### W-11. `코스 목록으로` 가 필터를 버린다 · P2

### W-12. 한 컨트롤을 세 가지 말로 부른다 · P2

### W-14. radiogroup 키보드 규약 위반 · P3

`role="radio"` 5개가 전부 탭 스톱이고 화살표 키 이동이 없다. WAI-ARIA radiogroup 패턴은 roving `tabindex` + 화살표 이동을 요구한다. `onKeyDown` 핸들러가 아예 없다 — [`walk-course-filter-fields.tsx:142-171`](../../../src/features/walk-course/walk-course-filter-fields.tsx).

이 세그먼트 문법은 `EmergencyTypeSegment`([#537](https://github.com/8llow8llowMe/hondigagae/issues/537))에서 그대로 가져온 것이므로 **같은 결함이 `/emergency` 에도 있을 가능성이 높다.** 고칠 때 공용화 범위를 먼저 확인한다.

### W-15. 같은 제목이 두 번 읽힌다 · P3 — **이 화면만의 결함이 아니다 (#798 에서 정정)**

`h1`(sr-only `산책 코스`) + `h2`(보이는 `산책 코스`) 가 연속이다 — **#810 이후 두 곳 모두 `제주올레 코스` 이고, 두 번 읽히는 구조 자체는 그대로다** — [`olle/page.tsx:96`](<../../../app/(main)/olle/page.tsx>) + `Surface title`. 스크린리더에 같은 문자열이 두 번 나간다.

> **저장소 전체의 의도된 패턴이다.** `/pets` · `/places`([#439](https://github.com/8llow8llowMe/hondigagae/issues/439)) · `/walk-courses` 가 모두 같은 모양이고,
> `app/(main)/pets/(list)/page.tsx` 에 근거 주석이 있다 — _"보이는 제목은 카드의 `h2` 다(§0 '섹션 제목은 섹션
> 안에 있다'). 이 화면의 카드는 하나뿐이고 그 카드의 이름이 곧 페이지의 이름이라, 밖에 두면 제목만 바닥 위에
> 떠 어느 묶음의 제목인지 모호해진다."_
>
> **코스 목록만 고치면 자매 화면과 패턴이 갈린다.** `Surface` 에 heading level 옵션이 없어, 제대로 고치려면
> `Surface` 가 `h1` 을 그릴 수 있게 하고 `sr-only h1` 을 걷는 **저장소 전체 변경**이 된다. D-4 를 걷은 이유다.

### W-16. 진입점이 홈 배너 하나뿐이다 · P3

`/walk-courses` 로 들어오는 링크는 [`home-view.tsx:499`](../../../src/features/home/home-view.tsx) 단 하나다. 전역 nav 에 없다는 것은 [#618](https://github.com/8llow8llowMe/hondigagae/issues/618) 공통명세 S6-1 의 의도된 결정이지만, **목록·상세에서 다른 화면으로 나가는 길도 없어** 이 기능이 서비스 안에서 고립돼 있다.

| 부제      | 반려견 관점을 넣어 서비스와 이어 붙인다 — `우리 아이랑 걸을 만한 제주올레 코스를 거리와 걷는 시간으로 골라 봐요.` (#810 착지값. 시간 축 이름은 §4-2 대로 `걷는 시간`) |

### 4-2. 활동량 라벨을 유지할 것인가 (W-12 뒷부분) — **필터 축은 `활동량`, 값 축은 `걷는 시간` (2026-09-21 개정)**

> **원문은 "축 이름까지 `걷는 시간` 으로 통일" 이었다.** 아래에 접어 남긴다.
> [#824](https://github.com/8llow8llowMe/hondigagae/issues/824) 에서 다시 판단해 **절반만 채택했다** —
> 값 축의 이름은 원문대로 통일하고, **필터 축은 `활동량` 으로 둔다.**

**두 축을 가른다.**

| 축                                  | 이름        | 근거                                                                                          |
| ----------------------------------- | ----------- | --------------------------------------------------------------------------------------------- |
| 코스가 가진 **값** (`durationText`) | `걷는 시간` | 원문대로. `소요시간` 과 섞어 쓰지 않는다 — 목록 열 머리와 상세 `<dl>` 이 상수 하나를 공유한다 |
| **거르는 조건** (세그먼트)          | `활동량`    | 선택지가 `낮음`·`보통` 이라 축 이름을 시간으로 바꾸면 이름과 값이 어긋난다                    |

**원문대로 축까지 바꾸면 [#735](https://github.com/8llow8llowMe/hondigagae/issues/735) 가 피하려던 상태로
돌아간다.** 그 이슈가 `걷는 시간` → `활동량` 으로 바꾼 이유가 _"선택지가 상한 시간(`4시간 이내`)이 아니라
활동량 이름(`낮음`·`보통`)이 되었기 때문"_ 이다. 선택지를 다시 시간으로 되돌리는 안(#824 ②)은 **FE 상한
복제본**(`ACTIVITY_MAX_HOURS`)을 되살린다 — 응답은 _적용된_ 상한 하나만 주므로 아직 고르지 않은 칸의
숫자는 FE 가 지어내는 값이 된다.

**"상한이 가려진다" 는 지적은 이름이 아니라 기준 줄이 푼다.** 고르고 나면
`{펫} 활동량({등급}) 기준으로 {상한}이 넘는 코스는 빼고 보여 줘요.` 가 **서버가 준 상한**으로 말한다
(#735 · #718). 고르기 **전**에 상한을 적지 않는 것은 그 값이 응답에 없기 때문이고, 그것이 #735 의 결정이다.

**#824 가 실제로 고친 것은 어휘가 갈린 두 자리다.**

| 자리                       | 고치기 전                  | 고친 뒤                      | 왜                                                                              |
| -------------------------- | -------------------------- | ---------------------------- | ------------------------------------------------------------------------------- |
| 목록 열 머리 · 상세 `<dl>` | `소요시간`                 | `걷는 시간`                  | §4-2 의 통일 규칙이 `pageDescription` 한 문자열에만 걸려 있어 새어 나갔다       |
| 0건 안내                   | `걷는 시간을 넓혀 보세요.` | `활동량 조건을 넓혀 보세요.` | 화면에 `걷는 시간` 이라는 **컨트롤이 없다** — 거를 수 있는 축은 `활동량` 하나다 |

규칙을 잠그는 테스트도 한 문자열에서 **walk-course 문구 전체 훑기**로 넓혔다 (`walk-course-entry.test.ts`).

활동량 상한 자체가 이상하다는 판단은 BE 이슈로 따로 올린다 — **이 저장소의 사용자는 FE 만 작업하므로
BE 이슈는 보고만 한다.**
