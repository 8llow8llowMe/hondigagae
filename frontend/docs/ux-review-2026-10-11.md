## 0. 총평

**만듦새는 상위권이다.** 가로 넘침 0건, 콘솔 오류 0건(404 화면의 의도된 404 응답만), 로딩 · 빈 · 오류 ·
오프라인 상태가 거의 모든 화면에 있다. **실데이터가 드러낸 문제는 화면이 아니라 화면이 싣는 내용**에 있다.

| #   | 핵심 문제                                    | dev 에서 본 것                                                                                                       |
| --- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 1   | **반려견 동반 데이터가 대부분 비어 있다**    | 장소 2,312곳 중 **72%(1,674곳)가 동반 여부 미확인**. 목록 · 지도에서는 미확인이 아무 표시 없이 섞인다                |
| 2   | **추천이 추천이 아니다**                     | 홈 `오늘 갈 만한 곳` 3장 = 장소 ID 앞 3곳. 오늘은 60 · 50 · 40점, 둘은 `주의 필요`, 하나는 동반 미확인               |

'반려견 데이터' 와 '판단' 두 축이 실데이터에서 동시에 약하다.** UI 개선보다 데이터 · 추천 · AI 품질이 먼저다.

## 3. 핵심 문제와 제안

우선순위 = 사용자 영향 × 빈도 × 신뢰 영향. **P0 은 서비스의 약속을 직접 깎는 것**이다.
**BE** 는 백엔드 결정 · API · 배치가 필요한 것이다(FE 세션은 `backend/` 를 고치지 않으므로 이슈로 요청).

### 3-1. [P0] 동반 여부 미확인이 72% — 그런데 화면은 그것을 말하지 않는다

**관찰**

- `/places` 목록(M · T · D)에서 `성산일출봉` · `성판악` · `천지연폭포` 처럼 미확인 장소는 **배지가 없다.**
  `동반 가능` · `부분 동반 가능` 배지가 붙은 카드 사이에 섞이면, 배지 없는 카드는 "특별한 제한 없음" 으로
  읽힌다. 상세에 들어가야 `정보 없음 · 방문 전 확인해요` 가 보인다.
- 기본 정렬이 **장소 ID 오름차순**이라 첫 화면은 관광지(TourAPI 선적재분)만 나오고 식당 815곳 · 숙박 270곳은
  필터를 걸어야 보인다. 지도도 첫 20곳만 핀으로 찍는다.
- 반대로 검색 랜딩(`/jeju/pet-friendly-stays` 등)은 "공공데이터에서 동반 가능으로 확인된 곳만" 이라 신뢰가 높다.
  **같은 서비스 안에서 랜딩이 메인 탐색보다 더 반려견 서비스답다.**

**제안**

1. **FE (바로)**: 목록 · 지도 시트 · 저장한 장소 카드에 미확인도 배지로 — `동반 미확인` (회색 점선, 장소 상세의
   `정보 없음` 과 같은 말). 미확인을 숨기지 말고 **보이게** 한다.
2. **FE (바로)**: `/places` 첫 진입 기본값을 `동반 가능만` 켬으로 — 끄면 전체. 검색 랜딩과 같은 기준이다.
   URL `searchParams` 기본값 규칙(architecture-guide §10)과 SEO 정규 URL 영향은 명세에서 확인한다.
3. **BE**: 정렬 기준 — ID 순이 아니라 `동반 확정 > 사진 있음 > 거리/권역` 같은 관련도 순. 지금 API 에 정렬
   파라미터가 없다.
4. **BE · 데이터**: 미확인 1,674곳의 보강 경로 — 식약처 음식점(동반 가능 확인 원천)과의 병합 범위 재점검,
   `petTourImportJob` 커버리지, 사용자 제보("여기 강아지 됐어요/안 됐어요")를 받는 가벼운 버튼.
   **제보 버튼은 데이터 공백을 메우는 가장 싼 방법**이다(카카오맵 · 네이버 지도의 정보 수정 제안과 같은 모양).

**지표**: 목록 첫 화면의 동반 확정 비율, 상세 → `일정에 담기` 전환율, 제보 수.

### 3-2. [P0] 홈 `오늘 갈 만한 곳` 이 추천이 아니다 (#1368 의 실화면 근거)

**관찰 (dev, 비로그인 · 로그인 동일)**

- 3장 = `생각하는 정원(125445)` · `수월봉(126434)` · `성산일출봉(126435)` — **장소 ID 앞 세 곳 그대로**다.
- 점수 순으로 다시 세우면 `수월봉 60 보통` · `성산일출봉 50 주의 필요` · `생각하는 정원 40 주의 필요`.
  셋 다 "강수확률 60~100% 로 야외 일정에 영향이 있습니다" 가 붙는다. 성산일출봉은 **동반 미확인**이다.
- 로그인해 반려견 조건(`몽` 폼스키 중형견 · 더위 민감)이 들어가도 후보 3곳은 비로그인과 같다 — 점수만 바뀐다.
- 바로 아래 `비 올 때 갈 만한 실내` 2곳(성산카페 어반정글 · 위플레이독 애견놀이터)이 **오늘 실제로 갈 만한
  곳**인데 위계가 아래다.

**제안**

1. **BE (#1368)**: 반려견 조건별 오늘 상위 N 추천 API. 이 보고서의 실측(ID 앞 3곳 · 40~60점 · 미확인 포함)을
   이슈에 근거로 붙인다. 계약에 **"동반 미확인 제외" · "강수/경보일 실내 우선"** 을 함께 넣자고 제안한다.
2. **FE (API 전 임시)**: 3장 중 `주의 필요` 이하만 있으면 제목을 `오늘 갈 만한 곳` 이 아니라 `오늘 상황` 정도로
   낮추고, 비 · 경보일에는 `비 올 때 갈 만한 실내` 를 위로 올린다. 미확인 장소는 후보에서 뺀다.

### 3-3. [P0] AI 일정이 요청을 지키지 못하고, 지키지 못했다고 말하지도 않는다

**관찰 (실제 Ollama, 2026-10-11 생성)**

| 입력                                                                                    | 결과                                                                                         |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 10/24(토)~10/25(일) · `몽` · "서귀포 위주로 이동은 짧게, 비 오면 실내 위주로 짜 주세요" | 1일차 `라 플라주(제주시 · 카페)` → `우키하우스(조천읍 · 숙박)`, 2일차 `선녀와나무꾼(조천읍)` |

- **지역 요청을 어겼다** — 세 곳 모두 제주시 · 조천(북동)이다. "서귀포" 는 자유 메모로만 들어가고, 폼의
  `더 자세히 → 지역: 서귀포시` 칩과 연결되지 않는다.
- **양이 빈약하다** — 1박 2일에 3곳(카페 1 · 숙소 1 · 실내 1). 2일차는 한 곳이다.
- **설명이 없다** — mock 에 있던 `이렇게 짰어요` 근거 블록이 이 결과에는 없다. 요청 중 무엇을 반영했고 무엇을
  못 했는지 알 수 없다.
- 생성 시간 약 75초. 진행 단계 표시(후보 장소 수집 → 일정 구성 n초째)와 "화면을 벗어나도 계속" 안내는 좋다.
- 계정의 기존 확정 일정(`몽과 제주 2박 3일`, 10/13~15)은 숙소가 구좌(동쪽)인데 2일차가 곽지(서쪽) → 서귀포 →
  구좌로 **하루 직선 약 115km**, 3일차는 수월봉(서쪽 끝)까지 62km. 화면이 항목마다 "하루 이동이 길어요" 를
  띄운다 — **경고는 정확한데, 애초에 그런 동선이 저장된다.**

**제안**

1. **FE (바로)**: 메모에 권역 이름(제주시 · 서귀포 · 동부 · 서부 · 애월 · 성산 …)이 보이면 `지역` 칩 선택을
   제안한다("서귀포시로 좁힐까요?"). 자유 메모에 기대지 말고 구조화된 조건으로 보낸다.
2. **BE (`ai-service`)**: 결과 검증 단계에 ① 지역 조건 위반, ② 하루 항목 수 하한, ③ 하루 직선 이동 상한
   (예: 40km)을 넣고, 어기면 재시도하거나 **"서귀포에서 조건에 맞는 곳이 부족해 제주시를 넣었어요"** 처럼
   이유를 응답에 싣는다. FE 는 그 문장을 `이렇게 짰어요` 에 그대로 렌더한다.
3. **FE**: 초안에 일자별 동선 지도(일정 상세 `여행 동선` 재사용)와 항목별 `다른 곳으로` — 사용자가 저장 전에
   품질을 판단하고 고칠 수 있게.
4. **FE**: 일정 상세에 `동선 다시 짜기(이동 짧게)` — 직선거리 기준 재정렬은 FE 만으로 가능하다.

**지표**: AI 초안 → `내 일정에 담기` 전환율, `전체 다시 만들기` 비율, 저장 후 항목 수정 수.

### 3-4. [P0] 판단 신호가 서로 부딪친다

**관찰**

- dev 오늘(비): 홈 `갈 만한 곳` 3장 전부 "강수확률 60~100% 로 야외 일정에 영향" — 그런데 섹션 제목은 "갈 만한 곳".
- 권역 카드: **"오늘은 어느 권역이든 좋아요"** 바로 아래 "강수확률 90% 로 야외 일정에 영향이 있습니다". 다섯 권역이
  모두 75점으로 같은 날, "차이가 없다" 가 "다 좋다" 로 표현됐다.
- 장소 상세(수월봉): 배지 `적합도 보통`, 요약 행 `동반 가능` · `지금 산책 주의 · 체감 25.9°C`, 그 아래 강수 100%.
  결론이 무엇인지 사용자가 조립해야 한다.
- mock 경보일 재현(폭염 경보 · 산책 `위험`)에서는 같은 화면에 야외 장소가 `82점 여행 적합` 으로 섰다.

**제안**

1. **판정 우선순위를 하나로**: 기상 경보 > 산책 위험 > 강수 > 여행 적합도. 상위 신호가 나쁘면 하위 신호는 그
   범위 안에서만 말한다.
2. 장소 상세 맨 위에 **결론 한 줄** — `오늘 이곳: 비가 와요. 18시 이후 잠깐 산책만` · `오늘 이곳: 좋아요`.
   점수 · 배지 · 산책 판정은 그 아래 근거로 내린다.
3. 권역 카드 문구: 점수가 모두 같으면 "오늘은 권역별 차이가 없어요 — 비가 와서 어디든 실내 위주가 좋아요".
4. 점수 계산에 경보 · 강수를 어떻게 반영할지는 BE(`SuitabilityEvaluator`) 판단 — #1368 과 묶는다.

### 3-5. [P0] 가치를 보기 전에 로그인 벽

**관찰 (dev 동일)**

**제안**

   사유 한 줄과 닫기.
2. 장소 상세 게스트 버튼 `로그인` → `♡ 저장` (누르면 위 시트). 명세 D8 에 결정 변경 근거를 남긴다.
3. 게스트 홈 첫 줄은 가입 요청이 아니라 **가치 문장 + 오늘 판정**. 반려견 등록 유도는 판정 카드 안 보조 링크로.
4. **BE**: 게스트 AI 초안(로그인은 `담기` 에서) — AI 작업 API 인증 정책 결정 필요. 그 전에는 고정 샘플 초안
   미리보기라도 보여 준다.

### 3-7. [P1] 재방문 · 공유 루프

**관찰**

- 일정 목록 5개 중 **4개 이름이 `몽과 제주 2박 3일`** — AI 기본 제목이 `{반려견}과 제주 N박 N일` 이라 생기는 일이다.
  카드에 사진 · 장소 수 · 지역이 없어 구분할 방법이 날짜뿐이다. 일정 상세 탭 제목은 모든 일정이 `여행 일정 · 혼디가개`.
- 지난 초안 3건이 정리되지 않고 쌓인다(AI 초안을 담고 버려 둔 흔적으로 보인다). 지난 확정 일정도 `확정` 그대로.
- **공유는 개선된 부분이 있다**: 확정 직후 "일정을 확정했어요. 이제 링크로 공유할 수 있어요." + `공유 링크` 버튼이
  바로 선다. 다만 다시 들어오면 버튼이 없고 `⋮` 안으로 들어간다. 모달은 `링크 만들기` → `복사` 두 단계.
- **공유 받은 화면**: 제목 · 날짜 · 일자별 장소(상세 링크 있음)뿐. 지도 · 판정 없음, "공유받은 일정이라 볼 수만 있어요"
  에서 끝난다 — `나도 만들기` · `내 일정으로 가져오기` 가 없다. OG 이미지는 서비스 공통 이미지.

**제안**

1. **AI 기본 제목에 차별점**을 — `몽과 서귀포 바다 1박 2일` 처럼 주 권역 · 테마를 넣는다(BE 응답 또는 FE 조합).
   목록 카드에 대표 사진 · `3곳 · 제주시`.
2. 지난 초안은 "다녀온 일정이 아니면 정리할까요?" 일괄 정리, 지난 확정은 "다녀왔나요? `완료로 표시`".
3. 확정 일정 상단에 공유 버튼 상시 노출, 모달은 열자마자 링크 발급 + 복사 · 공유 시트.
4. 공유 받은 화면 하단에 `이 일정으로 내 여행 만들기`(게스트면 로그인 시트 → 사본; **BE** 사본 API) +
   `우리 아이 기준으로 다시 판정하기`. 동선 지도를 싣는다. OG 이미지는 첫 장소 사진 + 일정 이름.
5. 일정 상세 `<title>` 에 일정 이름.

**지표**: 공유 링크 발급률, 공유 링크 열람 → 가입 전환율.
