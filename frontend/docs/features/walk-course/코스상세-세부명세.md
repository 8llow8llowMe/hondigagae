## D0. 화면 정의

- **경로**: `/walk-courses/[walkCourseId]`
- **인증**: **불필요**. `PROTECTED_PATHS` 에 넣지 않는다
- **진입 경로**: 코스 목록의 행 · 공유된 주소
- **이탈 경로**: `코스 목록으로` · 골든타임 안의 링크 없음(패널은 읽기 전용) · (#620 이후) 담기 시트

### D0-1. 숫자가 아닌 `walkCourseId` 는 **400** 이다 — 404 가 아니다

컨트롤러가 `@PathVariable long` 이라(`WalkCourseWebController.java:74`) 파싱 단계에서 갈린다. dev 실측:

| 주소                         | 상태 | 코드             | `fieldErrors[0].field` |
| ---------------------------- | ---- | ---------------- | ---------------------- |
| `/walk-courses/abc`          | 400  | `WALKCOURSE_113` | `walkCourseId`         |
| `/walk-courses/1234…3456789` | 404  | `WALKCOURSE_001` | —                      |

**`/places/{placeId}` 와 정확히 같은 모양이다** (`screen-inventory.md` §3). 그래서 같은 처치를 한다 —
`proxy.ts` 에 `/walk-courses/:path*` 매처와 숫자 판정을 추가하고, 형식이 틀리면 **`rewrite` 로 상태만 400** 으로
바꾼다 (`proxy.ts:29-51` 의 `PLACE_DETAIL_PATH` 주석이 근거다: 공개 경로라 크롤러가 잘못된 주소를 200 으로 읽고
모니터링이 실패를 세지 못한다). **`redirect` 도 `notFound()` 도 아니다** — 둘 다 사용자가 보던 화면을 잃거나
404 가 아닌 것을 404 라고 말한다.

| 폭               | 모양                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| 모바일 (390)     | 전폭 섹션을 세로로 쌓는다 — ① 머리(이름표·구간명·핵심값) ② 코스 정보 ③ **골든타임(좌표 있을 때만)** ④ 출처 |

**머리 = 페이지 머리다. 카드에 담지 않는다** (`DESIGN.md` §0 카드 판정 3문 — 페이지 머리(h1)는 카드가 아니다).

```text
1코스                                   ← h1 = courseLabel
시흥-광치기                              ← 구간명

15.1km          4~5시간                  ← 핵심값 2개. 단위를 드러낸다
시흥리정류장-광치기해변                  ← 시종점 원문
```

**이미지는 있을 때만 머리 위 전폭 미디어로 붙인다** (`DESIGN.md` §0 — 전폭 미디어는 카드가 아니다).
없으면 **자리를 만들지 않는다.** 실측 기준 29개 중 25개가 이 모양이다 (공통명세 S3-1).

**16:9 가 상한이다** ([#730](https://github.com/8llow8llowMe/hondigagae/issues/730)) — 390 에서 ≈220px.
1024 이상에서는 히어로가 **좌측 열**로 가고 우측에 머리(지표)와 골든타임이 선다. 히어로가 본문 폭을 다
먹던 동안에는 이 화면의 차별 정보인 골든타임이 접힘선 아래로 밀렸다 (1280 실측 1400px = 뷰포트의 155%).
`firstImage` 와 좌표는 **같은 4개**에만 있으므로(공통명세 S3-1), 2열이 서는 날은 우측에 세울 것이 실제로 있는 날이다.

## D3. 데이터 흐름

```text
/walk-courses/{id}
  → page.tsx (server)
      isWalkCourseId(id) 아니면 → 400 화면 (proxy 가 상태코드를 맞춘다)
      fetchQuery(GET /walk-courses/{id})   try/catch
      HydrationBoundary
  → WalkCourseDetailView (client)
      hasCoordinates(course) === false → 끝. 골든타임을 부르지 않는다
      true → useWalkTimes({lat, lng}, toPetCondition(selectedPet))
```

| 항목                       | 내용                                                                                                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| API                        | `GET /api/v1/walk-courses/{walkCourseId}` (+ 좌표가 있을 때만 `GET /api/v1/insights/walk-times`)                 |
| React Query key            | 코스: `walkCourseKeys.detail(walkCourseId)` / 골든타임: **기존 `insightKeys.walkTimes(lat, lng, conditionKey)`** |
| staleTime / gcTime / retry | 코스 **5분 / 30분 / 2** (목록과 같다) · 골든타임 **`INSIGHT_QUERY_OPTIONS`**(5분/30분/retry 1) 를 그대로 쓴다    |
| mutation 후 invalidate     | 없다 (이 이슈에서는 mutation 이 없다)                                                                            |
| 폴링                       | 없다                                                                                                             |

- **골든타임 key 를 새로 만들지 않는다.** `insightKeys.walkTimes` 는 **좌표 축**이라(`lib/insight/queries.ts:34`)
  홈에서 같은 좌표·같은 조건으로 이미 받아 뒀으면 그대로 재사용된다. 코스 전용 key 를 만들면 같은 답을 두 벌 캐시한다.
- **반려견 조건은 nav 선택견이다** (`useSelectedPet(authed)`). 목록의 활동량 기본값이 대표견인 것과 **다른 축이라
  일부러 다르다** — 저쪽은 *카탈로그를 좁히는 조건*이고 이쪽은 *판정의 기준*이다. 판정 화면(홈·장소 상세)은 전부
  nav 선택견을 쓴다. 이 어긋남 자체는 `코스목록-세부명세.md` D8-1 에 적어 뒀다.
- **미로그인이면 조건 없이 부른다.** 사람 기준 판정이 오고, 그것은 **정상 응답**이다. `petConditionApplied: false`
  일 때 반려견 이름을 붙이지 않는 규칙도 그대로다 (`screen-inventory.md` §3-1).

### D3-1. 좌표가 null 이면 **부르지 않는다** — 한 곳에서만 판정한다

```ts
// lib/walk-course/coordinates.ts
export function hasCoordinates(course: { lat: number | null; lng: number | null }): boolean {
  return course.lat !== null && course.lng !== null
}
```

- `useWalkTimes` 의 `enabled` 는 이미 `position !== null` 이다. **`position` 을 만들 때 걸러낸다** —
  `hasCoordinates(course) ? { lat: course.lat, lng: course.lng } : null`.
- **`lat ?? 0` 을 쓰지 않는다.** 서버는 `(0, 0)` 에 **200 으로 답한다** — 기니만 앞바다의 예보가 정상 응답으로
  와서, 화면은 틀린 것을 틀렸다고 말할 방법이 없다 (공통명세 S4-2).
- **`Number.isFinite` 로 넓히지 않는다.** 계약이 `Double | null` 이고(`WalkCourseItem.java:37,40`) `NaN` 은 오지
  않는다. 판정을 넓히면 테스트가 실제 계약이 아닌 것을 지키게 된다.

## D4. 상호작용

| 트리거                     | 동작                               | 결과                                                            |
| -------------------------- | ---------------------------------- | --------------------------------------------------------------- |
| `코스 목록으로`            | 들어올 때의 조건으로 목록 복귀     | **#783 에서 개정** — 아래 D4-1                                  |
| 골든타임 `다시 시도`       | `walkTimes.refetch()`              | **예보를 못 받았을 때만 렌더된다** (`onRetry` 를 그때만 넘긴다) |
| 반려견 전환 (전역 nav)     | 조건 key 가 바뀌어 골든타임 재조회 | **코스 조회는 재조회되지 않는다** — 코스는 반려견과 무관하다    |
| 404 화면의 `코스 목록으로` | `/walk-courses`                    | 재시도 버튼 대신 주는 **다음 행동**이다                         |

**D4-1. `코스 목록으로` 가 들어올 때의 조건을 돌려준다** ([#783](https://github.com/8llow8llowMe/hondigagae/issues/783) 에서 개정).

> **개정 전에는 "복원하지 않는다" 가 의도였다.** 근거는 _"뒤로가기가 그 역할을 한다"_ 와 _"링크가 어디로 가는지
> 이름과 같아야 한다"_ 였다. 앞쪽은 사실이지만 **그래서 화면 안 링크만 사용자를 배신했다** — `?activity=LOW`
> 로 29개를 6개까지 좁혀 놓고 상세에 들어갔다가 이 링크를 누르면 전체로 리셋됐다. 뒤쪽은 `코스 목록으로` 가
> **여전히 코스 목록으로 간다**는 점에서 깨지지 않는다.

- **상세 URL 에는 조건이 없다.** 상세 혼자서는 복원할 근거가 없으므로 **목록 행이 조건을 링크에 실어 보낸다**
  (`walkCourseFilterHref`, 목록 D0 의 직렬화와 같은 함수 — 기본값 생략 규칙이 한쪽에서만 바뀌지 않는다).
- **받은 쿼리를 그대로 되비추지 않는다.** 라우트가 `parseWalkCourseFilters` 로 한 번 거르고 다시 조립한다 —
  화이트리스트 밖 값(`?sort=DURATION_ASC`)이나 손으로 적어 넣은 잡음이 우리 링크에 실려 나가지 않는다.
- **성공·로딩만 복원한다.** 오류·404 의 `코스 목록으로` 는 `/walk-courses` 고정이다 — 코스를 못 받은 자리라
  사용자가 어느 목록에서 왔는지 화면이 주장할 근거가 없다.
- **상세 `generateMetadata` 가 `canonical` 을 못박는다.** 되돌림용 쿼리 때문에 같은 코스가 조합 수만큼 서로
  다른 크롤 가능 URL 이 된다 — 공개 SEO 화면이라(`architecture-guide.md` §9) 정규 주소를 하나로 모은다.
- **미해결**: 로그인 왕복(`toLoginHref`)이 경로만 실어 쿼리를 잃는다. 미로그인 사용자가 `일정에 담기` 로
  로그인하고 돌아오면 복원이 끊긴다.

**D4-2. `startEndPoint` 를 갈라 쓰지 않는다.** `제주민속촌주차장 입구-남원포구` 처럼 공백과 하이픈이 섞여 있고
시설명 안에 하이픈이 들어올 수 있다. **원문 한 줄로 렌더한다** (목록 D4-4 와 같은 규칙).

**D4-3. `baseDate` 를 `Date` 로 파싱하지 않는다.** 계약이 **문자열**이고(`WalkCourseDetailResponse.java:39`)
`2025-04-28` 은 자정 UTC 로 읽히면 KST 기준 하루 밀린다. **문자열 그대로 `2025-04-28 기준` 으로 렌더한다.**

### D5-1. 골든타임 문구를 여기서 다시 쓰지 않는다

`WalkTimesSection` 이 `goldenWindowStatus` 4갈래(`AVAILABLE` · `SUPPRESSED_BY_WARNING` · `ALL_HOURS_RISKY` ·
`NO_FORECAST`)와 `forecastCoverage` 분기를 **이미 확정된 문구로** 갖고 있다. 이 화면은 **데이터와 `onRetry` 만
넘긴다.** 문구를 새로 정하면 홈과 코스 상세가 같은 상태에 다른 말을 한다 — #270 이 정확히 그 결함이었다.

**기준점은 `basis="course-start"` 로 넘긴다** ([#779](https://github.com/8llow8llowMe/hondigagae/issues/779) 에서 개정).

> **개정 전에는 `positionFallback={false}` 였다.** _"폴백이 아니니 `false`"_ 까지만 따졌고, 그 `false` 가 화면에
> `현재 위치 기준` 을 내보낸다는 것을 놓쳤다 — 조회 좌표는 사용자 위치가 아니라 코스 시작점이라 **그 줄이 거짓**이었다.
> 그것을 덮으려 캡션 한 줄(D8-5 ①)을 덧붙였고, 결과적으로 한 카드가 기준점을 **두 번, 서로 다르게** 말했다.

`positionFallback: boolean` 은 `basis: 'current' | 'jeju' | 'course-start'` 로 바뀌었다. 표현할 수 없는 상태를
불린에 욱여넣으면 가장 가까운 거짓이 나간다는 것이 그 버그의 교훈이다. **캡션은 이 화면이 따로 그리지 않는다** —
`WalkTimesSection` 의 기준 줄이 시작점을 말한다.

### D5-2. 좌표가 없을 때 — 자리와 제목은 유지하고 안내 상자를 넣는다 (#730 에서 개정)

> **개정 전에는 "말은 하되 자리는 만들지 않는다" 였다.** 근거는 _"기다리면 채워질 것처럼 보이는 자리를 두지
> 않는다"_ 였고 그 걱정 자체는 지금도 맞다. 틀렸던 것은 **그 갈래가 예외라는 전제**다 — 25/29(86%)가 이
> 모양이라 "예외를 조용히 걷는다" 가 실제로는 **화면의 기본형을 절반 빈 화면으로** 만들었다
> (390 실측: 콘텐츠가 y≈850 에서 끝나고 문서 높이 1806 — 약 53%가 빈 공간).

- **스켈레톤·비활성 버튼은 여전히 두지 않는다.** 기다리면 채워질 것처럼 보이고, 비활성 버튼은 "왜 안 되는지"
  를 화면이 따로 설명해야 한다 (`place-filter-fields.tsx` 가 같은 이유로 컨트롤 자체를 숨긴다).
- **카드와 제목(`오늘 산책하기 좋은 시간`)은 좌표 있는 갈래와 같은 뼈대로 둔다.** 제목 문자열도 마크업도
  복제하지 않는다 — 문자열은 `messages.home.goldenHeading`, `h2` 는 `Surface` 의 `title` 슬롯이 그린다.
- **상자는 사실 둘만 담는다** ([#780](https://github.com/8llow8llowMe/hondigagae/issues/780) 에서 개정):
  ① 왜 없는지 ② 얼마나 흔한 일인지(**개수는 적지 않는다** — 서버가 센다). 대안은 사실이 아니라 **다음
  행동**이라 상자 밖 본문 흐름에 선다.

  > **개정 전에는 상자가 셋(대안 둘 포함)을 담았다.** 375 실측에서 안내가 본문 806px 중 408px(51%),
  > 상자만 250px 이었다 — **이 갈래가 25/29 라 그 과잉이 곧 화면의 기본형이었다.** #730 이 "절반 빈
  > 화면" 을 고치려다 "절반이 없다는 안내" 로 채운 셈이다. 접어 두는 안은 쓰지 않았다: 기본 갈래에
  > "펼쳐야 보이는" 한 겹을 더하는 것은 같은 실수를 형태만 바꿔 반복한다.

- **남는 대안은 하나다** — `시·종점 근처 장소 보기` → `/places`. **검색어를 채우지 않는다**:
  `startEndPoint` 는 갈라 쓰지 않기로 했고(D4-2), 서버 `keyword` 는 `title`·`addr1` 의 `%LIKE%` 라 그
  원문에서 만든 토막은 대부분 0건이다. **결과 없음으로 데려가는 대안은 대안이 아니다.**
  하나뿐이라 `<ul>` 로 감싸지 않는다 — "둘 중 고르는 것" 을 알리려던 문법인데 고를 것이 하나면 거짓이 된다.
- **`일정에 담기` 를 안내에서 말하지 않는다** (#780 에서 삭제). 그 버튼이 같은 화면 바로 아래에 **실물로**
  있다 — 개정 전에는 "버튼을 하나 더 두지 않는다" 까지만 지켰고 **말이 중복되는 것은 놓쳤다.** 안내가
  가리키는 대상과 그 대상이 나란히 있으면 안내가 아니라 잡음이다.
- **설명 문장은 `body-2` 다.** 높이를 줄이려 `caption` 으로 내리지 않는다 — `DESIGN.md` §3-1 이 본문 기본을
  `body-2` 로 두고 `caption` 을 메타·태그·배지·단위로 한정한다. 높이는 `gap`·`py` 로 줄인다.
- 문구가 **"아직"** 이라고 말하는 이유: 데이터가 채워지면 생기는 값이다 (적재 [#383](https://github.com/8llow8llowMe/hondigagae/issues/383)).
  "정보가 없어요" 는 영구적 결핍처럼 들린다.
- **목록에서는 이 상자도 만들지 않는다** (목록 D5-1).

## D6. 접근성

- h1 은 `courseLabel` 이다. 구간명은 그 아래 `<p>` — `1코스 시흥-광치기` 를 한 h1 에 몰지 않는다.
- 핵심값 2개(거리·소요시간)는 **`<dl>`** 이다. `거리`/`소요시간` 라벨이 글자로 있어야 숫자만 읽히지 않는다.
  **단위를 라벨이 아니라 값에 붙인다** — `15.1km`(값)가 스크린리더에서도 단위와 함께 읽힌다.
- `baseDate` 는 `<time dateTime="2025-04-28">` 로 감싼다. 문자열 그대로 렌더하되 시맨틱은 준다 (D4-3).
- 좌표 없음 안내는 **`role` 을 주지 않는다.** 오류가 아니라 이 코스의 사실이다 — `role="alert"` 를 붙이면
  스크린리더가 페이지 진입마다 경고로 읽는다.
- 골든타임 재시도 버튼의 접근 이름은 `날씨 다시 불러오기` — `다시 시도` 만이면 무엇을 다시 하는지 모른다.
- 터치 영역 44px. 색 외 전달: 골든타임 등급은 `MetricBadge` 의 낱말이 함께 선다 (`DESIGN.md` §7).
