## D0. 화면 정의

- **경로**: `/walk-courses/[walkCourseId]`
- **인증**: **불필요**. `PROTECTED_PATHS` 에 넣지 않는다
- **진입 경로**: 코스 목록의 행 · 공유된 주소
- **이탈 경로**: `코스 목록으로` · 골든타임 안의 링크 없음(패널은 읽기 전용) · (#620 이후) 담기 시트

### D0-1. 숫자가 아닌 `walkCourseId` 는 **400** 이다 — 404 가 아니다

컨트롤러가 `@PathVariable long` 이라(`WalkCourseWebController.java:74`) 파싱 단계에서 갈린다. dev 실측:

| 주소                         | 상태 | 코드             | `fieldErrors[0].field` |
| ---------------------------- | ---- | ---------------- | ---------------------- |
| `/walk-courses/abc`          | 400  | `WALKCOURSE_113` | `walkCourseId`         |
| `/walk-courses/1234…3456789` | 404  | `WALKCOURSE_001` | —                      |

**`/places/{placeId}` 와 정확히 같은 모양이다** (`screen-inventory.md` §3). 그래서 같은 처치를 한다 —
`proxy.ts` 에 `/walk-courses/:path*` 매처와 숫자 판정을 추가하고, 형식이 틀리면 **`rewrite` 로 상태만 400** 으로
바꾼다 (`proxy.ts:29-51` 의 `PLACE_DETAIL_PATH` 주석이 근거다: 공개 경로라 크롤러가 잘못된 주소를 200 으로 읽고
모니터링이 실패를 세지 못한다). **`redirect` 도 `notFound()` 도 아니다** — 둘 다 사용자가 보던 화면을 잃거나
404 가 아닌 것을 404 라고 말한다.

없으면 **자리를 만들지 않는다.** 실측 기준 29개 중 25개가 이 모양이다 (공통명세 S3-1).

먹던 동안에는 이 화면의 차별 정보인 골든타임이 접힘선 아래로 밀렸다 (1280 실측 1400px = 뷰포트의 155%).
`firstImage` 와 좌표는 **같은 4개**에만 있으므로(공통명세 S3-1), 2열이 서는 날은 우측에 세울 것이 실제로 있는 날이다.

## D3. 데이터 흐름

```text
/walk-courses/{id}
  → page.tsx (server)
      isWalkCourseId(id) 아니면 → 400 화면 (proxy 가 상태코드를 맞춘다)
      fetchQuery(GET /walk-courses/{id})   try/catch
      HydrationBoundary
  → WalkCourseDetailView (client)
      hasCoordinates(course) === false → 끝. 골든타임을 부르지 않는다
      true → useWalkTimes({lat, lng}, toPetCondition(selectedPet))
```

| 항목                       | 내용                                                                                                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| API                        | `GET /api/v1/walk-courses/{walkCourseId}` (+ 좌표가 있을 때만 `GET /api/v1/insights/walk-times`)                 |
| React Query key            | 코스: `walkCourseKeys.detail(walkCourseId)` / 골든타임: **기존 `insightKeys.walkTimes(lat, lng, conditionKey)`** |
| staleTime / gcTime / retry | 코스 **5분 / 30분 / 2** (목록과 같다) · 골든타임 **`INSIGHT_QUERY_OPTIONS`**(5분/30분/retry 1) 를 그대로 쓴다    |
| mutation 후 invalidate     | 없다 (이 이슈에서는 mutation 이 없다)                                                                            |
| 폴링                       | 없다                                                                                                             |

- **골든타임 key 를 새로 만들지 않는다.** `insightKeys.walkTimes` 는 **좌표 축**이라(`lib/insight/queries.ts:34`)
  홈에서 같은 좌표·같은 조건으로 이미 받아 뒀으면 그대로 재사용된다. 코스 전용 key 를 만들면 같은 답을 두 벌 캐시한다.
- **반려견 조건은 nav 선택견이다** (`useSelectedPet(authed)`). 목록의 활동량 기본값이 대표견인 것과 **다른 축이라
  일부러 다르다** — 저쪽은 *카탈로그를 좁히는 조건*이고 이쪽은 *판정의 기준*이다. 판정 화면(홈·장소 상세)은 전부
  nav 선택견을 쓴다. 이 어긋남 자체는 `코스목록-세부명세.md` D8-1 에 적어 뒀다.
- **미로그인이면 조건 없이 부른다.** 사람 기준 판정이 오고, 그것은 **정상 응답**이다. `petConditionApplied: false`
  일 때 반려견 이름을 붙이지 않는 규칙도 그대로다 (`screen-inventory.md` §3-1).

### D3-1. 좌표가 null 이면 **부르지 않는다** — 한 곳에서만 판정한다

```ts
// lib/walk-course/coordinates.ts
export function hasCoordinates(course: { lat: number | null; lng: number | null }): boolean {
  return course.lat !== null && course.lng !== null
}
```

- `useWalkTimes` 의 `enabled` 는 이미 `position !== null` 이다. **`position` 을 만들 때 걸러낸다** —
  `hasCoordinates(course) ? { lat: course.lat, lng: course.lng } : null`.
- **`lat ?? 0` 을 쓰지 않는다.** 서버는 `(0, 0)` 에 **200 으로 답한다** — 기니만 앞바다의 예보가 정상 응답으로
  와서, 화면은 틀린 것을 틀렸다고 말할 방법이 없다 (공통명세 S4-2).
- **`Number.isFinite` 로 넓히지 않는다.** 계약이 `Double | null` 이고(`WalkCourseItem.java:37,40`) `NaN` 은 오지
  않는다. 판정을 넓히면 테스트가 실제 계약이 아닌 것을 지키게 된다.

## D4. 상호작용

| 트리거                     | 동작                               | 결과                                                            |
| -------------------------- | ---------------------------------- | --------------------------------------------------------------- |
| `코스 목록으로`            | `/walk-courses` 로 이동            | **조건을 복원하지 않는다** — 브라우저 뒤로가기가 그 역할이다    |
| 골든타임 `다시 시도`       | `walkTimes.refetch()`              | **예보를 못 받았을 때만 렌더된다** (`onRetry` 를 그때만 넘긴다) |
| 반려견 전환 (전역 nav)     | 조건 key 가 바뀌어 골든타임 재조회 | **코스 조회는 재조회되지 않는다** — 코스는 반려견과 무관하다    |
| 404 화면의 `코스 목록으로` | `/walk-courses`                    | 재시도 버튼 대신 주는 **다음 행동**이다                         |

**D4-1. 뒤로가기로 목록 조건이 살아 있게 한다.** 목록의 조건은 URL 에 있으므로(목록 D0) 별도 복원 로직이 필요
없다. `코스 목록으로` 버튼이 조건 없는 `/walk-courses` 로 가는 것은 **의도**다 — 링크가 어디로 가는지 이름과
같아야 한다.

**D4-2. `startEndPoint` 를 갈라 쓰지 않는다.** `제주민속촌주차장 입구-남원포구` 처럼 공백과 하이픈이 섞여 있고
시설명 안에 하이픈이 들어올 수 있다. **원문 한 줄로 렌더한다** (목록 D4-4 와 같은 규칙).

**D4-3. `baseDate` 를 `Date` 로 파싱하지 않는다.** 계약이 **문자열**이고(`WalkCourseDetailResponse.java:39`)
`2025-04-28` 은 자정 UTC 로 읽히면 KST 기준 하루 밀린다. **문자열 그대로 `2025-04-28 기준` 으로 렌더한다.**

### D5-1. 골든타임 문구를 여기서 다시 쓰지 않는다

`WalkTimesSection` 이 `goldenWindowStatus` 4갈래(`AVAILABLE` · `SUPPRESSED_BY_WARNING` · `ALL_HOURS_RISKY` ·
`NO_FORECAST`)와 `forecastCoverage` 분기를 **이미 확정된 문구로** 갖고 있다. 이 화면은 **데이터와 `onRetry` 만
넘긴다.** 문구를 새로 정하면 홈과 코스 상세가 같은 상태에 다른 말을 한다 — #270 이 정확히 그 결함이었다.

**`positionFallback` 은 `false` 로 넘긴다.** 그 prop 은 "기기 위치를 못 얻어 제주 중심으로 조회했다" 를 뜻하는데
(#180), 여기 좌표는 **코스의 시작점**이라 폴백이 아니다. `true` 를 넘기면 화면이 없는 사실을 말한다.

### D5-2. 좌표가 없을 때 — 자리와 제목은 유지하고 안내 상자를 넣는다 (#730 에서 개정)

> **개정 전에는 "말은 하되 자리는 만들지 않는다" 였다.** 근거는 _"기다리면 채워질 것처럼 보이는 자리를 두지
> 않는다"_ 였고 그 걱정 자체는 지금도 맞다. 틀렸던 것은 **그 갈래가 예외라는 전제**다 — 25/29(86%)가 이
> 모양이라 "예외를 조용히 걷는다" 가 실제로는 **화면의 기본형을 절반 빈 화면으로** 만들었다
> (390 실측: 콘텐츠가 y≈850 에서 끝나고 문서 높이 1806 — 약 53%가 빈 공간).

- **스켈레톤·비활성 버튼은 여전히 두지 않는다.** 기다리면 채워질 것처럼 보이고, 비활성 버튼은 "왜 안 되는지"
  를 화면이 따로 설명해야 한다 (`place-filter-fields.tsx` 가 같은 이유로 컨트롤 자체를 숨긴다).
- **카드와 제목(`오늘 산책하기 좋은 시간`)은 좌표 있는 갈래와 같은 뼈대로 둔다.** 제목 문자열도 마크업도
  복제하지 않는다 — 문자열은 `messages.home.goldenHeading`, `h2` 는 `Surface` 의 `title` 슬롯이 그린다.
- 상자가 **셋**을 담는다: ① 왜 없는지 ② 얼마나 흔한 일인지(**개수는 적지 않는다** — 서버가 센다)
  ③ **대안 두 개**.
- 대안 ① `시·종점 근처 장소 보기` → `/places`. **검색어를 채우지 않는다** — `startEndPoint` 는 갈라 쓰지
  않기로 했고(D4-2), 서버 `keyword` 는 `title`·`addr1` 의 `%LIKE%` 라 그 원문에서 만든 토막은 대부분
  0건이다. **결과 없음으로 데려가는 대안은 대안이 아니다.**
- 대안 ② `일정에 담고 그날 판정 받기` → **아래 CTA 를 가리키는 글이다. 버튼을 하나 더 두지 않는다** —
  같은 이름의 컨트롤이 둘이면 보조기기에서 목적지가 둘로 들린다.
- 문구가 **"아직"** 이라고 말하는 이유: 데이터가 채워지면 생기는 값이다 (적재 [#383](https://github.com/8llow8llowMe/hondigagae/issues/383)).
  "정보가 없어요" 는 영구적 결핍처럼 들린다.
- **목록에서는 이 상자도 만들지 않는다** (목록 D5-1).

### D5-3. 걸을 만한 활동량 — 무엇을 말하고 무엇을 말하지 않는가 ([#748](https://github.com/8llow8llowMe/hondigagae/issues/748))

`fitsActivityLevels` 는 `List<CodeNameDescriptionMetadata>` 로 **상세에만** 온다
([#718](https://github.com/8llow8llowMe/hondigagae/issues/718)). [#735](https://github.com/8llow8llowMe/hondigagae/issues/735)
가 타입(`types/walk-course.ts:113-123`)과 테스트 fixture(`test/fixtures/walk-course.ts:62-79`)까지 옮겨 두었고
**화면에 그리는 것은 이 이슈가 처음이다. BE 작업은 없다.**

#### 갈래를 가르는 값은 `durationMaxMinutes` 다 — `fitsActivityLevels.length` 가 아니다

| `durationMaxMinutes` | `fitsActivityLevels`              | 뜻                                                                          |
| -------------------- | --------------------------------- | --------------------------------------------------------------------------- |
| `120` (10-1코스)     | `낮음` · `보통` · `높음` — **셋** | **안다.** 짧아서 정말 아무 아이나 걸을 만하다                               |
| `300` (1코스)        | `보통` · `높음`                   | **안다.**                                                                   |
| `null` (20코스)      | `낮음` · `보통` · `높음` — **셋** | **모른다.** 소요시간 원문을 파싱하지 못해 어느 활동량에서도 걸러지지 않았다 |

- **`length === 3` 으로 가르면 10-1코스가 "모른다" 로 떨어진다.** 서버 `WalkCourseActivityFit.fits` 는
  `LOW ≤ 240분` 이라 **120분짜리 코스도 세 값을 받는다** — mock 서버가 같은 규칙을 갖고 있어 로컬에서
  재현된다 (`lib/api/mock/walk-course-data.ts:168-173` `fits`, `:190-199` `fittingLevels`).
- 배열이 **빈 채로 오지 않는다** — `HIGH` 는 상한이 없어 항상 통과한다. 그래도 빈 배열이면 **줄을 그리지
  않는다**(모르는 갈래 문장으로 새지 않게).
- 판정은 **`lib/walk-course/activity-fit.ts` 한 곳에서만** 한다 — `hasCoordinates` 와 같은 이유다 (D2 · D3-1).
  두 필드를 호출부가 각자 조합하면 한쪽만 고쳐진다.

#### ① 모르는 갈래는 **침묵이 아니라 한 줄**이다

| 선택지                                               | 판단                                                |
| ---------------------------------------------------- | --------------------------------------------------- |
| (a) 활동량 줄 자체를 그리지 않는다 (침묵)            | 기각                                                |
| **(b) 한 줄로 부재를 설명한다**                      | **채택**                                            |
| (c) `durationText` 원문을 다시 보여 주고 주석을 단다 | 기각 — 같은 값을 두 번 말하고 `<dl>` 의 답과 겹친다 |

**(b) 를 택한 근거:**

- 이 저장소는 **부재가 화면의 기본형이거나, 말하지 않으면 사용자가 화면을 잘못 읽는 경우** 부재를 설명해
  왔다 — D5-2(#730 이 _"말은 하되 자리는 만들지 않는다"_ 를 뒤집은 자리) · `messages.walkCourse.noGoldenInScope`
  (_"그 사실을 말하지 않으면 사용자는 기능의 존재를 모른다"_).
- **침묵을 택한 선례는 주변이 이미 통째로 걷힌 화면이었다** — `plan/일정상세-세부명세.md` D13-3
  (_"완료에서 '왜 없는지' 를 말하지 않는다. 그 화면은 확정/완료 버튼·순서 편집까지 이미 걷힌 상태다"_)과
  같은 문서 D13-10 3번. **여기는 그 모양이 아니다**: 머리의 다른 줄(거리·소요시간·시종점)은 그대로 서 있고
  활동량 줄만 사라진다. 한 줄만 조용히 빠지는 것은 설명이 아니라 **차이의 은폐**다.
- **말하지 않으면 사용자가 앞 화면을 잘못 읽은 채로 남는다.** 이 코스는 목록의 활동량 필터를 **전부
  통과한다**(서버가 모르는 것을 나쁜 것으로 판정하지 않는다). `낮음` 으로 좁혀 들어온 사용자는 목록 기준
  줄에서 `… 4시간 이내 코스만 보여 줘요.` 를 읽고 들어오는데, 상세가 아무 말도 하지 않으면 그 문장이 이
  코스에도 적용된 것으로 남는다. **그 오해를 고칠 수 있는 자리가 지금은 여기뿐이다**(목록 쪽 몫은 D8-7).
- **`<dl>` 의 `소요시간` 이 이미 말해 준다는 반론은 성립하지 않는다.** `durationText` 는 **원문**이라
  파싱 실패가 `미정` 으로 보이는 코스도 있고 `6시간 30분 내외` 처럼 **정상적인 소요시간으로 읽히는** 코스도
  있다. 원문이 무엇인지는 화면이 모른다 — 실물 분포는 백엔드 미기동으로 확인하지 못했다(D8-8).
- **다만 D5-2 처럼 상자로 키우지 않는다.** 그 상자가 큰 이유는 ③ **대안 두 개**를 담기 때문인데, 여기에는
  대안이 없다(적재가 채운다). **한 줄이다.**

#### ② 아는 갈래는 **배지가 아니라 한 줄**이다

| 선택지                           | 판단                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| (a) 배지 나열 (`보통` `높음`)    | 기각                                                        |
| **(b) 한 줄 문장**               | **채택**                                                    |
| (c) `<dl>` 세 번째 칸으로 넣는다 | 기각 — 고정 2열이라 셋째 칸이 반 칸을 비운 채 걸린다 (#730) |

**(b) 를 택한 근거:**

- **쓸 수 있는 배지가 `Badge tone="neutral"` 하나뿐이다.** 등급 배지(`MetricBadge`)는 `suitability` ·
  `congestion` 축 전용이고, **값이 같아도 뜻이 다르면 토큰을 빌려 쓰지 않는다**가 규칙이다
  (`components/badge.tsx` 주석 · `DESIGN.md` §2-9 · #598). `Badge` 의 `brand` 톤을 등급 표시로 전용하는 것도
  금지돼 있다(`component-guide.md` §1 주석). 남는 중립 배지 세 개는 **정보를 더하지 않고 무게만 더한다.**
- **낱말만 나열하면 "누구의 활동량인지" 가 빠진다.** `낮음 · 보통` 은 코스의 활동량으로도 읽힌다. 목록은
  같은 모호함을 `{pet} 활동량({level}) 기준으로 …` 라는 **문장**으로 풀었다(`messages/walk-course.ts`
  `activityBasis`). 같은 화면군에서 같은 값을 다른 문법으로 말하지 않는다.
- `<dl>` 은 **고정 2열 그리드**다(`walk-course-summary-header.tsx:74-96`, #730 이 값 길이로 열이 밀리던 것을
  고친 자리). 활동량 값은 최대 세 낱말이라 다른 두 칸(`15.1km`)과 값의 모양 자체가 다르다 — **`<dl>` 안에
  넣지 않는다.**

**문구 (확정)** — 키 추가는 구현 단계에서 `messages/walk-course.ts` 의 `── 상세 ──` 절에 한다.

| 키                   | 값                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------- |
| `activityFit`        | `활동량({levels}) 아이가 걸을 만한 코스예요.`                                       |
| `activityFitUnknown` | `이 코스는 걷는 시간이 아직 정리되지 않아서 걸을 만한 활동량을 알려 드리지 못해요.` |

- **`{levels}` 는 서버 `name` 을 `·` 로 이은 문자열이다.** FE 에 한국어 매핑 테이블을 만들지 않는다
  (`api-integration-guide.md` §6 · `messages/walk-course.ts` 머리 주석: _"활동량 이름(`낮음`·`보통`)도 여기
  없다"_). 잇는 것은 번역이 아니라 나열이다.
- **괄호 형식은 목록의 `활동량({level})` 을 그대로 물려받는다.** 값이 하나(`활동량(높음) 아이가 …`)든
  셋(`활동량(낮음 · 보통 · 높음) 아이가 …`)이든 조사가 흔들리지 않는다 — `높음인 아이` 같은 어색한 결합을
  피하려고 목록이 이미 고른 형식이다.
- **`activityFitUnknown` 은 `noCoordinates` 와 같은 골격이다** (`이 코스는 … 아직 … 알려 드리지 못해요.`).
  **"아직"** 이라고 말하는 이유도 같다 — 적재([#383](https://github.com/8llow8llowMe/hondigagae/issues/383))로
  채워지는 값이라 "없어요" 는 영구적 결핍처럼 들린다.
- 둘 다 **해요체**다 (`DESIGN.md` §1 · `messages/message-tone.test.ts` 가 합쇼체를 막는다). **개수를 적지
  않는다** — 같은 테스트의 두 번째 축이다.

#### ③ **판정하지 않는다** — 서버가 말한 사실만 옮긴다

| 선택지                                                                           | 판단                                      |
| -------------------------------------------------------------------------------- | ----------------------------------------- |
| **(a) 판정하지 않는다 — 사실만 말한다**                                          | **채택**                                  |
| (b) nav 선택견의 `activityLevel.code` 가 목록에 있는지 판정해 말한다             | 기각                                      |
| (c) **중간** — 사실 나열 안에서 내 아이의 활동량에 해당하는 값만 표시로 구분한다 | **먼저 검토했고 기각** — 아래가 그 셈이다 |

**(c) 를 우선 검토안으로 놓고 셌다.** (c) 의 근거는 _"주장의 세기가 데이터와 같아진다"_ 다 — 서버가 이
활동량들이 맞다고 했고 내 아이는 그중 하나다, 그 이상은 말하지 않는다. 그 원칙 자체는 **이 문서가 ①에서
쓴 원칙과 같다**: `durationMaxMinutes === null` 에 배지 셋을 그리지 않는 이유는 **모르는 것을 아는 것처럼
말하지 않기 위해서**다.

**그런데 그 원칙을 (c) 에 끝까지 적용하면 (c) 가 걸린다.**

- 데이터가 뒷받침하는 가장 강한 주장은 **두 값짜리 사실**이다 — `내 아이 활동량 ∈ {levels}` 또는 `∉ {levels}`.
- (c) 는 그중 **∈ 쪽만 그린다.** `∉` 일 때는 **표시가 하나도 붙지 않는다.**
- 그래서 (c) 는 _데이터와 세기가 같은_ 것이 아니라 **한쪽으로 치우친 채 나머지 절반을 무표시에 실어
  보낸다.** 사용자는 그 무표시가 `우리 아이에겐 무리` 인지 `우리 아이를 몰라서` 인지 가릴 수 없다.
- **이것은 null 갈래가 저지르는 잘못의 거울상이다.** null 갈래의 죄는 _정보의 부재가 정보처럼 그려지는 것_
  (배지 셋 = "아무 아이나")이고, (c) 의 죄는 _표시의 부재가 판정처럼 읽히는 것_ 이다. **같은 원칙이 (c) 를
  기각한다.**
- 대칭으로 고치려면 `∉` 일 때도 무언가 말해야 하는데, 그 순간 (c) 는 **(b) 가 된다.** 즉 (c) 는 독립된
  선택지가 아니라 **(b) 를 절반만 하는 상태**다.

**그러면 (b) 인가 — 아니다. (b) 도 기각한다.**

1. **이 화면에는 반려견 축이 하나도 서 있지 않다.** `WalkCourseSummaryHeader` 는 `{ course }` 만 받고
   (`walk-course-summary-header.tsx:59`), `WalkCourseGoldenSlot` 은 `course` · `walkTimes` 만 받으며,
   `WalkTimesSection` 에는 **반려견 prop 자체가 없다**(`walk-times-section.tsx:57-63`). 골든타임이 속으로
   nav 선택견 조건을 쓰면서도(`walk-course-detail-view.tsx` `toPetCondition(pet)`) 화면에 이름을 적지 않는
   상태다 — **D8-2 가 _"기준 줄에 이름을 적는다"_ 고 했는데 구현되지 않았다**(골든 카드 캡션은
   `코스 시작점 기준이에요.` 하나뿐이다). 그 줄이 없는 채로 판정 문장부터 들이면, **화면의 유일한 개인화
   문장이 어느 아이 이야기인지 화면 어디에도 없는** 모양이 된다.
2. **상세로 들어오는 경로의 상당수에 반려견이 없다.** 공유 링크 · 일정 항목의 코스 · 목록을 `전체` 로 본
   경우, 그리고 **미로그인**(이 화면은 `PROTECTED_PATHS` 가 아니다 — D0). 판정 문장은 그 사용자에게서
   사라지므로 **"어떻게 들어왔느냐" 가 화면의 답을 바꾼다.**
3. **부정 판정은 다른 판정과 어긋날 수 있다.** 이 화면이 낼 수 있는 판정은 `activityLevel` **한 축**뿐인데,
   같은 아이·같은 산책에 대한 판정은 담은 뒤 일자 화면에서 **날씨·체중·더위민감까지 보고** 나온다. 같은
   상태에 두 화면이 다른 말을 하는 결함을 이 저장소는 이미 세 번 고쳤다(#204 · #262 · #270 — D5-1 이
   _"문구를 여기서 다시 쓰지 않는다"_ 로 닫은 자리). **판정의 집은 이미 있다.**
4. **(a) 의 비용은 작다.** 활동량은 사용자가 **자기 프로필에 직접 넣은 값**이고(`Pet.activityLevel`),
   화면이 쓰는 낱말이 그 프로필·목록 세그먼트와 **같은 서버 `name`** 이다. 사용자는 한 번의 대조만 하면 된다.

**그래서 이 화면에 `authed` · `pet` 분기를 새로 만들지 않는다.** `WalkCourseSummaryHeader` 의 시그니처는
`{ course }` 그대로다.

- **(c) 였다면 이 표의 아래 세 줄이 "표시 없음" 으로 퇴화한다.** 그 퇴화는 (c) 의 부작용이 아니라 (c) 의
  정의다 — 표시할 "해당 값" 이 없기 때문이다. 그리고 **그 퇴화한 화면은 `∉` 인 로그인 사용자가 보는 화면과
  글자 하나 다르지 않다.** 같은 마크업이 두 가지 뜻(모름 / 안 맞음)을 갖는 것은 이 문서가 ①에서 금지한 바로
  그 모양이다.
- **(a) 에서는 퇴화가 없다.** 문장이 반려견을 주어로 삼지 않아(`활동량(…) 아이가`) **네 줄이 같은 문장으로
  성립한다.** 미로그인 사용자가 잃는 것은 없다 — 그가 못 보는 문장이 애초에 없다.

##### 그 사용자에게 "반려견을 등록하면" 이라고 말할까 — 말하지 않는다

이 저장소는 그 유도를 **판정이 이미 서 있는 자리**에만 붙였다.

| 자리                    | 유도                                                                                       | 왜 성립하나                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 홈 판정 카드            | `반려견을 등록하면 우리 아이 기준으로 판정해요`(`messages/home.ts:418`)                    | 그 자리의 판정이 지금 **사람 기준**이고 등록하면 **그 자리가** 바뀐다                                                      |
| 장소 상세 적합도        | `반려견을 등록하면 크기·민감도까지 반영한 적합도를 볼 수 있어요.`(`messages/place.ts:185`) | 같다. 게스트에겐 점수·근거·`{name}에게` 를 아예 쓰지 않는다                                                                |
| 장소 필터의 크기 제한   | **없다 — 컨트롤 자체를 숨긴다**                                                            | 반려견이 없으면 그 축이 존재하지 않는다 (`use-selected-pet.ts` 주석 · `place-filter-fields.tsx`)                           |
| **이 화면의 담기 버튼** | **없다 — 버튼을 그대로 두고 로그인으로 보낸다**                                            | `walk-course-add-action.tsx`: _"안내 시트를 한 번 더 두지 않는다 … 버튼 자체는 항상 보인다 — 기능의 존재를 숨기지 않는다"_ |

- **활동량 줄에 유도를 붙이면 지키지 못할 약속이 된다.** (a) 를 택했으므로 **반려견을 등록해도 이 줄은 한
  글자도 바뀌지 않는다.** 홈·장소 상세의 두 선례가 성립하는 이유가 여기서는 성립하지 않는다.
- **이 화면에 유도가 설 자리가 있긴 하다 — 골든타임 카드다.** 미로그인이면 골든타임이 사람 기준으로
  판정되고(`petConditionApplied: false`), 등록하면 **그 카드가** 바뀐다. 즉 홈·장소 상세와 같은 조건이다.
  **다만 그것은 활동량이 아니라 `WalkTimesSection` 의 몫이고 이 이슈의 범위가 아니다** → D8-9.
- 그래서 이 화면의 미로그인 갈래는 **이미 있는 처리 그대로**다: 담기 버튼은 보이고 누르면 로그인으로 간다.
  활동량 줄은 누구에게나 같다. **설명을 하나 더 얹는 것은 화면 문법을 흐리는 참견이다.**

## D6. 접근성

- h1 은 `courseLabel` 이다. 구간명은 그 아래 `<p>` — `1코스 시흥-광치기` 를 한 h1 에 몰지 않는다.
- 핵심값 2개(거리·소요시간)는 **`<dl>`** 이다. `거리`/`소요시간` 라벨이 글자로 있어야 숫자만 읽히지 않는다.
  **단위를 라벨이 아니라 값에 붙인다** — `15.1km`(값)가 스크린리더에서도 단위와 함께 읽힌다.
- `baseDate` 는 `<time dateTime="2025-04-28">` 로 감싼다. 문자열 그대로 렌더하되 시맨틱은 준다 (D4-3).
- 좌표 없음 안내는 **`role` 을 주지 않는다.** 오류가 아니라 이 코스의 사실이다 — `role="alert"` 를 붙이면
  스크린리더가 페이지 진입마다 경고로 읽는다.
- **활동량 줄도 `role` 을 주지 않는다** (아는 갈래 · 모르는 갈래 둘 다). 오류가 아니라 이 코스의 사실이고,
  `role="alert"` 를 붙이면 스크린리더가 페이지 진입마다 경고로 읽는다 — 위 좌표 안내와 같은 축이다.
- **활동량 줄은 `<p>` 한 줄이다. `<dl>` 안에 넣지 않는다** (D5-3 ②). 값이 낱말 나열이라 `<dd>` 로 읽히면
  거리·소요시간과 같은 단일 지표로 들린다.
- 골든타임 재시도 버튼의 접근 이름은 `날씨 다시 불러오기` — `다시 시도` 만이면 무엇을 다시 하는지 모른다.
- 터치 영역 44px. 색 외 전달: 골든타임 등급은 `MetricBadge` 의 낱말이 함께 선다 (`DESIGN.md` §7).
