# 제주올레 코스 공통 명세

> 작성일: 2026-09-18
> 관련 백엔드 서비스: `tour-service` (`walkcourse` 컨텍스트)
> 이슈: [#618](https://github.com/8llow8llowMe/hondigagae/issues/618) · 이름·경로 [#810](https://github.com/8llow8llowMe/hondigagae/issues/810)
>
> **화면 이름은 `제주올레 코스`, 경로는 `/olle` 다** (#810). `산책 코스` / `/walk-courses` 였다 —
> 적재된 29개가 중앙값 15.7km 종주 코스라 `산책` 이 29개 중 28개에 대해 틀린 말이었고, 경로는
> 백엔드 리소스 이름을 복사한 것이었다. **BE 리소스 경로 `/api/v1/walk-courses` 는 그대로다** —
> 아래 API 표의 경로는 바뀌지 않았다.
>
> **계약 확인 근거 — 두 갈래를 모두 실측했다.**
>
> | 갈래           | 무엇                                                                                                                                                                                 | 언제                           |
> | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------ |
> | 백엔드 소스    | `WalkCourseWebController` · `WalkCourseItem` · `WalkCourseListResponse` · `WalkCourseDetailResponse` · `WalkCourseActivityFit` · `WalkCourseErrorCode` (`origin/develop` `2b0b62a4`) | 2026-09-18                     |
> | dev 게이트웨이 | `GET https://api-dev.hondigagae.com/tour-service/v3/api-docs` + 엔드포인트 실호출 6회 (아래 S2-1)                                                                                    | 2026-09-18 (로컬 BE 는 미기동) |
>
> **`docs/api/openapi/tour-service.json` 스냅샷(2026-09-14)을 정본으로 쓰지 않았다.** 이 컨텍스트는
> 2026-09-09 `1f021e90` 로 들어왔고 스냅샷에도 잡혀 있지만, 필드의 **실제 값 분포**(좌표 null 비율 등)는
> 스키마로 알 수 없다. 화면 분기가 그 분포에 걸려 있어 실호출로 확인했다.

## S0. 개요

- **한 줄 정의**: 제주올레 코스를 반려견이 걸을 만한 길이로 좁혀 보고, 좌표가 있는 코스는 오늘 언제 걷기 좋은지까지 이어 본다.
- **사용자가 달성하려는 것**: "우리 아이랑 올레 걸어 볼까" 에서 출발해 **걸을 만한 코스 하나**를 고르고, 그 코스가 오늘 걸을 만한 날씨인지까지 한 화면에서 끝낸다.
- **범위에 포함**: 코스 목록 · 코스 상세 · 걷는 시간 필터 · 정렬 · 좌표가 있는 코스의 골든타임
- **범위에서 제외**:
  - **일정에 코스 담기** — [#620](https://github.com/8llow8llowMe/hondigagae/issues/620) 이 맡는다 (`docs/features/plan/올레담기-세부명세.md`)
  - **코스 경로 폴리라인 · 지도 위 코스 그리기** — 응답에 **시작점 좌표 하나뿐**이고 경로 좌표열이 없다 (S3)
  - 코스 적재 배치 (`walkcourseimport`) — 백엔드 [#383](https://github.com/8llow8llowMe/hondigagae/issues/383)
  - 코스 즐겨찾기 · 후기 — 백엔드 API 없음

## S3. 데이터 모델

`dataBody` 기준이다. 공통 래퍼(`dataHeader.success` 판별)는 `docs/api-integration-guide.md` §2 를 따른다.

```ts
/** `GET /walk-courses` — 근거: WalkCourseListResponse.java:11-46 */
export type WalkCourseList = {
  courses: WalkCourseSummary[]
  /** 조건에 맞는 코스 수. **커서가 없다** — 29개 안팎이라 잘리지 않고 전부 온다 */
  totalCount: number
  /**
   * 서버가 실제로 적용한 활동량과 그 상한. **`null` 이면 거르지 않았다.**
   * 화면이 스스로 판정하지 않는다 (S4-1 규칙 5).
   *
   * 응답의 deprecated `petActivityLevelApplied`(boolean)는 **타입에 두지 않는다** — 같은
   * 사실을 두 곳에서 읽으면 둘이 어긋나는 날 어느 쪽을 믿을지 그때 정하게 된다 (#735).
   */
  appliedPetActivityLevel: WalkCourseAppliedActivityLevel | null
  /** 출처 표기. 상수가 아니라 서버가 내려주는 문자열이다 */
  providerName: string
}

/** 근거: AppliedPetActivityLevelItem.java (#718) */
export type WalkCourseAppliedActivityLevel = {
  /** 서버 enum metadata. `description` 은 **반려견 성향** 문구이지 소요시간 상한이 아니다 */
  level: CodeNameMetadata
  /** 상한(분). **`null` 은 `HIGH`(상한 없음)** — 객체 자체가 null 인 것과 뜻이 다르다 */
  maxDurationMinutes: number | null
}

/** 근거: WalkCourseItem.java:16-44 */
export type WalkCourseSummary = {
  /** **문자열이다.** Snowflake 라 Number() 를 거치면 정밀도를 잃는다 */
  walkCourseId: string
  /** `1코스` · `3코스 (A)` — 서버가 조립해 준다. FE 가 `courseNo + '코스'` 를 만들지 않는다 */
  courseLabel: string
  /** 구간명. `시흥-광치기` */
  name: string
  /** km. JSON number 로 온다 (`15.1`) */
  distanceKm: number
  /** 소요시간 **원문**. `4~5시간` · `1~2시간`. 파싱하지 않는다 */
  durationText: string
  /** 상한(분). **`null` 은 "제한 없음" 이 아니라 "원문 파싱 실패"** 다 (#718) */
  durationMaxMinutes: number | null
  /** 시종점 원문. `시흥리정류장-광치기해변` */
  startEndPoint: string
  /** **null 일 수 있다** — 원천/TourAPI 매칭에 좌표가 없는 코스 */
  lat: number | null
  lng: number | null
  /** 대표 이미지. **null 일 수 있다** */
  firstImage: string | null
}

/** `GET /walk-courses/{walkCourseId}` — 근거: WalkCourseDetailResponse.java:11-59 */
export type WalkCourseDetail = WalkCourseSummary & {
  /** 원천 데이터 기준일자. `2025-04-28` — **문자열이다** (LocalDate 가 아니다) */
  baseDate: string
  /**
   * 이 코스를 걸을 만한 활동량 전부 — **상세에만 있다** (#718). `durationMaxMinutes` 가
   * null 인 코스는 세 값이 다 담기는데 그것은 **"모른다"** 이지 "아무 아이나 된다" 가 아니다.
   */
  fitsActivityLevels: CodeNameMetadata[]
  providerName: string
}
```

- **nullable 필드**: `lat` · `lng` · `firstImage`. 셋 다 **`WalkCourseItem` 과 `WalkCourseDetailResponse` 양쪽에** 있다.
- **문자열 ID**: `walkCourseId`. 백엔드 내부는 `long` 이고 presenter 가 `String.valueOf` 로 내린다
  (`WalkCoursePresenter.java:27,43`). **`number` 로 타이핑하면 정밀도가 손상된다** — `facilityId`·`placeId` 와 같다.
- **enum metadata (`{code,name,description}`) 필드**: **#718 로 생겼다.** 목록의
  `appliedPetActivityLevel.level` 과 상세의 `fitsActivityLevels[]` 둘이다. 그 전에는 활동량이
  요청 파라미터로만 등장해 화면이 이름을 서버에서 받을 경로가 없었고, 기준 줄의 `낮음`·`4시간` 을
  반려견 프로필과 FE 상수로 메웠다 — 그 메움을 걷은 것이 #735 다 (S4-1 규칙 5·6).
  **아직 없는 자리**: 선택지를 그리는 컨트롤. 응답은 _적용된_ 활동량 하나만 내려주므로 아직 고르지
  않은 칸의 라벨은 여전히 FE 가 갖는다 (`api-integration-guide.md` §6 의 인정된 예외).
- **단위**: 거리 `km` · 소요시간 `시간`(원문 문자열) · 골든타임 온도 `℃`. **화면에 단위를 드러낸다** (`15.1km`).
- **`distanceKm` 는 BigDecimal 이 JSON number 로 온다.** `15.1` `4.2` `19.0` 처럼 소수 1자리다. 실측에서 `19.0` 이
  왔으므로 **`19` 로 줄여 쓰지 않는다** — 같은 열의 다른 값(`19.1`)과 자릿수가 어긋난다. 포맷은 소수 1자리 고정.

**화면 설계에 미치는 영향.**

- 골든타임으로 이어지는 코스가 **전부**다. 좌표 없는 갈래는 이제 **예외**이고, 그것이 원래 의도한 모양이다
  (`코스상세-세부명세.md` D5-2 는 갈래를 지우지 않고 남긴다).
- 목록 행의 썸네일이 **29행 전부**에 선다. 사진이 잡음이 아니라 식별자가 되었으므로 행의 **첫 칸**으로
  옮겼다 ([#767](https://github.com/8llow8llowMe/hondigagae/issues/767) · `코스목록-세부명세.md` D1-1).
- **`LOW` 를 골라도 골든타임을 볼 수 있다.** 활동량이 낮은 아이의 보호자가 기능을 한 번도 못 보던 상태
  (옛 D8-2)가 해소됐다.
- 상세의 히어로와 1024 2열이 **항상 선다** (`코스상세-세부명세.md` D1).

> **이 분포를 FE 가 상수로 박지 않는다.** 배치가 다시 돌면 값이 바뀐다 — 실제로 두 번 바뀌었다. 화면은
> `lat === null || lng === null` 한 가지만 보고, 위 숫자는 **테스트 fixture 와 판단 근거**로만 쓴다.
> **원천이 다시 빌 수 있다**: 이번 적재도 포털 파싱에 실패해 로컬 CSV 우회로 돌았다
> ([#828](https://github.com/8llow8llowMe/hondigagae/issues/828)).

## S4. 화면이 지켜야 할 계약 규칙

### S4-1. `petActivityLevel` — 채우는 규칙과 폴백

**상한은 서버가 갖는다** (`WalkCourseActivityFit.java:26-48`). FE 는 **다시 계산하지도, 적어 두지도
않는다** — 응답의 `appliedPetActivityLevel.maxDurationMinutes` 가 적용된 상한을 내려준다 (#718 · #735).

| 활동량   | 서버 상한         | 실측 결과 |
| -------- | ----------------- | --------- |
| `LOW`    | 240분 (**4시간**) | 6 / 29    |
| `MEDIUM` | 360분 (**6시간**) | 24 / 29   |
| `HIGH`   | **상한 없음**     | 29 / 29   |

> **이 표는 화면이 참조하는 값이 아니라 기록이다.** 아래 숫자를 FE 상수로 옮기면 서버가 상한을
> 바꾼 날 화면만 옛 숫자를 말한다 — 실제로 `lib/walk-course/activity.ts` 가 `4`·`6` 을 들고
> 있었고 #735 에서 걷었다.

- 소요시간을 모르는 코스(`durationMaxMinutes === null`)는 **어느 활동량에서도 걸러지지 않는다**
  (`WalkCourseActivityFit.fits` 가 `null` 에 참을 준다). 모르는 것을 나쁜 것으로 판정하지 않는다는 규칙이고,
  화면도 같은 태도를 쓴다.

**채우는 규칙 (확정)**

1. **URL 이 정본이다.** `?activity=LOW|MEDIUM|HIGH|ALL` 이고 `architecture-guide.md` §10 을 따른다.
2. **URL 에 `activity` 가 없으면** 서버 컴포넌트가 채운다 — `readSession()` 이 있으면 `GET /members/me/pets` 를
   **서버에서** 받아 **대표견**(`representative === true`, 없으면 첫 아이)의 `activityLevel.code` 를 쓴다.
3. **`HIGH` 는 보내지 않는다.** 결과가 필터 없음과 같고(실측 29/29), 보내면 `appliedPetActivityLevel` 이
   채워져 화면이 **좁히지 않았는데 좁혔다고 말하게 된다.** 대표견이 `HIGH` 면 파라미터 없이 조회한다.
   보낸 경우의 응답은 **객체가 있고 `maxDurationMinutes` 만 null** 이다 — 객체 자체가 null 인
   "필터 미적용" 과 뜻이 다르므로, 화면은 이 갈래에서 기준 줄을 **만들지 않는다**(좁힌 것이 없다).
4. **폴백 — 아래 넷 중 하나면 파라미터를 보내지 않는다.** 화면은 전체 29개로 열린다.
   - 미로그인
   - 반려견이 한 마리도 없음
   - `GET /members/me/pets` 실패 (**목록을 실패시키지 않는다** — 코스 조회는 공개 API 이고 반려견은 기본값 소스일 뿐이다)
   - 대표견의 `activityLevel.code` 가 `LOW`/`MEDIUM` 이 아님 (`HIGH` 포함, 모르는 코드 포함)
5. **기준 줄은 `appliedPetActivityLevel` 로 그린다.** 로컬 상태가 아니라 **응답**을 믿는다 — 장소 인사이트의
   `petConditionApplied` 와 같은 규칙이다 (`screen-inventory.md` §3-1). 활동량 이름도 상한도 그 객체가 준다.
6. **활동량 이름의 출처가 자리마다 다르다.**
   - **기준 줄** — 응답 `appliedPetActivityLevel.level.name`. 서버 enum metadata 를 그대로 렌더한다.
   - **세그먼트 선택지** — `messages.pet.options.activityLevel`(반려견 등록 폼과 **같은 목록**).
     응답은 _적용된_ 하나만 주므로 아직 고르지 않은 칸의 라벨이 없다 — `api-integration-guide.md` §6 이
     인정한 "서버가 값을 주지 않는 컨트롤" 이다. **표를 두 벌 만들지 않는다**: 새로 적으면 BE 가 문구를
     바꾼 날 등록 폼과 이 화면이 다른 말을 한다.
   - **상한 숫자** — 응답 `maxDurationMinutes`(분)를 `formatDuration` 으로 옮겨 적는다(`240` → `4시간`).
     단위 변환일 뿐이라 서버가 `270` 으로 바꾸면 화면도 `4시간 30분` 으로 따라간다.
   - 그래서 **세그먼트는 상한을 말하지 않는다** — `낮음`·`보통` 만 말하고, 고른 뒤 기준 줄이 그 활동량이
     몇 시간인지 드러낸다 (#735).

**왜 nav 의 선택 반려견이 아니라 대표견인가.** nav 선택은 `localStorage` 에 있어(`selected-pet-store.ts`) 서버가 읽을
수 없다. 서버 프리페치가 기본인 이 저장소에서 nav 선택을 쓰려면 **첫 렌더 뒤 재조회**가 되고, 목록이 29 → 6 으로
줄어드는 것이 눈에 보인다. 대표견은 서버가 읽을 수 있고 "지정이 없으면 대표견" 은 AI 일정·담기가 이미 쓰는 규칙이다
(`screen-inventory.md` §2). 대안은 `코스목록-세부명세.md` D8-1 에 남긴다.

### S4-2. 좌표가 null 인 코스에 골든타임 동선을 만들지 않는다

**서버가 명시한 규칙이다** — `WalkCourseItem.java:10-12`:

> `lat/lng` 가 null 인 코스가 있다 … 좌표가 있는 코스만 골든타임(`GET /api/v1/insights/walk-times?lat=&lng=`)과
> 이어진다 — 화면은 좌표가 null 이면 **그 버튼을 만들지 않아야 한다.**

화면이 지키는 형태는 셋이다.

| 지켜야 할 것 | 규칙                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 요청         | `lat === null \|\| lng === null` 이면 **`GET /insights/walk-times` 를 아예 부르지 않는다.** `enabled` 로 막는다 (홈의 `useWalkTimes` 와 같은 모양) |
| 자리         | 골든타임 패널을 **렌더하지 않는다.** 빈 패널·스켈레톤·비활성 버튼 어느 것도 두지 않는다 — 기다리면 채워질 것처럼 보인다                            |
| 말           | 자리를 지우는 대신 **한 줄로 이유를 밝힌다** (`코스상세-세부명세.md` D5). 소리 없이 사라지면 코스마다 화면이 다른 이유를 알 수 없다                |

**`0` 을 좌표로 쓰지 않는다.** `lat ?? 0` 은 적도·본초자오선(기니만)의 날씨를 묻는 요청이 되고, 서버는 200 으로 답한다 —
**틀린 답이 정상 응답으로 온다.** 판정은 `lat === null || lng === null` 하나로 하고 순수 함수로 뽑아 테스트한다.

## S5. 상태 / 에러

| 상태                   | 조건                                                  | 화면                                         | 문구                                                                           |
| ---------------------- | ----------------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------ |
| loading                | 첫 조회                                               | Skeleton                                     | —                                                                              |
| 조건에 맞는 코스 0개   | **200 + `courses: []`** (404 가 아니다)               | EmptyState (**재시도 없음**)                 | `조건에 맞는 코스가 없어요.` / `활동량 조건을 넓혀 보세요.` + `전체 코스 보기` |
| 데이터 부재 (404)      | 상세 — `WALKCOURSE_001`                               | EmptyState (**재시도 없음**)                 | 서버 `resultMessage` + `코스 목록으로` 버튼                                    |
| 일시 장애 (5xx·무응답) | tour-service 다운 · 게이트웨이 503                    | ErrorState (**재시도 있음**)                 | `코스를 불러오지 못했어요.` / `잠시 후 다시 시도해 주세요.`                    |
| 입력 오류 (400)        | `WALKCOURSE_101` · `WALKCOURSE_113` — 손으로 고친 URL | ErrorState, **재시도 없음** + 전체 보기 링크 | 서버 `resultMessage` 를 그대로 노출                                            |
| 미인증 (401)           | **이 화면에서는 나오지 않는다**                       | —                                            | 공개 API 다. 401 이 나오면 `GET /members/me/pets` 쪽이고 **조용히 폴백**한다   |

**404 에 재시도 버튼을 달지 않는 근거** (세 겹으로 확인했다)

1. **규칙**: `frontend/CLAUDE.md` 절대 규칙 — _"404에 재시도 버튼을 달지 않는다. 404는 데이터 부재이고 5xx가 일시
   장애다."_ 판정 함수는 `lib/api/error.ts` 의 `isRetriable`(5xx·무응답만 참)이고 React Query `retry` 도 같은 함수를 쓴다
   (`api-integration-guide.md` §7).
2. **계약**: `WalkCourseErrorCode.NOT_FOUND_WALK_COURSE` 가 `HttpStatus.NOT_FOUND` 로 못박혀 있다
   (`WalkCourseErrorCode.java:11`). 조회는 `WalkCourseRepositoryPort.findById` 단건이고 **부수 조건이 없다** —
   같은 id 로 다시 물어도 같은 404 다.
3. **실측**: dev 에서 존재하지 않는 id 로 두 번 호출해 같은 404 `WALKCOURSE_001` 을 받았다 (S2-1).
   **재시도는 사용자의 시간을 쓰고 아무것도 바꾸지 못한다.** 대신 `resultMessage` 를 노출하고 **다음 행동**
   (`코스 목록으로`)을 준다.

> **코스 목록의 "0개" 는 404 가 아니다.** `WalkCourseQueryProcessor.search` 는 필터 결과가 비어도 200 + 빈 배열을
> 준다 — 그때는 `resultMessage` 가 없으므로 위 404 행의 문구를 재활용하면 빈 문구가 나간다. **두 상태를 한 컴포넌트로
> 합치지 않는다.**
