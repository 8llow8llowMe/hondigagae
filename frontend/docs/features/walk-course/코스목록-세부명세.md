## D0. 화면 정의

- **경로**: `/olle`
- **인증**: **불필요**. `proxy.ts` `PROTECTED_PATHS` 에 **넣지 않는다** (공통명세 S1)
- **진입 경로**: 홈 골든타임 섹션 아래 `Banner`(공통명세 S6-1 추천안) · 코스 상세의 `코스 목록으로` · 주소 직접
- **이탈 경로**: 코스 행 클릭 → `/olle/[walkCourseId]`

**URL 이 조건을 소유한다** (`architecture-guide.md` §10). Zustand 에 두지 않는다.

| 쿼리       | 값                                                | 기본                         | 비고                                                 |
| ---------- | ------------------------------------------------- | ---------------------------- | ---------------------------------------------------- |
| `activity` | `LOW` · `MEDIUM` · `ALL`                          | **없음** = 대표견으로 채운다 | `ALL` 은 "자동 채움을 껐다" 는 **명시 값**이다       |
| `sort`     | `DISTANCE_ASC` · `DISTANCE_DESC` · `DURATION_ASC` | 없음 = `COURSE_NO`           | 기본값은 URL 에 쓰지 않는다 (`/places` 와 같은 규칙) |

**`activity` 에 `HIGH` 를 두지 않는다.** 결과가 필터 없음과 같고(실측 29/29) `appliedPetActivityLevel` 만
달라져 화면이 좁히지도 않은 것을 좁혔다고 말한다 (공통명세 S4-1 규칙 3). 주소에 손으로 `HIGH` 를 적어 넣으면
`ALL` 과 같게 읽는다.

**`ALL` 이 필요한 이유**: 값이 없을 때 대표견으로 채우므로, "필터 없음" 을 표현할 값이 따로 있어야 한다. `ALL`
없이 빈 값으로만 두면 **활동량 낮은 아이의 보호자가 전체 코스를 볼 방법이 사라진다** — 필터를 끄는 순간 다시
켜진다. 정규화는 `src/lib/url/walk-course-filters.ts` 한 곳이 갖는다 (`emergency-filters.ts` 와 같은 모양).

**`maxDistanceKm` 은 이번에 화면에 두지 않는다.** 계약에는 있지만(0.1~50) 코스가 29개뿐이라 정렬이 같은 일을 하고,
축이 둘이면 "6시간 이내 + 12km 이내" 의 교집합이 0 이 되는 조합을 사용자가 만들 수 있다. D8-3 에 남긴다.

## D1. 레이아웃

**목록 화면의 우측 열은 카드 하나이고 도구와 결과를 머리/본문으로 가른다** (`DESIGN.md` §0, #556).
좌측 필터 레일을 두지 않는다 — 축이 둘(걷는 시간·정렬)뿐이라 280 레일을 세우면 빈 열이 된다.

| 폭               | 모양                                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 모바일 (390)     | 전폭 섹션(좌우 테두리·radius 없음). 머리 = 제목 + 설명 줄 + 개수·기준 줄 + 걷는 시간 세그먼트 + 정렬. 본문 = 코스 행 목록. 카드 인셋 16 |
| 태블릿 (768)     | 같은 1열. 인셋 20. 걷는 시간 세그먼트와 정렬이 **한 줄**에 선다                                                                         |
| 데스크톱 (1024+) | 단일 카드 1열. 머리 고정 · 본문은 **6칸 표**(코스·거리·소요시간·시종점·썸네일·chevron) + 열 머리 (#797)                                 |

> **1024+ 의 본문이 표가 된 것은 #734 · #797 이다.** 이 절이 말하는 "카드 그리드가 아니다" 는 그대로 유효하다 —
> 사진 타일을 격자로 깔지 않는다는 뜻이고, 표는 **텍스트 행에 열을 준 것**이다. 열 트랙과 그 근거(코스 열 256
> 고정 · `max-content` 를 못 쓰는 이유 · 썸네일 40)는 `app/globals.css` 의 `.walk-course-row-grid` 주석이 정본이다.

### D1-1. 카드 그리드가 아니라 텍스트 행이다

**이미지가 29개 중 4개만 있다** (공통명세 S3-1). 사진 카드 그리드를 쓰면 **25장이 회색 플레이스홀더**이고 화면이
"데이터가 깨졌다" 로 읽힌다. 코스를 고르는 데 실제로 쓰는 값은 셋이다 — **이름표 · 거리 · 소요시간**. 전부 29개
모두 채워져 있다.

행 하나의 구성 (`PlaceRow` 와 같은 2열이 아니라 **1열 텍스트 행**):

```text
[1코스]  시흥-광치기                      ← 이름표(강조) + 구간명
15.1km · 4~5시간                          ← 메타 줄. 단위를 드러낸다
시흥리정류장 → 광치기해변                 ← 시종점. 원문의 `-` 를 `→` 로 바꾸지 않는다(D4-4)
```

- 썸네일은 **이미지가 있을 때만** 선행 열로 붙는다. 없는 행에 회색 사각형을 두지 않는다 —
  25행이 같은 회색이면 그것은 정보가 아니라 잡음이다.
- **행에 테두리를 두르지 않는다** (`DESIGN.md` §0 — L2 는 채움 또는 1px 구분선).

### 긴 한국어 실데이터로 확인할 항목

### D1-2. 세그먼트 칸은 데스크톱에서 제 라벨 폭을 갖는다 ([#818](https://github.com/8llow8llowMe/hondigagae/issues/818))

| 폭   | 칸                                                           |
| ---- | ------------------------------------------------------------ |
| ~767 | 세그먼트가 **전폭**, 칸은 `flex-1` **균등 분할**             |
| 768~ | 칸이 **내용 폭**(`md:flex-none md:px-4`). 그룹도 내용 폭이다 |

**균등 분할을 데스크톱까지 끌고 가면 가장 긴 라벨이 잘린다.** 도구 줄이 `md:flex-row` 로 가면
그룹은 남는 공간을 받지 않고 콘텐츠 폭만 갖는데, 그 좁은 폭을 칸이 균등하게 나누기 때문이다.
[#798](https://github.com/8llow8llowMe/hondigagae/issues/798) 이 `짧은 순`(40px) 을 `거리 짧은 순`(67px) 으로 늘리자 54px 칸에서 넘쳐
`거리 짧…` 이 됐다 — **오른쪽에 900px 넘는 빈 자리를 두고** 잘렸다.

`truncate` 는 그대로 둔다. **안전망이지 레이아웃 수단이 아니다** — 이 결함은 `truncate` 가
넘침을 조용히 삼켜서 유닛 테스트에 안 잡혔다. 폭 계약은 `e2e/olle-filter-label.spec.ts` 가 잰다.

### D1-3. 머리의 설명 줄은 조건을 타지 않는다 ([#811](https://github.com/8llow8llowMe/hondigagae/issues/811))

`Surface` 의 `description` 슬롯에 **세 줄이 위에서부터** 선다.

| 줄                | 언제                               | `aria-live` |
| ----------------- | ---------------------------------- | ----------- |
| `listDescription` | **항상**                           | 없음        |
| `listCount`       | 셀 수 있을 때(`countable`)         | `polite`    |
| `basisLine`       | `appliedPetActivityLevel` 이 올 때 | 없음        |

**설명 줄이 `countable` 을 타지 않는 것이 이 절의 요점이다.** 개수·기준은 로딩 중이거나
오류일 때 사라지는데, 전에는 슬롯이 통째로 비어 **스켈레톤 화면에 제목만 남았다** —
처음 들어온 사람이 가장 오래 보는 화면이 그것이다.

**`aria-live` 는 바뀌는 줄에만 붙인다** (D6). 고정 문구에 붙으면 조건을 만질 때마다 같은
문장이 다시 읽히고 정작 알려야 할 결과 수가 그 안에 묻힌다.

**문구가 `pageDescription` 과 한 낱말 다르다.** 목록에서는 바로 위 `h2` 가 `제주올레 코스`
라고 이미 말하므로 부제는 대상어를 빼고 **누구를 위해 · 무슨 기준으로**만 남긴다. 제목이
곁에 없는 자리(404 · 형식 오류 400 · 상세 `meta description`)는 대상어를 가진
`pageDescription` 이 그대로 맡는다 — 한 문장으로 두 자리를 겸하려다 한쪽이 어색해지는
것을 피한다.

## D3. 데이터 흐름

```text
/olle?activity=&sort=
  → page.tsx (server)
      readSession() → authed
      authed 면 serverFetch(GET /members/me/pets)  ← 실패해도 계속 간다
      resolveActivityParam(urlActivity, 대표견)     ← 순수 함수
      fetchQuery(GET /walk-courses?petActivityLevel=&sort=)
      HydrationBoundary
  → WalkCourseListView (client) — 같은 key 로 useQuery
```

| 항목                       | 내용                                                                                                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API                        | `GET /api/v1/walk-courses` (+ 로그인 시 `GET /api/v1/members/me/pets`)                                                                                                  |
| React Query key            | `walkCourseKeys.list(activityParam, sortParam)` — **서버가 실제로 보낸 값**이 key 다. URL 의 `ALL` 이 아니라 `null` 이 들어간다                                         |
| staleTime / gcTime / retry | **5분 / 30분 / 2** — 장소 목록과 같은 값이고 **이유도 같다**: 배치로 적재돼 세션 중 바뀌지 않는다. 구현 시 `api-integration-guide.md` §7 표에 `산책 코스` 행을 추가한다 |
| mutation 후 invalidate     | **없다.** 이 화면에 mutation 이 없다                                                                                                                                    |
| 폴링                       | **없다**                                                                                                                                                                |

- **`HydrationBoundary` 하나만 쓴다** (`architecture-guide.md` §9). 서버 프리페치와 클라이언트가 **같은 key** 여야 한다.
- **`loading.tsx` 를 두지 않는다.** 서버에서 `fetchQuery` 를 `try/catch` 로 감싸고 실패하면 오류 상태를 props 로
  내린다 — 일정 상세(D3)와 같은 방식이다.
- **반려견 조회 실패가 코스 목록을 실패시키지 않는다.** `Promise.allSettled` 가 아니라 순차이고, 펫 조회는
  `catch` 로 `null` 을 만든다. 코스는 공개 API 라 로그인 상태와 무관하게 떠야 한다 (공통명세 S4-1 폴백 4).

### D3-1. 정렬은 서버가 한다 — 클라이언트가 다시 세우지 않는다

`sort` 를 그대로 서버에 넘긴다. **어느 기준이든 코스 차례가 마지막 타이브레이크**이고
(`WalkCourseQueryProcessor.java:70-82`), `DURATION_ASC` 는 **소요시간을 모르는 코스를 뒤로 보낸다**(지우지도, 0분으로
앞세우지도 않는다). 클라이언트가 `courses` 를 다시 정렬하면 이 규칙이 조용히 깨진다.

실측(2026-09-18) `?maxDistanceKm=12&sort=DISTANCE_ASC` → `10-1(4.2) · 14-1(9.3) · 18-2(9.7) · 6(11.0) · 1-1(11.3) ·
21(11.3) · 18-1(11.4) · 9(11.8)`. **11.3km 동률에서 1-1코스가 21코스보다 앞**이다 — 타이브레이크가 실제로 돈다.

## D4. 상호작용

| 트리거                 | 동작                               | 결과                                                                             |
| ---------------------- | ---------------------------------- | -------------------------------------------------------------------------------- |
| 걷는 시간 `전체`       | `?activity=ALL` 로 이동            | 29개. 기준 줄이 사라진다                                                         |
| 걷는 시간 `4시간 이내` | `?activity=LOW`                    | 6개 (실측)                                                                       |
| 걷는 시간 `6시간 이내` | `?activity=MEDIUM`                 | 24개 (실측)                                                                      |
| 정렬 변경              | `?sort=…` (기본값이면 키를 지운다) | **`activity` 를 유지한다** — `walkCourseFilterHref` 가 조건을 통째로 다시 싣는다 |
| 코스 행 클릭           | `/olle/{walkCourseId}`             | 행 전체가 하나의 링크다                                                          |
| 뒤로가기               | 이전 조건으로 복원                 | URL 이 조건을 갖고 있어 자동                                                     |

**D4-1. 조건 변경은 `router.replace` 다.** 세그먼트를 세 번 만지면 히스토리에 세 칸이 쌓여 뒤로가기가 목록을
벗어나지 못한다. `/places` 필터와 같은 규칙이다.

**D4-2. 링크를 두 겹으로 만들지 않는다.** 행 전체가 링크이므로 행 안에 버튼(담기 등)을 넣지 않는다. 담기 진입은
[#620](https://github.com/8llow8llowMe/hondigagae/issues/620) 이 **상세에서** 연다.

**D4-3. 자동 채움은 한 번뿐이다.** URL 에 `activity` 가 생긴 뒤에는 대표견이 바뀌어도 값을 덮어쓰지 않는다.
사용자가 고른 조건을 서비스가 되돌리지 않는다.

**D4-4. `startEndPoint` 원문의 `-` 를 화살표로 바꾸지 않는다.** 원문에는 `제주민속촌주차장 입구-남원포구` 처럼
**공백과 하이픈이 섞여** 있고 시설명 안에도 하이픈이 들어올 수 있다. 문자열을 갈라 재조립하면 잘못 갈리는 코스가
생긴다 — **원문 그대로 렌더한다.** (D1-1 의 `→` 표기는 화면 스케치이고, 구현은 원문 한 줄이다.)

| success                          | 코스 행 목록                           | 캡션 `코스 {totalCount}개`                                                        |
| 기준 줄 (`applied === true`)     | 캡션 아래 한 줄                        | `{펫이름} 활동량({name}) 기준으로 {상한}이 넘는 코스는 빼고 보여 줘요.` (D5-3)    |
| 기준 줄 (`applied === false`)    | **줄 자체를 만들지 않는다**            | —                                                                                 |
| 조건 결과 0개 (200 + 빈 배열)    | `EmptyState`, **재시도 없음**          | `조건에 맞는 코스가 없어요.` / `걷는 시간을 넓혀 보세요.` + `전체 코스 보기` 버튼 |

| 출처 줄                          | 본문 맨 아래 캡션                      | 서버 `providerName` 을 그대로. FE 가 출처 문자열을 만들지 않는다                  |

### D5-6. 로딩은 결과와 같은 골격이다 (#800)

**스켈레톤이 실제 행과 같은 클래스를 쓴다** — 높이를 따로 계산해 맞추지 않는다. 한쪽만
고쳐지는 일을 막기 위해서다.

| 폭   | 고치기 전 스켈레톤 | 실제 행 | 지금 스켈레톤  |
| ---- | ------------------ | ------- | -------------- |
| 1440 | 101px              | 73px    | **73px**       |
| 1024 | 101px              | 73px    | **73px**       |
| 768  | 101px              | 105px   | 101px (그대로) |
| 390  | 93px               | 97px    | 93px (그대로)  |

1024 실측에서 6행이면 **168px 이 위로 당겨지고** 있었다. 지금은 0px 다.

**열 머리를 로딩에도 세운다.** 라벨 넷이 전부 고정 문구라 데이터를 기다릴 이유가 없고,
빼 두면 결과가 오는 순간 한 줄이 새로 끼어들어 아래 전체가 밀린다 — 행 골격을 맞춰 놓고도
점프가 남는다. `aria-hidden` 이라 보조기기에는 아무것도 더하지 않는다.

**1024 미만은 건드리지 않았다.** 거기서는 실제 행도 3줄 블록이라 골격이 이미 같다. 남는
4~12px 차는 썸네일이 있는 행(29개 중 4개)과 줄바꿈에서 오는 것이고, 고치기 전과 **같은
값**임을 확인했다(회귀 없음).

**chevron 자리에는 뼈대를 두지 않는다.** 데이터가 아니라 "누를 수 있다" 는 고정 장치라
로딩 중에 흉내 낼 것이 없다. 6번 트랙(`1.25rem`)이 자리를 이미 잡고 있어 가로도 안 밀린다.

### D5-1. 목록에서 좌표 유무를 말하지 않는다

좌표는 **골든타임을 이어 볼 수 있는가**만 정한다. 목록에서 25행에 "날씨 정보 없음" 배지를 달면, 코스를 고르는
축(거리·소요시간)과 무관한 사실이 화면의 4/5를 덮는다. **없는 것을 세지 않는다.** 그 사실은 그것이 실제로
필요해지는 자리 — **코스 상세의 골든타임 자리** — 에서 한 줄로 말한다 (`코스상세-세부명세.md` D5-2).

### D5-2. 상한은 응답이 말한다 — 세그먼트가 아니라 기준 줄이 (#735)

**D9-1·D9-2 가 [#718](https://github.com/8llow8llowMe/hondigagae/issues/718) 로 왔다.** 목록 응답이
`appliedPetActivityLevel = { level, maxDurationMinutes }` 를 내려주므로, 화면이 `4`·`6` 을 적던
자리가 전부 서버 값으로 바뀐다.

- **기준 줄** — `level.name` + `formatDuration(maxDurationMinutes)`. FE 상수를 참조하지 않는다.
  `lib/walk-course/activity.ts` 의 `ACTIVITY_MAX_HOURS` 는 **삭제했다**
- **세그먼트 선택지** — `전체 · 낮음 · 보통`. **상한 시간을 적지 않는다.** 응답은 _적용된_ 하나만
  내려주므로 아직 고르지 않은 칸의 숫자는 화면이 알 길이 없다 — `4시간 이내` 를 그대로 두면 그것이
  곧 복제본이다. 라벨 출처는 반려견 등록 폼과 **같은 목록**(`messages.pet.options.activityLevel`)이다
- **축 이름이 `걷는 시간` → `활동량` 으로 바뀐다.** 선택지가 상한이 아니라 활동량이 되었으므로
  라디오그룹 `aria-label` 과 보이는 캡션이 둘 다 `활동량` 이다 (캡션은 `aria-hidden`)
- **잃은 것과 되찾는 자리.** 고르기 _전에_ 몇 시간인지 모른다는 것이 이 교환의 비용이다. 고른 뒤
  기준 줄이 바로 아래에서 `활동량(낮음) 기준으로 4시간이 넘는 코스는 빼고 보여 줘요.` 라고 말해
  메운다 — **틀릴 수 있는 숫자를 먼저 보여 주는 것보다, 맞는 숫자를 한 박자 뒤에 보여 주는 편이 낫다**
  (문장이 `…이내 코스만` 에서 바뀐 이유는 D5-3)
- `HIGH` 를 적용한 응답(객체 있음 · `maxDurationMinutes: null`)에서는 **기준 줄을 만들지 않는다** —
  적을 상한 자체가 없다. 이 화면은 `HIGH` 를 보내지 않는다(S4-1 규칙 3)

### D5-3. 기준 줄은 **거른 기준**을 말한다 — `이내 코스만` 을 걷는다 ([#776](https://github.com/8llow8llowMe/hondigagae/issues/776))

**서버는 소요시간을 모르는 코스를 어느 활동량에서도 걸러내지 않는다** —
`WalkCourseActivityFit.fits` 는 `durationMaxMinutes == null` 이면 곧바로 참이다. _모르는 것을 나쁜
것으로 판정해 목록에서 지우면 사용자는 그 코스가 있다는 것조차 모른다_ 는 규칙이고, **그 규칙은
바꾸지 않는다.** 바꾸는 것은 화면 문구다.

`{상한} 이내 코스만 보여 줘요` 는 **보여 준 코스 전부**에 대한 단정이다. 소요시간 미상 코스가 하나라도
섞이면 그 순간 거짓이 되고, 화면은 자기가 거짓말한 줄을 모른다.

#### 실측 — 고치기 전에 셌다 (dev 게이트웨이 `GET /api/v1/walk-courses`, 2026-09-21)

| petActivityLevel | totalCount | `durationMaxMinutes: null` |
| ---------------- | ---------- | -------------------------- |
| (없음)           | 29         | **0**                      |
| `LOW`            | 6          | **0**                      |
| `MEDIUM`         | 24         | **0**                      |
| `HIGH`           | 29         | **0**                      |

상한 분포(전체 29): `120`×1 · `240`×5 · `300`×9 · `360`×9 · `420`×5 — **29개 전부 파싱됐다.**
`LOW` 결과 여섯도 전부 `240` 이하라 **오늘은 단정이 우연히 참이다.**

> **재적재 전 수치다.** BE [#722](https://github.com/8llow8llowMe/hondigagae/issues/722) 가 아직
> 미머지라 이 분포는 다음 적재에서 바뀔 수 있다. 응답 모양(`dataHeader` 래퍼)으로 살아 있는
> 경로임을 확인한 뒤 센 값이다 — 상태코드로 판정하지 않았다.

#### 판정 ① — 표현을 약하게 하지 않고, **주어를 바꾼다**

0건이라는 것은 **결함이 잠재적**이라는 뜻이다. 오늘 화면은 거짓말하지 않지만, 적재가 파싱 실패
코스를 하나 들여오는 순간 아무도 이 줄을 다시 보지 않는다. 그래서 **데이터 분포와 무관하게 항상 참인
문장**으로 바꾼다.

| 안                                                      | 기각·채택 이유                                                                                                                         |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| A. `{상한} 안에 걸을 수 있는 코스를 **먼저** 보여 줘요` | **기각.** `먼저` 가 정렬을 약속하는데 기본 정렬은 `COURSE_NO` 다 — 약속 하나를 지우고 못 지킬 약속을 새로 만든다                       |
| B. 단정을 두고 `모르는 코스가 섞여 있어요` 를 덧붙인다  | **기각.** 오늘 0건이라 그 문장이 **지금 거짓**이다. 캡션이 두 줄이 되는 비용을 없는 사실에 치른다                                      |
| C. 상한만 말하고 필터 약속을 뺀다                       | **기각.** 목록이 29 → 6 으로 줄어든 이유를 화면 어디도 말하지 않게 된다                                                                |
| **D. 거른 기준을 말한다 — `{상한}이 넘는 코스는 빼고`** | **채택.** `fits` 를 그대로 옮긴 문장이다: 서버는 **넘는다고 아는 것만** 뺀다. 미상 코스는 "넘는 코스" 가 아니므로 섞여도 문장이 참이다 |

확정 문구 (`lib/messages/walk-course.ts`):

- `activityBasis` — `{pet} 활동량({level}) 기준으로 {limit}이 넘는 코스는 빼고 보여 줘요.`
- `activityBasisWithoutPet` — `활동량({level}) 기준으로 {limit}이 넘는 코스는 빼고 보여 줘요.`

`{limit}` 은 `formatDuration` 결과라 언제나 `분`·`시간` 으로 끝난다 — 조사는 `이` 로 고정이다.
**#735 가 이 줄에 준 역할(세그먼트가 잃은 숫자를 이 줄이 갖는다)은 그대로다** — `{limit}` 이 남아 있다.

문장이 길어져 **375 에서 넘치는지 실측했다** (`text-caption` 12/18 · `break-keep` · 인셋 안 폭 343):

| 갈래                                     | 폭    | 줄 수 |
| ---------------------------------------- | ----- | ----- |
| 옛 문장 (이름 없음)                      | 244px | 1     |
| 새 문장 (이름 없음)                      | 278px | 1     |
| 새 문장 + `몽실이`                       | 312px | 1     |
| 새 문장 + 7자 이름 + `4시간 30분` (최악) | 343px | 2     |

**어느 갈래도 가로로 넘치지 않는다.** 최악이 두 줄인 것은 캡션이 감당하는 범위다.

#### 판정 ② — 목록 **행**에서는 구분하지 않는다 (재적재 후 다시 본다)

1. **표시할 행이 0건이다.** 있지도 않은 갈래를 위해 행 레이아웃을 건드리지 않는다.
2. **`durationText` 의 `미정` 은 서버 값이 아니다.** 백엔드에 그런 폴백이 없고
   (`WalkCourseItem.durationText` 는 **원문 그대로**), `미정` 은 FE fixture
   (`src/test/fixtures/walk-course.ts`)가 지어낸 문자열이다. _"행에 이미 단서가 있다"_ 는 전제는
   **성립하지 않는다** — 실제 미상 코스는 파싱에 실패한 원문을 그대로 달고 평범해 보인다.
3. 그래서 ② 를 하려면 **새 문법**이 필요한데, 그것은 D5-1 이 좌표에 대해 기각한 것과 같은 비용이다.
   다만 소요시간은 좌표와 달리 **코스를 고르는 축 그 자체**라 영구 기각이 아니다.
4. **다시 여는 조건**: 재적재(#722 · [#383](https://github.com/8llow8llowMe/hondigagae/issues/383))
   후 `durationMaxMinutes: null` 이 **1건이라도** 나오면 다시 본다. 그때까지 사용자가 놓치지 않는
   근거는 셋이다 — 기준 줄이 더는 단정하지 않고, 행에 `durationText` 원문이 그대로 있고, 상세가
   한 줄로 말한다(PR [#775](https://github.com/8llow8llowMe/hondigagae/pull/775)).

> **`코스상세-세부명세.md` D8-7 · D8-8 은 이 브랜치에서 닫지 않는다.** 두 행은 develop 에 없고
> **미머지 PR #775 에만** 있다. 여기서 같은 파일에 손대면 그 PR 과 충돌한다 — 위 실측은 그래서
> 이 문서에 적었고, D8-8 종료는 #775 머지 뒤 후속으로 남긴다.

## D6. 접근성

- 걷는 시간 세그먼트는 **`FilterList` 의 라디오 문법**이다. 그룹에 `aria-label="걷는 시간"`, 선택은 `aria-checked`.
  **색만으로 선택을 표시하지 않는다** — 배경 + weight 600 + `aria-checked` 3중 (nav 활성과 같은 규칙).
- 정렬도 같은 문법. `aria-label="정렬"`.
- 코스 행은 `<li>` 안의 링크 하나다. 링크의 접근 이름은 **`{courseLabel} {name}`** — `1코스 시흥-광치기`.
  이름표만이면 `1코스` 29개가 구분되지 않고, 구간명만이면 사용자가 아는 번호가 사라진다.
- **거리·소요시간을 `aria-hidden` 으로 감추지 않는다.** 링크 이름에는 없지만 행 안의 텍스트로 읽혀야 한다.
- 조건 변경 후 결과 수는 `aria-live="polite"` 로 알린다 — `코스 6개`.
- 터치 영역 44px. 행 높이가 그보다 낮아지지 않게 한다.
- 이미지 `alt` 는 **빈 문자열**이다. 바로 옆에 이름표가 글자로 있다.

## D7. 테스트 케이스

**이 저장소의 vitest 는 `environment: 'node'` 다** (`docs/testing-guide.md` §1). jsdom·testing-library 가 없고,
파일명은 **`*.test.ts`**(`.tsx` 는 수집되지 않는다), 엘리먼트는 `createElement`, 렌더는 `renderToStaticMarkup`,
검증은 **마크업 문자열**에 대한 `toContain` / `not.toContain` 이다. 클릭·포커스는 검증할 수 없다.

- 이미지가 있는 코스 → `<img` 가 있다 / **`firstImage: null` → `<img` 가 없다**
- `appliedPetActivityLevel` 객체 → 기준 줄 문구가 있다 / **`null` → `not.toContain`**

- **404·400 → `다시 시도` 가 없다** (필수) — 상세 쪽 테스트와 쌍이다
- **`LOW` 기준 줄 + `durationMaxMinutes: null` 코스가 섞인 목록** → `이내 코스만` 이 **없고**
  `{상한}이 넘는 코스는 빼고` 가 있다 (D5-3 판정 ①). 이름 없는 갈래도 **같은 세기**로 말한다
- 같은 목록에서 **미상 코스가 지워지지 않고** `durationText` **원문**이 그대로 있다 (D5-3 판정 ②)
- **기준 줄이 없는 갈래**(`basis: null`)에는 미상 코스가 섞여도 **약속 문장 자체가 없다** — 미로그인·
  `전체` 갈래에 회귀가 없다는 잠금이다
- 좌표가 null 인 행에 **`골든타임`·`날씨` 낱말이 없다** (D5-1)
- `startEndPoint` 가 **원문 그대로** 나온다 — `제주민속촌주차장 입구-남원포구` (D4-4)

**접근성 계약**

- 세그먼트 그룹에 `aria-label="걷는 시간"` 이 있다
- 선택된 세그먼트에 `aria-checked="true"` 가 있다 (**색 class 만으로 단언하지 않는다**)
- 행 링크의 접근 이름에 `courseLabel` 과 `name` 이 **둘 다** 들어 있다
- 결과 수 영역에 `aria-live="polite"` 가 있다
