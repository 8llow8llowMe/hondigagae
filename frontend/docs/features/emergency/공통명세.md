## E0. 화면 정의

- **경로**: `/emergency` (route group `(main)`)
- **인증**: 불필요. tour-service 는 공개 조회 서비스다
- **진입 경로**: 홈의 병원 배너, 전역 헤더의 병원 아이콘, 모바일 탭바
- **범위**: 목록 갈래(`?view=list`)와 지도 갈래(기본). 지도 설계는 [2026-09-09-emergency-map-unification-design.md](../../../../docs/superpowers/specs/2026-09-09-emergency-map-unification-design.md) 에 정본으로 둔다.

**데스크톱은 지도 위 400 부동 패널이다.** 아트보드 04 의 좌 480 / 우 지도 2단은 채택하지 않았다 — 이유는 설계 문서 §9.

**목록 갈래는 `/places` 와 같은 2단이다** — 좌 280 필터 레일(`.rail-layout .rail-layout-filter`) /
우 목록, 1440 컨테이너 ([#419](https://github.com/8llow8llowMe/hondigagae/issues/419)).
예전에는 이 갈래만 `max-w-screen-md`(768) 한 단이라, 1920 에서 목록은 768 · 지도는 전폭이 되어
**같은 화면의 보기 토글이 339px 옮겨 다녔다.**

**grid 를 페이지가 아니라 `EmergencyListView` 가 갖는다.** `/places` 는 레일이 URL 주도라 서버
컴포넌트가 좌측 칸에 바로 꽂지만, 이 화면은 조회에 좌표가 필요해 서버 프리페치가 없고
조건·반경·개수를 `useEmergencyBoard` 가 쥔다. 레일이 보드를 봐야 하므로 grid 가 클라이언트 경계
안으로 들어오고 `h1`·`ViewToggle` 도 우측 열로 내려갔다.

**필터 축은 `emergency-filter-fields.tsx` 한 곳이 소유한다.** 레일 · 목록 칩 · 지도 필터바 세
표면이 그것을 나눠 쓴다. 개수는 표면이 넘긴다 — 지도는 _영역 안 · `applyFilters` 전_, 목록은
*반경 전량*을 센다 (E3 · `facilityCounts`).

**목록 갈래는 3층 표면이다** (`DESIGN.md §0`, [#460](https://github.com/8llow8llowMe/hondigagae/issues/460) —
로드맵 #455 의 7번). `main` 이 `Canvas`(L0 전폭), 우측 열이 `SurfaceStack`, 목록이 **`Surface`
하나** — 장소 목록(#439) · 일정 목록(#445)과 같은 모양이다. 페이지 제목이 카드 제목으로 들어가고
`h1` 은 `sr-only`(지도 갈래의 `h1` 과 같다), 보기 토글은 카드 제목 줄의 `trailing`, 열 구분선은
걷었다(L0 바닥이 그 일을 한다). 로딩 · 오류 · 0건 두 갈래 · 목록이 전부 같은 카드 안이라 상태가
바뀌어도 카드가 생겼다 사라지지 않는다.

- **모바일 칩은 카드 밖이다.** 목록을 좁히는 도구이고 카드는 그 결과를 담는다(#439 판단). 그래서
  칩이 `EmergencySection` 에서 `EmergencyFilterChips` 로 갈라졌고, 스켈레톤이 칩 자리를 흉내 내지
  않는다 — 칩은 응답 전에도 실제로 서 있고 `showCounts` 가 false 라 숫자만 빠진다.
- **칩 인셋은 `INSET_CLASS.card`** — 768 에서 스택 24 + 20 = 44 로 카드 제목(45)과 1px 차이다
  (#443 · #451 이 정한 의도). `border-b` 는 없다 — 카드 위 8/24 간격이 이미 경계다.
  #457 이 장소 목록 · 일정 목록의 칩을 옮길 때 이 값을 참고한다.
- **인셋은 담는 곳이 정한다.** `EmergencySection` · `FacilityRow` · `EmergencySkeleton` ·
  `EmergencyFilterChips` 가 `inset` prop 을 갖고 기본값은 `card` 다. 행은 `SurfaceList` 안의 `li`
  라 구분선을 스스로 긋지 않는다(`last` 규약 제거). 끝의 `Band` 는 카드 안 1px 선이 됐다.

**지도 SDK 실패 폴백은 카드가 아니다.** 지도 갈래는 전폭 미디어라 `Canvas` 도 `Surface` 도 없고,
폴백 목록은 안내 줄과 같은 페이지 인셋에 선다 — `EmergencyBoardSection` · `EmergencyFilterChips`
둘 다 `inset="main"` 을 받는다(#452 가 담기 화면 폴백에서 잡은 것과 같은 회귀 지점).
**폴백의 칩은 `lg:hidden` 이 아니다** — 레일이 없어 무조건 숨기면 데스크톱에서 필터를 통째로
잃는다. 그 갈래는 카카오 키 도메인이 안 맞을 때 **항상** 오는 경로라 예외가 아니다 (E5).
`lg:hidden` 은 목록 갈래의 호출부가 건다. **폴백의 개수는 목록 갈래와 같은 반경 전량이다** —
지도가 마운트되지 않아 영역이 없으므로 "영역 안" 이 곧 반경 전량이고, 칩 아래 목록이 세는 것과
같은 배열이어야 두 숫자가 서로를 부정하지 않는다.

**반경은 레일에서도 `초기화` 대상이 아니다.** 필터가 아니라 조회 파라미터다 (E7).

### E0-1. 지도 갈래 — 카메라 · 선택 · 영역 규칙

전체 논거는 설계 문서(위 링크) §3~5 에 있다. 여기서는 이 문서만 읽는 사람이 놓치기 쉬운
세 가지만 짧게 남긴다.

- **첫 카메라는 반경에서 역산한다** (`framedCamera` / `levelForSpanMeters`). 위치를
  아직 못 받았거나 제주 밖 폴백이면 `/places` 와 **픽셀 단위로 같은** 첫 화면(제주
  해안선 anchor · level 9)이다 — 두 지도 화면이 같은 것으로 읽혀야 한다.
- **행을 고르면 `SELECTED_FACILITY_MAP_LEVEL`(4)까지 확대되고, 그 순간 목록·칩이
  세는 영역이 선택 직전 값으로 얼어붙는다(`frozenBounds`).** 얼리지 않으면 좁아진
  프레임 안에 몇 곳만 남아 다음 행을 이어 누를 수 없다 — 밀도가 높아서 피해가는
  문제가 아니라 이 얼림 때문에 4를 쓸 수 있는 것이다(`lib/geo/coord.ts`). 얼림은
  다시 그 행을 누르거나, 선택된 시설이 목록에서 빠지거나(필터·재조회), 반경·위치가
  바뀌면 풀린다.
- **지도를 옮겨도 재조회하지 않는다.** 이동은 이미 받아 둔 목록을 영역으로 거를
  뿐이다 — 재조회하면 `distanceMeters` 가 지도 중심 기준이 되어 "가까운 순 · 480m"
  이 거짓말이 된다. 더 넓게 찾는 손잡이는 반경 칩이다.

## E2. 계약

`GET /api/v1/emergencies/facilities`

| 파라미터      | 제약                                  | 화면이 보내는 값                             |
| ------------- | ------------------------------------- | -------------------------------------------- |
| `lat` `lng`   | **필수**, -90~~90 / -180~~180         | 현재 위치 또는 제주 중심                     |
| `radius`      | 1~50000, 기본 10000                   | 10000 에서 시작해 넓히기마다 ×2 (상한 50000) |
| `type`        | `ANIMAL_HOSPITAL` / `ANIMAL_PHARMACY` | **보내지 않는다** (E3)                       |
| `open24Only`  | 기본 false                            | **보내지 않는다** (E3)                       |
| `openNowOnly` | 기본 false                            | **보내지 않는다** (E3)                       |
| `size`        | 1~250, 기본 10                        | **250**(상한)                                |

응답은 `SliceResponse` 가 **아니다.** `totalCount` · `radius` · `open24Only` ·
`providerName` 이 함께 온다 (커서가 없다).

### E2-1. `totalCount` 는 자르기 전 총계다 — dev 실측

**반경 안 총계이고 `size` 와 무관하다** (BE [#285](https://github.com/8llow8llowMe/hondigagae/issues/285) / PR #296).
제주시청 (33.4996, 126.5312) · `radius=10000` 으로 `size` 만 바꿔 부른 결과다
(dev 실측 **2026-09-08**).

| `size` | `totalCount` |                     돌려준 개수 |
| -----: | -----------: | ------------------------------: |
|      3 |          136 |                               3 |
|     50 |          136 |                              50 |
|    250 |          136 |                             136 |
|    251 |            — | `HTTP 400` (백엔드 `@Max(250)`) |

**`totalCount` 는 136 으로 고정되고 `facilities.length` 만 따라 늘어난다.** 그래서
잘림을 `facilities.length < totalCount` 로 정직하게 판정할 수 있고, "반경 안에 실제로
몇 개인지" 도 말할 수 있다.

`radius=50000`(제주 전역)에서는 `totalCount=214` · 돌려준 개수 `214` 다 — **`size=250`
이면 제주 전역이 한 번에 다 온다.** 그래서 `MAX_SIZE` 를 상한 그대로 250 으로 쓴다.

#### 고치기 전 기록 (계약이 바뀌기 전 실측)

한때 `totalCount` 는 **`facilities.length` 와 같은 값**이었다. 같은 좌표·반경에서
`size` 를 따라 움직였다.

| `size` | `totalCount` | 돌려준 개수 | 구성              |
| -----: | -----------: | ----------: | ----------------- |
|      3 |            3 |           3 | 약국 3            |
|     10 |           10 |          10 | 약국 8 · 병원 2   |
|     50 |           50 |          50 | 약국 31 · 병원 19 |

그 시절에는 `facilities.length < totalCount` 가 **항상 거짓**이어서 잘림을 막지 못했고,
대신 **상한 도달**(`facilities.length >= MAX_SIZE`)로 판정했다
([#281](https://github.com/8llow8llowMe/hondigagae/issues/281) / PR #283).
그 우회는 [#297](https://github.com/8llow8llowMe/hondigagae/issues/297) 에서 걷었다 —
"잘렸다" 만 알려주고 "얼마나 더 있는지" 는 말하지 못했고, 상한만큼 정확히 온 정상
응답을 잘린 것으로 오판했다. **이 표는 되돌아보기 위한 기록이고 현재 계약이 아니다.**

### E2-2. 제주 밖 좌표는 오류가 아니라 조용한 0건이다

이 서비스의 데이터는 제주뿐이다. 제주 밖 좌표로 부르면 실패하지 않고 **빈 목록**이 온다.

| 기준 좌표                   | 응답                                                              |
| --------------------------- | ----------------------------------------------------------------- |
| 제주시청                    | `success: true` · `totalCount: 3`                                 |
| 서울시청 (37.5665, 126.978) | `HTTP 200` · `success: true` · `facilities: []` · `totalCount: 0` |

그래서 화면은 "반경 안에 없어요" 만 말하게 되고 사용자는 기능이 고장 났다고 읽는다.
**좌표를 얻는 자리에서 한 번 거른다** — `getCurrentPosition()` 이 제주 밖 좌표를
`kind: 'fallback'` · `reason: 'outside'` 로 내리고 제주 기준 좌표를 돌려준다
(`lib/geo/jeju-bounds.ts`). 화면마다 판정하면 어느 화면은 빠뜨린다.

## E3. 좁히기를 서버로 보내지 않는 이유

셋 다 서버 파라미터로 존재한다. 그런데 **아트보드는 칩마다 개수를 함께 보여준다**
(`전체 4 · 병원 3 · 약국 1 · 24시간 1 · 지금 진료중 2`).

서버로 좁히면 그 개수를 알기 위해 칩 수만큼 요청을 더 보내야 하고, 그러고도
**"지금 이 조건을 끄면 몇 개가 되는지" 를 말할 수 없다** — 결과 없음 화면(아트보드 03)이
바로 그것을 말해야 한다.

`size=250`(상한)으로 한 번 받아 와 화면에서 좁힌다. 요청은 하나이고 개수는 전부 정확하다.
제주 전역이 214곳이라 이 상한이면 실질적으로 전량이 온다 (E2-1).

**잘렸을 가능성을 감추지 않는다.** 받은 개수가 `totalCount` 보다 적으면 반경 안에 더
있으므로 **칩에서 숫자를 뺀다** (`countsAreComplete`). 틀린 개수는 없는 개수보다 나쁘다.

**상한에 닿았는지로 판정하지 않는다.** 상한만큼 정확히 왔는데 총계도 그만큼이면 다 받은
것이라 개수는 옳다 — 상한 도달 우회는 그 응답에서 숫자를 뺐다. 우회를 넣었던 이유와
걷은 이유는 E2-1 이다.

### E3-0. 이름·주소 검색도 화면에서 좁힌다 ([#584](https://github.com/8llow8llowMe/hondigagae/issues/584))

`/emergencies/facilities` 에는 `keyword` 파라미터가 **없다** (dev Swagger 실측). 그런데 이
화면은 이미 반경 안 전량을 받아 세 축을 화면에서 거르고 있으므로, 받아 둔 것을 한 번 더
거르는 일이라 **새 요청이 필요 없다.** `/places` 와 URL 키(`?keyword=`)가 같은 것은 의도다 —
검색을 누가 수행하는지는 갈려도, 주소를 손으로 고치는 사용자가 화면마다 다시 배우게 하지
않는다. 정규화는 `lib/url/keyword.ts` 한 곳이 소유한다.

**목록이 잘리면 이 판단이 깨진다.** 검색이 "받아 온 것 중에서" 가 되어 **있는 곳을 없다고
말하게 된다** — E3 의 `countsAreComplete` 가 개수에서만 막는 문제와 같은 뿌리다.

**미래형이 아니라 지금 판정할 수 있는 조건이다.** 조회는 `size=250` 고정이고 반경은 50km
까지 열려 있어, `facilities.length < totalCount` 는 도달 가능한 상태다 (`MAX_SIZE` 가
50→250 으로 오른 이유가 바로 그 잘림이었다 — E2-1). 그래서 **잘린 응답에서는 0건 화면이
"없어요" 를 확언하지 않는다**: `countsAreComplete` 가 false 면 "받아 온 목록 안에서"
라고 범위를 밝히고 반경을 좁히라고 안내한다. 개수는 숫자를 빼고 검색은 확언하는
비대칭을 두지 않는다. 전국으로 넓어져 잘림이 상시가 되면 서버 `keyword` 계약을 먼저 연다.

**규칙 셋**

- **이름과 주소를 한 건초더미로 본다.** 따로 보면 `"제주 병원"` 처럼 한 낱말은 주소에,
  한 낱말은 이름에 있는 검색이 실패한다
- **공백으로 끊어 전부 만족(AND) · 순서는 보지 않는다.** 통짜 부분문자열이면 사용자가
  아는 두 낱말을 붙여 써야만 찾힌다
- **자모 분해·초성 검색은 하지 않는다.** 직접 구현하면 틀리는 자리가 많고, 이 화면에서
  틀린 검색은 있는 병원을 없다고 말하는 것이다

**검색어는 축이 아니라 범위다.** 그래서 칩 개수를 세기 **전**에 통과시킨다
(`narrowByKeyword`) — 검색 중인데 칩이 반경 전량의 수를 말하면 눌러서 나오는 결과와
어긋난다. 대신 `FacilityFilters` 안에 두어 **`초기화` 가 검색어까지 지운다.**

**입력이 서는 자리는 넷이다.**

| 갈래             | 자리                                       | 모양                           |
| ---------------- | ------------------------------------------ | ------------------------------ |
| 목록             | 카드 머리(`Surface` 의 `tools`), 칩 **위** | 글자 `검색` 버튼               |
| 지도 · 1024 미만 | 지도 위 오버레이, **보기 토글 왼쪽**       | 아이콘 버튼 · 짧은 placeholder |
| 지도 · 1024 이상 | 좌측 400 패널 **맨 위**, 필터바 위         | 글자 `검색` 버튼               |
| 지도 SDK 폴백    | 안내 줄 아래, 칩 위                        | 글자 `검색` 버튼               |

**필터 레일에는 두지 않는다** — `hidden lg:block` 이라 1024 미만에서 검색이 통째로 사라진다.

**지도 갈래에도 두기로 뒤집었다.** 처음에는 `/places`(#431)를 따라 두지 않았고 근거는
_"지도 위에 도구를 하나만 띄우면 규칙이 갈린다"_ 였는데, **지도에서 검색어가 걸린 것을 알
방법이 없다는 것이 더 큰 구멍이었다** — 목록은 이유 없이 줄어 있고 화면 어디에도 그
검색어가 없다(칩은 유형·영업 조건만 상태를 보여주고, 캡션은 개수·반경뿐이며,
`emergencySummaryLine` 은 목록 갈래 전용이다). 필터바의 `초기화` 는 **푸는 손잡이일 뿐
무엇이 걸렸는지 말하지 않고**, 전량 리셋이라 검색어만 푸는 경로도 되지 못한다.

### E3-1. 유형 칩 라벨은 결과에서 역추적하지 않는다 ([#205](https://github.com/8llow8llowMe/hondigagae/issues/205))

이 결정의 직접적인 귀결이 하나 더 있다. 서버로 좁히지 않으므로 **개수 0 인 칩도 반드시
그린다** — 그런데 그 칩은 목록에 표본이 없다. 라벨을
`facilities.find((f) => f.facilityType.code === code)?.facilityType.name ?? code` 로 만들면
그때 `?? code` 로 떨어져 **화면에 `ANIMAL_HOSPITAL 0` 이 나간다.** dev 실측이다.

0건은 예외 상황이 아니다 — 반경 안에 병원만 있으면 약국 칩이, 데이터 적재 전에는 둘 다
코드로 뜬다. **그리고 그 순간이 사용자가 가장 헤매고 있을 때다.**

그래서 유형 칩 라벨은 `messages.emergency.typeByCode` 의 **고정 라벨 2종**을 쓴다.
`api-integration-guide.md` §6 의 "한국어 매핑 테이블 금지" 는 서버가 **준** 값을 다시
번역하지 말라는 뜻이고, 여기는 서버가 값을 줄 수 없는 자리다 — 등록 폼 선택지와 같은 층이다
(`docs/features/pet/공통명세.md` S6-1).

**목록 행·선택된 행의 펼침(전화·길찾기)은 그대로 서버 `name` 을 쓴다.** 거기는 데이터가
있는 자리다. `FacilitySelectedCard`(부동 카드)는 #353 에서 삭제됐다 — 길찾기는 선택된
행의 펼침 상태로 옮겼다(`facility-row.tsx` 의 `CallButton`/`DirectionsLink`,
`emergency-map-panel.tsx` 가 그린다).
`FACILITY_TYPE_CODES` 가 늘면 `satisfies Record<FacilityTypeCode, string>` 이 컴파일
단계에서 잡는다.

## E4. 아트보드가 못 박은 규칙 5가지

| 규칙                                             | 이유                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **서버 순서를 재정렬하지 않는다**                | 병원·약국이 거리순으로 섞여 온다. 24시간을 위로 올리면 "가까운 순" 과 어긋난다                                                                                                                                                                                                                                                                                                                  |
| **배지 3상태 = `openNow`**                       | `true` 진료중(초록 `--status-open-*` + 진한 글자) / `false` 영업 종료(빨강 `--status-closed-*`) / `null` 영업 여부 확인 필요(점선 중립). **#598 이 "색이 아니라 무게로 가른다" 위에 색을 얹었다** — 배지가 1행 오른쪽 끝으로 올라가 `24시간` 과 나란히 서면서 회색 배지 둘이 모양으로 구별되지 않게 됐다. **등급·장애 토큰을 빌려 쓰지 않는다** — 값이 같아도 자기 토큰을 쓴다 (DESIGN.md §2-9) |
| **진료시간은 서버 문자열 그대로**                | `"월~금 09:00~19:00, 토 09:00~13:00"` 을 파싱해 "오늘 19:00까지" 로 요약하지 않는다. 서식이 조금만 달라도 **틀린 시간을 말하게 된다**                                                                                                                                                                                                                                                           |
| **`tel` 이 null 이면 비활성 + 이유 + 다음 방법** | 자리가 사라지면 "이 병원만 뭔가 다르다" 가 아니라 "화면이 깨졌다" 로 읽힌다                                                                                                                                                                                                                                                                                                                     |
| **약국을 같은 목록 안에 태그로**                 | 유형으로 섹션을 나누면 "4.46km 약국" 이 "3.12km 병원" 보다 위로 올라간다. 거리가 우선이다                                                                                                                                                                                                                                                                                                       |

`open24Only` 를 켜면 **결과가 매우 적다는 사실을 화면이 알린다** — 백엔드 스키마가
"제주 동물병원 중 3곳뿐" 이라고 명시하고 화면에 알리라고 요구한다.

## E5. 위치 — 실패해도 화면이 비지 않는다

`lat`/`lng` 가 필수라 좌표가 없으면 조회 자체를 못 한다. **네 갈래를 구분해 안내하고
제주 중심으로 조회한다** (`src/lib/geo/current-position.ts`).

| 갈래                               | 사용자가 할 수 있는 일 | 화면                                 |
| ---------------------------------- | ---------------------- | ------------------------------------ |
| `denied`(권한 거부)                | 브라우저 설정을 바꾼다 | 안내 + `현재 위치로 다시 찾기`       |
| `timeout` · `POSITION_UNAVAILABLE` | 잠시 뒤 다시 누른다    | 안내 + `현재 위치로 다시 찾기`       |
| `unsupported`                      | **없다**               | 안내만. 다시 시도 버튼을 주지 않는다 |
| `outside`(제주 밖)                 | **위치를 옮겨야 한다** | 안내만. 다시 시도 버튼을 주지 않는다 |

**`outside` 는 실패가 아니다.** 좌표는 정확히 받았고, 다만 우리 데이터가 제주뿐이다
(E2-2). 그래서 문구를 권한 문제로 쓰지 않는다 — "위치를 확인하지 못했어요" 라고 하면
사용자가 브라우저 설정을 뒤진다. `positionOutside` 는 "지금 제주 밖에 있어요" 다.
다시 시도 버튼도 없다: **서울에서 다시 눌러도 서울이다.**

**폴백일 때 거리를 표시하지 않는다.** 제주 중심에서 480m 인 것을 "480m" 로 쓰면
사용자는 자기 위치에서 480m 로 읽는다. 기준 표기도 `현재 위치 기준` → `제주 중심 기준`
으로 바뀐다. **목록과 전화는 그대로 남는다** — 급할 때 여는 화면이다.

이 규칙은 좌표를 쓰는 **모든 화면에 함께 걸린다** — `/emergency` · 홈 골든타임 ·
홈 병원 배너가 같은 `getCurrentPosition()` 을 쓰므로, 제주 밖에서 열면 셋 다 제주
기준으로 답하고 거리를 감춘다.

## E6. 결과 없음 두 갈래

- **조건을 켜서 0건** → 아트보드 03. 켜진 조건을 하나씩 꺼 보고 **실제로 몇 개가
  나오는지 세어** 버튼으로 준다 (`reliefs`). 꺼도 0 이면 그 제안은 만들지 않는다.
  검색어가 걸려 있으면 제목이 **무엇으로 찾았는지 되돌려 주고**(`searchNarrowedTitle`),
  완화 후보 맨 뒤에 `검색어 지우면 {n}곳` 이 붙는다 — 사용자가 직접 친 말이라 가장
  버리기 아까운 조건이다 (#584)
- **조건 없이 0건** → 반경 문제다. `반경 넓히기`(×2, 상한 50km). 상한이면 버튼을 뺀다
