# 긴급 시설 목록 우선 · 위치 주 버튼 세부 명세

> 진단 근거: [`docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md`](../../superpowers/specs/2026-09-15-ui-ux-audit-design.md) **E-1 (P0) · E-2 (P0)**, 시안 §3 ① ②.
> `공통명세.md`(E0~E8) 가 이 화면의 정본이다. D0–D9 는 **기본 보기** 와 **위치 폴백 UI** 두 가지를 다룬다(#639). 그 뒤는 D8-1 이 "범위 밖" 으로 미뤄 둔 것을 하나씩 이어 받은 절이다 — **지도 클러스터 마커(E-1 후반)는 D10**(#655), **필터 순서(E-3)는 D11 · 영업시간 오늘 한 줄(E-4)은 D12**(#654).

## D0. 화면 정의

- **경로**: `/emergency`. 인증 불필요 (변경 없음).
- **현상 (2026-09-15 실측, 390px)**: 기본 보기가 지도라 첫 화면이 `이 지역 42곳 · 14곳 · 21곳 · 8곳 …` 알약이 겹친 지도다. 위치 권한이 없으면 목록 위에 `위치 권한이 없어 거리를 계산할 수 없어요.` 와 `현재 위치로 다시 찾기` secondary 버튼이 서는데, 응급 화면에서 가장 급한 행동이 가장 낮은 위계다.
- **바꾸는 것**
  1. **E-1** `EMERGENCY_DEFAULT_VIEW` 를 `'map'` → `'list'`. 지도는 카드 제목 줄 `ViewToggle` 로 한 탭.
  2. **E-2** 위치 폴백 UI 를 카드 **머리(고정 영역)** 로 올리고, `내 위치로 가까운 병원 찾기` **primary** 버튼 + 권역 세그먼트(`제주시 · 서귀포 · 동부 · 서부`) 로 바꾼다. 세그먼트는 기존 `researchAt(center)` 로 기준점을 옮긴다.
- **바꾸지 않는 것**: 필터 축·칩·레일 · `FacilityRow` · 지도 갈래 내부 · `useNearbyFacilities` · 반경 · 0건 두 갈래 · E5 "실패해도 화면이 비지 않는다"(제주 중심 폴백 조회는 그대로 먼저 돈다).

## D1. 레이아웃

목록 갈래(3층 표면, E0). 우측 카드 `Surface fill` 의 **머리**가 늘어난다.

```text
[Surface 머리 — 고정]
  병원 · 약국                                      [목록|지도]      (제목 · ViewToggle — 변경 없음)
  제주 214곳 · 지금 진료중 100곳                                   (부제 — 신규, E2-1 totalCount 기준)
  ┌ 위치 폴백일 때만 ─────────────────────────────────────────┐
  │ [ 내 위치로 가까운 병원 찾기 ]  (primary, 전폭, 44px)       │
  │ 위치를 켤 수 없으면 지역을 골라 주세요                       │
  │ (제주시) (서귀포) (동부) (서부)   ← 세그먼트 칩, 44px 탭    │
  └───────────────────────────────────────────────────────────┘
  [필터 칩 줄 — 변경 없음]
  가까운 순 · 반경 10km · {기준} 기준                            (요약 줄 — 기준 문구 갱신)
[Surface 본문 — 구른다]
  행 · 행 · 행 …
```

- 모바일(<768) 칩은 카드 밖(E0 규칙) — 위치 블록은 **카드 안 머리**다. 칩은 좁히는 도구지만 위치 블록은 "무엇을 기준으로 찾을지" 라 결과의 전제이고, 카드가 결과를 담으므로 그 머리에 든다.
- 데스크톱(≥1024) 목록 갈래는 좌 280 레일 / 우 카드. 위치 블록은 우 카드 머리 그대로 (레일에 두지 않는다 — 레일은 필터).
- 위치 블록 높이는 폴백일 때 약 140px. 첫 화면(844) 안에 첫 행 2개가 남는다 (실측 D7).

## D3. 데이터 흐름

### D3-1. 기준점 결정 (변경)

```text
anchor = searchCenter                       ← 지도 재검색 ('map')          (현행)
       ?? regionCenter                      ← 권역 세그먼트 ('region')     (신규)
       ?? position(granted)                 ← 현재 위치 ('current')        (현행)
       ?? JEJU_QUERY_CENTER (fallback)      ← 제주 중심 ('jeju')           (현행)
basis: 'map' | 'region' | 'current' | 'jeju'
showDistance: basis !== 'jeju'              ← 'region' 은 거리를 보여 준다 (기준점이 명시적이다)
```

- 권역을 고르면 `regionCode` 를 상태에 두고 `searchCenter` 는 비운다(둘이 동시에 있으면 지도 재검색이 이긴다 — 지도에서 돌아왔을 때 사용자가 마지막에 한 행동이 지도다).
- `내 위치로 가까운 병원 찾기` 는 기존 `board.locate` 를 부른다. 성공(`granted`)하면 `regionCode` 를 비워 `'current'` 로 돌아간다. 실패하면 폴백 블록이 그대로 남고 버튼 라벨은 바뀌지 않는다 — 브라우저가 권한을 영구 거부한 경우 "다시 찾기" 를 눌러도 프롬프트가 안 뜨는데, 그 사실은 아래 안내 문장(D4 `positionDeniedHint`)이 말한다.
- **좌표는 URL 에 두지 않는다** (현행 `useEmergencyBoard` 머리주석). ~~`regionCode` 도 URL 에 두지 않는다 — 기준점은 필터가 아니라 세션 맥락이다. 공유 URL 은 제주 중심으로 열린다.~~ → **#674 에서 뒤집혔다. `regionCode` 는 URL 이 소유한다 — 정본은 아래 D3-3.** 좌표(`searchCenter` · `position`)를 두지 않는다는 판단은 그대로다.

### D3-3. 권역의 URL 직렬화 (#674)

**D3-1 · D8-4 의 "`regionCode` 를 URL 에 두지 않는다" 를 뒤집는다.** 같은 화면의 나머지 조건(키워드 · 진료중 · 유형 · 반경)은 전부 `searchParams` 인데 권역만 컴포넌트 state 라, 한 화면 안에서 규칙이 갈려 있었다 (`architecture-guide.md` §10).

#### 현상 (dev.hondigagae.com, Playwright 실측 · 이슈 #674 본문)

| 단계               | URL                          | 화면                                    |
| ------------------ | ---------------------------- | --------------------------------------- |
| `/emergency` 진입  | `/emergency`                 | `제주 중심 기준` · 99곳                 |
| `서귀포` 클릭      | `/emergency` (**변화 없음**) | `서귀포 기준` · 14곳                    |
| 새로고침           | `/emergency`                 | `제주 중심 기준` · 99곳 (**권역 소실**) |
| `동부` 후 뒤로가기 | 직전 방문 URL                | 권역 되돌리기가 아니라 **화면 이탈**    |

#### 직렬화 규약 (확정)

| 항목        | 값                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------ |
| 필드        | `EmergencyBoardParams.regionCode: JejuRegionCode \| null`                                  |
| URL 키      | `region`                                                                                   |
| URL 값      | **`JEJU_REGION_CODES` 의 코드 그대로** — `JEJU_CITY` · `SEOGWIPO` · `EAST` · `WEST`        |
| 기본값      | `null` (권역 미선택). **기본값은 URL 에서 생략한다** — 빈 URL = 기본 상태                  |
| 검증        | **화이트리스트** (`readRadius` · `readFacilityType` 와 같은 방식). 정확히 일치할 때만 통과 |
| 파싱·직렬화 | `parseEmergencyBoardParams` · `toEmergencyBoardQuery` (`src/lib/url/emergency-filters.ts`) |

**값을 대문자 코드로 두는 이유.** 같은 화면의 `type=ANIMAL_HOSPITAL` 이 이미 코드를 그대로 싣는다. 권역만 `seogwipo` 로 낮추면 파싱과 직렬화 양쪽에 대소문자 왕복이 붙고, 그 왕복이 이 모듈의 유일한 매핑 레이어가 된다 (§10 "매핑 레이어를 없앤다"). **이슈 본문의 예시는 `?region=seogwipo` 였다** — 여기서 대문자로 확정한다 (D8-5 에 이견 여지를 남긴다).

#### 잘못된 값의 폴백 (확정)

`readRegion(value)` 은 예외를 던지지 않는다. URL 은 사용자가 손으로 고치는 값이다.

| 입력                        | 결과             | 화면                                            |
| --------------------------- | ---------------- | ----------------------------------------------- |
| `?region=SEOGWIPO`          | `'SEOGWIPO'`     | 서귀포 세그먼트 선택 · `서귀포 기준`            |
| 키 없음                     | `null`           | 미선택 · `현재 위치 기준` 또는 `제주 중심 기준` |
| `?region=`                  | `null`           | 미선택                                          |
| `?region=seogwipo` (소문자) | `null`           | 미선택 — 화이트리스트는 정확 일치만 본다        |
| `?region=HALLA` (없는 권역) | `null`           | 미선택 (D8-3: 한라산권은 4권역에 없다)          |
| `?region=EAST&region=WEST`  | `'EAST'` (첫 값) | 동부 — `read()` 의 현행 규칙 그대로             |

**`null` 로 떨어뜨리고 제주시(첫 칩)로 떨어뜨리지 않는다.** 잘못된 값이 조용히 어느 권역을 고른 것처럼 보이면, 사용자는 자기가 고르지 않은 기준의 거리를 읽는다.

#### 상태 소유권 — `useEmergencyNav` 가 단일 출처다

| 대상                                                           | 전                    | 후                                                         |
| -------------------------------------------------------------- | --------------------- | ---------------------------------------------------------- |
| `use-emergency-board.ts` 의 `useState<JejuRegionCode \| null>` | 컴포넌트 state        | **걷는다**                                                 |
| 읽기                                                           | 훅 내부 state         | `useEmergencyNav()` 가 `searchParams` 에서 읽는다          |
| `researchAtRegion(code)`                                       | `setRegionCode(code)` | `setRegionCode(code)` → `router.replace` (URL 에 쓴다)     |
| `locate()`                                                     | `setRegionCode(null)` | `setRegionCode(null)` → URL 에서 `region` 을 지운다        |
| `board.regionCode` 반환값                                      | state                 | nav 가 준 값 (**시그니처는 그대로** — 쓰는 쪽은 안 바뀐다) |

- `researchAtRegion` 이 `setSearchCenter(null)` 을 함께 부르는 것은 그대로다 (D3-1 — 둘이 동시에 살면 지도가 이겨 방금 누른 칩이 아무 일도 하지 않은 것처럼 보인다).
- `useEmergencyNav` 의 `useMemo([searchParams])` 안에 `regionCode` 가 함께 든다. 문자열이라 참조가 새로 생기지 않으므로 `EmergencyMapView` 의 메모 사슬(review #353 Minor)에 영향이 없다.
- `resolve-anchor.ts` 는 **건드리지 않는다.** 우선순위(`searchCenter ?? regionCenter ?? position ?? JEJU_QUERY_CENTER`)도 `basis` 도 그대로다 — 바뀌는 것은 `regionCode` 가 어디서 오느냐뿐이다.

#### 쓰기는 `replace` 다 (확정)

`use-emergency-nav.ts` 머리주석의 판단을 그대로 따른다 — **권역 세그먼트는 칩과 같은 축**이다(같은 `ChipGroup`, 카드 머리 같은 줄). 칩 한 번에 히스토리가 쌓이면 뒤로가기가 필터 되감기가 되고, 목록 → 상세 → 뒤로가기라는 정상 경로가 묻힌다. `architecture-guide.md` §10 의 쓰기 규칙("`router.replace` 기본, 명시적 이동만 `push`")과도 같다.

- **재현 표 4행("동부 후 뒤로가기 → 화면 이탈")은 고치지 않는다.** 그것이 `replace` 의 정의된 동작이다. 권역을 되돌리는 길은 **같은 칩을 다시 눌러 해제**하는 것이고(D4), 그때 URL 에서 `region` 이 빠진다.
- `viewModeHref` 로 조립하는 것도 그대로다 — 권역을 고를 때 `view=map` 이 떨어지면 지도가 목록으로 튄다.

#### `searchCenter` 는 이번에 함께 올리지 않는다 (확정)

이슈가 판단을 요구한 항목이다. **따로 뗀다.**

| 근거             | `regionCode`                | `searchCenter`                                             |
| ---------------- | --------------------------- | ---------------------------------------------------------- |
| 값의 모양        | 4개짜리 열거값              | 연속 좌표 2개 (소수점 자릿수 규칙부터 정해야 한다)         |
| 검증             | 화이트리스트로 끝난다       | 제주 bbox 범위 검사 — 이 모듈에 없는 방식이다              |
| URL 부담         | `?region=EAST`              | `?lat=33.4996&lng=126.5312`                                |
| 공유했을 때의 뜻 | "서귀포를 기준으로 본 목록" | "내가 지도를 어디로 밀어 뒀는지" — 받는 사람에게 뜻이 없다 |

`useEmergencyBoard` 의 `searchCenter` 주석(#396)이 이미 적어 둔 판단을 유지한다. 좌표를 URL 에 두지 않는다는 D3-1 의 결론도 그대로다.

**대신 비대칭 하나를 이번에 닫는다.** `regionCode` 만 URL 에 있으면 `?region=SEOGWIPO` 로 본 뒤 지도에서 재검색했을 때 URL 에 `region` 이 남고, 새로고침에서 사라진 `searchCenter` 대신 **서귀포가 되살아난다** — 사용자가 마지막에 한 행동이 지워진다.

- `researchAt(center)` 는 **`regionCode` 를 URL 에서 함께 지운다.** `researchAtRegion` 이 이미 대칭으로 `searchCenter` 를 비우고 있으므로(D3-1), 두 기준점 조작이 서로를 끄는 한 축이 된다.
- 그 결과 지도 재검색 후 새로고침은 `현재 위치` 또는 `제주 중심` 으로 열린다. **되살아나는 옛 권역보다 낫다** — 기준 줄이 말하는 문구와 실제 기준이 언제나 같다.

#### 테스트 케이스

- 단위 (`src/lib/url/emergency-filters.test.ts`)
  - `parseEmergencyBoardParams(new URLSearchParams('region=SEOGWIPO')).regionCode` → `'SEOGWIPO'`
  - 키 없음 · `region=` · `region=seogwipo` · `region=HALLA` → `null` (위 폴백 표 그대로)
  - `region=EAST&region=WEST` → `'EAST'`

### D10-3. 자릿수 규칙 (`clusterMarkerText`)

> **2026-09-23 갱신 (#671 D-1): 상한이 `999` 에서 `99` 로 내려왔다.** 아래 규칙은 새 상한 기준이다.

- `1`~`99` 는 **그대로** 쓴다 — `3` · `42` · `99`.
- `100` 이상은 `99+` 로 접는다. **원을 키우지 않는다** — 원이 늘어나는 유일한 경로를 막는 규칙이다.
- `NaN` · 음수 · 소수는 `0` · `0` · 버림으로 떨어뜨린다. 빈 원이 뜨면 그것이야말로 소음이다.
- `aria-label` 은 **접지 않은 실제 개수**를 말한다 (`99+` 마커도 이름은 `이 지역 1200곳`).
  - **접근성 이름도 함께 접는다** — `clusterMarkerLabel` 이 `clusterMarkerText` 의 결과를 그대로 싣는다(`이 지역 99+곳`). 보이는 글자가 이름에 없으면 **WCAG 2.5.3 Label in Name** 이 어긋나 음성 제어 사용자가 화면에서 읽은 `99+` 를 불러도 잡히지 않는다. 상한이 `999` 이던 때는 한 셀에 1000곳이 묶여야 생기던 일이라 드러나지 않았고, **세 글자로 내리면서 흔해졌다.**
  - **대가는 접힌 묶음에서 정확한 개수가 이름에도 안 남는다는 것이다.** 감수한다 — 사용자가 볼 수 없는 수를 스크린리더에만 주면 두 사람이 다른 화면을 읽게 된다. 정확한 수는 눌러서 확대하면 마커가 갈라지며 드러난다. `cluster.test.ts` 가 **전 구간에서 이름이 보이는 글자를 담는지** 잠근다.
  - **다만 상한이 내려오면서 이 어긋남이 훨씬 흔해졌다.** 긴급 시설은 제주 전체가 135곳이라 한 셀이 100 을 넘는 일이 사실상 없지만, 같은 마커를 쓰는 `/places` 는 다르다. 거기서 재검토할 값이다.

**이전 판의 근거가 틀렸다.** "안쪽 30px 에 네 글자가 들어간다" 는 **정사각 패딩 박스**를 잰 것이고, 이 마커는 원이다. `align-items: center` 라 글자는 세로 중앙에 앉으므로 쓸 수 있는 폭은 지름이 아니라 **현(弦)** 이다 — `2·√(r² − h²)`, `r = 15`, `h = 글자높이 ÷ 2`:

- figure height ≈ 0.73em → 8.76px → `h = 4.38` → `2√(225 − 19.2)` = **28.69px**
- cap-height ≈ 0.70em → 8.40px → `h = 4.20` → `2√(225 − 17.6)` = 28.80px
- em 박스(12px) → `h = 6.00` → `2√(225 − 36.0)` = 27.50px

390px 실측(글자 잉크 폭): `3` 7.4 · `42` 14.8 · `135` 22.1 · `999+` 29.5. **네 글자 29.5px 은 28.69px 예산을 0.8px 넘는다** — 꽉 찬 것이 아니라 넘친 것이다. 조임을 `-0.08em` 까지 내리면 28.3px 로 수치상 들어가지만 여유가 0.39px 뿐이고, figure height 를 0.80em 으로만 잡아도 0.1px 로 줄어든다. **추정 metric 에 기대는 주장을 다시 세우지 않고 세 글자로 내렸다** — `99+` 는 22.1px 에 여유 6.6px 다.

| 셀 평균의 치우침 | 알약(이전) |   원형(현재) |      히트 44 기준 |
| ---------------- | ---------: | -----------: | ----------------: |
| 없음 (셀 중앙)   |    **4쌍** |      **0쌍** |           **0쌍** |
| ±25%             |        3쌍 |  1쌍 (3.0px) | 1쌍 이상 (15.0px) |
| ±40%             |        3쌍 | 1쌍 (20.4px) | 1쌍 이상 (32.4px) |

**마지막 열이 실제 탭 판정이다.** 앞의 두 열은 32 **원**끼리를 세는데, 누르는 자리는
`::before` 가 넓힌 **44 히트박스**다 (`globals.css` 의 `.map-cluster::before`). 32 로 재고
"안 겹친다" 로 통과시키면 **손가락이 닿는 자리는 이미 겹쳐 있다.**

산식은 중심 간격 `d` 하나로 선다 — `원 겹침 = 32 - d`, `히트 겹침 = 44 - d`, 그래서
**히트 겹침은 원 겹침보다 항상 12px 크고**, 진 쪽에 남는 폭은 `d` 와 같다.

- `±40%` 의 20.4px 쌍은 `d = 11.6` 이라 **히트로는 32.4px 겹치고 진 쪽에 11.6px 만 남는다**
- `±25%` 의 3.0px 쌍은 `d = 29.0` 이라 히트 겹침 15.0px
- **셀 중앙 행만 0 이 확정이다.** 레벨 9 의 경도 방향 간격이 58.1px 라 `d > 44` 이기 때문이다

> **아래 두 행이 "1쌍 이상" 인 이유.** 원래 측정은 **원이 겹친 쌍만** 셌다. 원이 안 겹친
> 쌍(`32 ≤ d`)도 `d < 44` 면 히트박스는 겹치는데, 그 쌍들의 `d` 가 기록돼 있지 않아 여기서
> 되살릴 수 없다. **확정하려면 44 기준으로 다시 재야 한다** — 이 표가 32 로만 재어 온 것이
> 정확히 그 문제다.

> **#671 D-2 메모와 다른 숫자가 하나 있다.** 그 메모는 _"32.4px 겹치고 진 쪽은 5.6px 폭만
> 눌린다"_ 고 적었는데, 위 산식으로는 **11.6px** 이다(32.4 는 일치). 메모 쪽 산식을 재현하지
> 못해 여기서는 유도 과정을 함께 적어 둔다.

- 묶음 중심은 셀 중앙이 아니라 **실제 좌표의 평균**이라(바다 한가운데를 피하려는 결정, `cluster.ts`) 이웃한 두 평균이 공유 모서리 쪽으로 함께 쏠리면 원끼리도 닿는다.
- 레벨 10 이상으로 축소하면 **인접 셀 간격 자체가 32 미만**이라 평균이 어디 있든 닿는다.

**#671 D-3 이 둘 다 닫았다.** 위 표가 짚은 "후속 후보"(`cellSizeFor` 를 `metersPerPixel(level)`
기반으로)만으로는 부족했다는 것이 실측으로 드러났고, 처방이 **둘**이 됐다.

1. **셀 크기에 바닥을 깐다.** `cellSizeFor` 가 상수표와 `44 × metersPerPixel(level)` 중 큰
   쪽을 고른다. 표는 "이만큼은 접고 싶다" 로 남고 물리적으로 겹치는 단계에서만 바닥이 이긴다.
   **간격을 44 로 통일하지는 않는다** — 통일하면 확대 구간에서 셀이 오히려 작아져(레벨 5 는
   0.004 → 0.0019) 접히지 않는 이름표 핀이 늘고, 이름표는 폭이 87px 까지 간다.
2. **격자 다음에 거리로 한 번 더 합친다** (`clusterForLevel`). 바닥만으로는 안 되는 이유가
   위 첫 bullet 그대로다 — 셀 간격은 셀 **경계**의 간격이고 마커는 **평균점**에 찍히므로,
   경계에 몰린 두 평균은 셀이 아무리 커도 붙는다. 실측이 그것을 보여 줬다: 바닥을 깐 뒤에도
   `/emergency` 375px 에서 묶음 중심이 **17.0 · 27.2 · 29.2px** 로 붙어 있었다.

고친 뒤 같은 화면의 최소 중심 간격은 **47.2px** 이고, 붙어 있던 세 묶음(`21`·`20`·`3`)이
하나(`45`)로 합쳐졌다. 합계는 103곳 그대로다.

## D11. 필터 우선순위 (E-3, #654)

> 진단 근거: 감사 §2-4 **E-3 (P1)**, 시안 §3 ③. D0~D9(#639)가 "범위 밖" 으로 미뤄 둔 항목이다.

### D11-1. 현상과 바꾸는 것

- **현상 (390 실측)**: `전체 135 · 병원 50 · 약국 85` / `반경 10.0km · 24시간 1 · 지금 진료중 100`. 이 화면을 여는 사람의 과업은 _"지금 갈 수 있는 곳에 전화"_ 하나인데 그 축이 **여섯 번째**다.
- **바꾸는 것**
  1. 축 순서를 `[지금 진료중 · 24시간] / [전체 | 병원 | 약국] · 반경` 으로 뒤집는다. **줄 수는 그대로 둘이다** — 급한 화면에서 세로를 더 쓰지 않는다.
  2. `openNowOnly` 를 **기본 ON** 으로 한다 (`DEFAULT_FACILITY_FILTERS`).
  3. `24시간 1` 옆에 데이터 한계를 **늘** 적는다 — `24시간 진료가 확인된 곳은 1곳뿐이에요`.
- **바꾸지 않는 것**: 축의 종류·개수 · `EmergencyTypeSegment` 의 세그먼트 형태 · 반경이 `filters` 밖이라는 구분 · 0건 두 갈래 · 전화/길찾기 버튼.

### D11-2. 시안을 따르지 않은 자리 — `전체` 는 첫 줄로 올리지 않는다

시안 §3 ③ 은 첫 줄을 `지금 진료중 · 24시간 · 전체`, 둘째 줄을 `병원 · 약국 · 반경` 으로 그린다. **순서는 따르고 묶음은 지킨다.**

`전체 · 병원 · 약국` 은 #537 이 칩에서 **꽉 찬 세그먼트**로 올린 한 덩어리다(택일 축이 칩으로 서면 사용자가 병원과 약국을 함께 켤 수 있다고 기대한다 — `EmergencyTypeSegment` 머리주석). 시안대로 `전체` 만 윗줄로 올리면 그 택일 축이 두 줄로 갈려, `전체` 가 진료중·24시간과 함께 켜는 토글로 읽힌다. 보조기기에서는 `role="radiogroup"` 하나가 쪼개지는 일이기도 하다.

E-3 의 실제 지적("지금 진료중이 여섯 번째")은 **순서**이고, 그것은 묶음을 지키고도 해결된다.

### D11-3. 화면별 순서 (확정)

| 표면             | 파일                         | 순서                                                                        |
| ---------------- | ---------------------------- | --------------------------------------------------------------------------- |
| 모바일 칩 (목록) | `emergency-filter-chips.tsx` | `[지금 진료중 · 24시간]` / `[전체｜병원｜약국] · 반경 ▾` / 24시간 안내 캡션 |
| 데스크톱 레일    | `emergency-filter-rail.tsx`  | `영업 조건`(진료중 → 24시간) → `시설 유형` → `검색 반경`                    |
| 지도 툴바        | `emergency-filter-bar.tsx`   | `[지금 진료중 · 24시간 · 반경 ▾ · 초기화]` / `[유형 스크롤러]`              |

지도 툴바까지 맞추는 이유: 두 갈래는 `useEmergencyBoard` 하나를 공유해 **상태가 같다.** 같은 축을 다른 순서로 늘어놓으면 보기를 전환할 때 사용자가 다시 배워야 하고, 기본 ON 때문에 "왜 마커가 줄었나" 에 답하는 칩이 지도 쪽에서는 네 번째가 된다.

### D11-4. 기본 ON 의 대가와 되돌아가는 길

`openNowOnly` 는 `openNow !== true` 인 곳을 거른다 — **닫힌 곳뿐 아니라 판정할 수 없는 곳(`openNow === null`)까지 함께다** (`applyFilters`). dev 실측(제주시청 · 10km)에서 135곳 중 100곳만 남는다.

성립 조건은 **되돌아가는 손잡이가 두 군데 있다는 것**이다.

1. 첫 칩 — 이제 화면의 첫 컨트롤이고 `aria-pressed` 로 켜짐이 읽힌다.
2. 0건 화면의 완화 버튼 — `reliefs()` 가 이미 `openNowOnly` 를 첫 후보로 올린다 (`"지금 진료중" 끄면 {n}곳`).

**#639 규칙과 충돌하지 않는다.** #639 가 정한 것은 기본 **보기**(`EMERGENCY_DEFAULT_VIEW = 'list'`)와 **기준점**(`resolveAnchor` 우선순위)이고, 이 항목은 **필터 축의 기본값**이다. #639 의 "바꾸지 않는 것" 목록에 필터 축이 있었지만 그것은 그 문서의 범위 선언이고, 같은 문서 D8-1 이 E-3 를 별도 이슈로 넘겼다.

카드 부제 `제주 {total}곳 · 지금 진료중 {openNow}곳`(#639 D4)은 그대로 둔다 — 기본 ON 이 되면 뒤 숫자가 목록 길이와 같아지지만, 앞 숫자가 **감춘 것이 얼마나 되는지**를 계속 말해 준다.

### D11-5. URL 직렬화 (기본값이 뒤집힌 축)

`lib/url/emergency-filters.ts` 의 "기본값은 URL 에서 생략한다" 규칙은 그대로다. 기본값이 `true` 가 되면서 **실리는 쪽이 뒤집힌다.**

| 상태                  | URL                   |
| --------------------- | --------------------- |
| 지금 진료중 ON (기본) | `openNowOnly` 키 없음 |
| 지금 진료중 OFF       | `?openNowOnly=false`  |

- `readFlag(value, fallback)` 가 **그 축의 기본값**을 받는다. 예전처럼 `value === 'true'` 로 두면 파라미터 없는 URL(= 기본 상태)이 꺼진 채 열린다.
- 읽지 못하는 값(`1`·`on`)은 **꺼짐이 아니라 기본값**으로 떨어진다.
- 왕복 테스트에 `openNowOnly: false` 조합을 넣는다 — 생략 규칙이 뒤집히는 자리다.

### D11-6. `24시간` 문구

`24시간 1` 은 _"제주에 24시간 병원이 한 곳"_ 이 아니라 _"원본 데이터에 24시간이라고 적힌 곳이 한 곳"_ 이다. 그 차이를 말하지 않으면 사용자는 밤에 갈 수 있는 병원이 한 곳뿐이라고 읽고 실제로 문 연 곳을 지나친다.

`open24Note(count, showCounts)` 순수 함수 하나가 세 갈래를 만든다 (`facility-filters.ts`).

| 조건                          | 문구                                              |
| ----------------------------- | ------------------------------------------------- |
| 개수를 쓸 수 있고 1곳 이상    | `24시간 진료가 확인된 곳은 {n}곳뿐이에요`         |
| 개수를 쓸 수 있고 0곳         | `이 반경 안에는 24시간 진료가 확인된 곳이 없어요` |
| 목록이 잘려 개수를 쓸 수 없음 | `24시간 진료가 확인된 곳은 제주에 몇 곳뿐이에요`  |

- **목록 갈래(칩·레일)는 늘 세운다** — 칩이 숫자를 말하는 내내 한계도 말해야 한다. 오해는 칩을 켜기 전에 이미 자리를 잡는다.
- **지도 툴바만 켰을 때 뜬다** — 375 시트 툴바는 지도 위에 얹혀 세로가 없고, 캡션 한 줄이 전화 버튼을 화면 밖으로 미는 일이 실제로 있었다 (`messages.emergency.positionDenied` 주석).
- `showCounts` 는 칩 라벨과 **같은 값**이다 (`countsAreComplete`). 한쪽만 숫자를 말하면 화면 안의 두 문장이 서로를 부정한다.

## D12. 영업시간 오늘 한 줄 (E-4, #654)

> 진단 근거: 감사 §2-4 **E-4 (P1)**, 시안 §3 ④.

### D12-1. 두 번 기각된 파싱을 다시 여는 근거

`types/emergency.ts` 의 `operatingHours` 주석과 `facility-row.tsx` 의 `FacilityHours` 머리주석이 _"파싱해서 «오늘 19:00까지» 로 요약하지 않는다"_ 를 **두 번** 못박았다 (#537 · #598). 근거는 dev 실측 서식이다.

```text
월~화, 목~금,토 09:30~20:00, 일 09:30~14:00      ← 시각 없는 앞 조각, 공백 불규칙, 수요일 없음
월~금 09:00~21:00, 토 09:00~21:00, 법정공휴일 09:00~21:00   ← 일요일 항목 자체가 없음
```

_"수요일에 첫 줄을 잘못 읽으면 닫힌 병원으로 달려가게 된다"_ — 이 화면에서 가장 비싼 실패다.

**그 규칙이 지키려던 것은 «파싱하지 않는다» 가 아니라 «틀린 시간을 말하지 않는다» 다.** `lib/emergency/operating-hours.ts` 는 금지를 **불변식 세 겹**으로 바꿔 세운다.

1. **상태는 파싱하지 않는다.** `진료중` / `영업 종료` 는 서버 `openNow` 가 유일한 근거이고, 화면에서는 머리의 `OpenStatus` 배지가 말한다. 오늘 한 줄은 **시각**만 맡는다.
2. **읽지 못하면 침묵한다.** 조각 하나라도 모르는 말이면 `summarizeTodayHours` 가 `null` 을 돌려주고, 행은 **#598 의 렌더 그대로**(원문 `line-clamp-2`) 그린다. 기본값이 침묵이다.
3. **서버와 어긋나면 우리 읽기를 버린다.** 원문에서 읽은 "지금 열려 있나" 가 `openNow` 와 다르면 `null` 이다. `openNow === null`(서버도 판정 못 함)이면 FE 도 판정하지 않는다.

3번이 핵심이다 — **위 두 실측 문자열 중 첫 번째는 수요일에 정확히 이 검증에서 걸러진다**(원문대로면 닫혀 있는데 서버는 진료중이라고 한다). 요약은 새 사실을 만들지 않고 **서버가 이미 단정한 사실의 표현**일 뿐이며, 표현이 사실과 갈리면 표현을 버린다.

### D12-2. 문구 (확정)

상태 절(`진료중 ·`)을 배지에 넘긴다 — 감사 문구는 `진료중 · 24:00까지` 였지만, 바로 위 머리에 같은 말을 하는 배지가 있어 급할 때 훑는 눈이 어느 쪽을 봐야 할지 잃는다. 시안 §3 ④ 도 상태를 배지에 두고 줄에는 시각만 둔다.

| 갈래          | 문구                                  | 조건                                                   |
| ------------- | ------------------------------------- | ------------------------------------------------------ |
| `open24`      | **(줄 없음)**                         | `open24 && openNow === true`. D12-8 참고               |
| `openUntil`   | `오늘 {time}까지`                     | `openNow === true` 이고 원문 판정이 일치               |
| `opensAt`     | `{오늘\|내일\|{요일}요일} {time}부터` | `openNow === false` 이고 다음 영업 시각을 정할 수 있다 |
| `closedToday` | `오늘은 쉬어요`                       | 앞으로 이레 안에 여는 날이 없다                        |
| (요약 없음)   | 원문 `line-clamp-2`                   | 위 넷 중 어느 것도 확정하지 못했다 (가드 폴백)         |
| (원문 없음)   | `진료시간이 등록돼 있지 않아요`       | `operatingHoursKnown === false`                        |

**이틀 뒤부터는 요일로 말한다** — "모레" 는 세어 보게 만들고 사흘 뒤부터는 쓸 말도 없다.

**갈래는 배타적이다.** 위 넷 중 하나가 서면 원문은 그리지 않고, 원문이 서면 요약 문구는 없다 — 근거는 D12-4.

### D12-3. 다음 영업일 계산 — 휴무를 읽지 못하면 약속하지 않는다

서버 `openNow` 는 **오늘의 개폐**를 검증해 주지만 **다음 영업 시각은 검증해 주지 않는다.** 남는 위험이 여기 하나뿐이라 따로 잠근다.

- 오늘 아직 열기 전이면 `오늘 {time}부터`.
- 아니면 **하루씩 이레까지 건너뛰며** 휴무가 아니고 원문에 시각이 있는 첫 날을 찾는다 — 토요일 밤 · 일요일 휴무면 다음은 **이틀 뒤 월요일**이다. "내일" 이라고 쓰면 닫힌 병원 앞에 서게 된다.
- `restDate` 는 **매주 반복되는** `X요일` 토큰만 읽는다. `연중무휴`·`무휴`·`없음`·`null`(전체 일치)은 휴무 없음.
- **서수·주기 수식어가 섞이면 요약 자체를 포기한다** (`parseRestDays` → `null`). `첫째`·`둘째`·`셋째`·`넷째`·`다섯째`·`번째`·`격주`·`매월`·`마지막`·`홀수`·`짝수`·`N주`·`주차` (`IRREGULAR_CYCLE`). `매주` 는 예외다 — 매주 반복이라 요일 하나로 정확히 옮겨진다.

  **이 모듈의 단위는 요일이다.** `weekly[3]` 은 "수요일" 이지 "몇 번째 수요일" 이 아니라, 달을 모르는 자료구조로 달 단위 주기를 표현할 수 없다. 눌러 담으면 **여는 날이 휴무로 승격**된다 — 실측: `월~금 09:00~18:00` · `둘째·넷째 수요일` · **2026-09-02(첫째 수요일, 여는 날) 08:00** · 서버 `openNow=false` → **`내일 09:00부터`**. 한 시간 뒤 여는 병원을 하루 뒤로 민다. `매월 셋째 토요일` 은 이틀 뒤까지 밀렸다.

  **`openNow` 가드(D12-1 불변식 3)가 이것을 잡지 못한다.** 08:00 시점엔 "휴무다" 와 "아니다" 두 읽기가 **둘 다 «지금 닫힘»** 이라 불리언이 일치한다 — 가드는 개/폐 한 비트만 검증한다 (D12-7).

- `무휴` 는 **전체 일치**다. 부분 문자열로 보면 `격주 무휴` 가 "휴무 없음"(그리고 운영시간 쪽에서는 **주 7일 영업**)으로 뒤집힌다 — 주기를 모를 때 안전한 실패는 "모르겠다" 이지 "쉬는 날 없음" 이 아니다.

### D12-4. 원문을 어디에 두는가 — **접기를 두지 않는다**

> **이 절은 구현 중에 한 번 뒤집혔다.** 처음에는 오늘 한 줄을 `<summary>` 로 만들고 원문을 `<details>` 안에 뒀다 (근거: _"요약이 틀렸을 때 확인할 곳이 있어야 한다"_). 사용자 결정으로 걷었다 — 아래가 그 근거다. **다시 접자는 제안이 나오면 이 절을 먼저 읽는다.**

**접을 것이 원문 한 필드뿐이라 접기가 성립하지 않는다.**

이 화면이 서버에서 받는 진료시간 데이터는 `operatingHours` **문자열 하나**다 (`NearbyFacilityItem`). 오늘 한 줄은 바로 그 한 필드를 읽어 만든 것이므로, **요약이 선 순간 원문에는 오늘에 대해 더 말할 것이 남아 있지 않다.** 펼쳐서 나오는 것은 같은 데이터의 다른 표기일 뿐이고, **접기 전과 후의 정보량이 같으면 그것은 접기가 아니라 같은 사실을 두 번 두는 것**이다.

"요약이 틀렸을 때의 확인처" 라는 근거도 이 화면에서는 필요가 없다 — 요약이 미심쩍은 경우는 **애초에 요약이 서지 않는 경우**이고(D12-1 불변식 2·3), 그때는 아래 둘째 갈래로 떨어져 원문이 통째로 선다. 즉 **원문이 필요한 상황에서는 원문이 이미 화면에 있다.**

그래서 `FacilityHours` 는 D12-2 표의 세 갈래로만 남는다.

1. 원문 없음 → `진료시간이 등록돼 있지 않아요`
2. 요약 실패(가드 폴백) → **원문 그대로** `line-clamp-2` — 이 갈래는 불변식의 몸통이라 지우지 않는다
3. 요약 성공 → **오늘 한 줄만.** 원문도, 펼치기도, 손잡이도 없다

부수 효과 둘.

- **`min-h-11` 손잡이가 사라져 행이 짧아진다.** #598 이 `전체 시간표` 버튼을 걷은 이유(_"44px 터치 영역이 행마다 한 줄을 더 먹었다"_)가 여기서 한 번 더 관철된다.
- **목록 행과 지도 패널의 진료시간 렌더가 같아졌다** (아래 D12-5).

바꾸지 않는 것.

- **휴무는 여전히 자기 줄이다** (#598). `매주 수요일 휴무` 는 오늘의 사실이 아니라 **다음 방문의 사실**이라 오늘 줄에 섞지 않는다. 원문과 달리 요약이 흡수하지 못하는 정보라 접기 논리의 대상도 아니다.
- **전화·길찾기 버튼(40px×2, 8px 간격)은 그대로다** — 이 화면에서 가장 잘 된 요소다 (감사 E-4).

### D12-5. 목록 행과 지도 패널이 같은 렌더다

한때 이 둘이 갈려 있었다. `FacilityRowContent` 는 호출부가 **선택 버튼으로 감싸는데**(`emergency-map-panel.tsx`) `<summary>` 는 interactive content 라 `<button>` 안에 넣을 수 없어(`<a>` 를 넣지 못하는 것과 같은 제약, `facility-row.tsx` 머리주석) 그 갈래만 `collapsible={false}` 로 따로 그렸다.

**D12-4 가 접기를 걷으면서 그 제약 자체가 사라졌다.** `collapsible` prop 과 분기를 함께 걷었고, 두 표면은 이제 같은 세 갈래를 탄다 — 갈라 둘 이유가 없으면 갈라 두지 않는다.

### D12-6. 시각의 출처

`summarizeTodayHours(facility, now)` 는 `now.getDay()` · `getHours()` 로 **기기의 현지 시각**을 읽는다 (사용자는 제주에 있다). `FacilityRow` · `FacilityRowContent` 가 `now` 를 선택 prop 으로 받고 기본값이 `new Date()` 라, 소비처는 아무것도 넘기지 않고 **테스트만 시각을 고정한다.**

화면이 열린 채 자정을 넘겨도 이 줄은 갱신되지 않는다 — 그때는 서버 `openNow` 도 같이 낡아 있고, 요약은 그 값과 어긋나는 순간 원문으로 떨어진다 (D12-1 불변식 3). 타이머를 두지 않는 이유다.

### D12-7. 가드가 막지 못하는 것 — **개/폐 한 비트만 검증한다**

D12-1 불변식 3 은 서버 `openNow` 와 우리 읽기의 **불리언**만 맞춰 본다. 그래서 **두 읽기가 같은 개/폐를 내놓으면서 시각만 다른 경우**는 그대로 통과한다. 알려진 잔여 위험 둘.

1. **닫혔을 때의 다음 영업 시각.** 서버가 검증해 주지 않는다 → 휴무 문구를 읽지 못하거나 달 단위·격주 주기면 아예 말하지 않는다 (D12-3).
2. **물려받은 시각의 마감.** 기각 근거 원문(`월~화, 목~금,토 09:30~20:00, …`)은 **월요일 마감을 명시한 적이 없고**, 뒤에서 앞으로 물려받는 규칙(D12-1)이 토요일 값을 빌려온다. 월요일 15:00 · `openNow=true` 면 양쪽 다 "열림" 이라 가드를 통과해 `오늘 20:00까지` 가 선다. 통상 독법상 타당한 추론이지만 **검증된 사실은 아니다.**

**2번은 감수한다.** 물려받기를 막으면 dev 에서 흔한 그 서식이 통째로 요약을 못 받고, 폴백이 같은 원문이라 사용자가 잃는 것도 없다. 여기 적어 두는 것은 _"가드가 전부를 막는다"_ 로 읽히지 않게 하기 위해서다 — 시각까지 검증하려면 서버가 `todayOpenTo` 를 줘야 한다 (D15).

### D12-8. `24시간` 갈래는 줄을 갖지 않는다 — **같은 논리의 세 번째 적용**

`제주24시동물병원` 행은 26px 짜리 머리 한 줄 안에서 같은 사실을 **세 번** 말하고 있었다.

| 어디    | 무엇                   |
| ------- | ---------------------- |
| 이름    | `제주**24시**동물병원` |
| 배지    | `[24시간]`             |
| 오늘 줄 | `24시간 운영`          |

**이 문서가 이미 두 번 쓴 논리다.**

- **D12-2** — 상태 절(`진료중 ·`)을 배지에 넘겼다: _"같은 행이 같은 말을 두 번 하면 급할 때 훑는 눈이 어느 쪽을 봐야 할지 잃는다"_
- **D12-4** — 펼치기를 걷었다: _"접기 전과 후의 정보량이 같으면 그것은 접기가 아니다"_

**여기서만 적용되지 않았다.** `open24` 갈래에서 이 줄이 더하는 정보는 **0비트**다 — 다른 갈래와 달리 시각을 말하지도 않는다(24시간에는 마감이 없다). 사용자가 접기를 걷으라고 한 이유(_"데이터가 하난데 왜 접으려하는거야"_)와 같은 것이다.

`todayHoursLabel({kind:'open24'})` 가 **`null`** 을 돌려주고 호출부가 아무것도 그리지 않는다. `messages.emergency.hoursOpen24`("24시간 운영")는 지웠다.

**두 `null` 의 뜻이 다르다** — 섞으면 안 된다.

| 어디                  | 뜻                           | 화면         |
| --------------------- | ---------------------------- | ------------ |
| `summarizeTodayHours` | 읽지 못했다                  | **원문**     |
| `todayHoursLabel`     | 읽었는데 새로 말할 것이 없다 | **아무것도** |

**경계**: `open24 === true` 전부가 아니라 **`openNow === true` 인 갈래 하나**다. 나머지 둘은 애초에 요약이 서지 않아 원문으로 떨어진다 — `openNow === null` 은 서버가 판정하지 못한 것이고, `openNow === false`(24시간이라면서 지금 닫힘)는 **자료가 스스로 모순된 상태**라 우리가 고를 근거가 없다. 그래서 `TodayHours['open24']` 는 "오늘 하루 종일 연다" 가 확정된 갈래이고, 화면은 그 사실을 배지로 이미 말한다.

- **D14-2. `법정공휴일` 조각을 건너뛴다.** 오늘이 공휴일인지 FE 가 알 수 없어서다. 공휴일 당일에는 평일 시각을 말하게 되는데, 서버 `openNow` 가 같은 데이터를 쓰면 대조에서 걸리지 않는다. 공휴일 달력을 FE 에 두지 않는 대신 **BE 가 `todayHours` 를 계산해 주는 쪽**이 정답이다 (D15).
- **D14-3. 기본 ON 이 감추는 35곳을 화면이 말하지 않는다.** 카드 부제가 `제주 135곳 · 지금 진료중 100곳` 으로 전체를 계속 말하지만, "지금 100곳만 보고 있다" 를 요약 줄이 따로 말할지는 정하지 않았다. 줄을 하나 더 쓰는 판단이라 실사용 관찰 뒤로 미룬다.

## D15. BE 후속 요청 (#654)

- **오늘 기준 진료 시각을 서버가 계산해 준다** (`todayOpenFrom` · `todayOpenTo` · `nextOpenAt`). `openNow` 를 이미 계산하고 있으므로 같은 자리에서 나온다. FE 파싱은 그때 걷는다 — 공휴일(D14-2)과 다음 영업일(D12-3)은 FE 가 원리적으로 맞힐 수 없는 값이다.
- **`open24` 가 «확인됨» 인지 «해당 없음» 인지 가르는 값**이 있으면 D11-6 의 세 갈래 문구를 두 갈래로 줄일 수 있다. 지금은 `24시간 1` 의 `1` 이 "확인된 곳" 이라는 사실을 문장으로만 말한다.

## D16. 요약 부제가 지금 걸린 조건을 말한다 (#675)

> 같은 화면의 **권역 URL 직렬화는 #674** 가 D3-3 에서 다룬다. 이 절은 **부제 문구**만 다룬다.

### D16-1. 현상 (dev.hondigagae.com, Playwright 실측 · 이슈 #675 본문)

**① 키워드를 통째로 무시한다**

| 조건                | 목록                                   | 부제                            |
| ------------------- | -------------------------------------- | ------------------------------- |
| `/emergency` (기본) | 99곳                                   | `제주 135곳 · 지금 진료중 99곳` |
| `?keyword=한라`     | **4곳**                                | `제주 135곳 · 지금 진료중 99곳` |
| `?keyword=청사`     | **0곳** — `‘청사’ 로 찾은 곳이 없어요` | `제주 135곳 · 지금 진료중 99곳` |

`찾은 곳이 없어요` 와 `지금 진료중 99곳` 이 **같은 화면에 동시에** 떠 있다.

**② 권역을 골라도 "제주" 라고 말한다**

`서귀포` 선택 시 기준 줄은 `서귀포 기준` 인데 부제는 `제주 18곳` 이다. 18 은 서귀포 반경 안의 수다 — **숫자는 맞고 라벨이 틀렸다.**

`emergency-summary-line.ts` 주석은 이미 _"옆에 선 진료중 수가 참이 아닌 채 한 줄에 묶이면 줄 전체가 거짓말이 된다 — 그래서 줄째로 감춘다"_ 라고 적어 뒀다. 그 판단이 `countsAreComplete`(목록 잘림) 한 축에만 걸려 있었다.

### D16-2. 무엇을 세는가 — `narrowByKeyword` 를 통과한 배열

`emergencyHeadSubtitle` 이 세는 배열을 바꾼다.

```ts
const narrowed = narrowByKeyword(result.facilities, keyword)
```

- **칩 개수가 이미 같은 이유로 그 함수를 먼저 탄다** (`facility-filters.ts` · `emergency-list-view.tsx` 의 `EmergencyListView` `counts`). 검색어는 칩이 아니라 **범위**라, 검색 중에 부제가 반경 전량의 수를 말하면 목록과 어긋난다.
- **칩 축(`type` · `open24Only` · `openNowOnly`)은 세지 않는다.** 부제는 "이 범위에 몇 곳이 있고 그중 지금 몇 곳이 열렸나" 이고, 칩은 그 범위 안에서 고르는 축이다. `applyFilters` 를 태우면 `지금 진료중 {openNow}곳` 이 언제나 목록 수와 같아져 줄이 아무것도 알려주지 못한다.
- `openNow` 도 같은 `narrowed` 에서 센다 — 두 숫자가 다른 배열에서 나오면 한 줄로 묶일 수 없다.
- **잘린 목록에서 줄째로 감추는 기존 판단(`countsAreComplete`)은 그대로다.** 그 가드가 통과했다는 것은 반경 안 전량을 받았다는 뜻이고, 그래서 `narrowed.length` 는 **반경 안 검색 일치 수의 정확한 값**이다 — 받아 온 것 중에서 센 수가 아니다.

### D16-3. 검색 중일 때 `total` 을 무엇으로 보는가 (확정)

이슈가 판단을 요구한 항목이다. 세 선택지 중 **문구를 갈라 쓰고 `total` 을 검색 결과 수로 바꾼다** (선택지 B).

| 선택지                                            | 왜 택하지 않았나 / 택했나                                                                                                                                                               |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. `total` 만 검색 결과 수로 바꾸고 문구는 그대로 | `제주 4곳` 이 된다. 제주에 병원이 4곳이라는 뜻으로 읽힌다 — 라벨을 고치지 않으면 ②번 현상이 검색 축에서 똑같이 재발한다                                                                 |
| **B. 문구를 갈라 쓰고 수도 검색 결과 수로**       | **채택.** `emergencyBasisLabel` 이 이미 네 갈래를 갈라 쓰는 것과 같은 처방이다. 숫자가 무엇을 센 값인지 줄 안에서 스스로 말한다                                                         |
| C. 검색 중이면 줄째로 감춘다                      | 감출 이유가 없다. 줄째로 감추는 판단은 *셀 수 없을 때*의 처방인데, 검색 결과 수는 **셀 수 있다** (D16-2). 검색은 가장 많이 쓰는 조작이라 그때마다 줄이 사라지면 부제가 있으나 마나 하다 |

### D16-4. 문구 (확정)

`messages.emergency` 에서 `제주` 하드코딩을 걷는다.

| 키                  | 문구                                              | 언제                      |
| ------------------- | ------------------------------------------------- | ------------------------- |
| `subtitle`          | `{region} {total}곳 · 지금 진료중 {openNow}곳`    | 검색어 없음               |
| `subtitleKeyword`   | `‘{keyword}’ {total}곳 · 지금 진료중 {openNow}곳` | 검색 중                   |
| `subtitleRegionAll` | `제주`                                            | `{region}` 의 기본 치환값 |

- `{region}` 치환은 **`emergencyBasisLabel` 과 같은 출처**를 쓴다 — `regionCode !== null` 이면 `messages.emergency.regionLabel[regionCode]`, 아니면 `subtitleRegionAll`. 같은 화면의 두 줄이 `서귀포 기준` / `제주 18곳` 으로 갈리던 자리다.
- 따옴표는 `searchNarrowedTitle`(`‘{keyword}’ 로 찾은 곳이 없어요`)과 같은 `‘ ’` 를 쓴다.
- **검색 중에는 지역명을 붙이지 않는다.** `서귀포 ‘한라’ 1곳` 은 읽기 나쁘고, 검색 중 가장 강한 조건은 검색어다. 지역은 바로 옆 기준 줄(`서귀포 기준`)이 계속 말하므로 화면에서 정보가 사라지지 않는다.
- 단위는 그대로 `곳` 이다. 거리·반경은 이 줄이 말하지 않는다 (요약 줄 `가까운 순 · 반경 10.0km` 소관 — D12 이전 판단).

**시그니처** — 부르는 쪽(`emergency-list-view.tsx` 의 `EmergencyListView` `subtitle`)이 `board` 에서 두 값을 넘긴다.

```ts
export function emergencyHeadSubtitle(
  result: NearbyFacilityResult | null,
  keyword: string | null,
  regionCode: JejuRegionCode | null,
): string | null
```

`emergencyHeadSubtitle(result, board.filters.keyword, board.regionCode)`. 지도 갈래는 부제를 그리지 않는다 — `EmergencyMapView` 는 `emergencyBasisLabel` 만 쓴다 (변경 없음).

### D16-5. 네 갈래 (확정)

기본 반경 10km · 실측 수 기준. `한라` 는 목 기준이 아니라 dev 실측 예시다.

| 검색어 | 권역   | 부제                             |
| ------ | ------ | -------------------------------- |
| 없음   | 없음   | `제주 135곳 · 지금 진료중 99곳`  |
| 없음   | 서귀포 | `서귀포 18곳 · 지금 진료중 14곳` |
| `한라` | 없음   | `‘한라’ 4곳 · 지금 진료중 3곳`   |
| `한라` | 서귀포 | `‘한라’ 1곳 · 지금 진료중 1곳`   |

`total` 의 출처는 갈래마다 다르다 — **검색어가 없으면 `result.totalCount`**(자르기 전 서버 총계, #297), **검색 중이면 `narrowed.length`**. 서버가 `keyword` 를 모르므로(#584) 검색 축의 총계는 서버에서 올 수 없고, `countsAreComplete` 가 통과한 뒤라 화면에서 센 수가 곧 전량이다.

### D16-6. 목록 0건인데 숫자를 말하는 조합 (확정)

**`total === 0` 이면 줄째로 감춘다** — 신규 규칙이다. 현행은 `제주 0곳 · 지금 진료중 0곳` 을 그린다.

| 상황                                          | 세는 배열    | `total` | 부제                                                                                 |
| --------------------------------------------- | ------------ | ------- | ------------------------------------------------------------------------------------ |
| 응답 전 (`result === null`)                   | —            | —       | **없음** (현행 유지)                                                                 |
| 목록 잘림 (`countsAreComplete === false`)     | —            | —       | **없음** (현행 유지)                                                                 |
| 반경 안 0건                                   | `[]`         | 0       | **없음** (신규) — 본문 `반경 안에 병원·약국이 없어요` 가 같은 사실을 제목으로 말한다 |
| 검색 0건 (`?keyword=한라산`)                  | `[]`         | 0       | **없음** (신규) — 본문 `‘한라산’ 로 찾은 곳이 없어요` 가 말한다                      |
| 검색 1건인데 `지금 진료중` 칩에 걸려 목록 0건 | `[청사약국]` | 1       | `‘청사’ 1곳 · 지금 진료중 0곳` — **남긴다**                                          |
| 유형·24시간 칩으로 목록 0건                   | 전량         | 135     | `제주 135곳 · 지금 진료중 99곳` — **남긴다**                                         |

- 마지막 두 줄이 모순처럼 보이지만 아니다. **부제는 범위를 말하고 칩은 그 안에서 고르는 축이다** (D16-2). `‘청사’ 1곳 · 지금 진료중 0곳` 은 0건 본문과 싸우지 않고 **그 이유를 설명한다** — 바로 아래 relief 버튼 `지금 진료중 끄기 1곳`(`reliefs`)이 말하는 수와 같은 근거다.
- `0곳 · 0곳` 짜리 줄은 정보가 없다. 잘린 목록에서 침묵하는 것과 같은 결의 판단이다 — **말할 것이 없으면 줄을 세우지 않는다.**

### D16-7. 테스트 케이스

### D16-9. 미결 사항 (#675)

- **D16-9-1. 칩 축을 부제가 말할까** — 선택지 A: 말하지 않는다(채택 · D16-2). 선택지 B: `지금 진료중` 이 켜져 있을 때 "지금 100곳만 보고 있다" 를 한 줄 더 쓴다. **추천 A 유지** — D14-3 이 같은 질문을 실사용 관찰 뒤로 미뤄 뒀고, 줄을 하나 더 쓰는 판단은 이 이슈 범위 밖이다.
