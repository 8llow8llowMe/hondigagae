# 긴급 시설 목록 우선 · 위치 주 버튼 세부 명세

> 진단 근거: [`docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md`](../../superpowers/specs/2026-09-15-ui-ux-audit-design.md) **E-1 (P0) · E-2 (P0)**, 시안 §3 ① ②.
> `공통명세.md`(E0~E8) 가 이 화면의 정본이다. D0–D9 는 **기본 보기** 와 **위치 폴백 UI** 두 가지를 다룬다(#639). 그 뒤는 D8-1 이 "범위 밖" 으로 미뤄 둔 것을 하나씩 이어 받은 절이다 — **지도 클러스터 마커(E-1 후반)는 D10**(#655), **필터 순서(E-3)는 D11 · 영업시간 오늘 한 줄(E-4)은 D12**(#654).

## D0. 화면 정의

- **경로**: `/emergency`. 인증 불필요 (변경 없음).
- **현상 (2026-09-15 실측, 390px)**: 기본 보기가 지도라 첫 화면이 `이 지역 42곳 · 14곳 · 21곳 · 8곳 …` 알약이 겹친 지도다. 위치 권한이 없으면 목록 위에 `위치 권한이 없어 거리를 계산할 수 없어요.` 와 `현재 위치로 다시 찾기` secondary 버튼이 서는데, 응급 화면에서 가장 급한 행동이 가장 낮은 위계다.
- **바꾸는 것**
  1. **E-1** `EMERGENCY_DEFAULT_VIEW` 를 `'map'` → `'list'`. 지도는 카드 제목 줄 `ViewToggle` 로 한 탭.
  2. **E-2** 위치 폴백 UI 를 카드 **머리(고정 영역)** 로 올리고, `내 위치로 가까운 병원 찾기` **primary** 버튼 + 권역 세그먼트(`제주시 · 서귀포 · 동부 · 서부`) 로 바꾼다. 세그먼트는 기존 `researchAt(center)` 로 기준점을 옮긴다.
- **바꾸지 않는 것**: 필터 축·칩·레일 · `FacilityRow` · 지도 갈래 내부 · `useNearbyFacilities` · 반경 · 0건 두 갈래 · E5 "실패해도 화면이 비지 않는다"(제주 중심 폴백 조회는 그대로 먼저 돈다).

## D1. 레이아웃

목록 갈래(3층 표면, E0). 우측 카드 `Surface fill` 의 **머리**가 늘어난다.

```text
[Surface 머리 — 고정]
  병원 · 약국                                      [목록|지도]      (제목 · ViewToggle — 변경 없음)
  제주 214곳 · 지금 진료중 100곳                                   (부제 — 신규, E2-1 totalCount 기준)
  ┌ 위치 폴백일 때만 ─────────────────────────────────────────┐
  │ [ 내 위치로 가까운 병원 찾기 ]  (primary, 전폭, 44px)       │
  │ 위치를 켤 수 없으면 지역을 골라 주세요                       │
  │ (제주시) (서귀포) (동부) (서부)   ← 세그먼트 칩, 44px 탭    │
  └───────────────────────────────────────────────────────────┘
  [필터 칩 줄 — 변경 없음]
  가까운 순 · 반경 10km · {기준} 기준                            (요약 줄 — 기준 문구 갱신)
[Surface 본문 — 구른다]
  행 · 행 · 행 …
```

- 모바일(<768) 칩은 카드 밖(E0 규칙) — 위치 블록은 **카드 안 머리**다. 칩은 좁히는 도구지만 위치 블록은 "무엇을 기준으로 찾을지" 라 결과의 전제이고, 카드가 결과를 담으므로 그 머리에 든다.
- 데스크톱(≥1024) 목록 갈래는 좌 280 레일 / 우 카드. 위치 블록은 우 카드 머리 그대로 (레일에 두지 않는다 — 레일은 필터).
- 위치 블록 높이는 폴백일 때 약 140px. 첫 화면(844) 안에 첫 행 2개가 남는다 (실측 D7).

## D3. 데이터 흐름

### D3-1. 기준점 결정 (변경)

```text
anchor = searchCenter                       ← 지도 재검색 ('map')          (현행)
       ?? regionCenter                      ← 권역 세그먼트 ('region')     (신규)
       ?? position(granted)                 ← 현재 위치 ('current')        (현행)
       ?? JEJU_QUERY_CENTER (fallback)      ← 제주 중심 ('jeju')           (현행)
basis: 'map' | 'region' | 'current' | 'jeju'
showDistance: basis !== 'jeju'              ← 'region' 은 거리를 보여 준다 (기준점이 명시적이다)
```

- 권역을 고르면 `regionCode` 를 상태에 두고 `searchCenter` 는 비운다(둘이 동시에 있으면 지도 재검색이 이긴다 — 지도에서 돌아왔을 때 사용자가 마지막에 한 행동이 지도다).
- `내 위치로 가까운 병원 찾기` 는 기존 `board.locate` 를 부른다. 성공(`granted`)하면 `regionCode` 를 비워 `'current'` 로 돌아간다. 실패하면 폴백 블록이 그대로 남고 버튼 라벨은 바뀌지 않는다 — 브라우저가 권한을 영구 거부한 경우 "다시 찾기" 를 눌러도 프롬프트가 안 뜨는데, 그 사실은 아래 안내 문장(D4 `positionDeniedHint`)이 말한다.
- **좌표는 URL 에 두지 않는다** (현행 `useEmergencyBoard` 머리주석). `regionCode` 도 URL 에 두지 않는다 — 기준점은 필터가 아니라 세션 맥락이다. 공유 URL 은 제주 중심으로 열린다.

## D6. 접근성

- primary 버튼은 `Button` 44px. 폴백 블록의 첫 줄(`positionDenied`)은 `role="status"` 로 두어 위치 실패가 확정되는 순간 한 번 읽힌다. 현행 `PositionNotice` 에 없던 것이다 — 급한 화면에서 "왜 거리가 없나" 를 눈으로 찾게 하지 않는다.
- 세그먼트는 `ChipGroup`(기존 필터 칩과 같은 컴포넌트) · `aria-pressed`. 키보드 좌우 이동은 칩 그룹 현행 규약.
- 보기 토글 기본값이 목록이 되어 스크린리더 사용자의 첫 화면이 목록(읽을 수 있는 구조)이 된다 — 지도 기본은 캔버스가 첫 콘텐츠였다.

- 기존 e2e `protected-routes` · `surface` 스펙이 `/emergency` 기본 보기를 지도로 가정한 곳이 있으면 고친다 (grep `view=list`).

## D8. 미결 사항

- **D8-1. 지도 클러스터 알약 → 숫자 원형 마커 (E-1 후반)** — **#655 에서 닫혔다. 규격은 아래 D10 이 정본이다.** (이 문서 머리의 "범위 밖" 문장은 #639 당시 기준이다.)
- **D8-2. 데스크톱도 목록 기본인가** — 선택지 A: 폭 무관 목록 기본(URL 의미가 하나). 선택지 B: 데스크톱만 지도 기본. **추천 A.** `view` 는 URL 파라미터라 폭에 따라 기본값이 갈리면 같은 링크가 기기마다 다른 화면을 연다. 데스크톱 지도(400 부동 패널)는 잘 만들어져 있고 한 탭 거리다.
- **D8-3. 권역 세그먼트를 홈 권역 날씨의 5권역(한라산권 포함)과 맞출까** — 한라산권에는 병원이 없다. **4권역으로 확정.**
- **D8-4. `regionCode` 를 URL 에 둘까** — 두지 않는다 (D3-1). 공유 URL 이 남의 위치 맥락을 실어 나르지 않는다.

### D10-2. 규격

| 크기        | `width`·`height` **32px 고정** (`padding: 0`)                          | `padding` 으로 원을 만들면 자릿수마다 폭이 달라져 다시 알약이 된다                         |
| 모양        | `--radius-full` · `1px solid --border-strong` · `--bg` · `--shadow-md` | 알약이 쓰던 토큰 그대로. **새 색을 만들지 않는다**                                         |
| 글자        | `--fg` · 12px · 700 · `tabular-nums` · `letter-spacing: -0.04em`       | 12px 는 `DESIGN.md` §10 의 최소 글자다. 그 아래로 내리지 않는다                            |
| 좌표 기준   | `yAnchor: 0.5` (핀은 `1` 유지)                                         | 원에는 가리킬 뾰족한 끝이 없다. `1` 이면 원이 좌표 위로 통째로 떠서 이웃과 어긋나 보인다   |
| 접근성 이름 | `aria-label` = `messages.map.clusterCount` (`이 지역 {n}곳`)           | 원 안에는 숫자만 남는다. 이름까지 `42` 가 되면 무엇이 42인지 알 수 없다                    |
| 층          | `zIndex` **2** (선택 핀 10 · 일반 핀 1)                                | 일반 핀과 동률이면 DOM 순서가 이겨, 가로로 긴 이름표 핀이 32px 원을 덮어 못 누르게 된다    |
| 터치 영역   | 보이는 원 32 · `::before` 로 **히트 44×44**                            | 44px 규칙은 "지도 마커 포함"(`done-checklist.md`). 원을 44 로 키우면 줄인 폭을 도로 내준다 |

### D10-3. 자릿수 규칙 (`clusterMarkerText`)

- `1`~`999` 는 **그대로** 쓴다 — `3` · `42` · `135`.
- `1000` 이상은 `999+` 로 접는다. **원을 키우지 않는다** — 원이 늘어나는 유일한 경로를 막는 규칙이다.
- `NaN` · 음수 · 소수는 `0` · `0` · 버림으로 떨어뜨린다. 빈 원이 뜨면 그것이야말로 소음이다.
- `aria-label` 은 **접지 않은 실제 개수**를 말한다 (`999+` 마커도 이름은 `이 지역 1200곳`).
  - **접힌 구간에서만 WCAG 2.5.3 Label in Name 이 어긋난다** — 보이는 글자 `999+` 가 이름에 없다. 음성 제어 사용자가 "999+" 를 말해도 잡히지 않는다. 이름을 `이 지역 1200곳 (999+)` 로 만들어 맞출 수 있지만, **접힌 값을 이름에까지 실어 주는 대가가 더 크다** — 스크린리더 사용자에게 근사값을 두 번 읽히게 된다. 한 셀에 1000곳 이상이 묶여야 나오는 구간이라 이쪽을 택했다.

390px 실측(글자 잉크 폭 / 안쪽 30px 대비 좌우 여백): `3` 7.4 / 11.3 · `42` 14.8 / 7.6 · `135` 22.1 / 3.9 · `999+` 29.5 / 0.25. **네 글자는 원을 꽉 채운다** — 조임을 `-0.08em` 까지 내려도 좌우 1.2px 밖에 못 벌어진다. 한 셀에 1000곳 이상이 묶여야 나오는 값이고 긴급 시설 전체가 135곳이라, 원을 키우는 대신 이 꽉 참을 택했다.

### D10-4. 겹침 — 남는 부분이 있다

**격자 셀 간격이 마커 지름보다 좁아지는 확대 단계가 있다.** `cellSizeFor(level)` 과 `metersPerPixel(level)` 로 환산한 인접 셀 중심 간격(제주 위도 33.4°, 경도 방향이 좁다):

| level | 셀(도) | 위도 방향 px | 경도 방향 px |
| ----: | -----: | -----------: | -----------: |
|     6 |  0.004 |         55.7 |         46.5 |
|     8 |  0.012 |         41.7 |         34.9 |
| **9** |  0.040 |     **69.6** |     **58.1** |
|    10 |  0.040 |         34.8 |         29.0 |
|    12 |  0.120 |         26.1 |         21.8 |
|    13 |  0.120 |         13.0 |         10.9 |

`JEJU_MAP_LEVEL` 이 9 이고 반경 10km · 390px 카메라도 `levelForSpanMeters(20000, 390)` → **9** 다. 즉 **실제 첫 화면은 간격이 넉넉한 단계**다.

390px · 레벨 9 간격에 진단이 찍은 일곱 묶음(`42 14 21 8 4 7 5`)을 놓고 `getBoundingClientRect()` 쌍별 겹침을 센 결과:

| 셀 평균의 치우침 | 알약(이전) |   원형(현재) |
| ---------------- | ---------: | -----------: |
| 없음 (셀 중앙)   |    **4쌍** |      **0쌍** |
| ±25%             |        3쌍 |  1쌍 (3.0px) |
| ±40%             |        3쌍 | 1쌍 (20.4px) |

- 묶음 중심은 셀 중앙이 아니라 **실제 좌표의 평균**이라(바다 한가운데를 피하려는 결정, `cluster.ts`) 이웃한 두 평균이 공유 모서리 쪽으로 함께 쏠리면 원끼리도 닿는다. **겹침이 0 이 되지는 않는다.**
- 레벨 10 이상으로 축소하면 **인접 셀 간격 자체가 32 미만**이라 평균이 어디 있든 닿는다.
- **후속 후보**: `cellSizeFor` 를 도(degree) 상수표가 아니라 `metersPerPixel(level)` 기반으로 바꿔 셀을 **화면 픽셀 기준 고정 크기**로 만든다. 그러면 모든 단계에서 간격이 마커 지름을 넘는다. 묶는 규칙 자체가 바뀌어 `/places` 지도까지 영향이 가므로 **이 이슈에서는 하지 않았다.**

### D10-5. 공유 범위

`MapCanvas` 는 `/emergency` 와 `/places`(`place-map-view` · `place-mini-map`)가 함께 쓴다. 클러스터 표현은 **컴포넌트 하나에만 있으므로 두 화면이 같이 바뀐다.** 화면별로 갈라 두 벌을 만들지 않았다 — 같은 컨트롤이 화면마다 다르게 보이는 것이 더 나쁘다(`messages/map.ts` 머리주석의 같은 판단).

### D10-6. 건드리지 않은 것

- **클러스터 클릭 확대는 그대로 얼려 둔다.** `emergency-map-view.tsx` 의 `frozenBounds` doc-comment 가 "알려진 잔존 동작이지 결함이 아니다" 로 못박아 둔 결정이다.
- `clusterByGrid` · `cellSizeFor` · 묶음 중심 계산 · `EMERGENCY_DEFAULT_VIEW`.

### D10-7. 테스트 케이스

- 순수 로직 (`src/lib/map/cluster.test.ts`):
  - `clusterMarkerText`: `3`→`'3'` · `42`→`'42'` · `135`→`'135'` · `999`→`'999'` · `1000`→`'999+'`; 어떤 입력에서도 **길이 ≤ 4**; `NaN`→`'0'` · `-5`→`'0'` · `4.7`→`'4'`
  - `clusterMarkerLabel`: `42`→`이 지역 42곳`, `1200`→`이 지역 1200곳`(접지 않는다), 문구는 `messages.map.clusterCount` 에서 온다
- 브라우저 실측(390): 마커 rect 가 자릿수와 무관하게 `32×32`, 잉크가 원 밖으로 넘치지 않는다(`scrollWidth ≤ clientWidth`).
- **지도 SDK 를 태운 e2e 는 없다.** 카카오 웹 도메인에 등록된 로컬 출처가 `localhost:5174` 하나뿐이라 다른 포트에서는 SDK 가 `AccessDeniedError` 로 떨어지고 화면이 목록 폴백으로 간다 (`errorScript`). 위 실측도 같은 이유로 실제 `globals.css` 를 태운 390px 문서 안에서 마커 DOM 을 직접 놓고 쟀다.

## D11. 필터 우선순위 (E-3, #654)

> 진단 근거: 감사 §2-4 **E-3 (P1)**, 시안 §3 ③. D0~D9(#639)가 "범위 밖" 으로 미뤄 둔 항목이다.

### D11-1. 현상과 바꾸는 것

- **현상 (390 실측)**: `전체 135 · 병원 50 · 약국 85` / `반경 10.0km · 24시간 1 · 지금 진료중 100`. 이 화면을 여는 사람의 과업은 _"지금 갈 수 있는 곳에 전화"_ 하나인데 그 축이 **여섯 번째**다.
- **바꾸는 것**
  1. 축 순서를 `[지금 진료중 · 24시간] / [전체 | 병원 | 약국] · 반경` 으로 뒤집는다. **줄 수는 그대로 둘이다** — 급한 화면에서 세로를 더 쓰지 않는다.
  2. `openNowOnly` 를 **기본 ON** 으로 한다 (`DEFAULT_FACILITY_FILTERS`).
  3. `24시간 1` 옆에 데이터 한계를 **늘** 적는다 — `24시간 진료가 확인된 곳은 1곳뿐이에요`.
- **바꾸지 않는 것**: 축의 종류·개수 · `EmergencyTypeSegment` 의 세그먼트 형태 · 반경이 `filters` 밖이라는 구분 · 0건 두 갈래 · 전화/길찾기 버튼.

### D11-2. 시안을 따르지 않은 자리 — `전체` 는 첫 줄로 올리지 않는다

시안 §3 ③ 은 첫 줄을 `지금 진료중 · 24시간 · 전체`, 둘째 줄을 `병원 · 약국 · 반경` 으로 그린다. **순서는 따르고 묶음은 지킨다.**

`전체 · 병원 · 약국` 은 #537 이 칩에서 **꽉 찬 세그먼트**로 올린 한 덩어리다(택일 축이 칩으로 서면 사용자가 병원과 약국을 함께 켤 수 있다고 기대한다 — `EmergencyTypeSegment` 머리주석). 시안대로 `전체` 만 윗줄로 올리면 그 택일 축이 두 줄로 갈려, `전체` 가 진료중·24시간과 함께 켜는 토글로 읽힌다. 보조기기에서는 `role="radiogroup"` 하나가 쪼개지는 일이기도 하다.

E-3 의 실제 지적("지금 진료중이 여섯 번째")은 **순서**이고, 그것은 묶음을 지키고도 해결된다.

### D11-3. 화면별 순서 (확정)

| 표면             | 파일                         | 순서                                                                        |
| ---------------- | ---------------------------- | --------------------------------------------------------------------------- |
| 모바일 칩 (목록) | `emergency-filter-chips.tsx` | `[지금 진료중 · 24시간]` / `[전체｜병원｜약국] · 반경 ▾` / 24시간 안내 캡션 |
| 데스크톱 레일    | `emergency-filter-rail.tsx`  | `영업 조건`(진료중 → 24시간) → `시설 유형` → `검색 반경`                    |
| 지도 툴바        | `emergency-filter-bar.tsx`   | `[지금 진료중 · 24시간 · 반경 ▾ · 초기화]` / `[유형 스크롤러]`              |

지도 툴바까지 맞추는 이유: 두 갈래는 `useEmergencyBoard` 하나를 공유해 **상태가 같다.** 같은 축을 다른 순서로 늘어놓으면 보기를 전환할 때 사용자가 다시 배워야 하고, 기본 ON 때문에 "왜 마커가 줄었나" 에 답하는 칩이 지도 쪽에서는 네 번째가 된다.

### D11-4. 기본 ON 의 대가와 되돌아가는 길

`openNowOnly` 는 `openNow !== true` 인 곳을 거른다 — **닫힌 곳뿐 아니라 판정할 수 없는 곳(`openNow === null`)까지 함께다** (`applyFilters`). dev 실측(제주시청 · 10km)에서 135곳 중 100곳만 남는다.

성립 조건은 **되돌아가는 손잡이가 두 군데 있다는 것**이다.

1. 첫 칩 — 이제 화면의 첫 컨트롤이고 `aria-pressed` 로 켜짐이 읽힌다.
2. 0건 화면의 완화 버튼 — `reliefs()` 가 이미 `openNowOnly` 를 첫 후보로 올린다 (`"지금 진료중" 끄면 {n}곳`).

**#639 규칙과 충돌하지 않는다.** #639 가 정한 것은 기본 **보기**(`EMERGENCY_DEFAULT_VIEW = 'list'`)와 **기준점**(`resolveAnchor` 우선순위)이고, 이 항목은 **필터 축의 기본값**이다. #639 의 "바꾸지 않는 것" 목록에 필터 축이 있었지만 그것은 그 문서의 범위 선언이고, 같은 문서 D8-1 이 E-3 를 별도 이슈로 넘겼다.

카드 부제 `제주 {total}곳 · 지금 진료중 {openNow}곳`(#639 D4)은 그대로 둔다 — 기본 ON 이 되면 뒤 숫자가 목록 길이와 같아지지만, 앞 숫자가 **감춘 것이 얼마나 되는지**를 계속 말해 준다.

### D11-5. URL 직렬화 (기본값이 뒤집힌 축)

`lib/url/emergency-filters.ts` 의 "기본값은 URL 에서 생략한다" 규칙은 그대로다. 기본값이 `true` 가 되면서 **실리는 쪽이 뒤집힌다.**

| 상태                  | URL                   |
| --------------------- | --------------------- |
| 지금 진료중 ON (기본) | `openNowOnly` 키 없음 |
| 지금 진료중 OFF       | `?openNowOnly=false`  |

- `readFlag(value, fallback)` 가 **그 축의 기본값**을 받는다. 예전처럼 `value === 'true'` 로 두면 파라미터 없는 URL(= 기본 상태)이 꺼진 채 열린다.
- 읽지 못하는 값(`1`·`on`)은 **꺼짐이 아니라 기본값**으로 떨어진다.
- 왕복 테스트에 `openNowOnly: false` 조합을 넣는다 — 생략 규칙이 뒤집히는 자리다.

### D11-6. `24시간` 문구

`24시간 1` 은 _"제주에 24시간 병원이 한 곳"_ 이 아니라 _"원본 데이터에 24시간이라고 적힌 곳이 한 곳"_ 이다. 그 차이를 말하지 않으면 사용자는 밤에 갈 수 있는 병원이 한 곳뿐이라고 읽고 실제로 문 연 곳을 지나친다.

`open24Note(count, showCounts)` 순수 함수 하나가 세 갈래를 만든다 (`facility-filters.ts`).

| 조건                          | 문구                                              |
| ----------------------------- | ------------------------------------------------- |
| 개수를 쓸 수 있고 1곳 이상    | `24시간 진료가 확인된 곳은 {n}곳뿐이에요`         |
| 개수를 쓸 수 있고 0곳         | `이 반경 안에는 24시간 진료가 확인된 곳이 없어요` |
| 목록이 잘려 개수를 쓸 수 없음 | `24시간 진료가 확인된 곳은 제주에 몇 곳뿐이에요`  |

- **목록 갈래(칩·레일)는 늘 세운다** — 칩이 숫자를 말하는 내내 한계도 말해야 한다. 오해는 칩을 켜기 전에 이미 자리를 잡는다.
- **지도 툴바만 켰을 때 뜬다** — 375 시트 툴바는 지도 위에 얹혀 세로가 없고, 캡션 한 줄이 전화 버튼을 화면 밖으로 미는 일이 실제로 있었다 (`messages.emergency.positionDenied` 주석).
- `showCounts` 는 칩 라벨과 **같은 값**이다 (`countsAreComplete`). 한쪽만 숫자를 말하면 화면 안의 두 문장이 서로를 부정한다.

## D12. 영업시간 오늘 한 줄 (E-4, #654)

> 진단 근거: 감사 §2-4 **E-4 (P1)**, 시안 §3 ④.

### D12-1. 두 번 기각된 파싱을 다시 여는 근거

`types/emergency.ts` 의 `operatingHours` 주석과 `facility-row.tsx` 의 `FacilityHours` 머리주석이 _"파싱해서 «오늘 19:00까지» 로 요약하지 않는다"_ 를 **두 번** 못박았다 (#537 · #598). 근거는 dev 실측 서식이다.

```text
월~화, 목~금,토 09:30~20:00, 일 09:30~14:00      ← 시각 없는 앞 조각, 공백 불규칙, 수요일 없음
월~금 09:00~21:00, 토 09:00~21:00, 법정공휴일 09:00~21:00   ← 일요일 항목 자체가 없음
```

_"수요일에 첫 줄을 잘못 읽으면 닫힌 병원으로 달려가게 된다"_ — 이 화면에서 가장 비싼 실패다.

**그 규칙이 지키려던 것은 «파싱하지 않는다» 가 아니라 «틀린 시간을 말하지 않는다» 다.** `lib/emergency/operating-hours.ts` 는 금지를 **불변식 세 겹**으로 바꿔 세운다.

1. **상태는 파싱하지 않는다.** `진료중` / `영업 종료` 는 서버 `openNow` 가 유일한 근거이고, 화면에서는 머리의 `OpenStatus` 배지가 말한다. 오늘 한 줄은 **시각**만 맡는다.
2. **읽지 못하면 침묵한다.** 조각 하나라도 모르는 말이면 `summarizeTodayHours` 가 `null` 을 돌려주고, 행은 **#598 의 렌더 그대로**(원문 `line-clamp-2`) 그린다. 기본값이 침묵이다.
3. **서버와 어긋나면 우리 읽기를 버린다.** 원문에서 읽은 "지금 열려 있나" 가 `openNow` 와 다르면 `null` 이다. `openNow === null`(서버도 판정 못 함)이면 FE 도 판정하지 않는다.

3번이 핵심이다 — **위 두 실측 문자열 중 첫 번째는 수요일에 정확히 이 검증에서 걸러진다**(원문대로면 닫혀 있는데 서버는 진료중이라고 한다). 요약은 새 사실을 만들지 않고 **서버가 이미 단정한 사실의 표현**일 뿐이며, 표현이 사실과 갈리면 표현을 버린다.

### D12-2. 문구 (확정)

상태 절(`진료중 ·`)을 배지에 넘긴다 — 감사 문구는 `진료중 · 24:00까지` 였지만, 바로 위 머리에 같은 말을 하는 배지가 있어 급할 때 훑는 눈이 어느 쪽을 봐야 할지 잃는다. 시안 §3 ④ 도 상태를 배지에 두고 줄에는 시각만 둔다.

| 갈래          | 문구                                  | 조건                                                    |
| ------------- | ------------------------------------- | ------------------------------------------------------- |
| `open24`      | `24시간 운영`                         | `open24 && openNow === true`. 마감 시각을 말하지 않는다 |
| `openUntil`   | `오늘 {time}까지`                     | `openNow === true` 이고 원문 판정이 일치                |
| `opensAt`     | `{오늘\|내일\|{요일}요일} {time}부터` | `openNow === false` 이고 다음 영업 시각을 정할 수 있다  |
| `closedToday` | `오늘은 쉬어요`                       | 앞으로 이레 안에 여는 날이 없다                         |
| (요약 없음)   | 원문 `line-clamp-2`                   | 위 넷 중 어느 것도 확정하지 못했다 (가드 폴백)          |
| (원문 없음)   | `진료시간이 등록돼 있지 않아요`       | `operatingHoursKnown === false`                         |

**이틀 뒤부터는 요일로 말한다** — "모레" 는 세어 보게 만들고 사흘 뒤부터는 쓸 말도 없다.

**갈래는 배타적이다.** 위 넷 중 하나가 서면 원문은 그리지 않고, 원문이 서면 요약 문구는 없다 — 근거는 D12-4.

### D12-3. 다음 영업일 계산 — 휴무를 읽지 못하면 약속하지 않는다

서버 `openNow` 는 **오늘의 개폐**를 검증해 주지만 **다음 영업 시각은 검증해 주지 않는다.** 남는 위험이 여기 하나뿐이라 따로 잠근다.

- 오늘 아직 열기 전이면 `오늘 {time}부터`.
- 아니면 **하루씩 이레까지 건너뛰며** 휴무가 아니고 원문에 시각이 있는 첫 날을 찾는다 — 토요일 밤 · 일요일 휴무면 다음은 **이틀 뒤 월요일**이다. "내일" 이라고 쓰면 닫힌 병원 앞에 서게 된다.
- `restDate` 는 **매주 반복되는** `X요일` 토큰만 읽는다. `연중무휴`·`무휴`·`없음`·`null`(전체 일치)은 휴무 없음.
- **서수·주기 수식어가 섞이면 요약 자체를 포기한다** (`parseRestDays` → `null`). `첫째`·`둘째`·`셋째`·`넷째`·`다섯째`·`번째`·`격주`·`매월`·`마지막`·`홀수`·`짝수`·`N주`·`주차` (`IRREGULAR_CYCLE`). `매주` 는 예외다 — 매주 반복이라 요일 하나로 정확히 옮겨진다.

  **이 모듈의 단위는 요일이다.** `weekly[3]` 은 "수요일" 이지 "몇 번째 수요일" 이 아니라, 달을 모르는 자료구조로 달 단위 주기를 표현할 수 없다. 눌러 담으면 **여는 날이 휴무로 승격**된다 — 실측: `월~금 09:00~18:00` · `둘째·넷째 수요일` · **2026-09-02(첫째 수요일, 여는 날) 08:00** · 서버 `openNow=false` → **`내일 09:00부터`**. 한 시간 뒤 여는 병원을 하루 뒤로 민다. `매월 셋째 토요일` 은 이틀 뒤까지 밀렸다.

  **`openNow` 가드(D12-1 불변식 3)가 이것을 잡지 못한다.** 08:00 시점엔 "휴무다" 와 "아니다" 두 읽기가 **둘 다 «지금 닫힘»** 이라 불리언이 일치한다 — 가드는 개/폐 한 비트만 검증한다 (D12-7).

- `무휴` 는 **전체 일치**다. 부분 문자열로 보면 `격주 무휴` 가 "휴무 없음"(그리고 운영시간 쪽에서는 **주 7일 영업**)으로 뒤집힌다 — 주기를 모를 때 안전한 실패는 "모르겠다" 이지 "쉬는 날 없음" 이 아니다.

### D12-4. 원문을 어디에 두는가 — **접기를 두지 않는다**

> **이 절은 구현 중에 한 번 뒤집혔다.** 처음에는 오늘 한 줄을 `<summary>` 로 만들고 원문을 `<details>` 안에 뒀다 (근거: _"요약이 틀렸을 때 확인할 곳이 있어야 한다"_). 사용자 결정으로 걷었다 — 아래가 그 근거다. **다시 접자는 제안이 나오면 이 절을 먼저 읽는다.**

**접을 것이 원문 한 필드뿐이라 접기가 성립하지 않는다.**

이 화면이 서버에서 받는 진료시간 데이터는 `operatingHours` **문자열 하나**다 (`NearbyFacilityItem`). 오늘 한 줄은 바로 그 한 필드를 읽어 만든 것이므로, **요약이 선 순간 원문에는 오늘에 대해 더 말할 것이 남아 있지 않다.** 펼쳐서 나오는 것은 같은 데이터의 다른 표기일 뿐이고, **접기 전과 후의 정보량이 같으면 그것은 접기가 아니라 같은 사실을 두 번 두는 것**이다.

"요약이 틀렸을 때의 확인처" 라는 근거도 이 화면에서는 필요가 없다 — 요약이 미심쩍은 경우는 **애초에 요약이 서지 않는 경우**이고(D12-1 불변식 2·3), 그때는 아래 둘째 갈래로 떨어져 원문이 통째로 선다. 즉 **원문이 필요한 상황에서는 원문이 이미 화면에 있다.**

그래서 `FacilityHours` 는 D12-2 표의 세 갈래로만 남는다.

1. 원문 없음 → `진료시간이 등록돼 있지 않아요`
2. 요약 실패(가드 폴백) → **원문 그대로** `line-clamp-2` — 이 갈래는 불변식의 몸통이라 지우지 않는다
3. 요약 성공 → **오늘 한 줄만.** 원문도, 펼치기도, 손잡이도 없다

부수 효과 둘.

- **`min-h-11` 손잡이가 사라져 행이 짧아진다.** #598 이 `전체 시간표` 버튼을 걷은 이유(_"44px 터치 영역이 행마다 한 줄을 더 먹었다"_)가 여기서 한 번 더 관철된다.
- **목록 행과 지도 패널의 진료시간 렌더가 같아졌다** (아래 D12-5).

바꾸지 않는 것.

- **휴무는 여전히 자기 줄이다** (#598). `매주 수요일 휴무` 는 오늘의 사실이 아니라 **다음 방문의 사실**이라 오늘 줄에 섞지 않는다. 원문과 달리 요약이 흡수하지 못하는 정보라 접기 논리의 대상도 아니다.
- **전화·길찾기 버튼(40px×2, 8px 간격)은 그대로다** — 이 화면에서 가장 잘 된 요소다 (감사 E-4).

### D12-5. 목록 행과 지도 패널이 같은 렌더다

한때 이 둘이 갈려 있었다. `FacilityRowContent` 는 호출부가 **선택 버튼으로 감싸는데**(`emergency-map-panel.tsx`) `<summary>` 는 interactive content 라 `<button>` 안에 넣을 수 없어(`<a>` 를 넣지 못하는 것과 같은 제약, `facility-row.tsx` 머리주석) 그 갈래만 `collapsible={false}` 로 따로 그렸다.

**D12-4 가 접기를 걷으면서 그 제약 자체가 사라졌다.** `collapsible` prop 과 분기를 함께 걷었고, 두 표면은 이제 같은 세 갈래를 탄다 — 갈라 둘 이유가 없으면 갈라 두지 않는다.

### D12-6. 시각의 출처

`summarizeTodayHours(facility, now)` 는 `now.getDay()` · `getHours()` 로 **기기의 현지 시각**을 읽는다 (사용자는 제주에 있다). `FacilityRow` · `FacilityRowContent` 가 `now` 를 선택 prop 으로 받고 기본값이 `new Date()` 라, 소비처는 아무것도 넘기지 않고 **테스트만 시각을 고정한다.**

화면이 열린 채 자정을 넘겨도 이 줄은 갱신되지 않는다 — 그때는 서버 `openNow` 도 같이 낡아 있고, 요약은 그 값과 어긋나는 순간 원문으로 떨어진다 (D12-1 불변식 3). 타이머를 두지 않는 이유다.

### D12-7. 가드가 막지 못하는 것 — **개/폐 한 비트만 검증한다**

D12-1 불변식 3 은 서버 `openNow` 와 우리 읽기의 **불리언**만 맞춰 본다. 그래서 **두 읽기가 같은 개/폐를 내놓으면서 시각만 다른 경우**는 그대로 통과한다. 알려진 잔여 위험 둘.

1. **닫혔을 때의 다음 영업 시각.** 서버가 검증해 주지 않는다 → 휴무 문구를 읽지 못하거나 달 단위·격주 주기면 아예 말하지 않는다 (D12-3).
2. **물려받은 시각의 마감.** 기각 근거 원문(`월~화, 목~금,토 09:30~20:00, …`)은 **월요일 마감을 명시한 적이 없고**, 뒤에서 앞으로 물려받는 규칙(D12-1)이 토요일 값을 빌려온다. 월요일 15:00 · `openNow=true` 면 양쪽 다 "열림" 이라 가드를 통과해 `오늘 20:00까지` 가 선다. 통상 독법상 타당한 추론이지만 **검증된 사실은 아니다.**

**2번은 감수한다.** 물려받기를 막으면 dev 에서 흔한 그 서식이 통째로 요약을 못 받고, 폴백이 같은 원문이라 사용자가 잃는 것도 없다. 여기 적어 두는 것은 _"가드가 전부를 막는다"_ 로 읽히지 않게 하기 위해서다 — 시각까지 검증하려면 서버가 `todayOpenTo` 를 줘야 한다 (D15).

## D14. 미결 사항 (#654)

- **D14-1. 요약이 서는 비율을 dev 실물로 재지 않았다.** 로컬 BE 가 뜨지 않아 mock 4건으로만 확인했다. `parseWeeklyHours` 가 실제 135곳 중 몇 곳을 읽는지 재서, 너무 낮으면 문법을 넓히고 너무 높으면 검증이 헐거운지 본다. **넓히기 전에 D12-1 불변식 3(서버 대조)을 먼저 확인한다.**
- **D14-2. `법정공휴일` 조각을 건너뛴다.** 오늘이 공휴일인지 FE 가 알 수 없어서다. 공휴일 당일에는 평일 시각을 말하게 되는데, 서버 `openNow` 가 같은 데이터를 쓰면 대조에서 걸리지 않는다. 공휴일 달력을 FE 에 두지 않는 대신 **BE 가 `todayHours` 를 계산해 주는 쪽**이 정답이다 (D15).
- **D14-3. 기본 ON 이 감추는 35곳을 화면이 말하지 않는다.** 카드 부제가 `제주 135곳 · 지금 진료중 100곳` 으로 전체를 계속 말하지만, "지금 100곳만 보고 있다" 를 요약 줄이 따로 말할지는 정하지 않았다. 줄을 하나 더 쓰는 판단이라 실사용 관찰 뒤로 미룬다.

## D15. BE 후속 요청 (#654)

- **오늘 기준 진료 시각을 서버가 계산해 준다** (`todayOpenFrom` · `todayOpenTo` · `nextOpenAt`). `openNow` 를 이미 계산하고 있으므로 같은 자리에서 나온다. FE 파싱은 그때 걷는다 — 공휴일(D14-2)과 다음 영업일(D12-3)은 FE 가 원리적으로 맞힐 수 없는 값이다.
- **`open24` 가 «확인됨» 인지 «해당 없음» 인지 가르는 값**이 있으면 D11-6 의 세 갈래 문구를 두 갈래로 줄일 수 있다. 지금은 `24시간 1` 의 `1` 이 "확인된 곳" 이라는 사실을 문장으로만 말한다.
