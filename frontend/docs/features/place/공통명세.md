# 장소 탐색 공통 명세

> 작성일: 2026-08-26
> 관련 백엔드 서비스: `tour-service` (place 컨텍스트)
> **계약 확인 근거**: 백엔드 소스 실측 — `PlaceWebController`, `PlaceItem`, `PlaceDetailResponse`,
> `ContentType`, `PetAllowanceType`. **로컬 Swagger 미기동 상태라 실호출 확인은 하지 못했다.**
> 백엔드 기동 후 `/fe-api-check` 로 재검증한다.

## S0. 개요

- **한 줄 정의**: 반려견과 갈 수 있는 제주 장소를 조건으로 찾아본다.
- **사용자가 달성하려는 것**: 반려견 동반 가능 여부와 장소 종류로 후보를 좁혀 상세로 진입한다.
- **범위에 포함**: 목록 조회, 필터, 무한 스크롤, 카드 표시, 상세 진입
- **범위에서 제외**:
  - 지도 뷰 — 별도 작업 (`external-api-guide.md`)
  - 상세 화면 — 별도 명세
  - 정렬 — **백엔드에 정렬 파라미터가 없다**
  - 즐겨찾기 / 여행 적합도 — 백엔드 미착수 (`screen-inventory.md` §6)

### 장소 찾기 — 보기 전환과 필터 (2026-09-08 개편)

| 항목                | 규칙                                                                                                                                                                                                                       |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본 보기           | **지도** (`PLACES_DEFAULT_VIEW`). `/places` = 지도, `/places?view=list` = 목록. 긴급 시설은 그대로 목록이 기본이다                                                                                                         |
| 보기 전환 버튼 위치 | 두 보기가 **같은 좌표**다 — `px-4 md:px-10` · `pt-5 lg:pt-6`. 지도에서는 그 값을 `absolute top-5 right-4 md:right-10 lg:top-6` 으로 재현한다                                                                               |
| 지도 필터           | **두 줄이다.** 1행 = 유형 축 가로 스크롤러 + `ScrollRail`(fade 마스크 + 원형 화살표), 2행 = `반려견 동반 가능만`·`지역`·`더보기`. 한 줄이던 때는 400 폭에서 유형이 세 개만 보이고 뒤쪽(쇼핑·여행코스)에 닿을 방법이 없었다 |
| 동반 축 위치        | **2행 맨 왼쪽 상시 토글**이다 (`ALLOWED` 한 갈래). 목록 칩 줄과 **같은 자리·같은 모양**이라 두 보기에서 한 번만 배운다. `더보기` 시트에서는 뺐다 — 같은 필터를 두 곳에서 만지면 어느 쪽이 참인지 흐려진다                  |
| "지도에 보이는 N곳" | **제목이 아니라 캡션**이다. 필터 줄 아래 한 줄로 내렸다. 지도가 조회 자리에서 벗어난 동안에는 `목록 N곳` 으로 주장을 뺀다 (`lib/map/visible-count.ts`)                                                                     |
| 패널 접기·펼치기    | 접기는 패널 **오른쪽 밖으로 튀어나온 북마크 탭**(24×44)이다. 높이는 닫혔을 때 펼치기 버튼이 서는 자리와 같다. 패널의 오른쪽 위 모서리는 `rounded-tr-none` — 둥근 모서리에 탭을 붙이면 곡선만큼 지도가 초승달로 비친다      |
| 현재 위치 버튼      | **제주 안일 때만** 렌더한다 (`getCurrentPosition()` → `kind === 'granted'`). 보기 전환 토글 바로 아래에 세로로 붙는다                                                                                                      |
| 목록 페이지네이션   | **무한 스크롤.** 커서는 그대로고 "더 보기" 버튼만 없앴다 (`InfiniteScrollSentinel`)                                                                                                                                        |
| 카드 클릭           | 그 핀으로 **부드럽게 확대 + 이동**한다 (`SELECTED_PLACE_MAP_LEVEL` = 5, 폭 약 5km). 이미 그보다 가까우면 확대하지 않고 이동만 한다                                                                                         |
| 패널 여백           | 상단 24(보기 전환 토글과 같은 높이) · 하단 **32**. 카카오 축척·로고 막대가 지도 왼쪽 아래 20px 를 쓰므로 16 이면 그 위에 바로 얹힌다 (실측: 막대가 바닥 0~19px)                                                            |
| 지도 이동 시 재검색 | **자동으로 하지 않는다.** 팬·줌·장소 선택은 `이 지역에서 재검색` 버튼을 띄울 뿐이고, 조회는 누를 때 한 번 나간다 (#396 을 이 화면에도 들였다)                                                                              |
| 필터 조작과 `view`  | 필터·초기화는 **`view` 를 유지한다** (`placeFilterHref` → `viewModeHref`). 조건만 새로 직렬화하면 `?view=list` 가 떨어져 **목록에서 필터를 만진 사람이 지도로 튄다** — 기본 보기가 지도라서 생기는 함정이다                |

### 묶음 마커 — 규격의 정본은 긴급 세부명세다 ([#671](https://github.com/8llow8llowMe/hondigagae/issues/671) D-4)

**`/places` 의 지도는 `/emergency` 와 같은 컴포넌트를 쓴다.** `place-map-view.tsx` 와
`place-mini-map.tsx` 가 둘 다 `features/map/map-canvas.tsx` 의 `MapCanvas` 를 `dynamic`
으로 불러온다 — 긴급 시설 지도와 **같은 하나**다.

그래서 **묶음(cluster) 마커 규격이 바뀌면 이 화면도 함께 바뀐다.** 핀이 가까이 모이면
`clusterByGrid` 가 묶어 숫자 원 하나로 세우는 동작이 `/places` 에도 그대로 있다.

**규격을 여기에 옮겨 적지 않는다.** 정본은
[`긴급시설-목록우선-세부명세.md`](../emergency/긴급시설-목록우선-세부명세.md) **D10**
(원 32px · 히트박스 44 · 접는 상한 · 겹침 측정)이고, 복사하면 둘이 갈린다. 원형 마커의
표면 예외(테두리 토큰 · `letter-spacing` · `inset`)는 `DESIGN.md` §0-4 다.

> **묶는 규칙을 바꾸는 작업은 이 화면까지 검증한다.** `cellSizeFor` 를 손대면 `/emergency`
> 와 `/places` 가 동시에 바뀐다 (D10-5 · #671 D-3). 일정 동선 지도는 예외다 — `ordered`
> 모드는 `cellSize` 에 `0` 을 넘겨 **묶지 않는다.**

### 이름·주소 검색 — 지도 보기에도 둔다 ([#596](https://github.com/8llow8llowMe/hondigagae/issues/596))

[#431](https://github.com/8llow8llowMe/hondigagae/issues/431) 은 검색을 **목록 갈래 본문
열에만** 두기로 했다. 근거는 _"지도 갈래는 필터 레일도 칩도 없으니 검색만 예외로 두면
지도 위에 도구가 하나만 떠 규칙이 갈린다"_ 였는데, **그 전제가 그때 이미 참이 아니었다** —
지도에는 `PlaceMapFilterBar` 가 패널 머리와 시트 툴바 양쪽에 있다.

그리고 더 큰 구멍이 남았다: **지도에서 검색어는 보이지 않는 필터다.** 칩은 자기 축만
상태를 보여주고 캡션은 개수뿐이라, `?keyword=` 를 달고 넘어온 사용자는 목록이 왜 줄었는지
알 수 없다. `초기화` 는 전량 리셋이라 검색어만 푸는 경로도 되지 못한다.
`/emergency` 가 [#584](https://github.com/8llow8llowMe/hondigagae/issues/584) 에서 같은
판단으로 먼저 뒤집었고, 자리·`compact` 기준·폭 실측을 그쪽이 정본으로 갖는다
(`docs/features/emergency/공통명세.md` E3-0).

| 갈래             | 자리                                     | 모양                           |
| ---------------- | ---------------------------------------- | ------------------------------ |
| 목록             | 본문 열 맨 위, 카드 **밖** (#431 · #531) | 글자 `검색` 버튼               |
| 지도 · 1024 미만 | 지도 위 오버레이, **보기 토글 왼쪽**     | 아이콘 버튼 · 짧은 placeholder |
| 지도 · 1024 이상 | 좌측 400 패널 **맨 위**, 필터바 위       | 글자 `검색` 버튼               |
| 지도 SDK 폴백    | 안내 줄 아래                             | 글자 `검색` 버튼               |

**폭 실측 (2026-09-14 · `localhost:5174` · 카카오 SDK 정상)** — `/emergency` 와 같은 값이다.

| 자리           |                                                                 안쪽 폭 |
| -------------- | ----------------------------------------------------------------------: |
| 좌측 패널 툴바 | 374 (목록 갈래 모바일 검색 343 보다 넓다 — `compact` 를 쓰지 않는 이유) |
| 오버레이 375   |                     입력 193 · 아이콘 버튼 44 · 토글 90, 셋이 같은 윗변 |
| 오버레이 768   |       폼 448(`max-w-md` 상한) · 입력 396. 상한이 없으면 538 로 벌어진다 |

**`searchable` 은 화면이 켠다 — 기본은 끔이다.** 담기 화면(#370)은 `PlaceMapView` 를 같이
쓰지만 **목록 갈래에도 검색이 없어서**, 지도에만 켜면 같은 화면의 두 보기가 다른 도구를
갖는다. 그 화면에 검색을 들일지는 별개 판단이라 이 이슈에서 결정하지 않는다.

**`/emergency` 와 다른 점 하나: 여기는 검색어를 서버로 보낸다** (`keyword`, #421). 그래서
지도에서 제출하면 `router.replace` → RSC 재프리페치로 **서버 재조회**가 돈다 (실측: 1440
에서 `지도에 보이는 19곳` → `14곳`). `/emergency` 는 받아 둔 목록을 화면에서 좁힌다.

**유형 축의 표시 순서를 계약 순서와 갈라 뒀다.** `CONTENT_TYPE_CODES`(`types/place.ts`)는
백엔드 enum 선언 순서이고, 화면 순서는 `CONTENT_TYPE_FILTER_ORDER`(`features/place/filter-labels.ts`)다
— 갈 곳 → 먹을 곳 → 잘 곳. 지도 필터 줄은 폭이 400 이라 **앞 세 개만 스크롤 없이 보인다.**
레일·시트도 같은 순서를 쓴다. enum 값이 추가되면 순서 배열도 채워야 하고, 잊으면 화면에서
조용히 빠지므로 `filter-labels.test.ts` 가 잡는다.

**지도 첫 화면**은 확대 단계 9 이고 중심은 계산값이다 — 자세한 근거는
`docs/external-api-guide.md` §1 과 `lib/geo/coord.ts` 머리주석.

**카드 클릭의 확대 단계를 5 보다 내리지 않는다.** 이 규칙은 목록이 지금 보이는 영역을
세던 시절의 것이다 — 4(폭 2.6km)로 내리면 카드 하나를 누른 순간 목록이 한두 건으로 남아
**다음 카드를 이어 누를 수 없었다.** 아래 재검색 버튼 개편으로 목록이 `searchedBounds` 를
세게 되어 그 증상 자체는 사라졌지만, 확대 단계는 **지도에서 무엇을 읽을 수 있는가**로도
정해지는 값이라 근거를 하나 잃었다고 내리지 않는다.

**유형 줄의 "더 있다" 신호는 홈과 같은 `ScrollRail` 을 쓴다** (`components/scroll-rail.tsx`).
`ChipGroup` **자신이 스크롤러**여야 한다 — 바깥 div 를 스크롤러로 삼으면 넘치는 방향의
끝 여백이 무시돼 마지막 칩이 잘린다. 그래서 `ChipGroup` 이 `ref` 와 `onScroll` 을 받는다.

**"지도 이동 시 재검색" 체크박스를 걷었다.** #240 이 넣은 것인데, 켜고 끄는 것이 바꾸는
것은 **데이터 출처**(`GET /places/nearby` ↔ 목록 캐시)여서 화면만 보고는 무엇이 달라지는지
알 수 없었다. 끈 상태에서도 영역 필터는 계속 돌아 화면 밖 장소가 빠지니 사용자에게는
"아무 일도 안 하는 체크박스" 로 보였다. 지도를 옮기는 것이 곧 "여기를 보여 줘" 다.
**대신 목록을 고정할 방법이 없어졌다** — 지도를 살짝 건드리면 목록이 바뀐다. 그것이 문제로
드러나면 체크박스가 아니라 "이 지역에서 다시 찾기" 버튼(사용자가 명시적으로 누르는 형태)으로
돌아오는 것이 맞다.

**그 문제가 드러나 버튼으로 돌아왔다.** 위 단락이 예고한 그대로다 — 자동 재조회의 전제
("지도를 옮기는 것이 곧 '여기를 보여 줘' 다")가 **한 곳을 골라 확대하는 조작**에서 깨졌다.
확대는 사용자가 다른 지역을 보겠다고 한 것이 아니라 우리가 그 핀으로 옮겨 준 결과인데,
그때마다 좁아진 프레임으로 목록이 다시 조회돼 방금 보던 결과가 사라졌다. 화면을 조금
옮기는 것만으로도 같은 일이 났다.

이제 `/emergency` 와 **같은 규칙**이다 (#396) — 문구·모양·자리까지 같은 버튼을 쓴다
(`messages.map.researchHere` · `.map-research-offset`). 두 화면의 차이는 둘뿐이다.

|                          | `/places`                                                          | `/emergency`                                          |
| ------------------------ | ------------------------------------------------------------------ | ----------------------------------------------------- |
| 조회 반경                | 화면에서 역산 (`boundsRadiusMeters`)                               | URL 이 소유하는 반경 칩                               |
| 확대·축소만으로 권하는가 | **권한다** (`originScreenRadius`) — 축소가 곧 "더 넓게 찾아 줘" 다 | 권하지 않는다 — 눌러도 반경이 안 바뀌어 거짓말이 된다 |

판정은 두 화면이 같은 순수 함수를 쓴다 (`lib/map/research-offer.ts`, 임계값은 반경의 30%).

**목록이 세는 영역도 `bounds` 가 아니라 `searchedBounds` 다.** 재조회만 막고 영역 필터를
`bounds` 에 두면 "목록이 흔들린다" 가 그대로 남는다 — 팬·줌·선택이 그대로 목록을 줄인다.
조회 자리가 곧 목록의 자리다. `/emergency` 가 선택 순간에만 `frozenBounds` 로 얼려 두는
일을, 이 화면은 그 하나로 항상 한다.

**확대와 이동의 순서가 정해져 있다** — `anchor` 로 핀을 화면에 붙인 채 확대하고, 그다음
중심을 맞춘다. 반대 순서(이동 → 확대)는 이동이 실행되지 않았을 때 **옛 중심을 확대**해서
고른 장소가 화면에서 사라진다 (dev 실측: 목록이 "지도에 보이는 0곳" 이 됐다).
`prefers-reduced-motion` 이면 애니메이션 없이 즉시 옮긴다 — 지도의 이동·확대는 SDK 가
JS 로 그리는 것이라 `app/globals.css` 의 전역 규칙이 닿지 않는다.

**모두 단일값이다. 배열 파라미터가 없다.**

### enum 값

- `contentType`: `TOURIST_SPOT`(12) `CULTURE`(14) `FESTIVAL`(15) `COURSE`(25) `LEPORTS`(28) `LODGING`(32) `SHOPPING`(38) `RESTAURANT`(39)
- `petAllowanceType`: `ALLOWED` `PARTIALLY_ALLOWED` `NOT_ALLOWED` `UNKNOWN`

> **미결(BE 확인 필요)**: Spring 기본 바인딩은 `name()` 기준이므로 `?contentType=TOURIST_SPOT` 을 전제했다.
> 코드값(`"12"`) 바인딩용 컨버터가 있는지 Swagger 로 확인한다.

## S3. 데이터 모델

`dataBody` 기준. 공통 래퍼는 `docs/api-integration-guide.md` §2 참조.

```ts
type SliceResponse<PlaceItem> = { contents: PlaceItem[]; hasNext: boolean }

type PlaceItem = {
  placeId: string // 문자열이다. 백엔드 내부는 long(Snowflake 크기)
  contentType: { code: string; name: string; description?: string | null }
  title: string
  addr1: string | null
  sigunguCode: string | null
  lat: number | null // 위도. 백엔드가 Double 로 정규화
  lng: number | null // 경도
  firstImage: string | null // TourAPI 외부 원본 URL
  firstImage2: string | null
  petAllowanceType: { code: string; name: string; description?: string | null }
  tel: string | null
}
```

| 항목          | 내용                                                                        |
| ------------- | --------------------------------------------------------------------------- |
| nullable 필드 | `addr1` `sigunguCode` `lat` `lng` `firstImage` `firstImage2` `tel`          |
| 문자열 ID     | `placeId` — **`number` 로 타이핑 금지**                                     |
| enum metadata | `contentType` `petAllowanceType` — **서버 `name` 을 그대로 렌더한다**       |
| 단위          | 좌표는 도(degree). 거리 계산은 이 화면 범위 밖                              |
| 외부 이미지   | `firstImage` 는 TourAPI 원본 URL → `next.config` `remotePatterns` 등록 필요 |

## S4. 상태 / 에러

| 상태        | 조건                   | 화면                           | 문구 (확정)                                                                   |
| ----------- | ---------------------- | ------------------------------ | ----------------------------------------------------------------------------- |
| loading     | 최초 진입 / 필터 변경  | `Skeleton` 카드 6개            | —                                                                             |
| success     | `contents.length > 0`  | 카드 목록                      | —                                                                             |
| empty       | `200` + `contents` 0건 | `EmptyState` (**재시도 없음**) | "조건에 맞는 장소가 없습니다." / "필터를 바꿔 다시 찾아보세요."               |
| 데이터 부재 | `404`                  | `EmptyState` (**재시도 없음**) | 서버 `resultMessage` 그대로 + 위 안내                                         |
| 일시 장애   | `5xx` · 무응답         | `ErrorState` (**재시도 있음**) | "장소를 불러오지 못했습니다." / "잠시 후 다시 시도해 주세요." / `[다시 시도]` |
| 입력 오류   | `400` (`size` 범위 등) | `ErrorState`                   | "요청 조건이 올바르지 않습니다." / `[필터 초기화]`                            |

**nullable 처리 (에러가 아니라 숨김)**

| 필드 없음    | 처리                                             |
| ------------ | ------------------------------------------------ |
| `firstImage` | 이미지 자리에 플레이스홀더. 카드 레이아웃은 유지 |
| `addr1`      | 주소 줄 숨김                                     |
| `tel`        | 전화 줄 숨김                                     |
| `lat`/`lng`  | 목록에는 영향 없음 (지도 뷰에서 마커 제외)       |
