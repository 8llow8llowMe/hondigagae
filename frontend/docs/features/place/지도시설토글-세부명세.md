# 장소 찾기 지도 — 병원 · 약국 함께 보기 토글 세부명세

> 상태: **명세** (#1286, 2026-10-09)

선행: 장소 핀 개편 `지도핀-세부명세.md`(#1280) · 미리보기 `지도미리보기-재설계-세부명세.md`(#1227/#1233) ·
도킹 `지도패널-도킹-세부명세.md`(#1232) · 긴급 시설 `../emergency/긴급시설-목록우선-세부명세.md`(D10 묶음 원).
디자인 정본 `DESIGN.md` §0-4 · 상태 소유 `architecture-guide.md` §9 · §10.

## D0. 무엇을 고치는가

장소 찾기 지도(`/places`, `view=map`)에는 **장소만** 있다.

1. **"이 근처에 동물병원이 있나" 를 같은 지도에서 볼 수 없다.** 반려견 여행 중 실제로 묻는 질문인데, 지금은
   `/emergency` 로 화면을 옮겨야 하고 그 사이 필터 · 지도 위치 · 고른 장소가 끊긴다.
2. **`/emergency` 시설 핀은 예전 흰 이름표(`.map-pin`)다.** #1280 이 장소 핀을 원 + 아이콘으로 바꿀 때 범위 밖으로
   남겨 뒀다(`지도핀-세부명세.md` D3 "긴급 시설 핀 — 그대로").

이 명세는 **지도 핀 층만 더한다.** 목록 패널 · 시트 · 개수 · 정렬 · 빈 상태는 바뀌지 않는다.

## D2. 핀 · 묶음 모양

### D2-1. 시설 핀 (사각)

| 상태                                    | 사각                                                                                     | 이름                                                          |
| --------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 병원 기본                               | **24 × 24** · 모서리 `--radius-sm`(4) · `--brand-600` 채움 · 흰 테두리 2 · `--shadow-md` | level ≤ 6 에서만 선다 (장소 원과 같은 규칙)                   |
| 약국 기본                               | 위와 같고 채움만 `--fg-subtle` (`.map-pin-dot-muted` 그대로)                             | 글자 `--fg-muted`                                             |
| 이름 (level ≤ 6 · 호버 · 포커스 · 선택) | 그대로                                                                                   | 장소 원과 **같은 알약** — 사각 오른쪽 4 · 12px/600 · 최대 160 |
| 선택 (병원 · 약국 공통)                 | **32 × 32** · `--fg` 채움                                                                | 검은 알약 · 13px · 최대 220 — 장소 원과 같다                  |

- **치수 근거.** 사각은 같은 폭의 원보다 면적이 27% 크다. 24² = 576 은 원 26(531)과, 32² = 1024 는 고른 원
  34(908)와 면적이 비슷하다 — 같은 무게로 읽히고 모양만 갈린다.
- **모서리 4.** `--radius-md`(8)는 24 에서 변의 1/3 이라 14px 거리에서 원과 헷갈린다. 모양으로 가르는 것이
  이 결정의 전부라 모서리를 작게 둔다. 토큰 밖 값을 만들지 않는다.
- **원 핀과 같은 규칙** — 중심이 좌표(`yAnchor 0.5`) · 이름 알약은 상자 밖 `position: absolute` · 안 설 때는
  시각적으로만 숨김 · 버튼 접근 이름 = 시설명.
- **누르는 자리 44** — `::before` 가 패딩 상자에서 넓힌다(§0-4 와 같은 계산).
  - 기본: 패딩 상자 24 − 4 = 20 → `inset: -12px` (20 + 12 × 2 = 44)
  - 선택: 패딩 상자 32 − 4 = 28 → `inset: -8px` (28 + 8 × 2 = 44)
- **아이콘** 흰색(`--fg-inverse`) 14px · 선택 18px — 원 핀과 같다.

### D2-2. 아이콘 둘 (`lib/map/pin-icons.ts`)

`MapPinIcon` 에 키 둘을 더한다. 결은 기존과 같다(24 격자 · `currentColor`).

| 키      | 뜻   | 그림                                                                                                            |
| ------- | ---- | --------------------------------------------------------------------------------------------------------------- |
| `cross` | 병원 | **채운 십자** — 선 1.5 십자는 14px 에서 0.9px 이라 사라진다. `fill="currentColor" stroke="none"` 인 굵은 더하기 |
| `pill`  | 약국 | 45° 기운 캡슐 + 가운데 가름선 (선 1.5)                                                                          |

- 어느 시설에 어느 키인지는 **긴급 도메인이 정한다** — `lib/emergency/facility-pin.ts`(신규, D7-1).
  `facilityType.code` 로 고른다(`ANIMAL_HOSPITAL` → `cross` · `ANIMAL_PHARMACY` → `pill` · 모르는 코드 → `pin`).
  한국어 `name` 으로 고르지 않는다 — `lib/place/pin-icon.ts` 와 같은 규칙.
- `pin-icons.test.ts` 의 개수 단언(10)을 12 로 올린다.

### D2-3. 시설 묶음 (사각) — 권고

| 항목        | 장소 묶음 (그대로)                  | 시설 묶음 (신규)                               |
| ----------- | ----------------------------------- | ---------------------------------------------- |
| 모양        | 원 32 · `--radius-full`             | **사각 30** · `--radius-sm`(4)                 |
| 테두리      | `--brand-600` 2                     | 같다                                           |
| 면          | `--bg`                              | 같다                                           |
| 숫자        | `--brand-700` 12px/700 · `99+` 상한 | 같다                                           |
| 겹친 모양   | `::after` 원 3px 오른쪽 위          | `::after` **사각** 3px 오른쪽 위 (같은 모서리) |
| 누르는 자리 | 패딩 28 → `inset: -8px`             | 패딩 26 → `inset: -9px` (26 + 9 × 2 = 44)      |
| 접근 이름   | `이 지역 {n}곳`                     | **`이 지역 병원·약국 {n}곳`**                  |

- **왜 모양까지 가르나.** 숫자만 다른 같은 원 둘이 나란히 서면 `12` 가 장소 12곳인지 병원 12곳인지 화면만 보고
  모른다 — §0-4 가 #671 C-4 에서 바로잡은 "정보를 `aria-label` 로만 옮긴" 상태로 되돌아간다. 사각 묶음은 사각 핀이
  접힌 것이라 **핀과 묶음이 같은 모양 문법**을 쓴다.
- **30 인 이유.** 사각 30(900)은 원 32(804)와 면적이 비슷하다. 글자 예산은 원처럼 현(弦)으로 잘리지 않고 패딩 상자 폭
  26 전체다 — 세 글자 `99+`(22.1px)가 3.9px 여유로 들어간다.
- `/emergency` 지도는 시설뿐이라 묶음도 **사각이 된다** — D8-2 결정.

## D3. 데이터 흐름 · 상태

### D3-1. 조회 범위 — 고정 중심 · 50km (권고)

`GET /emergencies/facilities?lat=33.4996213&lng=126.5311884&radius=50000&size=250`

| 항목      | 값                                                  | 근거                                                                     |
| --------- | --------------------------------------------------- | ------------------------------------------------------------------------ |
| 중심      | `JEJU_QUERY_CENTER` (`lib/geo/current-position.ts`) | 조회 기준점 상수가 이미 있다. 지도 기준(`JEJU_MAP_ANCHOR`)을 쓰지 않는다 |
| 반경      | `MAX_RADIUS_METERS` = 50,000                        | 백엔드 `@Max(50000)`. 실측 최원거리 40,499m — 9.5km 여유                 |
| 개수      | `MAX_SIZE` = 250                                    | 백엔드 `@Max(250)`. 실측 213곳                                           |
| `type` 등 | 보내지 않는다                                       | 병원 · 약국 둘 다 그린다                                                 |

**지도 중심을 따르지 않는 이유.**

- 한 번 받으면 섬 전체가 끝난다 — 지도를 옮길 때마다 다시 부를 일이 없다. `/places` 가 지킨 "지도를 옮겼다고
  스스로 재조회하지 않는다"(#396)와 맞는다.
- 중심을 따르면 key 가 매번 갈려 캐시가 쌓이고, 경계 밖 시설이 나타났다 사라진다.

**거리를 쓰지 않는다.** `distanceMeters` 는 제주시청에서 잰 값이라 사용자와 무관하다 — 핀 캡션 `null` ·
요약 `showDistance={false}`. (`/emergency` 는 위치 기준이라 그대로 쓴다.)

**잘림.** `countsAreComplete(result)`(`facility-filters.ts`)가 `false` 면(`facilities.length < totalCount`)
받은 만큼만 그리고 D5 의 잘림 안내를 띄운다. 지금 213 < 250 이라 생기지 않는다 — 데이터가 늘었을 때의 보험이다.

**캐시.** `useNearbyFacilities` 의 key 와 옵션(`staleTime` 1분 · 실패 1회 재시도)을 그대로 쓴다. `openNow` 가
시각에 따라 바뀌어서 짧은 값이다(훅 머리주석).

### D3-2. 토글 상태 — 화면 안 상태 (권고)

`PlaceMapView` 안의 `useState<boolean>(false)`. **URL 에 싣지 않는다.**

| 상황                                             | 화면 안 상태                          | URL(`?facilities=true`)이었다면                                                         |
| ------------------------------------------------ | ------------------------------------- | --------------------------------------------------------------------------------------- |
| 필터 칩 · 검색 (`router.replace`)                | 유지 (같은 페이지, 다시 마운트 안 됨) | `placeFilterHref` 가 이 키를 실어야 한다 — 빠지면 칩마다 꺼진다(#372 와 같은 함정)      |
| 장소 미리보기 열기 · 닫기 (`pushState` · `back`) | 유지                                  | **어긋난다** — 미리보기 연 뒤 끄고 ✕ 로 닫으면 `back` 이 켜진 칸으로 돌아가 다시 켜진다 |
| 목록 보기 ↔ 지도 보기                            | 꺼진다                                | 목록은 시설이 없어 실을 곳이 없다 — 돌아오면 어차피 다시 조립해야 한다                  |
| 상세 갔다 뒤로                                   | 꺼진다                                | 유지                                                                                    |
| 새로고침 · 공유                                  | 꺼진다                                | 유지                                                                                    |
| SDK 실패 폴백(#1289, `fallbackListHref`)         | 무관 — 목록으로 옮겨지며 사라진다     | `fallbackListHref` 가 이 키도 지워야 한다                                               |

- **판단 질문(§10): "링크로 공유했을 때 같은 화면이 나와야 하는가?"** 시설 층은 결과 조건이 아니라 **보기 층**이다 —
  카메라 위치 · 재검색 여부 · 패널 접힘과 같은 수명이고, 그 셋도 URL 에 없다. 상세에서 돌아오면 지도 위치도 처음으로
  돌아가므로 토글만 남는 쪽이 오히려 어긋난다.
- **잃는 것:** 상세 → 뒤로, 새로고침에서 다시 켜야 한다. 한 번 누르면 되는 일이라 받아들인다.
- 필터 변경에서 `PlaceMapView` 가 다시 마운트되지 않는다는 전제는 **구현 때 실측**한다(D7-4). 다시 마운트되면 이
  권고를 다시 판단한다.

### D3-3. 선택 모델

`MapCanvas` 의 `selectedId` 하나로 장소와 시설을 함께 다룬다 — **동시에 하나만**이 구조로 지켜진다.

| 항목                   | 규칙                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------- |
| 시설 핀 id             | `facility:{facilityId}` (`facilityPinId`). 장소 id 는 숫자 문자열(`isPlaceId`)이라 겹치지 않는다          |
| 고른 장소              | 지금처럼 `?place=` (`usePlacePreview`)                                                                    |
| 고른 시설              | `useState<string \| null>` — `facilityId`(문자열, 숫자로 바꾸지 않는다)                                   |
| `MapCanvas` 에 넘길 값 | 시설이 골라져 있으면 `facilityPinId(id)`, 아니면 고른 장소 id                                             |
| `onSelect(id)`         | `readFacilityPinId(id)` 가 값을 주면 시설 갈래, 아니면 장소 갈래                                          |
| 시설을 고르면          | 장소 미리보기를 닫는다(`select(null)`) → 시설 id 를 놓는다 → 접힌 스택을 편다(`selectPlace` 와 같은 규칙) |
| 장소를 고르면          | 시설 선택을 비운다 → 지금 `selectPlace` 그대로                                                            |
| 토글을 끄면            | 시설 선택을 비운다 — 요약이 닫힌다                                                                        |
| 데이터가 바뀌면        | 요약은 최신 응답에서 id 로 찾는다(1분마다 `openNow` 갱신). 없으면 선택을 비운다                           |

- 카메라는 지금 장소와 같다 — `selectedLevel` = `SELECTED_PLACE_MAP_LEVEL`(5), `selectedOffset` 은 같은 미리보기
  자리를 재므로(D4-3) 요약에 덮이지 않는 곳으로 옮긴다.
- **포커스 되돌림 effect 를 고친다.** 지금은 장소 미리보기가 닫히고 포커스가 `body` 면 그 장소 행에 포커스를
  돌려준다(`place-map-view.tsx` `lastPreviewRef`). 장소 → 시설로 갈아탈 때도 미리보기가 닫히므로, **시설이 골라져
  있으면 건너뛴다** — 안 그러면 방금 연 시설 요약에서 포커스를 빼앗아 숨은 목록 행으로 보낸다.

### D3-4. 응답 (`dataBody`)

래퍼 판별은 `api-integration-guide.md` 를 따른다. 화면이 읽는 필드:

```ts
type NearbyFacilityResult = {
  facilities: NearbyFacilityItem[] // 가까운 순, 병원 · 약국 섞임
  totalCount: number // size 로 자르기 전 총계 — 잘림 판정
  radius: number
  open24Only: boolean
  providerName: string
}
type NearbyFacilityItem = {
  facilityId: string // Snowflake — 문자열. 숫자로 바꾸지 않는다
  facilityType: { code: 'ANIMAL_HOSPITAL' | 'ANIMAL_PHARMACY'; name: string; description: string }
  name: string
  addr: string
  lat: number
  lng: number
  tel: string | null // null = 등록된 번호 없음
  operatingHours: string | null // null = 확인 필요(휴무 아님)

```

  만들지 않는다. 핀 아이콘만 `code` 로 고른다.
- 타입은 `src/types/emergency.ts` 그대로 — 바꿀 것 없다.

### D4-2. 시설 핀을 누르면

- 그 시설을 고른다(D3-3) — 핀이 고른 사각(32 · 검은 채움 · 이름 알약)이 되고, 지도가 그 자리로 옮기며 level 5 까지 확대한다.

### D4-3. 시설 요약 — 미리보기 자리

## D5. 상태별 화면

| 상태              | 토글                                   | 지도                         | 토글 아래 안내 카드                                                 |
| ----------------- | -------------------------------------- | ---------------------------- | ------------------------------------------------------------------- |
| 꺼짐 (기본)       | `aria-pressed=false`                   | 장소만                       | 없음 · **요청 없음**                                                |
| 켬 · 불러오는 중  | `aria-pressed=true` · `aria-busy=true` | 장소만                       | 없음 — 숨은 알림만 `facilityLoading`                                |
| 켬 · 받음         | `aria-pressed=true`                    | 장소 + 시설 사각 · 각자 묶음 | 없음 — 숨은 알림 `facilityShown`                                    |
| 켬 · 잘림         | `aria-pressed=true`                    | 받은 만큼                    | `facilityTruncated` (닫기 없음 — 끄면 사라진다)                     |
| 켬 · 5xx · 무응답 | `aria-pressed=true` 유지               | 장소만                       | `facilityLoadFailed` + **`다시 시도`** (`refetch`)                  |
| 켬 · 4xx          | `aria-pressed=true` 유지               | 장소만                       | `resultMessage`(없으면 `facilityLoadFailed`) — **재시도 버튼 없음** |
| 다시 끔           | `aria-pressed=false`                   | 장소만 · 시설 선택 해제      | 사라진다                                                            |

- **오류를 토스트로 말하지 않는다**(`toast.tsx` 규칙) — 다시 시도할 자리가 남아야 한다. 판정은 `shouldOfferRetry(error)`
  (`lib/api/error.ts`). 훅이 이미 일시 장애를 1회 재시도한 뒤의 실패다.
- **안내 카드 자리:** 오른쪽 위 컨트롤 묶음 바로 아래, 오른쪽 정렬 · `max-w-xs` · `bg-bg` · `border-border` ·
  `rounded-lg` · `shadow-md` · `px-3 py-2` · `text-body-2`. 묶음이 `pointer-events-none` 이라 카드에 다시 켠다.
  모바일은 재검색 알약(`lg:hidden`)보다 **위**다.
- 실패해도 토글을 끄지 않는다 — 사용자의 뜻(켬)을 지우면 "눌렀는데 안 눌린" 버튼이 된다.
- 받은 0곳(서버가 빈 배열)은 실측상 생기지 않는다. 생기면 `facilityShown` 의 `{n}` = 0 으로 말한다.

## D6. 접근성

- 토글: `aria-pressed` · 접근 이름 고정 · 높이 44(모바일 44 × 44) · `focus-visible` 링은 `ViewToggle` 과 같다.
- 숨은 상태 알림 하나(`role="status"` · `aria-live="polite"` · `sr-only`)를 토글 옆에 늘 두고 글자만 바꾼다 — 나타났다
  사라지는 live region 은 읽히지 않는다. 실패 카드는 `role="alert"`.
- 시설 핀: `<button aria-pressed>` · 접근 이름 = 시설명(선택 시 캡션 없음 — 거리를 쓰지 않는다).
- 시설 묶음: 보이는 숫자를 담은 `이 지역 병원·약국 {n}곳` — WCAG 2.5.3(보이는 글자가 이름에 있다)은 `clusterMarkerText` 를
  통과시키는 기존 구조로 지킨다.
- 요약: `section aria-label="병원·약국 요약"` · `tabIndex={-1}`. **포커스를 잃었을 때만** 요약으로 데려온다(핀은 선택 때
  다시 그려져 포커스가 `body` 로 떨어진다) — 장소 미리보기의 "보이는 곳에 포커스가 있으면 빼앗지 않는다" 와 같은 규칙.
- 요약을 ✕ 로 닫으면 포커스를 **토글 버튼**으로 돌려준다 — 고른 핀은 다시 그려져 사라졌고, 시설은 목록 행이 없다.
- **대비** (`contrast.test.ts`):
  - 흰 십자 / `--brand-600` — 기존 원 핀과 같은 약 5.3:1
  - 흰 알약 / `--fg-subtle`(#878D96) — 약 3.3:1 (비텍스트 3:1)
  - 켬 토글 글자 `--fg-inverse` / `--fg`
- 색만으로 가르지 않는다: 장소 ↔ 시설은 모양(원 ↔ 사각), 병원 ↔ 약국은 아이콘(십자 ↔ 알약)이 가르고 채움 명도는 덧붙이는 신호다.

  층" 이라 축이 다르다. 아이콘 키로 사각을 추론하면 다음에 사각 아이콘이 하나 늘 때마다 그 표가 같이 늘어야 한다.
  `shape` 는 지도 층의 말(원 · 사각)이라 지도 컴포넌트가 시설을 모르는 채로 남는다(`component-guide.md` §9).
- **`shape: 'square'` 는 `icon` 이 있을 때만 뜻이 있다.** 아이콘 없는 핀(예전 이름표)은 `shape` 를 무시한다.
- **`features/place` → `features/emergency` 가져오기** (`facility-row` · `use-nearby-facilities`)는 `home-view` 가 이미 같은
  훅을 가져오는 선례를 따른다. 경계 규칙("feature 간 직접 임포트를 피한다")과의 관계는 D8-4.

### D7-5. 남는 위험

- **`/emergency` 이름이 멀리서 사라진다.** 지금은 이름표라 늘 서 있다. 원 핀 규칙(level ≤ 6)을 따르면 반경 10km 첫 화면에서는
  사각만 보인다. 목록 패널 · 시트가 늘 이름을 말하고, 핀을 누르면 이름이 선다 — 받아들인다. 실측에서 거슬리면 D8-2 와 함께 본다.
- **약국 사각 경계.** `--fg-subtle` 채움은 밝은 타일 위에서 3:1 언저리다(흰 테두리 2 · 그림자가 경계를 돕는다). 실측에서 묻히면
  채움을 `--fg-muted` 로 한 단 올린다 — 새 색은 만들지 않는다.
- **오버레이 수.** 켜면 핀이 최대 약 213개 늘고, 핀 effect 는 선택 · 줌마다 전부 다시 그린다. 섬 전체에서는 묶음이 덜어
  주지만 level 4 이하 제주시내는 수십 개가 된다. 실측에서 끊기면 후속으로 다룬다.
- **Tab 정류장.** 시설 핀도 버튼이라 키보드 사용자에게 정류장이 는다 — 장소 핀과 같은 구조라 이번에 새로 만드는 문제는 아니다.
- **모바일 컨트롤 기둥이 44 + 8 길어진다.** 시트 최대 단계 상한(`MAP_TOP_CONTROLS_INSET` 136)은 첫 줄만 비켜 가므로, 최대
  단계에서 토글 · `내 위치` 가 시트에 덮인다(지금 `내 위치` 와 같은 처지). 재검색 알약은 한 칸 아래로 내려간다.

## D8. 미결 사항

### D8-1. 시설 요약이 열린 채 뒤로가기 — **결정: A** (사용자 2026-10-09)

장소 미리보기는 `?place=` 를 push 해 **모바일 뒤로 제스처가 미리보기를 닫는다**. 시설 요약은 화면 안 상태라 **뒤로가 `/places` 를 떠난다.**

| 선택지                    | 좋은 점                               | 대가                                                                                    |
| ------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------- |
| A. 화면 안 상태 (이 명세) | 구현이 작다 · 토글 상태와 수명이 같다 | 모바일에서 요약 → 뒤로 = 화면 이탈. 장소 미리보기와 동작이 다르다                       |
| B. `?facility={id}` push  | 장소와 같은 뒤로 동작 · 새로고침 복원 | 링크에 시설이 있으면 층이 켜져야 한다 → 토글도 URL 로 가야 하고 D3-2 의 어긋남이 생긴다 |

**결정: A 로 내고 실측에서 판단.** B 는 토글 URL 화와 묶여 있어 범위가 두 배가 된다. 뒤로 제스처 이탈이 거슬리면 B 를 후속
이슈로 연다(`placePreviewHistoryAction` 을 그대로 쓸 수 있다).

### D8-2. `/emergency` 묶음도 사각으로 — **결정: A** (사용자 2026-10-09)

결정은 "`/emergency` 는 핀 모양만" 이었다. 그런데 묶음 모양을 **모양(`shape`)으로 고르면** 시설뿐인 `/emergency` 묶음도 사각이 된다.

| 선택지         | 대가                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| A. 사각 (추천) | 묶음 원 규격(D10)이 `/emergency` 에서 바뀐다 — 정본 D10 갱신            |
| B. 원 유지     | `MapCanvas` 에 "모양과 묶음 모양을 따로 고른다" 는 prop 이 하나 더 는다 |

**결정: A.** "사각 = 시설" 이 두 화면에서 같아야 `/places` 에서 배운 모양이 `/emergency` 에서도 통한다.

### D8-3. 요약에서 `/emergency` 로 가는 길

`주변 병원·약국 더 보기` → `/emergency?view=map` 같은 링크. 결정 2 가 "페이지 이동 없음" 이라 이번에는 **두지 않는다(추천)**.
요약만으로 전화 · 길찾기가 끝나고, 거리순 탐색이 필요하면 전역 헤더의 긴급 진입점(`EmergencyIcon`)이 있다.

### D8-4. 교차 feature 가져오기

`features/place` 가 `features/emergency` 의 `facility-row` · `use-nearby-facilities` 를 가져온다.

| 선택지                                                        | 대가                                                          |
