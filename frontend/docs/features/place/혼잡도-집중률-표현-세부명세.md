# 혼잡도 집중률 표현 세부 명세

> 진단 근거: [`docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md`](../../superpowers/specs/2026-09-15-ui-ux-audit-design.md) **D-3 (P1)**, 시안 §2 ④.
> 화면 정본은 [`장소상세-세부명세.md`](./장소상세-세부명세.md) **D1-2**. 이 문서는 **집중률 숫자의 표현**만 바꾼다.

## D0. 화면 정의

- **경로**: `/places/[placeId]` 혼잡도 카드 (`PlaceCongestionPanel`). 인증 불필요.
- **이슈**: #651 · 브랜치 `feature/fe/651-congestion-rate-expression`

### 현상 (2026-09-15 실측, 390×844, dev API, `/places/126434` 수월봉, 30일)

```
가장 덜 붐비는 날   9월 21일 (월)        [보통]
집중률 57.77
```

`57.77` 이 높은 값인지 낮은 값인지 **비교 기준이 화면에 없다.** 소수 둘째 자리는 예측값의 정밀도를 실제보다 높게 보이게 한다. 같은 카드의 `sr-only` 도 `집중률 79` 와 `집중률 87.42` 가 섞여 자릿수가 들쭉날쭉하다.

실측 분포 (30일 중 **아는 날 25일**, 5일은 `UNKNOWN`):

| 값   | 수치  |
| ---- | ----- |
| 최저 | 57.77 |
| 평균 | 82.79 |
| 최고 | 88.18 |

**57.77 은 평균보다 25 낮은 날이다.** 화면은 그 사실을 말하지 않고 있었다.

### 바꾸는 것

1. 집중률을 **정수**로 내린다 — `가장 덜 붐비는 날` 줄과 막대 `sr-only` 둘 다.
2. 같은 기간 평균과의 **상대 표현**을 붙인다 — `집중률 58 · 이 기간 평균 83보다 25 낮아요`.

### 바꾸지 않는 것 — 그리고 그 이유

- **`점선은 아직 모르는 날이에요` 범례 · `7일만 보기` 토글** — 진단이 "이미 잘 된 것" 으로 꼽았다.
- **막대 색·높이·트랙 높이 · `UNKNOWN` 점선 · 배지 축** (#603 결정 전부).
- **회색 잔여 영역 (`bg-band` 트랙)** — 진단은 "지우고 막대 높이만" 을 제안했지만 **지우지 않는다.** D8 에 근거를 적는다.
- 서버 값 자체. **반올림은 표시에서만** 하고 `concentrationRate` 는 그대로 둔다.

## D1. 레이아웃

`LeastCrowded` 블록 한 곳만 바뀐다. 줄 수는 그대로다 — 둘째 줄의 내용만 길어진다.

```text
[bg-band 블록]
  가장 덜 붐비는 날   9월 21일 (월)              [보통]
  집중률 58 · 이 기간 평균 83보다 25 낮아요      ← 이 줄만 바뀐다
```

- 390 에서 둘째 줄은 한 줄에 들어간다(실측 D7). 넘치면 자연스럽게 접힌다 — 고정 높이를 주지 않는다.
- 막대는 손대지 않는다.

## D2. 컴포넌트 구성

| 대상                     | 신규/수정 | 위치                                        | 비고                                    |
| ------------------------ | --------- | ------------------------------------------- | --------------------------------------- |
| `congestionRateSummary`  | **신규**  | `lib/insight/congestion.ts`                 | 정수 · 평균 · 차이를 내는 **순수 함수** |
| `LeastCrowded`           | 수정      | `features/place/place-congestion-panel.tsx` | 둘째 줄 문구                            |
| `DayColumn` 의 `sr-only` | 수정      | 같은 파일                                   | 집중률을 정수로 읽는다                  |
| `messages/place.ts`      | 수정      | `lib/messages/`                             | 상대 표현 문구                          |

**계산을 `lib/insight` 에 둔다.** 평균·차이·반올림은 화면 문구가 아니라 값의 규칙이고, 이 카드는 props 만 받는 presentational 컴포넌트라 계산이 들어오면 테스트가 렌더 문자열에만 기댄다.

## D3. 데이터 흐름

**새 API 를 부르지 않는다.** 평균은 화면이 이미 받은 `dailyCongestions` 에서 낸다.

**`UNKNOWN` 날짜를 평균에서 뺀다.** `concentrationRate` 가 `null` 인 날은 값이 없는 것이지 0 이 아니다 — 넣으면 평균이 내려가 "평균보다 낮다" 가 과장된다.

**분모는 `아는 날` 이다 — 카드 머리의 기간과 다르다.** 수월봉 30일은 머리에 `9.15 – 10.14` 가 적히지만 평균의 분모는 25일이다. 화면이 이 분모를 따로 말하지는 않는다 — 같은 카드의 `점선은 아직 모르는 날이에요` 범례가 모르는 날이 있다는 것을 이미 말하고, 분모까지 적으면 한 줄이 두 줄이 된다. **BE 가 나중에 `averageConcentrationRate` 를 내리면 분모 정의가 갈릴 수 있다** — 그때 이 문단이 갈림길이다 (D9).

> **"FE 가 다시 고르지 않는다" 규칙과 충돌하지 않는다.** 그 규칙이 막는 것은 **서버의 답을 FE 가 다시 정하는 것**이다 (`leastCrowded` 를 다시 뽑으면 같은 기간에 다른 날을 추천하게 된다). 평균은 답이 아니라 **서버가 보낸 분포를 그대로 요약한 값**이고, 어떤 날을 고르지도 바꾸지도 않는다.

## D4. 문구 (확정)

### D4-1. 집중률 줄

| 조건                                | 문구                                        |
| ----------------------------------- | ------------------------------------------- |
| 아는 날이 둘 이상 · 평균과 차이 > 0 | `집중률 58 · 이 기간 평균 83보다 25 낮아요` |
| 아는 날이 하나 · 또는 차이 0        | `집중률 58`                                 |

- **차이를 반올림한 값끼리 뺀다.** 원값으로 빼면 `평균 83보다 25 낮아요` 옆에서 `83 − 58 = 25` 가 어긋나는 경우가 생긴다(예: 82.5 → 83, 57.4 → 57, 원값 차 25.1 → 25 이지만 표시는 26 이어야 맞다). **화면에 보이는 세 숫자가 서로 맞아야 한다.**
- **`30일 중 가장 한산` 이라 쓰지 않는다.** 기간은 7일일 수도 있고(토글), 전부 붐비는 주라면 가장 덜 붐비는 날도 `혼잡` 이다 — #650 에서 같은 오독을 막은 것과 같은 축이다. 등급은 옆 배지가 계속 말한다.
- **`%` 를 붙이지 않는다.** 집중률은 단위가 없는 0~100 지표다 (기존 주석).

### D4-2. 막대 `sr-only`

`집중률 {정수}`. 눈으로 보는 값과 보조기기가 읽는 값이 갈리지 않게 한다 — 지금은 `79` 와 `87.42` 가 섞여 있다.

## D5. 상태별 화면

| 상태                    | 집중률 줄                    |
| ----------------------- | ---------------------------- |
| 로딩 · 실패             | 바뀌지 않는다 (기존 갈래)    |
| `leastCrowded === null` | 블록 자체가 없다 (기존 규칙) |
| 아는 날 1일             | `집중률 58` — 비교 문구 없음 |
| 모든 아는 날이 같은 값  | `집중률 58` — 차이가 0 이다  |
| 아는 날 2일 이상        | 비교 문구가 붙는다           |

## D6. 접근성

- 줄이 하나 늘지 않고 기존 줄이 길어질 뿐이라 구조 변화가 없다.
- `tabular-nums` 유지 — 숫자 셋이 한 줄에 선다.
- 색으로 말하는 것이 없다.

## D7. 테스트 케이스

`congestion.test.ts` (순수 함수)

1. 소수를 정수로 내린다 (`57.77` → `58`)
2. 평균을 정수로 내린다
3. 차이는 **반올림한 값끼리** 뺀 값이다 (82.5 · 57.4 → 평균 83 · 값 57 · 차이 26)
4. `UNKNOWN`(`concentrationRate === null`)은 평균에서 빠진다
5. 아는 날이 하나면 평균·차이가 `null` 이다
6. 모든 값이 같으면 차이가 `null` 이다 (평균 == 값)
7. 아는 날이 없으면 평균·차이가 `null` 이다

`place-congestion-panel.test.ts` (렌더)

8. `집중률` 줄에 소수점이 없다
9. 비교 문구가 평균과 차이를 함께 말한다
10. 아는 날이 하나면 비교 문구가 없다
11. 막대 `sr-only` 의 집중률에 소수점이 없다
12. `%` 를 붙이지 않는다

## D8. 미결 사항 — 회색 잔여 영역을 지우지 않는 근거

진단 D-3 은 "회색 잔여 영역은 지우고 막대 높이만" 을 제안했다. **따르지 않는다.** 실측 근거 셋:

1. **그 회색이 0~100 축이다.** 이 차트는 기간 안 최댓값으로 정규화하지 않고 **트랙 높이를 집중률 100 으로 고정**한다 (#603 · `DayColumn` 주석). 회색을 지우면 `58` 이 무엇에 대한 58 인지 화면에서 사라진다.
2. **실데이터가 좁은 구간에 몰린다.** 수월봉 30일은 57.77~~88.18 이다 — 막대가 트랙의 58~~88% 를 차지한다. 기준면을 지우면 이 막대들이 **전부 꽉 찬 것처럼** 보여 "어느 날이 덜 붐비나" 가 오히려 안 읽힌다.
3. **`UNKNOWN` 칸이 깨진다.** 모르는 날은 **트랙 전체**를 점선 상자로 둔다. 아는 날의 트랙만 없애면 점선 상자가 화면에서 **유일한 전체 높이 요소**가 되어 가장 붐비는 날처럼 읽힌다.

**진단이 말한 문제(회색의 뜻을 모르겠다)는 D4-1 의 상대 표현이 글자로 푼다** — `집중률 58 · 이 기간 평균 83보다 25 낮아요` 를 읽고 나면 회색은 남은 척도로 읽힌다. 시각 요소를 지우는 대신 말을 붙이는 쪽을 골랐다.

y축 눈금도 같은 이유로 넣지 않는다 — 칸 폭이 36px 이고, 홈 골든타임 곡선도 같은 판단으로 y축을 걷었다 (#635 커밋 `78c0a6f1`).

## D9. BE 후속 요청

지금은 없다. **새 API 를 부르지 않는다.**

다만 BE 가 뒤에 `averageConcentrationRate` 를 응답에 넣는다면 **분모 정의를 맞춰야 한다** — FE 는 `concentrationRate !== null` 인 날만 센다. 서버가 `UNKNOWN` 을 0 으로 넣어 평균을 내면 화면 숫자와 API 필드가 어긋난다.
