## D0. 화면 정의

- **경로**: `/places/[placeId]` (route group `(main)`)
- **인증**: **불필요.** tour-service 는 security 의존이 없는 공개 조회 서비스다 → `proxy.ts` `PROTECTED_PATHS` 에 넣지 않는다
- **진입 경로**: 장소 목록(`/places`)의 카드 링크, 외부 공유 링크 직접 진입
- **이탈 경로**: 상단 "장소 목록으로" 링크, 브라우저 뒤로 가기

### 범위

넣어 그 우회가 필요 없어졌다.

## D1. 레이아웃 — **아트보드 기준으로 재배치했다** (이슈 [#64](https://github.com/8llow8llowMe/hondigagae/issues/64))

> 아래는 `혼디가개 장소 상세.dc.html` 01(모바일 390) · 03(데스크톱 1440) · 04(상태) 절이 정본이다.
> **이전 판(#11)의 "한 컬럼을 유지한다 · 사진 그리드 3열"은 아트보드를 보지 않고 쓴 것이라 폐기했다.**
> 사진은 상단 갤러리 한 곳에서만 말하고(본문 아래 "사진" 섹션 없음), 데스크톱은 2단이다.

| 뷰포트           | 본문 여백 | 레일 여백 | 배치                                             |
| ---------------- | --------- | --------- | ------------------------------------------------ |
| 모바일 (375)     | 16        | 16        | 한 컬럼                                          |
| 태블릿 (768)     | 40        | 40        | 한 컬럼 — **레일 여백도 본문을 따른다**          |
| 데스크톱 (1024+) | 40        | 24        | 2단 — 좌 `--rail-context`(400) sticky / 우 `1fr` |

**레일 여백(24)을 쓰는 것은 판정 패널뿐이다.** 기본 정보가 우측 본문으로 옮겨 가면서
`DetailSection` 에는 레일 인셋 갈래가 남지 않았다.

**768 에서 레일 여백을 24 로 두면 안 된다.** 그 폭에서는 판정 패널이 레일이 아니라 한 컬럼
본문의 한 블록이라, 24 를 쓰면 제목·행과 다른 축에서 시작한다 (실렌더로 확인).
그래서 인셋은 `px-4 md:px-10 lg:px-6` 이다.

세로 순서 (**DOM 순서 = 모바일 순서**):

```text
브레드크럼(전폭)
  ├ A  갤러리 · 사진 출처 · 제목+등급배지 · 메타 줄 · 속성 배지 · 판정 요약 3줄(모바일)
  ├ B  적합도 판정 · 산책 위험도 · 하단 바
  ├ A2 기간 혼잡도 · 기본 정보(+지도·길찾기)
  └ C  반려견 동반 정보 · 장소 소개 · 이용 안내 · 정보 출처
```

**모바일에서 판정(B)은 제목 카드(A) 바로 뒤다** ([#909](https://github.com/8llow8llowMe/hondigagae/issues/909)).
예전에는 A 가 혼잡도·기본 정보·지도까지 품어 판정이 390 에서 **다섯 번째 섹션**이었다
(#905 검토 §1 6번). 데스크톱은 판정이 좌측 레일 첫 자리라 **폭마다 위계가 갈렸고**, 이 서비스의
차별점(D1-1 "이 화면이 존재하는 이유")이 모바일 첫 화면 밖에 있었다. 위계를 데스크톱에 맞춘다.

- **이전 결정을 뒤집은 부분**: "기본 정보는 판정보다 앞" 이었다. 그 근거는 기본 정보가 **레일**에
  있던 시절 데스크톱에서 판정 아래로 밀렸던 것이고, 데스크톱에서는 지금도 기본 정보가 판정
  옆(우측 본문)이라 그대로다. 모바일에서만 판정 카드 한 장 뒤로 가며, 위치는 제목 아래 메타
  줄과 요약 행이 그 앞에서 먼저 말한다.
- **혼잡도는 판정 다음이다.** #603 이 혼잡도를 기본 정보 위로 올린 것은 그대로다 — 순서가
  "지금"(판정) → "언제"(혼잡도) → "어디·몇 시"(기본 정보) 가 된다.
- **요약 행의 앵커**(`동반` → 반려견 동반 정보 · `지금 산책` → 산책 위험도 · `붐빔` → 혼잡도)는
  대상 id 가 그대로라 바뀌지 않는다. 산책·붐빔 대상이 바로 아래로 올라왔을 뿐이다.

레일에는 **판정 성격의 것만** 남는다.

데스크톱은 **B 가 1열 1~3행에 걸치고, A · A2 · C 가 2열**에 차례로 간다
(`.rail-layout-detail-head` — 공용 `.rail-layout-detail` 은 법률 문서가 두 블록으로 쓴다).
행 템플릿 `max-content max-content minmax(0, 1fr)` 로 레일이 길 때 초과분을 마지막 행으로 보낸다.
데스크톱의 보이는 배치는 이전과 같다. 탭 순서만 갤러리·제목 → 레일 → 혼잡도·기본 정보 → 본문으로 바뀐다.
**트리를 폭마다 둘로 나누지 않는다** — 같은 내용이 두 번 렌더되면 스크린리더가 중복해 읽는다.
열 구분선은 A·C 의 `border-left` 다 (sticky 인 좌측 열에 걸면 그 열 높이에서 끊긴다).

긴 한국어 실데이터로 확인할 항목:

- 공백 없는 긴 장소명 (`제주특별자치도립김창열미술관`) — 제목이 가로로 넘치면 안 된다.
  `break-words` 만으로는 부족하고 **`min-w-0` 이 함께 필요하다.** flex 항목의 기본
  `min-width: auto` 는 min-content 아래로 내려가지 않고, 한국어는 `keep-all` 이라 제목
  전체가 하나의 끊을 수 없는 덩어리다 — 375 에서 등급 배지가 우측 인셋을 16px 넘었다(실측)
- `etcAcmpyInfo` 는 **개행 포함 장문**(TEXT 컬럼)이다. 줄바꿈이 살아야 하고 잘라내지 않는다
- `overview` 는 TEXT 이고 `<br>` 이 섞여 온다. 모바일은 140자를 넘을 때만 접는다
  (**길이를 재지 않고 글자 수로 가른다** — 렌더 후 버튼이 끼어들면 본문이 밀리고, 서버·클라이언트
  렌더가 다른 결론을 내면 하이드레이션이 어긋난다)

## D1-1. 적합도 패널 — **이 화면이 존재하는 이유다**

목록에 없던 점수·근거가 여기서 처음 나온다. `GET /places/{placeId}/suitability` 를
**선택된 반려견 조건**으로 부른다 (`petId` 가 아니라 속성 쿼리 파라미터다 — 공개 API 라
서버가 반려견을 조회할 수 없다).

| 지키는 것                | 이유                                                                         |
| ------------------------ | ---------------------------------------------------------------------------- |
| 화자는 반려견이다        | "몽실이에게 {서버 등급명}". **등급 문구를 FE 가 다시 쓰지 않는다**           |
| 근거는 서버 순서 그대로  | `reasons` 는 점수 영향이 큰 순서로 온다. 재정렬하면 그 정보가 사라진다       |
| `scoreDelta` 를 안 쓴다  | 산식이 공개되지 않아 "-27" 을 설명할 수 없다. 부호만 읽어 흐리기에만 쓴다    |
| `score === null` ≠ 0점   | `INSUFFICIENT` 은 "나쁨" 이 아니라 "모름" 이다. 점수 자리를 만들지 않는다    |
| 기준 각주를 붙인다       | 예보 시각과 반려견이 바뀌면 값이 달라진다 — `{날짜} 예보 기준 · {이름} 기준` |
| `indoorAlternatives` 0건 | 섹션을 렌더하지 않는다. 비 예보일 때만 채워진다                              |

**반려견이 없으면(미로그인 · 미등록) 판정을 말하지 않는다** (아트보드 04-③).
점수·근거·화자 셋을 모두 빼고 지역 날씨(최고 체감온도 · 강수확률)와 등록 유도만 남긴다 —
기준이 되는 반려견이 없는데 판정을 말하면 그 판정이 누구 것인지 알 수 없다.

아트보드가 여기에 적은 **체감온도는 이제 적합도 응답에 있다** —
[PR #235](https://github.com/8llow8llowMe/hondigagae/pull/235) 가 `weather.maxFeelsLikeTemperature` 를
더했고 [#253](https://github.com/8llow8llowMe/hondigagae/issues/253) 이 붙였다. 그전에는 없어서
최고기온으로 대신하고 있었다. **중기예보 구간은 값이 null 이라 그때만 `최고기온` 이 서고
라벨도 함께 바뀐다** — 최고기온을 체감온도라고 부르지 않는다.

**라벨은 `최고 체감온도` 다** ([#259](https://github.com/8llow8llowMe/hondigagae/issues/259)).
이 값은 **하루 최대**인데 바로 아래 산책 위험도가 같은 체감온도를 **그 시각** 기준으로 내므로
(`feelsLikeCelsius`), 둘 다 `체감온도` 이면 게스트 경로에서 기준이 다른 두 숫자가 같은 이름으로
나란히 선다. **이름을 나누지 않고 기준을 나눈다** — 같은 물리량이라 이름이 갈리면 사용자는
서로 다른 값으로 읽는다. 폴백인 `최고기온` 과도 짝이 맞는다.

> **두 값 모두 기상청 여름철 체감온도다** ([#292](https://github.com/8llow8llowMe/hondigagae/issues/292)).
> BE `46f35e4` 이전에는 NOAA 열지수였고 이 문서도 그렇게 적고 있었다. 열지수
> (`heatIndexCelsius`)는 판정에서 내려와 산책 위험도의 **참고값**으로만 남았다 —
> `체감온도 계산 근거` 문단 안에서 `참고 열지수` 라는 이름으로 서고, 평면에는 서지 않는다.

**장소 조회와 판정 조회는 따로 실패한다.** 판정이 죽어도 기본 정보는 그대로 쓸모가 있으므로
패널 안에서만 재시도를 준다 — 화면 전체를 `ErrorState` 로 덮지 않는다.

조회 key 는 홈과 **공유한다** (`src/lib/insight/queries.ts` 의 `insightKeys`). 홈에서 이미
받아 둔 판정이 있으면 상세가 다시 부르지 않는다. key 가 `features/home` 에 있으면 장소 기능이
홈을 가로질러 import 하게 되므로 `lib/insight` 로 옮겼다.

## D1-3. 판정 요약 3줄 — [#650](https://github.com/8llow8llowMe/hondigagae/issues/650)

정본은 [`장소상세-판정요약-세부명세.md`](./장소상세-판정요약-세부명세.md). 여기서는 **이 화면에 블록이 하나 늘었다는 사실**만 적는다.

제목 카드 **안**, 태그 줄 아래에 L2 1px 선으로 이어 `동반 · 지금 산책 · 덜 붐비는 날` 세 줄이 선다. 각 줄은 아래 세부 섹션으로 가는 앵커다.

**`lg:hidden` 이라 데스크톱 배치는 바뀌지 않는다** — ≥1024 는 좌측 레일이 이미 판정을 첫 화면에 올리고 혼잡도는 본문 맨 위(D1-2)에 있어, 요약을 또 그리면 같은 답이 한 화면에 두 번 선다. 390 실측에서 동반은 1797px, 산책 판정은 1519px 아래였다는 것이 이 블록이 생긴 이유다 (진단 D-1).

이 때문에 `--gallery-h-mobile` 이 214 → **200** 으로 줄었다.

## D1-2. 기간 혼잡도 카드 — [#430](https://github.com/8llow8llowMe/hondigagae/issues/430)

`GET /places/{placeId}/congestions` 를 붙인 자리다. **판정 카드 밖, 바로 아래의 새 L1
카드**이고 좌측 레일의 마지막 카드다.

### 왜 판정 카드 안이 아닌가

§0 의 "카드 경계는 이야기 단위" 다. 판정 카드가 하는 말은 _"오늘 가도 되나 → 지금 걷기
안전한가 → 그러면 담을까"_ 이고, 이 카드는 **다른 시간 축**(_"이번 주엔 언제"_)이다. 같은
카드에 넣으면 하단 바가 이야기 가운데로 들어오거나, 담기 뒤에 새 질문이 붙는다.

**접힌 서랍으로도 넣지 않는다** — 이 서비스의 차별점이 기본 상태에서 안 보인다. **별도
화면(`/places/[placeId]/congestions`)도 만들지 않는다** — 진입 동선을 새로 뚫어야 하고 그
화면이 갖는 것은 그래프 하나뿐인데, `placeId` 는 이미 이 화면에 있다.

**적합도의 `congestion`(그 날 하나)과 겹치지 않는다.** 착수를 막고 있던 근거는 _"그 필드로
화면이 이미 채워져 있다"_ 였는데, 실제로는 **장소 상세가 그 필드를 화면에 쓰지 않는다** —
혼잡 배지가 있는 곳은 홈의 `place-insight-row` 뿐이다.

### 그래프의 형태

**세로 막대다.** 축이 날짜 하나뿐이고 사용자가 하는 일이 "어느 칸이 낮은가" 를 한눈에
고르는 것이다. 선 그래프는 값 사이를 이어 *연속적인 추세*로 읽히게 하는데 혼잡도는 날짜마다
끊긴 값이고 중간에 모르는 날이 섞인다. 히트맵은 칸의 높이를 없애 `concentrationRate` 차이를
색 단계로만 남긴다.

| 규칙                | 내용                                                                                                                                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `UNKNOWN` 날짜      | **빈칸도 짧은 막대도 아니다** — 둘 다 "한산하다" 로 읽힌다. 트랙 전체를 `--metric-unknown-500` 점선으로 두고 막대를 그리지 않는다                                                                                                    |
| 색                  | `congestionTone` 그대로. `LOW`(한산)가 초록 · `MODERATE` 앰버 · `HIGH` 회색. **붐비는 날에 빨강을 쓰지 않는다** — 사람이 많은 것은 위험이 아니다                                                                                     |
| 막대 높이           | **트랙 전체가 집중률 100** 이다. 기간 안 최댓값으로 정규화하지 않는다 — 한산한 주와 성수기 주가 같은 그림이 된다                                                                                                                     |
| 숫자                | **`leastCrowded` 한 곳에만** 적는다. 일곱 칸에 집중률을 전부 적으면 카드가 표가 된다. **정수 + 같은 기간 평균과의 차이**로 적는다 — `집중률 58 · 이 기간 평균 83보다 25 낮아요` (#651, [세부명세](./혼잡도-집중률-표현-세부명세.md)) |
| 서버가 고른 날 표시 | 등급 색이 아니라 **선택 표시기**(`--brand-500`)다 — 전부 붐비는 주면 최선일도 `HIGH` 라, 등급 색으로 두르면 없는 한산함을 말한다                                                                                                     |
| 7일 ↔ 30일          | 30일은 같은 막대를 **가로 스크롤 레일**로 늘린다. 폭에 맞춰 30칸을 나누면 날짜를 적을 자리가 없어지고, **날짜 없는 막대는 고를 수 없다**                                                                                             |

### 상태

| 상태                    | 화면                                                                                                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 조회 중                 | 제목은 그대로 두고 본문만 스켈레톤 — 카드가 통째로 사라지면 자리가 흔들린다                                                                                                 |
| 실패                    | **이 카드만 덮는다.** 판정 둘과 기본 정보는 그대로 쓸모가 있다                                                                                                              |
| `leastCrowded === null` | 추천일 자리를 **만들지 않고** "자료가 아직 없어요" 로 간다. 404 가 아니라 빈 상태라 **재시도를 달지 않는다**. 문구는 차트 **아래가 아니라 차트 위 veil 안**이다 (아래 #670) |

### 자료가 하나도 없을 때 — 차트를 덮는다 ([#670](https://github.com/8llow8llowMe/hondigagae/issues/670))

`leastCrowded === null` 갈래의 **표현만** 바꾼다. 집중률 계산·기간 토글 동작·서버 계약·`UNKNOWN` 점선 규칙은 그대로다.

#### 현상

빈 상태 처리는 이미 있었는데 **차트가 함께 그려졌다.** 기본 기간이 30일이라 `border-metric-unknown-500 border-2 border-dashed` 트랙 30칸이 카드를 가득 채우고, 설명은 그 아래 12px 로 붙어 있었다 — **먼저 읽히는 것이 "깨진 그래프"** 다.

#### 결정

| 항목        | 결정                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------- |
| 차트        | **지우지 않는다.** 그대로 그리고 그 위에 반투명 면(veil)을 덮는다                                     |
| 문구        | 차트 아래에서 **veil 안 가운데**로 옮긴다. 같은 말을 두 번 하지 않는다 — 아래 블록은 없앤다           |
| 문구 키     | `detailCongestionEmptyTitle` · `detailCongestionEmptyDescription` **그대로.** 새 문구를 만들지 않는다 |
| 흐림 수단   | **반투명 `--bg` 면 한 겹 — `bg-bg/70`** (실측으로 정했다, 아래). `backdrop-filter` 는 얹지 않는다     |
| 차트 취급   | 이 갈래에서만 **장식**이다 — `aria-hidden` + 조작 불가 (스크롤·화살표 없음)                           |
| 기간 토글   | **렌더하지 않는다** (현행 유지). veil 안에도 밖에도 두지 않는다                                       |
| 재시도 버튼 | **없다.** 404 가 아니라 빈 상태라는 기존 결정을 뒤집지 않는다                                         |
| 경계        | `leastCrowded === null`(전부 `UNKNOWN`) **일 때만.** 일부만 `UNKNOWN` 이면 veil 이 서지 않는다        |

#### 왜 차트를 지우지 않는가

지우면 카드에 제목·기간·문구만 남아 **카드가 통째로 사라진 것처럼** 보인다. 남은 칸 수(7/30)·트랙 높이·날짜 축이 _"여기는 날짜별 붐빔을 보는 자리"_ 라고 말해 주고, 그래야 문구의 "자료가 아직 없어요" 가 **무엇의 자료인지** 붙는다. 빈 상태는 자리를 없애는 것이 아니라 자리의 뜻을 유지한 채 비어 있음을 말하는 것이다 (`component-guide.md` 의 `EmptyState` 와 같은 태도).

동시에 그 칸들이 **읽히면 안 된다.** 점선 30칸은 "모르는 날 30일" 이라는 뜻을 이미 다 말했고, 그 위에 시선을 더 둘 이유가 없다. 그래서 **보이되 읽히지 않는** 상태로 내린다.

#### 흐림 수단 — 반투명 면이 먼저다

**1차는 `--bg`(흰색) 반투명 면 한 겹이다.** 카드 자체가 `bg-bg` 라(`Surface`) veil 은 **카드 배경색의 알파 변형**일 뿐이고, `DESIGN.md` 밖의 새 색을 만들지 않는다. 기존 선례와 같은 형태다 — `photo-viewer.tsx` 의 `bg-fg/95`, `photo-gallery.tsx` 의 `bg-fg/60`.

- **Tailwind 불투명도 수식어(`bg-bg/<n>`)를 쓴다.** `bg-[color-mix(...)]` 같은 형태는 eslint `noComplexArbitrary` 가 막는다 — 그 형태가 필요해지면 `globals.css` 에 유틸 한 줄을 두는 경로다 (`.overlay-backdrop` 과 같은 경로, `styling-guide.md`)
- **`--metric-unknown-500` 을 veil 에 쓰지 않는다.** 점선 테두리 전용 토큰이다 (`DESIGN.md` §2-3)
- **`--bg-sunken` · `--band` 로 덮지 않는다.** 둘 다 "다른 층" 을 뜻하는 면이라, 이 카드 안에 없던 층이 하나 생긴 것처럼 읽힌다

**`backdrop-filter: blur()` 는 기본이 아니다.** 얹는 조건은 하나 — 아래 두 기준을 동시에 만족하는 알파 구간이 **없을 때**만이다. 이유:

- 가리는 대상이 **2px 점선**이다. 사진·글자처럼 정보 밀도가 높은 면이 아니라, 알파만으로도 질감까지 내려간다
- Safari 는 `-webkit-` 접두가 필요하고, `backdrop-filter` 는 합성 레이어를 새로 만들어 **스크롤·리렌더마다 뒤 화면을 다시 샘플링**한다. 이 카드는 본문 맨 위라 진입 직후 스크롤 구간에 걸린다
- 저장소에 `backdrop-blur` 선례가 **0건**이다. 첫 사용처를 빈 상태 하나로 열지 않는다

#### 대비 — 실측으로 `bg-bg/70` 을 정했다

veil 알파는 **추측으로 정하지 않았다.** 아래 두 기준을 동시에 만족하는 구간을 토큰 실측값으로 구하고 그 가운데를 잡았다.

| #   | 기준                 | 재는 법                                                                                                                                                                                                  |
| --- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 문구가 읽힌다        | veil 합성면 위에서 `--fg`(제목) · `--fg-muted`(설명)가 **4.5:1 이상**. **최악의 경우로 잰다** — 문구 뒤에 점선(`#A8AEB8`)이 지나가는 픽셀이 기준면이다. 흰 배경값(17.79:1 / 6.36:1)을 그대로 믿지 않는다 |
| 2   | 점선이 읽히지 않는다 | 합성 후 점선 대비가 **3:1 미만**. `DESIGN.md` 의 비텍스트 최소 대비를 뒤집어 쓴다 — 3:1 아래면 그것은 **신호가 아니라 질감**이다. 동시에 0 은 아니어야 한다(칸 경계가 눈에 남아야 차트임을 안다)         |

**결과 — 알파 `70%` (`bg-bg/70`).**

| 조건                                                                      | 만족 구간     |
| ------------------------------------------------------------------------- | ------------- |
| 기준 1 — 점선 위 최악 픽셀에서 `--fg` · `--fg-muted` 둘 다 4.5:1 이상     | **54% 이상**  |
| 기준 2 — 합성 후 점선이 3:1 미만                                          | **모든 알파** |
| 기준 2 의 뒷조건 — 점선이 0 이 아니다 (`--band` 대비 `1.142` 를 바닥으로) | **81% 이하**  |

교집합 `[54%, 81%]` 의 가운데는 68 이고, Tailwind 표준 눈금에 맞춰 **70** 을 쓴다.

**둘째 기준은 구속력이 없었다.** `--metric-unknown-500`(`#A8AEB8`)은 흰 배경에서 이미 **2.231:1** 이라 알파 0 에서도 3:1 아래다 — 점선 테두리 토큰이 애초에 "신호가 아니라 질감" 쪽 값이었다는 뜻이다. 그래서 위쪽 경계를 **"점선이 사라지지 않는다"** 로 잡았고, 그 바닥을 임의의 숫자 대신 **이 디자인 시스템에서 가장 조용한 정식 면(`--band` 위 `--bg`, 1.142:1)** 의 대비로 두었다. 그보다 옅어지면 칸 경계가 시스템 안의 어떤 면보다도 흐려져 "차트가 거기 있다" 는 신호가 끊긴다.

**390 · 1280 실측** (`MOCK_API=true`, `/places/212481712381923332` — mock 버킷 2 는 30일 전부 `UNKNOWN`):

| 잰 것                                  | 390            | 1280           | 판정                        |
| -------------------------------------- | -------------- | -------------- | --------------------------- |
| 합성면 알파 (`getComputedStyle`)       | `0.7`          | `0.7`          | —                           |
| 제목(`--fg`) / 점선 위 최악 픽셀       | **14.33**      | **14.33**      | ≥ 4.5 ✅                    |
| 설명(`--fg-muted`) / 점선 위 최악 픽셀 | **5.12**       | **5.12**       | ≥ 4.5 ✅                    |
| 합성 후 점선 대비                      | **1.242**      | **1.242**      | < 3 ✅ · > 1.142 ✅         |
| veil 이 차트를 덮는 범위               | `inset-0` 일치 | `inset-0` 일치 | 어긋남 없음 ✅              |
| 페이지 가로 넘침 (`documentElement`)   | 390 = 390      | 1274 = 1274    | 없음 ✅                     |
| `aria-hidden` 안의 초점 가능 요소      | 0              | 0              | `aria-hidden-focus` 없음 ✅ |
| veil 안의 버튼·링크                    | 0              | 0              | ✅                          |

합성은 해상도와 무관하므로 대비 수치는 두 폭에서 같다. 폭이 가르는 것은 **덮이는 면적**인데(390 에서 358px, 1280 본문 열에서 796px), 문구가 가운데에 고정이라 두 폭에서 같은 위치에 선다 — 390 에서 제목·설명이 각각 한 줄에 들어간다.

**`backdrop-blur` 를 얹지 않는다.** 위 구간이 비지 않았으므로 조건 자체가 성립하지 않는다 (D8-8).

#### 기간 토글은 이 갈래에 없다 — 그대로 둔다

이슈는 "토글이 veil 밖에 남는지" 를 물었지만, **이 갈래에는 토글이 애초에 렌더되지 않는다** (`place-congestion-panel.tsx` 의 `leastCrowded === null` 분기 · 테스트 `빈 상태에는 펼치기를 두지 않는다`). #670 은 그 결정을 **뒤집지 않는다.**

근거: `fromDate` 를 보내지 않으므로 서버가 오늘로 잡고(`lib/api/insight.ts`), **7일 구간은 30일 구간의 앞 7일**이다. 30일이 전부 `UNKNOWN` 이면 7일도 전부 `UNKNOWN` 이다 — 토글은 **결과가 이미 정해진 선택지**를 내밀게 되고, 눌러도 같은 빈 화면이 돌아오면 그때야말로 카드가 고장 난 것으로 읽힌다. 왕복 한 번을 더 쓰는 것은 덤이다.

"가리면 카드가 죽은 것처럼 보인다" 는 우려는 **veil 이 직접 답한다** — 죽은 카드와 다른 점은 _왜 비었는지_ 를 가운데에서 말하고 있다는 것이고, 카드 머리의 기간 표기(`fromDate ~ toDate`)도 그대로 살아 있다.

#### 가로 스크롤 — veil 은 고정이고, 뒤는 구르지 않는다

veil 은 스크롤 콘텐츠와 **함께 움직이지 않는다.** 스크롤러의 **뷰포트**(`Chart` 의 `relative` 래퍼)에 `absolute inset-0` 으로 앉아, 문구가 언제나 카드 가운데에 선다. 함께 구르면 문구가 옆으로 빠져 나간다.

그런데 **뒤가 구를 수 있으면 veil 이 고정인 것 자체가 이상해진다** — 덮개는 붙박이인데 그 아래 그림만 미끄러진다. 그래서 이 갈래에서는 차트를 **장식으로 내린다**:

| 항목                    | 이 갈래                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `overflow-x-auto`       | **주지 않는다.** 넘치는 칸은 `overflow-hidden` 으로 자른다 — `BodySkeleton` 이 이미 쓰는 그림이다                           |
| `ScrollRailArrows`      | **렌더하지 않는다.** `aria-hidden` 면 아래에 초점 받는 버튼이 남으면 `aria-hidden-focus` 위반이다                           |
| `INSET_BLEED_END_CLASS` | **붙이지 않는다.** 인셋에서 자른다 — 카드 끝까지 여는 이유("잘린 칸이 '더 있다' 로 읽혀야 한다")가 구를 수 없는 면에는 없다 |
| veil 의 덮는 범위       | 같은 래퍼 `inset-0`. bleed 를 걷었으므로 **veil 밖으로 삐져나오는 점선 칸이 없다**                                          |
| 포인터                  | veil 이 이벤트를 **받는다**(`pointer-events` 기본). 아래 차트는 조작 대상이 아니다                                          |

#### 일부만 `UNKNOWN` 인 갈래는 건드리지 않는다

| 갈래                                     | 표현                                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------- |
| 전부 `UNKNOWN` (`leastCrowded === null`) | **veil + 문구.** 점선의 뜻이 아니라 **이 장소에 자료가 없다**는 사실을 말한다          |
| 일부 `UNKNOWN` (`leastCrowded !== null`) | **현행 그대로.** 차트는 조작 가능하고 `detailCongestionUnknownNote` 가 점선을 설명한다 |
| `UNKNOWN` 없음                           | **현행 그대로.** 설명 줄도 없다                                                        |

경계를 `hasUnknown` 이 아니라 **`leastCrowded === null`** 로 잡는다. 아는 날이 하루라도 있으면 그 날이 답이고, 답이 있는 카드를 덮으면 서비스가 할 말을 스스로 가린다.

#### 에러 갈래와 섞이지 않는다

`failed || data === null` 은 veil 이 아니라 `detailCongestionErrorTitle` + 재시도 버튼 그대로다. **두 갈래는 배타적이다** — veil 은 `data` 가 정상으로 온 뒤 그 내용이 비었을 때만 선다. veil 안에 재시도·버튼·링크를 **하나도 두지 않는다**: 누를 것이 생기는 순간 사용자는 이것을 고칠 수 있는 오류로 읽는다.

#### 바꾸지 않는 것

집중률 계산(`barHeightPercent` · 평균 비교) · 기간 토글 동작 · `insightKeys` 와 `staleTime` · `congestionsPath` 쿼리 · `UNKNOWN` 점선 토큰 · 아는 날의 `bg-band` 트랙 · 배지 축(#652) · 서버 계약 전부.

### 기간은 URL 에 두지 않는다

7 ↔ 30 은 한 카드 안에서 끝나는 **펼침**이라 `useState` 다 (`architecture-guide.md` §10 의
"아코디언" 행). `/places/{id}` 링크를 받은 사람이 봐야 하는 것은 그 장소이지 내가 펼쳐 둔
기간이 아니다.

### 조회

`insightKeys.congestions(placeId, days)` — **조건이 아니라 일수가 key 에 들어간다.** 이
엔드포인트는 반려견 조건을 받지 않으므로 조건을 섞으면 반려견 전환마다 같은 답을 다시 받아
온다. `staleTime` 은 인사이트 표준값(5분 / 30분 / retry 1)이다.

### 이 세그먼트에는 `loading.tsx` 를 두지 않는다 (실측 근거)

`loading.tsx` 는 Suspense 경계를 만들고, 경계가 있으면 응답이 **먼저 스트리밍되기 시작한다.**
그 뒤에 던진 `notFound()` 는 not-found UI 는 렌더하지만 **HTTP 상태를 200 으로 남긴다** (soft 404).

더 함정인 것은 **`loading.tsx` 가 자식 세그먼트까지 감싼다**는 점이다. 목록의
`app/(main)/places/loading.tsx` 가 `/places/[placeId]` 까지 감싸고 있었다.

실측 (2026-08-27, `/places/999999999999999999`):

| 구성                                          | 응답                              |
| --------------------------------------------- | --------------------------------- |
| `places/loading.tsx` 가 자식까지 감쌈         | **200** + not-found UI (soft 404) |
| 목록을 `places/(list)/` 로 옮겨 스코프를 좁힘 | **404** + not-found UI            |

그래서 목록 라우트를 `app/(main)/places/(list)/` 로 옮겼다. **URL 은 `/places` 그대로다.**
공개 화면이라 크롤러가 없는 장소를 정상 페이지로 인식하는 쪽이 스켈레톤이 없는 쪽보다 나쁘다.
일반 규칙은 `architecture-guide.md` §7 에 적었다.

## D3. 데이터 흐름

```text
화면 진입 → server page (fetchQuery, retry:false)
              ├─ 성공 → dehydrate → HydrationBoundary → PlaceDetailView (같은 key 로 캐시 히트)
              ├─ 404  → notFound() → not-found.tsx
              └─ 그 외 → 무시 → 클라이언트가 재조회
```

| 항목                       | 내용                                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------------------- |
| API                        | `GET /api/v1/places/{placeId}` (FE 경로 `/places/{placeId}`)                                             |
| React Query key            | `placeKeys.detail(placeId)` — 이미 존재. 서버·클라이언트 공유                                            |
| staleTime / gcTime / retry | **5분 / 30분 / 2** — `api-integration-guide.md` §7 "장소 목록·상세" 표준값. `PLACE_QUERY_OPTIONS` 재사용 |
| mutation 후 invalidate     | 없음 (조회 전용)                                                                                         |
| 폴링                       | 없음                                                                                                     |

### 왜 `prefetchQuery` 가 아니라 `fetchQuery` 인가

목록 화면은 `prefetchInfiniteQuery(...).catch(() => undefined)` 를 쓴다. 프리페치 실패를 화면 전체
실패로 만들지 않기 위해서다. **상세는 404를 `notFound()` 로 보내야 하므로 실패의 종류를 알아야 한다.**
`prefetchQuery` 는 에러를 삼켜서 404와 5xx를 구분할 수 없다. `fetchQuery` 는 던지므로 잡아서 판정한다.

- `fetchQuery` 도 성공 시 같은 캐시에 채우므로 `dehydrate` 는 동일하게 동작한다
- 프리페치 `retry: false` 는 목록과 같은 이유다 — 전역 기본값(5xx 2회)을 상속하면 백엔드가 죽었을 때
  **서버 렌더가 재시도 백오프만큼 통째로 블로킹된다** (`architecture-guide.md` §9)

### `architecture-guide.md` §9 확정표

이 화면은 표에 **"장소 상세 — 서버 프리페치 / 이후 client"** 로 이미 등재돼 있다. 그대로 따른다.

| **하단 바만 폭마다 두 번 그린다**              | 모바일 sticky(01) 와 데스크톱 레일(03) 은 위치가 아예 다르다. `hidden`(`display:none`) 으로 갈라 어느 폭에서든 a11y 트리에 하나만 남는다 — 본문 트리를 나누지 않는 이유(중복 낭독)가 여기에는 걸리지 않는다 |

### 저장 상한을 화면이 미리 막지 않는다

반려견 5마리 상한(#83)과 다르다. 장소 상세는 즐겨찾기 목록을 이미 갖고 있지 않아, 상한을
미리 알려면 **저장 버튼 하나 때문에 목록 전량을 받아야 한다.** 서버의 `FAVORITE_002`(400)를
그대로 안내하는 쪽이 싸다.

### 원천에서 사라진 장소는 미리 막는다 ([#146](https://github.com/8llow8llowMe/hondigagae/issues/146))

**바로 위 "저장 상한" 과 반대 결정이다.** 갈림길은 _"화면이 이미 그 사실을 갖고 있는가"_ 다 —
상한은 즐겨찾기 목록 전량을 받아야 알지만, `delisted` 는 **지금 그리고 있는 상세 응답에
실려 온다.** 알면서 400 을 맞게 두지 않는다.

| 동작                | delisted 일 때    | 서버가 막는 방식                                                                  |
| ------------------- | ----------------- | --------------------------------------------------------------------------------- |
| `일정에 담기`       | **잠근다**        | `PLAN_004` — `PlanCommandProcessor` 의 `findVisiblePlaceIds`                      |
| `저장`(POST)        | **잠근다**        | `FAVORITE_001` — `FavoriteCommandProcessor` 의 `findSummaries` 가 빈 목록         |
| `저장 해제`(DELETE) | **잠그지 않는다** | 가시성 검사를 타지 않는다 — 예전에 저장해 둔 곳을 지울 길이 막히면 그게 더 나쁘다 |

**이유를 버튼 위에 적는다.** `disabled` 만 걸면 스크린리더도 마우스도 왜 잠겼는지 얻지
못하고, 토스트로 흘리면 눌러 본 사람만 본다.

안내 배너는 **2열로 들어가기 전 폭 전체**에 둔다. 좌측 레일에 넣으면 모바일에서 갤러리·제목
아래로 밀리고, 우측 본문에 넣으면 데스크톱에서 잠긴 하단 바와 멀어진다. **붉게 칠하지
않는다** — 오류가 아니라 이 장소가 놓인 상태다 (`Banner` 가 같은 이유로 danger 배경을 쓰지 않는다).

### 닫힌 시트는 마운트하지 않는다 (실측으로 잡았다)

`BottomSheet` 가 `open` 으로 렌더만 막으면 **그 안의 훅은 그대로 돈다.** 장소 상세를 열기만
해도 `GET /plans` 가 나가고, 미로그인에게는 그것이 401 이라 전역 재발급까지 헛돈다.
`PlaceAddToPlanSheet` 가 `!open` 이면 `null` 을 돌려준다.

## D4-2. 사진 뷰어 (`PhotoViewer`) — [#247](https://github.com/8llow8llowMe/hondigagae/issues/247)

**왜 필요했나.** 데스크톱 모자이크는 대표 1 + 썸네일 2 만 그리고 나머지를 `+N` 으로 덮는다.
그 `+N` 이 장수만 말하고 아무 데도 가지 않아 **4장째부터는 화면에 도달할 경로가 없었다.**
모바일 캐러셀은 전부 그리지만 200px 라 작다. 뷰어 하나가 두 문제를 같이 닫는다 —
**갤러리의 모든 타일과 `+N` 이 이것을 연다.**

| 항목        | 규칙                                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 여는 위치   | 누른 타일의 사진. `+N` 은 **가려진 첫 사진**(데스크톱에서 4번째)에서 연다                                                                         |
| 맞춤        | **`object-contain`** — 갤러리 타일(`object-cover`)과 반대다. 확대해 보려고 연 화면에서 가장자리를 잘라내면 여는 의미가 없다. **실측 확인** — 아래 |
| 이동        | 좌우 버튼 · `ArrowLeft`/`ArrowRight`. **순환하지 않는다** — 끝에서 처음으로 돌면 카운터가 뒤로 뛰어 몇 장 남았는지 읽을 수 없다                   |
| 닫기        | `Esc` · 닫기 버튼 · 바탕. **포커스는 눌렀던 타일로 돌아온다** (`useOverlay`)                                                                      |
| 방향키 범위 | **닫혀 있으면 걸지 않는다** — 상세 화면의 가로 스크롤을 가로채면 안 된다                                                                          |

**`Modal` 을 쓰지 않는다.** 그쪽은 제목·설명·본문·조작부 네 자리를 가진 카드 레이아웃
(`max-w-sm`, 흰 배경, 패딩 20)이라 전면 사진과 맞지 않는다. 다만 다이얼로그 **계약**은 같은
것을 쓴다 — `useOverlay` 가 Esc · 바탕 스크롤 잠금 · 포커스 복귀를 준다.

**일러스트 타일은 뷰어를 열지 않는다** (D5 "0장이면 카테고리 일러스트 한 장").

#### `object-contain` 은 실사진으로 확인했다 (2026-09-07)

한동안 미검증이었다 — mock 이미지가 **일부러 404 인 가짜 경로**였고 dev 에도 다중 이미지
장소가 없어 확인 경로가 없었다. BE 백필로 생겼고, mock 이 실제 URL 을 쓰게 되면서
([#247](https://github.com/8llow8llowMe/hondigagae/issues/247) C) 로컬에서 닫혔다.

**원천의 비율 분포** (dev 제주 26곳 · 고유 248장 중 200장 측정, https 로 200 전수 성공):

| 비율      | 크기     | 장수       |
| --------- | -------- | ---------- |
| 1.50      | 940×627  | 144        |
| 1.33      | 940×705  | 35         |
| 1.00      | 940×940  | 12         |

**파노라마는 없다.** 걱정하던 둘 중 하나는 원천에 존재하지 않았고, 남는 것은 세로 하나다.

세로 사진(627×940)을 뷰어에서 실측했다 — 1280×752 상자에 **502×752 로 그려지고 좌우

## D5. 상태별 화면

| 상태                                 | 표시                                                                                      | 문구 (확정)                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| loading                              | 섹션 내부 `PlaceDetailSkeleton` (이미지 + 제목 + 3섹션). **`loading.tsx` 는 두지 않는다** | —                                                                                        |
| success                              | 전체 섹션                                                                                 | —                                                                                        |
| **데이터 부재 (404)**                | **서버**: `notFound()` → `not-found.tsx`                                                  | "장소를 찾을 수 없습니다" / "주소가 잘못되었거나 삭제된 장소입니다." / `[장소 목록으로]` |
| 데이터 부재 (404, 클라이언트 재조회) | `EmptyState` — **재시도 없음**                                                            | 서버 `resultMessage` 그대로 + 위 안내 + `[장소 목록으로]`                                |
| 일시 장애 (5xx·무응답)               | `ErrorState` — 재시도 있음                                                                | "장소 정보를 불러오지 못했습니다" / "잠시 후 다시 시도해 주세요." / `[다시 시도]`        |
| 입력 오류 (400)                      | `EmptyState` — **재시도 없음**                                                            | "요청 조건이 올바르지 않습니다" / 서버 `resultMessage` / `[장소 목록으로]`               |
| 부분 데이터 없음 (nullable)          | **숨김**                                                                                  | —                                                                                        |

400에 재시도를 주지 않는 이유: 주소 자체가 잘못된 것이라 같은 URL을 다시 불러도 같은 400이다.
`ErrorState` 는 `onRetry` 가 필수 prop 이므로 여기서는 중립 톤 `EmptyState` + 목록 링크를 쓴다.

**400이 실제로 발생한다.** 컨트롤러가 `@PathVariable long placeId` 라, 숫자가 아닌 `placeId` 로 진입하면
`MethodArgumentTypeMismatchException` → `PLACE_113` **400** 이다. 404가 아니다.
`/places/abc` 같은 URL을 손으로 고쳐 들어오는 경로가 여기 해당한다.

#### 사진은 두 자리로 온다 — `images` 가 비면 `firstImage`

계약에 사진 자리가 둘이다. `images[]`(추가 이미지)와 `firstImage`(대표 이미지)다.
**dev 실측(2026-09-04)에서 `images` 는 모든 장소가 빈 배열이었고 사진은 `firstImage` 로만
왔다** — `firstImage` 가 있는 장소 12건을 상세로 전수 조회해 확인했다. 그래서 갤러리는
`images` 가 비면 `firstImage` 로 1장을 만든다 (`src/lib/place/gallery.ts`).

**대표 이미지 자리를 따로 만들지 않는다.** 이전 판의 "`firstImage` null → 플레이스홀더,
16:9 유지" 는 폐기된 #11 판의 잔재로, `DESIGN.md` §7-3(고정 높이 200/300)과 어긋난다.
제주 400건 표본에서 사진이 있는 곳은 119건(30%)뿐이라 — 출처가 `관광정보 API` 인 장소만
갖는다 — 회색 "이미지 없음" 면을 상세 첫 화면에 두면 그 면이 대부분 장소의 첫인상이 된다.

#### 0장이면 카테고리 일러스트 한 장 (#241 · #247)

**규칙이 바뀌었다.** 예전에는 `0장 = 갤러리 섹션 미렌더` 였다. 그 근거는 위의 회색 면이었고,
**그것은 회색 벽의 문제였지 자리의 문제가 아니었다.** [#241](https://github.com/8llow8llowMe/hondigagae/issues/241)
로 카테고리 일러스트가 들어와 벽이 사라졌으므로 자리를 되살린다 — 갤러리가 통째로 빠지면
상세가 제목부터 시작해 목록·홈과 리듬이 어긋난다.

- **회색 타일 폴백은 넣지 않는다.** 없애려던 바로 그 벽이 돌아온다.
- **자산이 없는 카테고리는 여전히 렌더하지 않는다** (`placeIllustration()` 이 `null`).
  상세와 목록이 갈리는 지점은 이제 이것 하나다 — 목록 썸네일은 그때도 타일을 남긴다
  (행 높이를 지켜야 한다).
- **일러스트 타일은 누를 수 없고 사진 출처 줄도 붙지 않는다.** 한국관광공사가 준 사진이
  아니라 우리가 그린 도형이라, 출처를 달면 없는 사진의 출처를 표기하게 된다.
- `galleryImages()` 는 **사진만 모은다.** 일러스트를 그 목록에 끼우면 장수 카운터(`1/8`)와
  뷰어가 그것을 사진으로 센다 — 자리 채우기는 `PhotoGallery` 의 몫이다.

**이미지 URL 은 `http://` 로 온다.** `next.config.ts` 가 `unoptimized: true` 라 그 URL 이
브라우저에 그대로 나가고, https 로 서비스되는 dev·prod 에서는 mixed content 로 차단된다 —
로컬(http)에서는 드러나지 않는다. `imageSrc()`(`src/lib/image/remote-host.ts`)가 허용 호스트
판정과 함께 https 로 올린다.

**`petInfo === null` 은 유일한 예외다** (아트보드 04-①). 동반 여부는 이 서비스의 핵심 질문이라,
섹션이 사라지면 "확인해 봤는데 없더라" 와 "확인조차 안 했다" 를 구분할 수 없다. 대신 점선
"정보 없음" 배지 + "동반 가능 여부가 등록되지 않았어요. 방문 전 전화로 확인해 주세요." +
전화 링크를 둔다 — 숨기는 대신 **다음 행동**을 준다.

### 반려견 동반 정보는 `dl` 이 아니라 체크 목록이다

여기 담기는 것은 라벨-값 표가 아니라 **동반 조건 문장**이다. 원문 라벨은 남기되(값만 두면
"유모차" 가 왜 적혀 있는지 알 수 없다) 각 줄이 하나의 조건으로 읽히게 한다.
가공값 2종(`allowanceScope` · `allowedPetSize`)이 맨 앞이고, `name` 이 아니라 **`description`**
을 쓴다 — `name` 은 이미 제목 옆 배지가 말하고 있다.

여기에 두 줄을 반드시 붙인다:

1. **반려견을 대입한 줄** — "체중 제한" 을 옮기는 것과 "몽실이(소형견)는 들어갈 수 있어요"
   까지 쓰는 것은 규정 전달과 판단 지원의 차이다. 판정은 backend `AllowedPetSize#allows` 를
   이식한 `src/lib/place/pet-size.ts` 가 한다.
   **`UNKNOWN` 을 "불가" 로 말하지 않는다** — 통과 여부는 `true` 지만 화면 문장은 "판단할 수
   없어요" 다. 모름을 확신처럼 말하면 그 문장이 거짓이 된다 (`allowsPetSize` 와 `petSizeVerdict`
   의 결과 축이 다른 이유)
2. **현장 확인 문구** — 동반 조건은 관광 API 값이라 최신이 아닐 수 있다. 이 줄이 없으면
   우리가 보증한 것으로 읽힌다

| 동반 유형 · 동반 가능 동물 · 동반 시 필요사항 · 기타 안내              | `petInfo.acmpyTypeCd` · `acmpyPsblCpam` · `acmpyNeedMtr` · `etcAcmpyInfo`     |
| 사고 대비사항 · 부대시설 · 비치 품목 · 구매 가능 품목 · 대여 가능 품목 | `petInfo.rela*`                                                               |
| 원천 표기                                                              | `intro.chkPet` — DTO 주석이 **"판단은 petInfo 우선"** 이라 참고 값으로만 둔다 |
| 사라진 장소 안내 · 잠긴 이유                                           | `delisted` — `detailDelisted*` 3종 (#146)                                     |

**용어는 `DESIGN.md` §1 을 따른다.** 우리가 쓰는 라벨은 "반려견" 으로 고정하고, 서버 원문에 "애완동물"
이 들어 있어도 **원문은 그대로 노출한다** (`styling-guide.md` §7).

## D5-2. 저작권 출처 표기

`cpyrhtDivCd` 는 **`TourApiPlaceCatalogAdapter` 에서만 채워진다.** 값이 있으면 원천이 TourAPI 라는 뜻이라
"한국관광공사" 표기가 성립한다 (문화정보원·식약처 원천은 이 값이 null 이다).

```text
사진·정보 출처: 한국관광공사 · 공공누리 제1유형 (출처 표시)
```

| `cpyrhtDivCd` | 표시                                   |
| ------------- | -------------------------------------- |
| `Type1`       | 공공누리 제1유형 (출처 표시)           |
| `Type3`       | 공공누리 제3유형 (출처 표시·변경 금지) |
| 그 외 문자열  | **출처 표시 대상** (기본값 폴백)       |
| `null`        | `sourceName` 으로 대체한다 (아래)      |

**`cpyrhtDivCd` 가 없는 원천은 `sourceName` 을 쓴다** ([#112](https://github.com/8llow8llowMe/hondigagae/issues/112)).
문화정보원·식약처 장소는 지금까지 출처 줄이 **아예 없었다** — #16 으로 `sourceName` 이 들어와 그 자리를 채운다.

```text
정보 출처: 식약처
```

**두 값을 겹쳐 쓰지 않는다.** `cpyrhtDivCd` 가 있는 쪽은 공공누리 표기 의무가 있어 **기관명**
("한국관광공사")이어야 성립하고, `sourceName` 의 "관광정보 API" 로 바꾸면 그 의무를 만족하지 못한다.
둘 다 없으면 줄 자체를 숨긴다.

**이 매핑은 예외적으로 허용된다.** "FE에 코드→한국어 매핑 테이블을 만들지 않는다"(`api-integration-guide.md` §6)
는 **서버가 `name` 을 함께 주는 enum metadata** 에 대한 규칙이다. `cpyrhtDivCd` 는 표시명이 없는 raw string
이라 FE 매핑 외에 방법이 없다. 모르는 코드 폴백을 반드시 둔다.

## D5-3. HTML 원문 처리 (보안)

`homepage` 와 `overview` 는 외부 원천의 **HTML 문자열**이다.

- **`dangerouslySetInnerHTML` 을 쓰지 않는다.** 공공 API라도 신뢰 경계 밖의 문자열이고, 배치가
  원문을 그대로 저장한다
- `parseHomepage()` 가 `href` 만 뽑는다. **`http` / `https` 만 허용**하고 `javascript:` 등은 거부한다.
  anchor 가 여러 개면 첫 번째만 쓰고, anchor 가 아니면 문자열 자체를 URL 로 시도한다
- `toPlainText()` 는 `<br>` 계열을 개행으로 바꾸고 나머지 태그를 제거한 뒤 엔티티를 되돌린다.
  렌더는 `whitespace-pre-line` 으로 하고 **잘라내지 않는다** (`styling-guide.md` §4)

## D5-4. 외부 이미지 호스트

`next/image` 는 `remotePatterns` 에 없는 호스트를 받으면 **런타임에 던진다.** 상세 화면은 대표 이미지가
가장 큰 요소라, 미등록 호스트 하나로 화면 전체가 죽는다.

`isAllowedImageHost()` 로 먼저 판정하고, 미등록이면 사진 없음과 **같은 자리**로 떨어뜨린다(카테고리
일러스트, 자산이 없으면 "이미지 없음" 타일). 허용 목록은 `src/lib/image/remote-host.ts` 에 두고
**`next.config.ts` 가 그 목록을 임포트한다** — 두 곳에 같은 목록을 적으면 반드시 어긋난다.

**호스트 목록은 실측으로 닫혔다** (2026-09-04 dev 게이트웨이 제주 400건 · [PR #228](https://github.com/8llow8llowMe/hondigagae/pull/228)).
`tong.visitkorea.or.kr` **하나뿐**이고, 이미지를 가진 119건이 전부 출처 `관광정보 API` 다 —
문화정보원 174건·식약처 102건은 `firstImage` 가 전부 null 이다.

**"사진이 없다" 와 "사진이 있는데 못 쓴다" 는 다른 갈래다** ([#67](https://github.com/8llow8llowMe/hondigagae/issues/67) B).
뒤쪽은 **실데이터로 만들 수 없어** 거절 경로가 단위 테스트에만 잠겨 있었다 — 위 실측대로 dev 에는
미등록 호스트 URL 이 없다. 그래서 mock 이 그 케이스를 한 곳에 싣는다
(`api/mock/place-data.ts` 의 `UNREGISTERED_HOST_IMAGE` — 애월 펜션). 예약된 `.invalid` 도메인이라
(RFC 2606) mock 이 남의 서버를 부르지 않는다.

> **거절만으로는 부족하다.** `imageSrc` 가 `null` 을 돌려주는 것까지가 절반이고, **호출부가 그
> `null` 을 받아 자리를 채우는 것**이 나머지다. 넘겨 버리면 `next/image` 가 런타임에 던져 화면
> 전체가 죽는다. 그래서 mock 이 이 장소를 늘 눈에 보이는 자리에 둔다.

## D5-5. 영업 상태 ([#294](https://github.com/8llow8llowMe/hondigagae/issues/294))

`intro.open24` · `intro.openNow` 를 **`운영시간` 원문 위의 판정값**으로 세운다.

### 자리

`기본 정보` 의 `운영시간` `InfoRow` **안**이다. 판정값이 위, 원문이 아래다.

```text
운영시간  [영업 중]
          09:00~17:50 (입장 마감 17:10)
```

별도 행(`영업 상태`)으로 떼지 않는다 — 판정값과 원문이 같은 크기로 서면 어느 쪽이 답인지
흐려진다. 제목 옆 히어로에도 두지 않는다: 그 자리는 적합도·산책 위험도가 사는 **판정 축**이고
(`DESIGN.md` — `MetricBadge` 는 판정 축 전용) 영업 여부는 판정이 아니라 속성이다.

**`useTime` 이 없으면 행 자체가 사라지고 판정값도 함께 사라진다.** 기존 동작을 그대로 둔
것이고, 근거 없이 판정만 오는 갈래는 **계약상 없다** — 백엔드가 `useTime` 원문을 파싱해
`weekly_hours_spec` 을 만들고 `openNow` 는 그 spec 에서 나온다
(`backend/docs/features/267-place-open-hours.md`).

### 조합 규칙

| `open24`         | `openNow` | 화면                       |
| ---------------- | --------- | -------------------------- |
| `true`           | 무엇이든  | **`24시간` 배지만**        |
| `false` / `null` | `true`    | `영업 중` — 무게를 준 배지 |
| `false` / `null` | `false`   | `영업 종료` — 그대로       |
| `false` / `null` | `null`    | **아무것도 그리지 않는다** |

**`open24` 가 `true` 면 `openNow` 를 버린다.** 24시간인 곳에 "지금 영업 중" 은 동어반복이고
"영업 종료" 는 모순이다. 그리고 **그 모순이 실제로 온다** — 긴급 시설 dev 응답의 청사약국이
`운영시간 10:00~24:00` 인데 `open24: true` / `openNow: false` 다(백엔드가 `24:00` 을 24시간으로
읽은 듯하다). 모순을 나란히 두면 사용자가 판단할 수 없고, 원문이 바로 아래 있어 확인할 수 있다.

`open24` 의 `null` 을 `false` 와 구분해 다루지 않는다. "24시간이라고 말할 근거가 없다" 와
"24시간이 아니다" 는 이 화면에서 같은 결과다.

### `null` 을 드러내지 않는다 — 긴급 시설과 갈리는 지점

긴급 시설(`features/emergency/facility-row.tsx` 의 `OpenStatus`)은 같은 `null` 을 **점선 배지**
("영업 여부 확인 필요")로 드러낸다. 여기서는 드러내지 않는다.

|                | 긴급 시설                               | 장소 상세                     |
| -------------- | --------------------------------------- | ----------------------------- |
| 원문이 없는 곳 | **있다** (`operatingHoursKnown: false`) | 없다 (계약상)                 |
| `null` 의 뜻   | "전화해서 확인해야 한다" — **정보**     | "원문을 읽으면 된다" — 노이즈 |

**실측이 이 결정을 밀었다.** dev 장소 200곳 전수 조회(2026-09-08)에서 `openNow` 가 **전부
`null`**, `open24` 가 **전부 `false`** 였다. 드러냈다면 `intro` 가 있는 131곳 전부가
"영업 여부 확인 필요" 배지 하나만 달고 있었고, 바로 아래에는 `매일 09:00~18:00` 이 적혀 있었다.

그래서 `messages/place.ts` 에 **"확인 필요" 문구를 만들지 않았다.** 문구가 없는 것이 이 규칙의
표시다.

### 표현

긴급 시설과 **같은 규칙**을 쓴다 — **등급 색 금지**(초록·주황은 산책 위험도 전용), 색이 아니라
**무게로 가른다**, `Badge tone="neutral"`.

**두 컴포넌트를 합치지 않았다.** 문구가 다르고(`진료중` vs `영업 중`) 위의 `null` 처리가
갈린다 — 프롭으로 분기를 실으면 양쪽 다 읽기 어려워진다. 대신 양쪽 주석이 서로를 가리킨다.

### `staleTime` 은 5분 그대로다

긴급 시설은 `openNow` 때문에 1분으로 내렸다(`use-nearby-facilities.ts`). 여기서는 내리지 않는다.

- 긴급 시설은 **"지금 당장 가야 하는"** 화면이고, 장소 상세는 **계획** 화면이다
- `openNow` 하나 때문에 전체를 1분으로 내리면 사진·소개·적합도까지 5배 자주 재조회한다
- 개·폐점 경계의 최대 5분 오차는 **판정값 바로 아래 원문이 있어** 사용자가 확인할 수 있다

근거는 `features/place/queries.ts` 의 `PLACE_QUERY_OPTIONS` 주석에도 남겼다.

### 로컬 확인은 mock 으로만 된다

**dev 는 이 화면을 보여주지 못한다** (위 실측). `lib/api/mock/place-detail-data.ts` 의 변이를
4개에서 **6개로 늘려** 4갈래를 전부 싣는다 — 영업 중 · 영업 종료 · 24시간(`openNow` 어긋남
포함) · 판정 근거 없음.

`MOCK_API=true` 로 `/places/{placeId}` 를 여러 번 열면 순환한다.

## D6. 접근성

- 대표 이미지는 **장식이 아니다** → `alt` 에 장소명을 넣는다. 추가 이미지는 `imgName` 이 있으면 그 값,
  없으면 `alt=""` (목록 카드의 썸네일과 달리 사진 섹션은 콘텐츠다)
- icon-only 버튼 없음. 모든 조작 대상이 텍스트 라벨을 가진다
- 키보드 순회: 뒤로 가기 → 전화 → 홈페이지 → 사진 링크 없음(정적) → 재시도(에러 시)
- 터치 영역 44px: "장소 목록으로" 링크와 `Button` (`size="md"` = 44px)
- 색 외 정보 전달: 반려견 동반 등급은 **배지 색 + 서버 `name` 텍스트**를 함께 쓴다.
  `leashRequired` 는 색이 아니라 "목줄 필요" 텍스트 배지로 표현한다
- `EmptyState` / `ErrorState` 의 제목은 heading 요소다 (기존 컴포넌트가 보장)
- 섹션 제목은 `h2`, 화면 제목은 `h1` — 건너뛰지 않는다

### 혼잡도 빈 상태 veil (#670)

- **덮이는 차트는 `aria-hidden` 이다.** 전부 `UNKNOWN` 인 30일을 그대로 두면 스크린리더가
  `9월 21일 월요일 정보 없음` 을 **30번** 읽는다 — 눈으로는 한 덩어리로 지나가는 것이
  보조기기에서만 30줄이 된다. `BodySkeleton` 이 칸 수를 숨기는 것과 같은 판단이다
- **`aria-hidden` 안에 초점 받는 것을 남기지 않는다** (`aria-hidden-focus`). 그래서 이
  갈래에서는 `ScrollRailArrows` 를 렌더하지 않고 `overflow-x-auto` 도 주지 않는다 —
  스크롤 컨테이너는 브라우저에 따라 키보드 초점을 받는다
- **veil 안 문구는 읽힌다.** `aria-hidden` 을 veil 밖(차트 래퍼)에만 건다. 이 카드에서
  보조기기가 듣는 것은 `제목 → 기간 → 자료가 아직 없어요 → 한산하다는 뜻은 아니에요` 넷이다
- veil 문구에 `role="status"` 를 쓰지 않는다 — 진입 시점의 정적 콘텐츠지 갱신이 아니다
- 문구 대비는 **합성면 기준**이다 (D1-2 의 기준 1). 흰 배경 수치를 그대로 쓰지 않는다

## D7. 테스트 케이스

### 순수 로직 (TDD)

| 대상                   | 핵심 주장                                                                                                                        |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `parseHomepage()`      | anchor 에서 href 추출 / anchor 여러 개면 첫 번째 / anchor 아닌 순수 URL 도 처리 / **`javascript:` 거부** / 빈 문자열·null → null |
| `toPlainText()`        | `<br>` `<br/>` `<BR>` → 개행 / 나머지 태그 제거 / `&amp;` `&lt;` `&nbsp;` 복원 / null → null / 태그만 있으면 null                |
| `copyrightLabel()`     | `Type1`/`Type3` 매핑 / **모르는 코드는 폴백 문구** / null → null                                                                 |
| `isAllowedImageHost()` | 등록 호스트 true / 미등록 false / URL 아님 false / 프로토콜 불일치 false                                                         |
| `isPlaceUnavailable()` | **`delisted: true` 는 200 으로 온다** / 404(병합)도 같은 결론 / 아직 못 받았으면 false / 500·401 은 판정하지 않는다 (#146)       |

### 렌더 분기 (`PlaceDetailSection`)

- **404 에서 재시도 버튼이 없다** / 서버 `resultMessage` 를 그대로 노출한다
- **5xx·무응답에서 재시도 버튼이 있다**
- 400 에서 재시도가 아니라 목록으로 안내한다
- `intro` null → "이용 안내" 섹션이 렌더되지 않는다
- `petInfo` null → "반려견 동반 정보" 섹션이 렌더되지 않는다
- `images` 빈 배열 + `firstImage` null → **카테고리 일러스트**로 자리를 채운다 (회색 면·사진 출처는 없다). 일러스트 자산이 없는 카테고리에서만 섹션이 렌더되지 않는다
- `overview` null → "장소 소개" 섹션이 렌더되지 않는다
- `intro` 는 있는데 내부 값이 전부 null → 섹션이 렌더되지 않는다
- 서버 enum `name` 을 그대로 렌더한다 (하드코딩 한국어가 아니다)
- **모르는 `petAllowanceType.code` 에서도 화면이 비지 않는다** (배지 톤 폴백)
- 하단 바가 `bottom-16` 과 `md:bottom-0` 을 함께 갖는다 — 탭바가 사라지는 `md` 부터 바닥에 붙는다 (#247)
- `leashRequired: false` → "목줄 필요" 배지가 없다
- 로딩 중에는 skeleton 만 나오고 본문·에러가 함께 나오지 않는다
- **`delisted: true` → 안내가 나오고 상세 정보는 그대로 남는다** (200 이라 빈 화면이 아니다)
- `delisted: false` → 안내가 없다 / **404 는 이 경로가 아니다** (빈 화면으로 간다)
- **영업 상태 4갈래** (D5-5 · [#294](https://github.com/8llow8llowMe/hondigagae/issues/294)):
  `openNow: true` → `영업 중` / `false` → `영업 종료` / **`open24: true` → `openNow` 가
  어긋나도 `24시간` 만** / **`openNow: null` → 배지가 아예 없다**
- **어느 갈래에서도 `useTime` 원문이 남는다** — 판정값은 위계를 가르는 것이고 원문을
  대체하지 않는다. `useTime` 이 null 이면 행이 사라져 판정값도 함께 사라진다

### 하단 바 (`PlaceDetailActionBar`)

- `delisted` → 잠긴 이유가 버튼 **위에** 나온다 (`disabled` 만으로는 이유를 알 수 없다)
- `delisted` + 미저장 → 담기·저장 **둘 다** 잠긴다
- `delisted` + 저장됨 → **담기만** 잠기고 `저장 해제` 는 살아 있다
- 평소에는 아무것도 잠기지 않는다

### 혼잡도 빈 상태 veil (`PlaceCongestionPanel`) — [#670](https://github.com/8llow8llowMe/hondigagae/issues/670)

node 환경 + `renderToStaticMarkup` 문자열 단언이다 (`testing-guide.md` §1). fixture 는 이미 있는 `congestionAllUnknown`(전부 `UNKNOWN` · `leastCrowded: null`)과 `congestion`(일부 `UNKNOWN`)을 쓴다 — 새 fixture 를 만들지 않는다.

**전부 `UNKNOWN` (`congestionAllUnknown`)**

| 주장                           | 단언                                                                                                                                                  |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 차트를 지우지 않는다           | 점선 트랙(`border-metric-unknown-500`)이 **여전히 있다**. 칸 수도 기간과 같다                                                                         |
| 문구가 veil **안**에 있다      | veil 요소의 클래스(`absolute inset-0`)에서 잘라 낸 뒤 조각에 `detailCongestionEmptyTitle` · `detailCongestionEmptyDescription` 이 **둘 다** 들어 있다 |
| 같은 말을 두 번 하지 않는다    | `detailCongestionEmptyTitle` 등장 횟수가 **1** 이다 (`split(...).length - 1`)                                                                         |
| 점선 설명을 겹쳐 내지 않는다   | `detailCongestionUnknownNote` 가 **없다** — 이 갈래는 점선의 뜻이 아니라 자료 부재를 말한다                                                           |
| 덮인 차트가 초점을 받지 않는다 | `overflow-x-auto` · `scroll-rail` 이 **둘 다 없다** — 스크롤 컨테이너가 없으면 화살표도 키보드 초점도 생길 자리가 없다                                |
| `aria-hidden` 은 차트에만      | veil 앞 조각에 `aria-hidden` 이 **있고**, veil 안 조각에는 **없다**. `role="status"` 도 없다                                                          |
| 기간 토글이 없다               | `detailCongestionExpand` · `detailCongestionCollapse` 가 **없다** (기존 단언 유지)                                                                    |
| 재시도가 없다                  | `<button` · `<a ` 가 **0개**, `messages.common.retry` · `detailCongestionErrorTitle` 도 없다                                                          |
| 덮을 차트가 없을 때            | `dailyCongestions: []` 면 veil 없이 문구만 선다 — `inset-0` 은 높이 0 이 되어 문구를 지운다                                                           |

> **화살표 라벨(`detailCongestionPrevDays` · `detailCongestionNextDays`)의 부재로 재지 않는다.**
> `ScrollRailArrows` 는 스크롤 여지를 **잰 뒤에만** 그려서 서버 렌더에서는 정상 갈래에서도
> 나오지 않는다 — 라벨 부재는 이 환경에서 언제나 참인 공허한 단언이다 (`testing-guide.md` §5).
> 화살표와 키보드 초점을 만들어 내는 **수단**(스크롤 컨테이너)을 대신 잰다. 실제로 뜨는지는
> `e2e/place-congestion.spec.ts` 가 본다.
>
> **`absolute inset-0` 로 잘라 내는 것이 성립하는 전제**는 "이 갈래에서 그 클래스를 내는
> 요소가 veil 하나" 라는 것이다 — 화살표를 렌더하지 않는 결정이 곧 이 단언의 전제다.
> 화살표를 되살리면 이 테스트가 먼저 깨진다. 그게 맞는 순서다.

**일부만 `UNKNOWN` (`congestion`)**

| 주장                 | 단언                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------- |
| veil 이 서지 않는다  | `detailCongestionEmptyTitle` · `detailCongestionEmptyDescription` 이 **없다**         |
| 기존 설명이 그대로다 | `detailCongestionUnknownNote` 가 있다 (기존 단언 유지)                                |
| 카드가 살아 있다     | `detailCongestionExpand` 또는 `detailCongestionCollapse` 가 있다 — 토글이 여전히 선다 |

**`UNKNOWN` 이 없을 때**: 위 셋 중 `detailCongestionUnknownNote` 도 없다 (기존 단언 유지).

`aria-hidden` 의 **포함 관계**(점선이 그 안에 있는가)는 문자열 단언으로 정확히 재기 어렵다 — veil 을 경계로 마크업을 갈라 `aria-hidden` 과 점선 트랙이 **둘 다 veil 앞 조각에** 있고 veil 안 조각에는 `aria-hidden` 이 없다는 것까지 잰다. 실제 DOM 포함 관계는 브라우저 실측으로 확인했다: 390·1280 모두 `aria-hidden` 컨테이너 안의 초점 가능 요소 0개, veil 안의 버튼·링크 0개 (D1-2 실측 표).

### mock 계층

- 상세가 **`PlaceDetail` 형태**를 돌려준다 (목록 타입이 아니다)
- 없는 장소는 **404 + `PLACE_002`** 다
- nullable 케이스(`intro` null / `petInfo` null / `images` 빈 배열)를 실제로 포함한다
- **delisted 장소를 한 곳 포함한다** — 404 가 아니라 200 + 플래그라 fixture 없이는 그 분기를 로컬에서 볼 수 없다 (#146)
