# 지도 보기 장소 미리보기 세부 명세

> 상위: `공통명세.md` S1 "장소 찾기 — 보기 전환과 필터". 이 문서는 **지도 보기에서 고른 장소의 미리보기**만 정한다.
> 이슈: [#1227](https://github.com/8llow8llowMe/hondigagae/issues/1227) · 짝 이슈 [#1226](https://github.com/8llow8llowMe/hondigagae/issues/1226)(방문 핵심 줄)
> 시안: [`docs/superpowers/specs/2026-10-07-place-map-preview-mockups.html`](../../superpowers/specs/2026-10-07-place-map-preview-mockups.html) — 착수 전 시안이다. 구현에서 달라진 점은 D6 에 적었다.

## D0. 화면 정의

- **경로**: `/places`(지도 보기). 고른 장소가 `?place={placeId}` 로 남는다. 인증 불필요.
- **왜**: 행을 누르면 핀만 강조되고, 무엇인지 더 알려면 상세로 갔다가 돌아와야 했다(지도 · 검색 영역을 잃는다).
  네이버 지도처럼 **목록 옆에서 "갈 만한가" 를 판단**하게 한다. 상세의 모든 정보를 옮기지 않는다.
- **켜는 곳은 `/places` 하나다** (`PlaceMapView` 의 `preview` prop). 담기 지도(`/plans/.../add`)는 켜지 않는다 — 행마다
  담기 버튼이 있고, 그 화면의 일은 "이 일정에 넣을 곳 고르기" 라 미리보기가 그 버튼과 같은 일을 두 번 한다.

## D1. 폭별 배치

| 폭        | 자리                                                             | 목록                                    |
| --------- | ---------------------------------------------------------------- | --------------------------------------- |
| ≥ 1280    | 목록 옆 — `left` = 16 + 400 + 탭 24 + 12 (`.map-preview-beside`) | 그대로                                  |
| 1024~1279 | 목록 자리(`left-4`) — 머리 줄에 `‹ 목록`                         | `lg:max-xl:invisible` (a11y · Tab 제외) |
| < 1024    | 목록 시트 자리 — 탭바 위, 높이는 내용만큼(`.map-preview-sheet`)  | 시트 `hidden` (언마운트하지 않는다)     |

- 데스크톱 패널은 목록 패널과 **같은 폭(400) · 같은 위아래 여백(`top-6` · `bottom-8`)** 이다.
- **옆자리는 목록 접기 탭(패널 밖 24)까지 비킨다.** 400 바로 옆(428)에 붙였을 때 미리보기가 탭을 덮어 목록을 접을 수 없었다(실측).
- **1280 부터 목록을 접었으면 펼치기 버튼(16 · 44) 오른쪽**에 선다(`.map-preview-after-handle`) — 버튼 자리에 서면 버튼을
  덮어 목록으로 돌아갈 길이 닫기 하나가 된다(리뷰 지적).
- **재검색 알약**도 1280 부터 미리보기가 목록 옆에 서면 남은 지도의 가운데로 옮긴다(`.map-research-beside-preview`) — 지도
  가운데가 미리보기 뒤라, 장소를 골라 확대한 바로 그 순간 뜨는 알약이 가려졌다.
- 모바일 시트 상한은 **목록 시트 `max` 와 같은 식**이다: `max(45dvh, 100dvh − 136 − 탭바)`. 136(`MAP_TOP_CONTROLS_INSET`)은
  헤더를 포함한 뷰포트 기준 값이라 `--header-h` 를 또 빼지 않는다(첫 구현이 두 번 뺐다).
- **1024~1279 에 3단을 두지 않는다.** 400 + 12 + 400 이면 지도가 300 남짓 남아 고른 핀 둘레가 안 보인다.
- 목록을 `inert` 가 아니라 `invisible` 로 감춘다 — `inert` 는 폭마다 갈라 걸 수 없다. `visibility: hidden` 도 a11y 트리와 Tab 순서에서 빠진다.
- 모바일 시트는 언마운트하지 않는다 — 닫으면 보던 목록 스크롤 · 단계 그대로 돌아온다.
- 면(배경 · 테두리 · 곡률 · 그림자)은 **담는 쪽(`place-map-view.tsx`)이 갖는다** — 지도 위에 뜨는 표면의 소유자가 그 파일이다(`token-usage.test.ts` FLOATING).

## D2. 담는 것

```text
‹ 목록(1024~1279)                     상세 보기 ›   ✕
[사진 한 장 — 데스크톱만, 높이 160]
수월봉                                  [적합도 여행 적합]
제주시 한경면 고산리 · 야외 · 1.2km      ← 목록 행과 같은 메타
상시 개방   064-710-6043   길찾기         ← 방문 핵심 줄 (#1226)
┌ 몽실이   여행 적합 / 근거 첫 줄       ← 반려견이 있을 때만
│ 동반     동반 가능 · 소형견
└ 지금 산책 안전 · 체감 22.7℃
[로그인 | 저장]  [일정에 담기]           ← 상세 하단 바 그대로
```

- **넣지 않는 것**: 혼잡도 30일 · 이용 안내 전문 · 장소 소개 전문 · 사진 모자이크. 상세의 몫이다.
- **두 겹으로 그린다.** 목록 행(`PlaceSummary`)으로 이름 · 사진 · 메타를 **즉시** 그리고, 상세 · 판정 응답이 오는 대로
  나머지를 채운다. 목록에 없는 id(공유 링크 · 재검색 밖)면 상세 응답으로 그린다.
- **판정 줄**: 동반 · 지금 산책은 상세 판정 요약과 **같은 함수**(`verdictSummaryLines`)다 — 같은 장소에 같은 문장.
  혼잡도 인자는 빈 값으로 넘겨 그 줄을 만들지 않는다. 요약 컴포넌트를 그대로 쓰지 않는다: `lg:hidden` 이고 줄마다 같은
  문서 안 앵커로 뛴다.
- **적합도 근거는 반려견이 있을 때만** — 상세도 게스트에게 점수 · 근거를 보이지 않는다. 등급은 이름 옆 배지가 말한다.
- **하단 바는 `PlaceDetailActionBar` 를 그대로 쓴다** — 저장 · 담기 · 미로그인 `로그인` · 사라진 장소 잠금(#146)이 한 곳에 있다.
- **`상세 보기` 는 머리 줄이다** — 하단 바에 세 칸을 두면 390 에서 담기가 좁아진다(시안 검토 포인트 9).
- 로그인 안내 시트의 `returnTo` 는 상세 고정이다 (`PlaceLoginPromptSheet`) — 로그인 뒤에는 상세로 돌아가 담기를 잇는다.

## D3. URL — `?place={placeId}`

`lib/url/place-preview.ts` · `features/place/use-place-preview.ts`.

- **`router` 가 아니라 `window.history` 로 바꾼다.** `/places` 서버 페이지는 `searchParams` 로 목록을 프리페치한다 —
  `router.replace` 면 고를 때마다 RSC 를 다시 받는다. 네이티브 `pushState`/`replaceState` 는 `useSearchParams` 와
  동기화되고 서버를 부르지 않는다. **실측(2026-10-07, 5174)**: 열기 · 바꾸기 · 닫기 동안 RSC 요청 0건.
- **처음 열 때 push · 바꿀 때 replace · 닫기는 쌓은 칸이면 `back()`.** 실측 (`navigation.currentEntry.index`):
  열기 2→3, 다른 장소 3→3, ✕ 3→2, 다시 열고 브라우저 뒤로가기 → 2 · 패널 닫힘.
- **쌓은 칸 표시는 ref 다.** `history.state` 에 실으면 안 된다 — **Next 가 `pushState` 를 가로채 데이터를 자기 내부 키
  (`__NA` · 트리)로 갈아 끼운다** (실측). 새로고침 · 공유 링크로 들어오면 쌓은 칸이 없어 닫기가 replace 로 간다.
- **무엇을 할지는 순수 함수가 정한다** (`placePreviewHistoryAction`) — 테스트가 갈래를 잠근다.
- **쌓은 칸 표시는 뒤로 · 앞으로 가기(`popstate`)에 버린다.** 쌓은 칸을 지나 공유 링크로 들어온 칸에 돌아왔는데 표시가
  남아 있으면 ✕ 가 back 해서 사이트 밖으로 나간다(리뷰 재현). 버리면 최악이 "칸 하나가 남는다" 다.
- **장소 id 모양이 아니면 읽지 않는다** (`isPlaceId`) — 손으로 만든 주소가 조회를 쏘지 않는다.
- **필터를 바꾸면 닫힌다.** `placeFilterHref` 가 `place` 를 싣지 않는다 — 결과 목록이 바뀌는 순간이라 의도다. 보기 전환
  링크도 싣지 않는다. 쌓은 칸 위에서 필터를 바꾸면 `router.replace` 가 그 칸을 필터 칸으로 덮어, 그때의
  뒤로가기는 "필터 이전으로" 가 된다 — 드문 순서라 받아들인다.

## D4. 조회

- **공유 링크로 들어오면 상세는 서버가 받는다** (`/places` 페이지, architecture-guide.md §9). 판정 둘(적합도 · 산책)은
  반려견 조건이 클라이언트 스토어에 있어 서버가 같은 key 를 만들 수 없다 — 클라이언트가 묻는다(§9 표에 예외로 적었다).
- 상세 · 적합도 · 산책 위험도를 **상세 화면과 같은 query key** 로 건다 — 같은 반려견 조건(`useSelectedPet` →
  `toPetCondition`)이어야 key 가 겹친다. `상세 보기` 로 넘어가면 첫 화면이 캐시로 뜬다.
- **패널이 마운트될 때만 조회한다** — 고르지 않은 행 · 마우스를 올린 행은 부르지 않는다. 실측: 공유 링크 진입에서
  BFF 요청은 `places/{id}` · `suitability` · `walk-safety` 3건.
- 부모가 `key={placeId}` 로 마운트한다 — 장소를 바꾸면 `담았다` · 시트 상태가 새로 시작한다.
- **줄마다 따로 실패한다.** 판정 하나가 죽으면 그 줄만 빠진다. 목록에도 없고 상세도 못 받으면 `장소 정보를 불러오지
못했어요` · `상세 보기` · 닫기만 남는다 — 재시도는 상세 화면이 갖는다(404 는 빈 화면, 5xx 는 재시도로 제대로 가른다).

## D5. 지도 카메라 — 고른 핀을 미리보기 밖에 둔다

- **문제**: 1440 에서 목록 + 미리보기가 왼쪽 850px 남짓을 덮어, 정중앙(720)으로 옮긴 핀이 미리보기 뒤였다.
- **해결**: `MapCanvas` 의 `selectedOffset` — 고르는 순간 덮인 크기를 재서, 핀을 **덮이지 않은 띠의 가운데**에 둔다
  (`lib/map/offset-center.ts`, 카카오 `getProjection()`). 데스크톱은 `x = (패널 오른쪽 − 지도 왼쪽) / 2`. 모바일은 위
  (검색 · 보기 전환 `MAP_TOP_CONTROLS_INSET`)와 아래(시트)가 다 덮여 그 사이 띠의 가운데다 — 띠가 없으면 옮기지 않는다.
- **확대 전에, 지금 단계로 잰다.** 좌표 차이를 `2^(최종 단계 − 지금 단계)` 로 줄여 쓴다(카카오 단계는 한 칸마다 배율 두 배).
  확대가 끝난 뒤 투영을 읽는 첫 구현은 **지도 리뷰가 막았다** — 예약이 마지막 프레임보다 먼저 오거나 숨겨진 탭에서
  애니메이션이 멈추면 이전 배율로 재게 되고, 9 → 5 면 16배가 틀어져 핀이 화면 밖으로 나간다.
- **묶음 마커 클릭도 같은 오프셋을 쓴다** — 미리보기가 열린 채 펼치면 펼친 자리가 미리보기 뒤였다.
- **공유 링크(`?place=`)로 들어와도 카메라가 간다.** 선택이 첫 렌더부터 있는데 그때는 지도가 없어 선택 effect 가
  돌아갔다 — effect 가 `status`(`loading → ready` 한 번) 도 본다. 실측: 진입 뒤 단계 9 → 5. `pins` 는 의존성에 넣지 않는다(#240).
  고른 장소가 지금 핀 목록에 없으면(재검색 밖) 카메라는 옮기지 않고 미리보기만 연다.
- **고르는 순간 부른다** — 폭마다 배치가 갈리고 시트 높이는 내용만큼이라 값으로 넘기면 늘 한 박자 늦다.
- **실측(1440, 축소 모션 갈래)**: 핀 화면 좌표 (1134, 481) = 기대값(미리보기 오른쪽 영역 가운데) (1134, 482).
  **애니메이션 갈래의 마지막 이동은 실측하지 못했다** — 브라우저 패널이 숨겨져 rAF 가 멈춘 상태였다(아래 함정). 계산은
  단위 테스트(`offset-center.test.ts`)가 잠근다.
- **실측(375, 위 컨트롤 띠를 빼기 전)**: 핀 y 256, 미리보기 시트 위 345 — 보인다(오프셋이 없으면 지도 정중앙 ≈ 406 이라 시트 뒤였다). 기대값(201)과의
  차이는 **고르는 순간의 시트가 상세 응답 전이라 더 낮았기** 때문이다. 핀이 가려지지만 않으면 되므로 응답 뒤 다시 옮기지 않는다
  — 두 번 움직이는 지도가 더 거슬린다.
- 미리보기가 없을 때(담기 지도 · 닫힘)는 정중앙 그대로다 — 목록 패널만 있을 때의 동작은 이 이슈가 바꾸지 않는다.

> **측정 함정**: 브라우저 패널이 숨겨져 있으면 카카오 이동 · 확대 애니메이션(rAF)이 진행되지 않아 지도가 안 움직이는 것처럼
> 보인다. `matchMedia('(prefers-reduced-motion: reduce)')` 를 페이지에서 참으로 바꾸면 즉시 이동 갈래라 숨겨진 채로 잴 수 있다.

## D5-1. 포커스

- **열 때**: 포커스가 보이지 않게 된 요소(1024~1279 의 `invisible` 목록 행 · 모바일 `hidden` 시트 행)에 남아 있으면 미리보기
  이름(`h2 tabIndex=-1`)으로 데려온다. 1280 부터는 행이 보이므로 **빼앗지 않는다** — 목록을 훑는 중이다. 폭이 아니라 "지금
  포커스가 보이는가" 로 가른다.
- **닫을 때**: 포커스가 `body` 로 떨어졌으면(✕ 가 언마운트) 고른 행(`data-place-id`)으로 돌려준다. 사용자가 이미 다른 곳으로
  옮겼으면 건드리지 않는다.
