# 지도 핀 — 카테고리 아이콘 원 세부명세

> 상태: **명세 확정 · 구현 전** ([#1280](https://github.com/8llow8llowMe/hondigagae/issues/1280), 2026-10-08) — 사용자 결정 C안

## D0. 무엇을 고치는가

지금 장소 핀(`.map-pin`)은 **흰 이름표뿐**이다 (`lib/map/pin-content.ts` · `app/globals.css` `.map-pin`).

1. **카카오 기본 지명과 구분되지 않는다.** 흰 바탕 · 검은 글자라 `제주국제공항` · `삼양` 같은 카카오 표기와
   같은 무게로 읽힌다. 카카오 JS SDK 는 기본 POI 를 숨기는 방법이 없다 — 우리 표시가 튀어야 한다.
2. **좌표를 가리키는 점이 없다.** 이름표 상자뿐이라 장소가 상자 가운데인지 아래인지 모른다.
3. **무엇인지 말하지 않는다.** 이름 외에 카테고리가 지도에 없다.
4. **섬 전체 보기에서 이름 20개가 겹친다.** `/places` 첫 화면은 섬 전체(level 10 근처)다.
5. **묶음 원(`2`)이 회색 테두리라 도로 번호처럼 읽힌다.**

## D1. 결정 (사용자 2026-10-08)

| 질문            | 결정                                                                  | 근거                                                                                   |
| --------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 핀이 더 말할 것 | **카테고리 아이콘**                                                   | 무엇인지가 먼저 읽힌다. 동반 여부는 목록 · 미리보기가 말한다                           |
| 모양            | **C안** — 멀리선 아이콘 원만, 가까우면 원 + 이름 알약                 | 섬 전체에서 이름이 겹치지 않는다. 이름을 맨글자로 두면(B안) 카카오 표기와 다시 닮는다  |
| 이름이 서는 줌  | **500m 축척(카카오 level ≤ 6)**                                       | 동네 하나를 보는 정도. 미리보기 확대(250m · level 5)에서는 주변 이름이 다 보인다       |

## D2. 모양과 상태

| 상태                                    | 원                                                                  | 이름                                                                          |
| --------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 기본                                    | 지름 **26** · `--brand-600` 채움 · 흰 테두리 2 · `--shadow-md`      | level ≤ 6 에서만 선다                                                         |
| 이름 (level ≤ 6 · 호버 · 포커스 · 선택) | 그대로                                                              | 원 오른쪽 **4** · 흰 알약(`--bg` · `--border` · 12px/600 · 최대 160 · 말줄임) |
| 선택                                    | 지름 **34** · `--fg` 채움                                           | 검은 알약(`--fg` · `--fg-inverse`) · 13px · 최대 220 · 캡션(거리) 유지        |
| 흐림 (담기 지도의 이미 담은 곳)         | `--fg-subtle` 채움                                                  | 글자 `--fg-muted`                                                             |
| 묶음 (긴급 지도와 공유)                 | 지름 32 · `--bg` 채움 · **`--brand-600` 테두리 2** · 겹친 원 그대로 | 숫자 `--brand-700` · 12px/700 · `99+` 상한 그대로                             |

- **원의 중심이 좌표다.** 오버레이에 넘기는 상자는 **원(26 · 선택 34) 하나**이고 `xAnchor 0.5` · `yAnchor 0.5` 다.
  이름 알약은 그 상자 밖에 `position: absolute`(`left: 100% + 4`)로 매단다 — 이름이 서고 사라져도 원이 움직이지 않는다.
- **아이콘**은 흰색(`--fg-inverse`) 14px — 선택 원은 18px.
- **누르는 자리는 44** — 원 26 에 `::before` 로 넓힌다(`DESIGN.md` §0-4 의 `inset` 계산과 같은 방식). 이름이 선
  때는 원 + 알약 전체가 누르는 자리다.
- **z 순서**: `stacking.ts` 그대로(묶음 > 선택 > 일반). 호버 · 포커스로 이름이 선 핀은 일반 핀 층 안에서 위로
  올리지 않는다 — 카카오 `CustomOverlay` 의 zIndex 를 호버마다 바꾸면 겹친 이웃이 깜빡인다. **겹침은 받아들인다.**

### D2-1. 아이콘 9종

`contentType.code` 로 고른다 — **한국어 `name` 으로 고르지 않는다** (`lib/place/illustration.ts` 와 같은 규칙).

| 갈래                            | 아이콘(뜻)      |
| ------------------------------- | --------------- |
| `TOURIST_SPOT`                  | 산 · 경치       |
| `RESTAURANT`                    | 수저            |
| `RESTAURANT` + 원천 분류 `카페` | 커피잔          |
| `LODGING`                       | 침대            |
| `CULTURE`                       | 기둥 건물       |
| `FESTIVAL`                      | 깃발            |
| `COURSE`                        | 발자국 길       |
| `LEPORTS`                       | 자전거          |
| `SHOPPING`                      | 쇼핑백          |
| 그 밖                           | `PinIcon`(범용) |

카페 판정은 목록 행 유형 낱말(`placeTypeLabel`, `features/place/filter-labels.ts`)과 **같은 판정**이다 — 그 안의
조건(`RESTAURANT` + 원천 분류 `카페`)을 `isCafePlace` 로 뽑아 둘이 함께 쓴다. 칩으로 카페를 골랐는데 핀이
수저면 고른 것과 다른 말을 한다(#1181 과 같은 결함).

아이콘은 `components/icons` 와 같은 결(24 격자 · 선 1.5 · `currentColor`)로 새로 그린다.

### D2-2. 이름이 서는 조건

`level ≤ 6` **또는** 선택 **또는** 호버 · 키보드 포커스(`:hover` · `:focus-visible`, CSS).

- level 은 `map-canvas.tsx` 가 이미 핀 effect 의 의존값으로 들고 있다 — 이름 상시 표시 여부를 `PinContentInput` 에
  넘긴다(`named`). 호버 · 포커스는 JS 없이 CSS 가 연다.
- **이름이 화면에 없어도 접근 이름은 장소명이다** — 버튼의 `aria-label` 이 늘 이름을 말한다.

## D3. 범위

| 핀                               | 이번 범위  | 이유                                                                                       |
| -------------------------------- | ---------- | ------------------------------------------------------------------------------------------ |
| `/places` 지도                   | **바뀐다** |                                                                                            |
| 담기 지도(`plan-add-place-view`) | **바뀐다** | 같은 `PlaceMapView` · 흐림 갈래가 여기서 쓰인다                                            |
| 묶음 원                          | **바뀐다** | 긴급 지도와 공유 — 두 화면이 함께 바뀐다(정본 `긴급시설-목록우선-세부명세.md` D10 도 갱신) |
| 긴급 시설 핀                     | 그대로     | 병원 · 약국 토글(후속 D)에서 **장소 원과 다른 모양**(십자 사각 등)으로 따로 정한다         |
| 동선 순번 핀 · 기준점 이름표     | 그대로     | 다른 일을 하는 표시다(`DESIGN.md` §0-4)                                                    |
| 상세 미니맵 · 올레 시작점 지도   | 그대로     | 누를 것이 없는 정적 핀(`map-pin-static`)                                                   |

**아이콘은 옵트인이다.** `MapPin` 에 `icon` 하나를 더하고 그것을 가진 핀만 원 모양이 된다. 지도 컴포넌트는
카테고리를 모른다 — 고르는 일은 장소 도메인(`lib/place/pin-icon.ts`)이 한다(`component-guide.md` §9).

## D4. 구조

- `MapPin` · `PinContentInput` 에 `icon?: MapPinIcon`(아이콘 키 문자열 유니온) · `named?: boolean`.
- `pinContent` 는 아이콘이 있으면 `.map-pin-dot` 갈래의 서술자를 낸다 — 클래스 · 이름 · 접근 이름 · 아이콘 키.
- **아이콘 마크업은 고정 SVG 다.** `markerElement` 가 키로 정적 SVG 문자열을 골라 붙인다 — 사용자 데이터가
  마크업에 섞이지 않는다(이름은 지금처럼 `textContent`). `map-canvas-marker-wiring.test.ts` 의 통로 단일성은 그대로.
- 핀 effect 는 이미 `level` 에 의존한다(묶음 격자가 줌마다 달라서다) — `named` 를 같은 자리에서 계산해 넘기면
  줌이 바뀔 때 함께 다시 그려진다. 새 의존값이 생기지 않는다.

## D5. 접근성

- 핀은 `<button aria-pressed>` 그대로, 접근 이름은 늘 장소명.
- **대비** (`contrast.test.ts` 에 잠근다):
  - 흰 아이콘 / `--brand-600`(#237A54) — 약 5.3:1
  - 원 `--brand-600` / 카카오 밝은 타일 — 3:1 이상(WCAG 1.4.11). 흰 테두리 2 가 어두운 타일 위 경계를 준다
  - 묶음 테두리 `--brand-600` / `--bg` · 숫자 `--brand-700` / `--bg`
- 키보드 포커스는 이름을 연다 — 지금 어느 핀에 있는지 보인다.

## D7. 남는 위험

- **level ≤ 6 에서 제주시내처럼 빽빽한 곳은 이름 알약이 겹친다.** 충돌 회피(라벨 배치)는 하지 않는다 — 묶음이
  level 4 이하에서 풀리므로 level 5–6 에서는 묶음이 먼저 덜어 준다. 실측에서 심하면 후속으로 다룬다.
- 아이콘 9종은 새로 그리는 자산이다 — 14px 에서 서로 구별되는지 실측으로 본다.
