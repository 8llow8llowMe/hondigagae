> 진단 근거: [`docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md`](../../superpowers/specs/2026-09-15-ui-ux-audit-design.md) **D-1 (P1)**, 시안 §2.

### 바꾸는 것

1. **제목 카드 안, 태그 줄 아래**에 판정 요약 3줄을 둔다. 각 줄은 아래 세부 섹션으로 가는 **앵커**다.
2. `--gallery-h-mobile` 214 → **200**.

### 바꾸지 않는 것

- 섹션 순서 · 카드 경계 · 혼잡도 패널 위치(#603) · 판정 카드 내용 · 데스크톱 2단 배치

## D1. 레이아웃

```text
[제목 카드 — Surface titleId=place-detail-heading]
  ┌ 갤러리 (모바일 200 / 데스크톱 300) ─────────────────┐
  └─────────────────────────────────────────────────────┘
  수월봉                                      [여행 적합]   ← h1 + 적합도 배지
  제주시 · 관광지                                           ← metaLine
  (동반가능) (소형) (실내 여부 미확인)                       ← 태그 줄
  ──────────────────────────────  ← L2 1px 구분선 (§0)
  동반        정보 없음 · 방문 전 확인해요              >   ← 판정 요약 3줄 (lg:hidden)
  지금 산책   안전 · 체감 25.5℃                        >
  덜 붐비는 날 9월 21일 (월)                            >
[혼잡도 카드] [기본 정보] [지도] … [판정 카드] [반려견 동반 정보] …
```

- **제목 카드 안이다 — 새 L1 카드를 만들지 않는다.** 이 세 줄은 "이 장소가 무엇인가" 의 답이라 이름과 한 몸이다. 카드를 새로 쪼개면 `§0 카드 경계는 이야기 단위` 에서 이름과 답이 다른 이야기가 된다.
- **판정 카드가 적합도·산책을 `1px 선` 으로 잇는 것과 같은 장치**다 (`place-detail-section.tsx` 의 판정 카드 주석). 태그 줄과 요약 줄 사이에 L2 구분선 하나.
- **`lg:hidden` — 모바일·태블릿 전용이다.** ≥1024 는 좌측 레일이 적합도·산책을 이미 첫 화면에 올리고 혼잡도는 본문 맨 위에 있어, 요약을 또 그리면 **같은 답이 한 화면에 두 번** 선다. `display:none` 이라 스크린리더에서도 사라진다 — DOM 을 폭마다 나누지 않는다는 이 화면의 규칙(`.rail-layout-detail` 주석)을 지키면서 중복만 없앤다.
- 줄 높이는 **최소 44px** (DESIGN.md §7 터치 영역). 3줄 + 구분선 ≈ 148px.

## D3. 데이터 흐름

**새 API 를 부르지 않는다.** 세 줄 모두 화면이 이미 가진 prop 에서 읽는다.

| 줄            | 출처                                                         | 이미 누가 쓰나              |
| ------------- | ------------------------------------------------------------ | --------------------------- |
| 동반          | `place.petAllowanceType` · `place.petInfo`                   | 태그 줄 · 반려견 동반 섹션  |
| 지금 산책     | `walkSafety.data.walkSafetyLevel` · `feelsLikeCelsius`       | `PlaceWalkSafetyPanel`      |
| 덜 붐비는 날  | `congestion.data.leastCrowded`                               | `PlaceCongestionPanel`      |

- **세 판정은 따로 실패한다** (`PlaceDetailSectionProps` 주석). 한 줄이 죽어도 나머지 두 줄은 선다.
- **`leastCrowded` 를 FE 가 다시 고르지 않는다** — 서버 `CongestionSnapshot.leastCrowded` 가 한 곳이다 (`insight.ts` 주석). 요약도 그 값만 읽는다.
- **날짜 표기는 `splitDay` 를 재사용한다** (`lib/insight/congestion.ts`). 혼잡도 패널과 같은 문구가 나와야 한다.

## D4. 상호작용 · 문구 (확정)

### D4-1. 줄 구성

| 줄            | 라벨          | 값 (예)                    | 앵커 대상 id                  |
| ------------- | ------------- | -------------------------- | ----------------------------- |
| 1             | `동반`        | `정보 없음 · 방문 전 확인해요` | `place-pet-info-heading`      |
| 2             | `지금 산책`   | `안전 · 체감 25.5℃`        | `place-walk-safety-label`     |
| 3             | `덜 붐비는 날` | `9월 21일 (월)`            | `place-congestion-heading`    |

### D4-2. 동반 줄 (항상 있다)

`place` 가 없으면 이 화면 자체가 렌더되지 않으므로 **동반 줄은 언제나 선다.**

| `petAllowanceType.code` | 값                                  |
| ----------------------- | ----------------------------------- |
| `UNKNOWN`               | `정보 없음 · 방문 전 확인해요`      |
| 그 외                   | 서버 `name` (+ `petInfo` 가 있으면 ` · {allowedPetSize.name}`) |

- **`UNKNOWN` 을 "불가" 로 단정하지 않는다** — 목록 행·태그 줄과 같은 규칙(#530). 태그 줄은 `UNKNOWN` 배지를 **감추지만** 요약 줄은 **말한다**: 감추는 이유는 배지 옆 태그에 걸려 읽히기 때문이고, 여기서는 그것이 답 자체다.

### D4-3. 지금 산책 줄

| 상태                    | 표시                                  |
| ----------------------- | ------------------------------------- |
| `loading`               | 스켈레톤 줄 (자리 유지)               |
| `failed` 또는 `data === null` | **줄을 만들지 않는다**          |
| 성공                    | `{walkSafetyLevel.name} · 체감 {feelsLikeCelsius}℃` |
| 성공 · `feelsLikeCelsius === null` | 등급만 (`0.0℃` 로 채우지 않는다 — 영하로 읽힌다) |

**실패한 줄을 남기지 않는 이유**: 아래 판정 카드가 이미 재시도 버튼을 갖고 있다. 요약에 죽은 줄을 두면 앵커가 갈 곳 없는 링크가 된다.

### D4-4. 덜 붐비는 날 줄

| 상태                            | 표시                       |
| ------------------------------- | -------------------------- |
| `loading`                       | 스켈레톤 줄                |
| `failed` 또는 `leastCrowded === null` | **줄을 만들지 않는다** |
| 성공                            | `{month}월 {day}일 ({weekday})` |

**`leastCrowded === null` 은 "한산" 이 아니라 "아는 날이 하나도 없다" 다** (`insight.ts` 주석). 혼잡도 패널이 자리를 만들지 않는 것과 같게 간다.

### D4-5. 앵커

- 각 줄은 `<a href="#{id}">`. 같은 문서 안 이동이라 `next/link` 를 쓰지 않는다.
- 앵커 대상에 **`scroll-mt-20`** — 헤더가 `sticky top-0 h-14` 라 없으면 제목이 헤더 뒤로 들어간다. 약관 목차(`legal-document-view.tsx`)가 같은 이유로 같은 값을 쓴다.
- 우측 `ChevronRightIcon size={16}` — 이동 항목이라는 신호. 마이페이지·`/about` 이동 행과 같다.

## D6. 접근성

- 블록은 `<ul>` / `<li>` — 세 줄은 목록이다. 쉼표로 이은 한 문장이면 스크린리더가 한 덩어리로 읽는다 (`/about` 출처 목록과 같은 근거).
- 각 링크의 접근 이름은 **라벨 + 값**이 이어 읽힌다 (`동반, 정보 없음 · 방문 전 확인해요`). 값만 읽히면 무엇의 답인지 모른다.
- 블록에 `aria-label` 로 이름을 준다 — 제목(h) 을 새로 만들면 `h1` 바로 아래 `h2` 가 생겨 카드 제목 위계가 흔들린다.
- 색만으로 등급을 전하지 않는다 — 등급어(`안전`·`주의`)가 글자로 있다.
- 터치 영역 44px.

## D8. 미결 사항

- **적합도 줄은 넣지 않는다.** 이름 옆 배지가 이미 적합도를 말하고, 축 라벨 문제는 #652(G-1)가 따로 다룬다. 요약에 넣으면 같은 화면에서 `여행 적합` 이 두 번 선다.
- **데스크톱에 요약을 둘지**는 #652 이후 다시 본다. 축 라벨이 붙으면 레일 판정과 요약의 어휘가 달라질 수 있다.
- 갤러리 200 은 **토큰 한 줄**이라 되돌리기 쉽다. 342×200 = 1.71 로 16:9(1.78)에 가까워진다.
