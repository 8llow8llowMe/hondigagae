# 저장한 장소 세부 명세

> 이슈 [#127](https://github.com/8llow8llowMe/hondigagae/issues/127) · 아트보드 `혼디가개 저장한 장소.dc.html` (표면 2a)
> 계약 근거: backend plan-service favorite 컨텍스트 **소스 실측** — `FavoriteWebController` ·
> `FavoritePlacesResponse` · `FavoritePlaceItem` (`origin/develop` `c57a0da`, 2026-09-01).
> 백엔드 미기동 상태라 Swagger 대신 소스가 근거다.

## D0. 화면 정의

장소 상세의 저장(북마크) 토글이 쌓이는 곳이다. 저장은 #118 로 되는데 **다시 찾아갈 화면이
없어서** 저장이 사실상 쓰이지 않는 기능이었다.

이 목록은 AI 일정 생성의 `pinnedPlaceIds`(즐겨찾기 우선 반영)가 읽는 원천이기도 하다 —
다만 **그 배선은 이 화면이 하지 않는다** (D8-1).

**라우트는 `/favorites` 다.** `/mypage/favorites` 가 아닌 이유가 둘이다.

1. 이슈 체크리스트가 `PROTECTED_PATHS` 등록을 과제로 넣었다. `/mypage` 하위였다면 이미
   덮여 있어 할 일이 아니다.
2. `/mypage` 레이아웃은 `max-w-screen-md` 설정 목록인데, 아트보드 03 은 1440 전폭에
   1200 이상 2열 그리드를 요구한다. **컨테이너가 맞지 않는다.**

진입점은 아트보드대로 둘이다 — 모바일은 내 정보(마이페이지) 안의 행, 데스크톱은 아바타
팝오버. 탭바는 4개 고정이라 늘리지 않는다 (전역nav-세부명세 D4-1).

## D1. 레이아웃

**3층 표면(3a)이다** — L0 바닥 위에 **카드 하나**, 그 안에 목록이 든다 (`DESIGN.md §0`,
이슈 #462). 2a 헤더 바(`h-14 border-b`)와 전폭 행 목록은 걷었다.

| 폭                    | 구성                                                                                                           |
| --------------------- | -------------------------------------------------------------------------------------------------------------- |
| 모바일 (~767)         | 카드가 **전폭으로 내려앉는다**(radius·좌우 테두리 없음). 카드 머리에 제목 + `최근 저장순 · N/100곳`            |
| 태블릿 (768~1279)     | 카드 1열. 바닥 여백 24(`SurfaceStack`), 카드 안 좌우 인셋 20(`INSET_CLASS.card`)                               |
| 데스크톱 (1280~ `xl`) | **카드 안 2열 그리드.** 한 행이 1360까지 늘어나면 이름과 해제 버튼이 눈으로 이어지지 않는다 (아트보드 03 주석) |

**쌓기는 1440 캡 안이다**(`SurfaceStack className="content-container"`). 아트보드 03 은 "전폭
가변" 을 전제했지만 그것은 **1440 캡 규약(`DESIGN.md §7`, #376)보다 앞선 전제**였고, §7 은
전폭을 지도 화면에만 허용한다. 캡 없이 두면 같은 페이지의 헤더·푸터(`content-container`)와
본문이 갈린다 — **1920 실측에서 헤더 로고 x=277 대 카드 제목 x=45** 였다(#462). 캡은 바닥이
아니라 쌓기에 건다: `Canvas` 에 걸면 캡 바깥이 흰색으로 남는다(§0).

2열 접기 근거는 캡 안에서 그대로 성립하고(1280~1440), 캡이 붙으면 **행 폭이 유한해진다** —
캡이 없을 때 2560 에서 트랙이 1255 까지 자라 "1360 이면 이어지지 않는다" 는 근거가 스스로
무너지던 것이 사라진다.

**2열 규약은 행이 아니라 목록이 갖는다** (#462). 2a 때는 행이 `last`·`lastGridRow`·
`columnDivider` 세 prop 으로 선을 직접 그었고, 그래서 **행 수와 자기 위치를 아는 호출자만**
목록을 그릴 수 있었다. 지금은 `SurfaceList columns={2}` 가 `.surface-list-2col`
(`app/globals.css`) 하나로 맡는다 — 2열에서 어긋나는 것은 두 군데뿐이다: 첫 시각적 행의
**오른쪽 칸 위선**과 **열 사이 세로선**(오른쪽에 짝이 있을 때만). 3번째 항목부터는 1열과
같은 `li+li` 규칙이 맞게 당긴다.

**접는 지점은 아트보드의 1200 이 아니라 `xl`(1280) 이다.** 1200 짜리 커스텀 breakpoint 를
새로 만들지 않았다 — 이 화면 하나 때문에 토큰이 늘면 다음 사람이 어느 축을 써야 하는지
모른다. 아트보드의 근거("1440 에서 행이 1360까지 늘어난다")는 1280 에서도 그대로 성립한다.

## D2. 컴포넌트 구성

```
app/(main)/favorites/page.tsx          Canvas(L0) + SurfaceStack + sr-only h1 + 서버 프리페치
  ├ loading.tsx                        같은 층의 스켈레톤 (Canvas + Surface + SurfaceList)
  ├ error.tsx                          세그먼트 예외
  └ FavoriteListView (client)          조회 상태 → props
      └ FavoriteListSection            **L1 카드.** 머리(제목·개수·상한) + 상태 분기
          ├ FavoriteRowSkeleton        행 골격 (L2 항목)
          └ FavoritePlaceRow           L2 항목 — li + 인셋, 저장 해제 버튼
```

**카드를 페이지가 아니라 `FavoriteListSection` 이 그린다.** `최근 저장순 · N/100곳` 과 상한
배지가 응답에서 오는데 제목과 한 덩어리여야 해서다 (일정 응급 브리핑 #461 과 같은 판단) —
페이지가 카드를 그리면 개수 줄만 카드 안으로 따로 내려보내야 하고, 그러면 제목 줄과 개수
줄 사이에 카드 여백이 한 번 더 낀다. 페이지는 바닥·쌓기·`sr-only` h1 만 맡는다.

**개수 줄은 셀 수 있을 때만 낸다** — 로딩 중에는 아직 모르고(`0/100곳` 은 거짓말이다),
오류에는 셀 수 없으며, 0건에는 `EmptyState` 가 같은 말을 이미 한다.

`PlaceRowContent` 를 **재사용하지 않는다.** `PlaceSummary` 는 `contentType`/`petAllowanceType`
이 metadata 객체인데 `FavoritePlaceItem` 은 `contentTypeName`/`petAllowanceName` 평문 문자열이고,
무엇보다 **`title` 이 nullable 이다.** 억지로 맞추면 `PlaceRowContent` 에 nullable 분기가
생겨 장소 목록 쪽이 오염된다.

## D3. 데이터 흐름

| 항목               | 값                                                          |
| ------------------ | ----------------------------------------------------------- |
| 조회               | `GET /api/v1/favorites/places`                              |
| 해제               | `DELETE /api/v1/favorites/places/{placeId}` (멱등)          |
| query key          | `favoriteKeys.list()` — **장소 상세와 같은 캐시다**         |
| staleTime / gcTime | 30초 / 10분 (`FAVORITE_QUERY_OPTIONS`)                      |
| 커서               | **없다.** 상한 100곳이라 전량이 온다 → 무한 스크롤이 아니다 |

**서버 프리페치를 한다.** 보호 리소스라 `readSession()` 으로 토큰을 읽고, 없으면 건너뛰고
클라이언트가 조회한다 (BFF 가 401 → 재발급을 처리한다). 실패해도 `catch` 로 삼켜 화면
전체를 버리지 않는다 — `/pets` 와 같은 형태다 (architecture-guide.md §9).

**해제 후 `favoriteKeys.all` 을 무효화한다.** 해제 응답에 본문이 없어(`Response<Void>`)
무효화가 유일한 갱신 수단이다. 같은 키를 장소 상세가 쓰므로 **상세로 돌아가면 하단 바의
저장 상태가 이미 맞다.**

## D4. 상호작용

**정렬 컨트롤을 두지 않는다.** 응답은 최근 저장순 하나뿐이다. 이름순·거리순을 클라이언트에서
흉내 내면 100곳 중 화면에 온 만큼만 정렬돼 **틀린 순서**가 된다. 대신 순서가 무엇인지 헤더에
글자로 적는다 (아트보드 01 주석).

**해제해도 행이 즉시 사라지지 않는다.** 아이콘만 빈 상태로 바뀌고 행은 남는다 — 실수로
지운 것을 그 자리에서 되살릴 수 있게 하기 위해서다. 목록에서 실제로 빠지는 것은 다음
조회부터다. `undo` 를 붙이지 않는다: 저장·해제가 멱등이라 **같은 버튼을 다시 누르는 것이
곧 되돌리기**다 (오버레이 규칙).

**낙관적 업데이트를 하지 않는다.** 해제 실패 시 되돌려야 하고, 연타는 `ref` 로 막는다 —
`use-place-favorite.ts` 와 같은 판단이다.

**행을 붙잡아 두는 것은 별도 로직이다** (`lib/favorite/retain.ts`). 해제 직후 무효화가 돌면
서버 목록이 그 항목을 **빼고** 오므로, `unsaved` 집합만으로는 행이 그냥 사라진다 — 실제로
그렇게 만들었다가 브라우저에서 사라지는 것을 보고 고쳤다. 항목과 원래 index 를 들고 있다가
서버 목록에 되끼운다.

**되살리면 맨 앞으로 이동한다.** `addFavorite` 가 실제 재저장이고 목록이 최근 저장순이라
그렇다. 자리를 억지로 지키지 않는다 — 서버가 말하는 순서가 정본이다.

**헤더 카운트는 서버 값을 그대로 쓴다.** 붙잡아 둔 행은 실제로 저장돼 있지 않으므로
`12/100` 에 포함하면 거짓말이 된다. 행은 남아도 카운트는 줄어드는 것이 맞다.

## D5. 상태별 화면

| 상태         | 화면                                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 로딩         | 카드 안 행 골격 스켈레톤. 카드 제목은 그대로 두고 **개수 줄은 내지 않는다**                                                                          |
| 빈 목록      | `EmptyState` — "아직 저장한 장소가 없어요" + `장소 둘러보기`(`ButtonLink`, `/places`). **재시도 없음** · `<a>` 안에 `<button>` 을 넣지 않는다 (#913) |
| 5xx·무응답   | `ErrorState` — "목록을 불러오지 못했어요 / 저장은 그대로 남아 있어요." + 다시 시도                                                                   |
| 상한 도달    | 카드 머리에 `가득 찼어요` 배지 + 카드 안 안내 한 줄. 목록은 그대로 그린다                                                                            |
| 요약 없는 행 | 행을 **남긴다.** 이름 자리에 "이름을 불러오지 못했어요", 아래 `장소 번호 {placeId}` + `장소 상세에서 열기`                                           |

**요약 없는 행을 감추지 않는 이유**: `title` 이 null 인 것은 tour-service 조회 실패이지
저장이 사라진 것이 아니다. 감추면 "저장한 게 사라졌다" 가 된다. 이름이 없으니 **행 전체를
링크하지 않고** 별도 링크를 준다.

**오류는 섹션 단위다.** 화면 전체를 덮지 않는다 (아트보드 02).

## D6. 접근성

- 행 전체 링크(`<a>`) 안에 해제 버튼(`<button>`)을 넣을 수 없다 → **제목만 링크**로 두고
  버튼을 형제로 놓는다 (`plan-add-place-row.tsx` 와 같은 구조)
- 해제 버튼은 `aria-label` 에 장소명을 넣는다 — "저장 해제" 만으로는 어느 행인지 모른다
- 상한 도달을 `disabled` 만으로 말하지 않는다. 이유를 글자로 함께 낸다
- 액션 열 고정 폭 — 버튼과 상태 문구의 폭이 달라 앞 열이 행마다 밀리면 목록을 훑을 수 없다
- **보이는 제목은 카드의 `h2`(`favorite-list-heading`)이고 페이지의 `h1` 은 `sr-only` 다** —
  제목이 카드 안으로 들어갔기 때문이다 (#462, 장소 목록 #439 와 같은 방식). 카드는
  `aria-labelledby` 로 그 `h2` 를 가리킨다
- 네 상태(로딩·오류·빈·목록)가 **같은 좌우 축**에 선다(`INSET_CLASS.card`) — 축이 갈리면
  목록이 바뀌는 순간 왼쪽 선이 뛴다 (#451)

빼먹으면 로그인 없이 접근된다 (`proxy.ts` 주석 · auth-guide.md §5).

**`use-favorite-unsave` 자체에는 테스트를 만들지 않았다.** 이 저장소는 jsdom 없이
`renderToStaticMarkup` 문자열 assertion 을 쓰므로 훅의 비동기 분기를 직접 돌릴 수 없다 —
대신 자리 보존 로직을 `lib/favorite/retain.ts` 로 **순수 함수로 뽑아** 그쪽을 덮었다.
실제 해제·되살리기·토스트는 브라우저 실렌더로 확인했다.

**1. 데스크톱 선택 → AI 일정 넘기기 (아트보드 03 의 절반) — 해소됐다**

아트보드 03 은 행마다 선택 체크박스를 두고 `선택한 N곳으로 AI 일정 만들기`(최대 10곳)로
넘긴다. `pinnedPlaceIds` 를 쓰는데, #127 시점에는 FE 가 이 필드를 미뤄 둔 상태였다
(`types/ai-plan.ts` 주석) → **[#128](https://github.com/8llow8llowMe/hondigagae/issues/128)
으로 넘겼다.** 선택 상태가 쓰이는 곳이 없어 지금 넣으면 죽은 UI 라는 것이 이유였다.

→ **#128 은 반대 방향으로 풀었다.** 선택을 이 화면에 두지 않고, AI 일정 조건 입력 쪽에
`저장한 곳 먼저 넣기` 토글과 장소 고르기 시트(`저장한 장소` 탭)를 뒀다. **이 화면에
체크박스를 만들지 않는다** — 같은 일을 두 화면이 각자 하면 어느 쪽이 이기는지 알 수 없다.

→ **남은 것은 안내 한 줄이었고 [#408](https://github.com/8llow8llowMe/hondigagae/issues/408)
에서 넣었다.** 아트보드 01 하단의 _"생성 화면의 '저장한 곳 먼저'를 켜 주세요"_ 다.
AI 일정 쪽에는 `preferFavoritesLink: '저장한 장소 보기'` 로 이리 오는 길이 있는데
되돌아가는 길이 없어, 저장을 쌓아도 그것이 어디 쓰이는지 이 화면이 말하지 않았다.
문구는 토글 이름(`preferFavoritesLabel`)을 **그대로 인용한다** — 한 글자만 갈려도
사용자가 그 컨트롤을 화면에서 찾지 못한다. 목록이 비면 `EmptyState` 갈래라 내지 않는다.

**2. `error.tsx` 만 아직 2a 다 — 해소됨 ([#475](https://github.com/8llow8llowMe/hondigagae/issues/475))**

`page.tsx` · `loading.tsx` 는 L0 바닥 + 카드인데 세그먼트 예외 화면(`error.tsx`)은 흰 바탕에
페이지 인셋(16/40)의 `ErrorState` 로 남아 있었다 — 예외가 뜨는 순간 화면이 다른 체계로 바뀌었다.
`/places` 의 `error.tsx` 도 같은 상태라 #462 에서 이 화면만 고치지 않았다(선례가 한쪽으로
정리돼야 한다). **로드맵 12번(2a 제거)이 두 화면을 같이 옮겼다** — 둘 다 `Canvas` + 정상
화면과 같은 카드이고, 상태 컴포넌트는 `inset="card"` 다.

**3. 저장일 표시 — 백엔드에 없다**

아트보드 03 은 행마다 `2026-08-30 저장` 을 표시한다. **`FavoritePlaceItem` 에 날짜 필드가
없다.** `FavoriteEntity extends BaseEntity` 라 DB 에는 있지만 응답에 노출되지 않는다.

→ 저장일을 **그리지 않는다.** 없는 값을 만들 수 없다. D9-1 로 요청한다.
