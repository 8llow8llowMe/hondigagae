> **화면 정본**: `혼디가개 마이페이지·내 반려견.dc.html` 01(마이페이지 — 모바일)
> 작성일: 2026-08-31
> 계약 근거는 공통명세와 같다 (backend `origin/develop` `8e44ddc` 소스 실측).

## D0. 화면 정의

- **경로**: `/mypage` · `/mypage/password` · `/mypage/withdraw` — route group `(main)`
- **인증**: **필요**. `proxy.ts` `PROTECTED_PATHS` 에 `'/mypage'` 가 **이미 있다**
- **진입 경로**: 모바일 탭바 `내 정보` · 데스크톱 헤더 아바타 팝오버
- **이탈 경로**: `/pets` · `/login`(로그아웃·탈퇴 후) · 약관 문서

**세 화면을 한 이슈로 묶는 이유**: 아트보드 01 의 계정 섹션이 `비밀번호 변경`·`회원탈퇴`
행을 담고 있어, `/mypage` 만 먼저 머지하면 **404 진입점이 두 개 생긴다.** 일정 목록·만들기를
한 이슈로 묶은 것과 같은 판단이다 (plan 공통명세 "왜 두 화면을 한 이슈로 묶었나").

## D1. 레이아웃

### 모바일 (390 — 아트보드 01)

```text
내 정보
  아바타 · 이름 · 이메일                    [수정]
─── 8px 밴드 ───
내 반려견                                    ›
  아바타 겹침 · 몽실이 · 초코 · 2/5
─── 8px 밴드 ───
계정
  비밀번호 변경                              ›
  이용약관                                   ›
  개인정보 처리방침                          ›
  버전                                  1.0.0
─── 8px 밴드 ───
  로그아웃
  회원탈퇴
```

- **`내 반려견` 이 계정 설정보다 위다.** 탭바가 4개 고정이라 반려견은 이 화면을 통해서만
  들어온다 (아트보드 01 주석). 아바타를 겹쳐 보여 몇 마리인지 바로 읽히게 한다.
- **위험한 액션은 마지막에, 약하게.** 로그아웃 `16/600`, 회원탈퇴 `14/500` `--fg-muted`.
  **둘 다 danger 색을 쓰지 않는다** — 실수를 막는 건 색이 아니라 위치와 확인 단계다
  (아트보드 01 주석).

### 데스크톱 (1024+)

아트보드에 데스크톱 마이페이지 절이 없다. **레일을 쓰지 않는다** — 이 화면은 설정 목록이라
맥락 패널에 담을 것이 없다. 홈·상세와 달리 `max-w-screen-md` 한 칼럼을 가운데 두고,
그 근거를 주석으로 남긴다 (장소 목록이 지도 전에 그랬던 것과 같은 방식).

## D3. 데이터 흐름

| 항목                          | 내용                                                                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| API                           | `GET`/`PATCH /members/me` · `POST`/`DELETE /me/profile-image` · `POST`/`DELETE /me/password` · `POST /me/password/setup` · `POST /me/withdraw` |
| React Query key               | `memberKeys.me()` (신규)                                                                                                                       |
| staleTime / retry             | 5분 / 전역 기본. 서버 프리페치는 `retry: false`                                                                                                |
| mutation 후                   | `PATCH`·`DELETE 이미지` 응답이 회원 정보 전체 → **`setQueryData`**                                                                             |
| 업로드 후                     | 응답이 `{key, url}` 뿐 → **`profileImageUrl` 만 갈아끼운다** (공통명세 S1)                                                                     |
| 비밀번호 **최초 설정** 후     | `memberKeys.me()` **invalidate** — `hasPassword` 가 바뀐다                                                                                     |
| 비밀번호 **변경**·**전환** 후 | **세션 정리 + `/login`** — 서버가 refresh 쿠키를 지운다 (공통명세 S1). invalidate 로 끝내면 안 된다                                            |
| 탈퇴·로그아웃 후              | 세션 정리 + `queryClient.clear()` + `/login` 으로 replace                                                                                      |

`/mypage` 는 `GET /members/me` 를 서버에서 프리페치한다. 404 가 나올 수 없는 리소스라
`prefetchQuery` + `.catch(() => undefined)` 로 충분하다 — **일정 목록과 같은 형태고,
장소·일정 상세의 `fetchQuery` + `notFound()` 와는 다르다.**

`반려견 N/5` 는 `GET /members/me/pets` 를 함께 부른다 — **최대 5마리라 항상 전량이 오고
`SliceResponse` 가 아니다.** 실패해도 그 행만 빠지고 나머지는 보인다 (plan 공통명세 S8 규칙).

## D4. 상호작용

| 트리거          | 동작                                 | 결과                                        |
| --------------- | ------------------------------------ | ------------------------------------------- |
| `수정`          | `MyProfileEditModal`                 | 닉네임 + 프로필 이미지를 한 자리에서        |
| 닉네임 저장     | `PATCH /members/me`                  | `setQueryData`                              |
| 이미지 선택     | `POST /me/profile-image` (multipart) | **선택 즉시 업로드한다** (모달 저장과 분리) |
| 이미지 삭제     | `DELETE /me/profile-image`           | 응답으로 회원 정보 갈아끼움                 |
| `내 반려견`     | `/pets` 로 이동                      |                                             |
| `비밀번호 변경` | `/mypage/password`                   | 계정 상태에 따라 폼이 갈린다                |
| `로그아웃`      | `ConfirmModal` → `POST /auth/logout` | 세션 정리 → `/login`                        |
| `회원탈퇴`      | `/mypage/withdraw`                   | 확인 화면                                   |
| 탈퇴 확인       | `POST /members/me/withdraw`          | 세션 정리 → `/login`                        |

**이미지는 모달 저장과 분리해 즉시 업로드한다.** 업로드가 별도 API 고 응답 모양도 다르다.
한 `저장` 버튼에 묶으면 "닉네임은 저장됐는데 이미지는 실패" 를 한 버튼으로 설명해야 한다.

### 아트보드의 예고를 이행한다 — 소셜 계정

아트보드 01 주석이 **스스로 이렇게 적어 뒀다**:

> 소셜 로그인은 범위 밖 — 이메일 계정만 다루므로 비밀번호 변경이 항상 보인다.
> 소셜 계정이 추가되면 이 행을 숨기고 "카카오로 연결됨"을 표시해야 한다.

**그 시점이 지금이다.** 백엔드에 소셜 로그인·계정 연결/전환이 들어와 있다
([#55](https://github.com/8llow8llowMe/hondigagae/issues/55)). 계정 섹션은 이렇게 그린다:

| 상태      | 계정 섹션                                         |
| --------- | ------------------------------------------------- |
| 일반      | `비밀번호 변경` ›                                 |
| 소셜 전용 | `{provider} 로 연결됨` (읽기) + `비밀번호 설정` › |
| 연결됨    | `{provider} 로 연결됨` (읽기) + `비밀번호 변경` › |

`provider` 표시명은 **FE 매핑이 불가피하다** — 서버가 `"KAKAO"` 원문 문자열만 준다
(metadata 객체가 아니다). `src/lib/member/provider.ts` 에 매핑 + **모르는 값 폴백**을 둔다.
장소 상세의 `cpyrhtDivCd` 와 같은 예외 처리다 (장소상세-세부명세 D8).

## D6. 접근성

- 설정 목록은 `<ul>`. 이동 항목은 `<a>`, 동작 항목은 `<button>` — **모양이 같아도 역할이 다르다**
- 파일 입력은 보이는 `<label>` 과 연결한다. `<input type="file">` 을 숨기고 버튼만 두면
  키보드로 닿지 않는다
- 업로드 진행·성공·실패를 `aria-live="polite"` 로 알린다
- 로그아웃·탈퇴 `ConfirmModal` — 기본 포커스는 취소
- 터치 영역 44px, `버전 1.0.0` 은 조작 불가라 목록 항목이 아니라 정의 목록으로 그린다

## D7. 테스트 케이스

**순수 로직**

- 계정 상태 판정 — `(null,true)`→일반 / `(KAKAO,false)`→소셜 전용 / `(KAKAO,true)`→연결됨 /
  `(null,false)`→**판별 불가**
- `provider` 표시명 매핑 + 모르는 값 폴백
- 비밀번호 정규식이 회원가입과 **같은 규칙**임을 고정 (8자 미만 / 특수문자 없음 / 공백 포함)

**렌더 분기 (404 / 5xx 필수)**

- 회원 정보 5xx → `ErrorState`
- 반려견 조회 실패 → 그 행만 빠지고 나머지 유지
- 프로필 이미지 null → 이니셜 아바타
- 계정 상태 3종 각각 계정 섹션이 다르게 그려진다
- 판별 불가 상태에서 **비밀번호 동작 버튼이 하나도 나오지 않는다**

**접근성 계약**

- 파일 입력이 `<label>` 과 연결돼 있다
- 이동/동작 항목이 `<a>`/`<button>` 으로 갈린다

**mock**

`src/lib/api/mock/member-data.ts` 를 새로 만들고 `resolveMock` 체인에 붙인다.
**계정 상태 3종을 모두 낼 수 있어야 한다** — 그러지 않으면 D5 의 분기를 화면으로 확인할
방법이 없다. multipart 업로드도 mock 이 받아야 한다 (파일을 저장하지 않고 고정 URL 반환).
