# 마이페이지 세부 명세

> 상위 공통명세: `docs/features/member/공통명세.md`
> **화면 정본**: `혼디가개 마이페이지·내 반려견.dc.html` 01(마이페이지 — 모바일)
> 작성일: 2026-08-31
> 계약 근거는 공통명세와 같다 (backend `origin/develop` `8e44ddc` 소스 실측).

## D0. 화면 정의

- **경로**: `/mypage` · `/mypage/password` · `/mypage/withdraw` — route group `(main)`
- **인증**: **필요**. `proxy.ts` `PROTECTED_PATHS` 에 `'/mypage'` 가 **이미 있다**
- **진입 경로**: 모바일 탭바 `내 정보` · 데스크톱 헤더 아바타 팝오버
- **이탈 경로**: `/pets` · `/login`(로그아웃·탈퇴 후) · 약관 문서

**세 화면을 한 이슈로 묶는 이유**: 아트보드 01 의 계정 섹션이 `비밀번호 변경`·`회원탈퇴`
행을 담고 있어, `/mypage` 만 먼저 머지하면 **404 진입점이 두 개 생긴다.** 일정 목록·만들기를
한 이슈로 묶은 것과 같은 판단이다 (plan 공통명세 "왜 두 화면을 한 이슈로 묶었나").

## D1. 레이아웃

### 모바일 (390 — 아트보드 01)

**3층 표면(3a)이다** (`DESIGN.md §0`, 이슈 #466). 2a 의 `Band` 셋이 **카드 둘 + 카드 밖
액션**으로 갈렸다.

```text
[L0 바닥 — --bg-sunken]

┌─ L1 카드 · lead ──────────────────────────┐
│ 내 정보                                    │  ← h2 (h1 은 sr-only)
│   아바타 · 이름 · 이메일           [수정]  │
│ ─────────────────────────────────────────  │  ← 카드가 긋는 선
│   내 반려견                            ›   │  ← L2 항목 (li)
│     아바타 겹침 · 몽실이 · 초코 · 2/5      │
│   ─────────────────────────────────────    │  ← SurfaceList 가 항목 사이에만
│   저장한 장소                          ›   │
│     3/100곳                                │
└────────────────────────────────────────────┘

┌─ L1 카드 ─────────────────────────────────┐
│ 계정                                       │
│   카카오로 연결됨                          │  ← 읽기 전용 (li 안 텍스트)
│   ─────────────────────────────────────    │
│   비밀번호 변경                        ›   │
│ ─────────────────────────────────────────  │  ← 목록 밖이라 dl 이 스스로 든다
│   버전                              1.0.0  │
└────────────────────────────────────────────┘

  로그아웃                                      ← 카드 아님. L0 위, 카드 축(16/20)
  회원탈퇴
```

- **프로필은 혼자 카드가 되지 못한다.** 자기 제목이 없고 담는 항목도 하나라 카드 판정
  ①③ 에 걸린다 (`DESIGN.md §0`). 반려견·저장한 장소와 한 카드에 든다 — `[나 · 내
반려견 · 내가 저장한 곳]` 이 한 이야기고, 홈이 프로필·판정·골든타임을 카드 하나에
  담은 것과 같은 판단이다(#428).
- **`lead` 는 첫 카드가 갖는다.** 이 화면에서 사람이 보러 오는 것은 계정 설정이 아니다.
- **로그아웃·회원탈퇴는 카드가 아니다.** 액션은 판정에서 빠진다. 왼쪽 정렬은 아트보드
  그대로 두되 인셋을 `main`(16/40)이 아니라 **`card`(16/20)** 로 잡는다 — L0 위에 있어도
  축은 바로 위 카드 안 글줄과 같아야 한다 (`plan-add-place-header`, #451).
- **2a 헤더 바(`border-b h-14`)를 걷었다.** 제목이 첫 카드 머리로 들어갔고, 바닥 위에 선
  하나만 남기면 카드 테두리와 나란히 두 줄로 읽힌다 (#464 와 같다).
- **네 상태가 카드 머리를 공유한다** (#451). 로딩·오류에서도 제목 줄은 서 있고 몸통만
  갈린다. 다만 **조회 실패면 계정 카드를 내지 않는다** — 소셜 연결 여부·비밀번호 유무가
  전부 회원 정보에서 오므로 값 없이 그리면 "일반 계정" 을 단정하게 된다 (D5).
- **오류 판정은 술어 하나다** — `errorStatus !== null || member === null`. 프리페치로
  캐시가 찬 뒤 refetch 만 5xx 로 실패하면 `member` 가 남은 채 `errorStatus` 만 채워지는데,
  카드 본문과 계정 카드 표시를 각각 다른 조건으로 판정하면 그 구간에서 오류도 재시도도
  나오지 않는다.
- **로딩·오류에서는 로그아웃·회원탈퇴를 내지 않는다.** 라우트 스켈레톤에도 없어서,
  내면 스켈레톤에서 실화면으로 넘어갈 때 두 줄이 새로 생긴다.
- **`내 반려견` 이 계정 설정보다 위다.** 탭바가 4개 고정이라 반려견은 이 화면을 통해서만
  들어온다 (아트보드 01 주석). 아바타를 겹쳐 보여 몇 마리인지 바로 읽히게 한다.
- **위험한 액션은 마지막에, 약하게.** ~~로그아웃 `16/600`~~ → **로그아웃은 `secondary` 버튼**
  ([#913](https://github.com/8llow8llowMe/hondigagae/issues/913)), 회원탈퇴 `14/500` `--fg-muted`.
  **둘 다 danger 색을 쓰지 않는다** — 실수를 막는 건 색이 아니라 위치와 확인 단계다
  (아트보드 01 주석).
  - **#466 의 맨 글자 결정을 뒤집은 근거**: 사용성 검토(#905 §6)에서 로그아웃이 **누르는 것으로
    읽히지 않았다** — 바로 아래 `회원탈퇴`(링크)와 모양이 같아 둘 다 안내 문구처럼 보였다.
    "약하게" 는 색이 아니라 **위치**(맨 마지막 · 카드 밖)와 **무게**(primary 가 아니다)로 지킨다.
  - **`ghost` 가 아닌 이유**: 이슈는 `ghost` 를 적었지만 `ghost` 는 글자가 `--fg-muted` 라 지금의
    진한 `16/600` 보다 더 약해진다. 테두리가 있는 가장 낮은 변형이 `secondary` 다 (89×44 실측).

### 데스크톱 (1024+)

아트보드에 데스크톱 마이페이지 절이 없다. **레일을 쓰지 않는다** — 이 화면은 설정 목록이라
맥락 패널에 담을 것이 없다. 홈·상세와 달리 `max-w-screen-md` 한 칼럼을 가운데 두고,
그 근거를 주석으로 남긴다 (장소 목록이 지도 전에 그랬던 것과 같은 방식).

**폭을 갖는 것은 `main` 이 아니라 `SurfaceStack` 이다** (3a, #466). 바닥(`Canvas`)은
전폭이어야 하고 쌓기가 폭을 갖는다 — 합치면 컨테이너 바깥이 흰색으로 남는다 (#453 · #462).
`md` 이상에서 카드가 radius 12 와 좌우 테두리를 얻고, 그 아래에서는 전폭이다.

### 하위 두 화면 (`/mypage/password` · `/mypage/withdraw`)

폼 규약은 일정 만들기(#453) · 반려견 등록(#464)과 같다 — **카드 하나 + 카드 밖 액션**.
폭은 `max-w-screen-md`(768)에서 **`max-w-2xl`(672)** 로 좁아졌다 (폼 한 단 폭).

```text
[L0]  ← 내 정보로 돌아가기
┌─ L1 카드 · lead ──────────────────────┐
│ 비밀번호 변경 / 비밀번호 설정          │  ← 계정 상태에 따라 갈린다
│   카카오로 연결됨                      │  ← 부제
│   [현재 비밀번호] [새 비밀번호] [변경] │
└────────────────────────────────────────┘
  비밀번호를 없애고 카카오로만 로그인해요  ← 카드 아님 (액션)
  …설명…                        [없애기]
```

- **`h1` 은 `sr-only` 이고 보이는 제목은 카드의 `h2` 다.** 두 화면 다 카드가 하나라 그
  이름이 페이지 이름을 대신한다 — 반려견 등록(#464) · 일정 만들기(#453)와 같다. 탈퇴
  화면의 카드는 제목이 없었는데 이 규약에 맞춰 `회원탈퇴` 를 갖게 했다.
  **`h1` 을 보이게 두면 위계가 뒤집힌다**: `lead` 카드 제목이 `display`(28/800)라
  `title-1`(22/700)인 `h1` 보다 커진다 (`DESIGN.md §11`).
- **뒤로가기는 L0 이고 인셋은 `card`(16/20)다.** 아래 카드 안 글줄과 같은 세로선에 선다
  (`md` 이상에서 카드 테두리 1px 만큼 남는 어긋남은 그대로 둔다 — 눈으로 보이지 않는다).
  데스크톱 세로 여백은 `SurfaceStack` 의 `md:p-6` 에 맡긴다 (`plan-add-place-header`, #451).
- **카드는 `PasswordView` · `WithdrawView` 가 그린다.** 비밀번호는 머리 값이 응답에서
  오므로 `styling-guide.md §3-1` 의 "응답에서 오면 섹션이" 에 걸린다. 로딩·오류·판별
  불가에서는 어느 폼인지 단정할 수 없어 **제목을 주지 않고 `aria-label` 로 대신하지도
  않는다** — 카드가 하나뿐이라 `h1` 이 이미 이름 짓는다.
- **`소셜 전용으로 전환` 은 카드가 아니다.** 액션이고 담는 것도 하나뿐이라 판정 ③ 에
  걸린다 — 반려견 삭제(#464)와 같은 자리다. 2a 때 그 블록이 스스로 긋던 `border-t` 가
  하던 일을 카드 경계가 맡는다.
- **탈퇴 실패 문구(`FormAlert`)는 카드 밖, 버튼과 같은 덩어리**다. 그 오류를 내는 것이
  아래 버튼이라 카드 안에 두면 원인에서 멀어진다 (D6).

## D3. 데이터 흐름

| 항목                          | 내용                                                                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| API                           | `GET`/`PATCH /members/me` · `POST`/`DELETE /me/profile-image` · `POST`/`DELETE /me/password` · `POST /me/password/setup` · `POST /me/withdraw` |
| React Query key               | `memberKeys.me()` (신규)                                                                                                                       |
| staleTime / retry             | 5분 / 전역 기본. 서버 프리페치는 `retry: false`                                                                                                |
| mutation 후                   | `PATCH`·`DELETE 이미지` 응답이 회원 정보 전체 → **`setQueryData`**                                                                             |
| 업로드 후                     | 응답이 `{key, url}` 뿐 → **`profileImageUrl` 만 갈아끼운다** (공통명세 S1)                                                                     |
| 비밀번호 **최초 설정** 후     | `memberKeys.me()` **invalidate** — `hasPassword` 가 바뀐다                                                                                     |
| 비밀번호 **변경**·**전환** 후 | **세션 정리 + `/login`** — 서버가 refresh 쿠키를 지운다 (공통명세 S1). invalidate 로 끝내면 안 된다                                            |
| 탈퇴·로그아웃 후              | 세션 정리 + `queryClient.clear()` + `/login` 으로 replace                                                                                      |

`/mypage` 는 `GET /members/me` 를 서버에서 프리페치한다. 404 가 나올 수 없는 리소스라
`prefetchQuery` + `.catch(() => undefined)` 로 충분하다 — **일정 목록과 같은 형태고,
장소·일정 상세의 `fetchQuery` + `notFound()` 와는 다르다.**

`반려견 N/5` 는 `GET /members/me/pets` 를 함께 부른다 — **최대 5마리라 항상 전량이 오고
`SliceResponse` 가 아니다.** 실패해도 그 행만 빠지고 나머지는 보인다 (plan 공통명세 S8 규칙).

## D4. 상호작용

| 트리거          | 동작                                 | 결과                                        |
| --------------- | ------------------------------------ | ------------------------------------------- |
| `수정`          | `MyProfileEditModal`                 | 닉네임 + 프로필 이미지를 한 자리에서        |
| 닉네임 저장     | `PATCH /members/me`                  | `setQueryData`                              |
| 이미지 선택     | `POST /me/profile-image` (multipart) | **선택 즉시 업로드한다** (모달 저장과 분리) |
| 이미지 삭제     | `DELETE /me/profile-image`           | 응답으로 회원 정보 갈아끼움                 |
| `내 반려견`     | `/pets` 로 이동                      |                                             |
| `비밀번호 변경` | `/mypage/password`                   | 계정 상태에 따라 폼이 갈린다                |
| `로그아웃`      | `ConfirmModal` → `POST /auth/logout` | 세션 정리 → `/login`                        |
| `회원탈퇴`      | `/mypage/withdraw`                   | 확인 화면                                   |
| 탈퇴 확인       | `POST /members/me/withdraw`          | 세션 정리 → `/login`                        |

**이미지는 모달 저장과 분리해 즉시 업로드한다.** 업로드가 별도 API 고 응답 모양도 다르다.
한 `저장` 버튼에 묶으면 "닉네임은 저장됐는데 이미지는 실패" 를 한 버튼으로 설명해야 한다.

## D5. 상태별 화면

| 상태                 | 표시                      | 문구 (확정)                                                   |
| -------------------- | ------------------------- | ------------------------------------------------------------- |
| loading              | `Skeleton`, `aria-hidden` | —                                                             |
| 회원 정보 실패 (5xx) | `ErrorState` + 재시도     | `내 정보를 불러오지 못했어요` / `잠시 후 다시 시도해 주세요.` |
| 반려견 조회 실패     | **그 행만 숨김**          | —                                                             |
| 반려견 0마리         | 행은 남기고 문구만        | `아직 등록한 반려견이 없어요`                                 |
| 프로필 이미지 없음   | 이니셜 아바타             | — (사진이 없는 것이 정상 상태다)                              |
| 업로드 실패 (형식)   | `FormAlert`               | 서버 `resultMessage` 그대로                                   |
| 업로드 실패 (5xx)    | `FormAlert` + 다시 시도   | `이미지를 올리지 못했어요. 잠시 후 다시 시도해 주세요.`       |
| 닉네임 검증 실패     | 필드 오류                 | 서버 `MemberValidationMessage` 복제본 (`// MEMBER_NNN` 주석)  |
| 비밀번호 — 일반 계정 | 변경 폼                   | `현재 비밀번호` + `새 비밀번호`                               |
| 비밀번호 — 소셜 전용 | 최초 설정 폼              | `비밀번호를 설정하면 이메일로도 로그인할 수 있어요.`          |
| 비밀번호 — 연결됨    | 변경 폼 + 전환 영역       | `비밀번호를 없애고 {provider} 로만 로그인해요`                |
| 계정 상태 판별 불가  | 안내만                    | `계정 상태를 확인하지 못했어요. 잠시 후 다시 시도해 주세요.`  |

### 아트보드의 예고를 이행한다 — 소셜 계정

아트보드 01 주석이 **스스로 이렇게 적어 뒀다**:

> 소셜 로그인은 범위 밖 — 이메일 계정만 다루므로 비밀번호 변경이 항상 보인다.
> 소셜 계정이 추가되면 이 행을 숨기고 "카카오로 연결됨"을 표시해야 한다.

**그 시점이 지금이다.** 백엔드에 소셜 로그인·계정 연결/전환이 들어와 있다
([#55](https://github.com/8llow8llowMe/hondigagae/issues/55)). 계정 섹션은 이렇게 그린다:

| 상태      | 계정 섹션                                         |
| --------- | ------------------------------------------------- |
| 일반      | `비밀번호 변경` ›                                 |
| 소셜 전용 | `{provider} 로 연결됨` (읽기) + `비밀번호 설정` › |
| 연결됨    | `{provider} 로 연결됨` (읽기) + `비밀번호 변경` › |

`provider` 표시명은 **FE 매핑이 불가피하다** — 서버가 `"KAKAO"` 원문 문자열만 준다
(metadata 객체가 아니다). `src/lib/member/provider.ts` 에 매핑 + **모르는 값 폴백**을 둔다.
장소 상세의 `cpyrhtDivCd` 와 같은 예외 처리다 (장소상세-세부명세 D8).

## D6. 접근성

- 설정 목록은 `<ul>`. 이동 항목은 `<a>`, 동작 항목은 `<button>` — **모양이 같아도 역할이 다르다**
- 파일 입력은 보이는 `<label>` 과 연결한다. `<input type="file">` 을 숨기고 버튼만 두면
  키보드로 닿지 않는다
- 업로드 진행·성공·실패를 `aria-live="polite"` 로 알린다
- 로그아웃·탈퇴 `ConfirmModal` — 기본 포커스는 취소
- 터치 영역 44px, `버전 1.0.0` 은 조작 불가라 목록 항목이 아니라 정의 목록으로 그린다

## D7. 테스트 케이스

**순수 로직**

- 계정 상태 판정 — `(null,true)`→일반 / `(KAKAO,false)`→소셜 전용 / `(KAKAO,true)`→연결됨 /
  `(null,false)`→**판별 불가**
- `provider` 표시명 매핑 + 모르는 값 폴백
- 비밀번호 정규식이 회원가입과 **같은 규칙**임을 고정 (8자 미만 / 특수문자 없음 / 공백 포함)

**렌더 분기 (404 / 5xx 필수)**

- 회원 정보 5xx → `ErrorState`
- 반려견 조회 실패 → 그 행만 빠지고 나머지 유지
- 프로필 이미지 null → 이니셜 아바타
- 계정 상태 3종 각각 계정 섹션이 다르게 그려진다
- 판별 불가 상태에서 **비밀번호 동작 버튼이 하나도 나오지 않는다**

**접근성 계약**

- 파일 입력이 `<label>` 과 연결돼 있다
- 이동/동작 항목이 `<a>`/`<button>` 으로 갈린다

**mock**

`src/lib/api/mock/member-data.ts` 를 새로 만들고 `resolveMock` 체인에 붙인다.
**계정 상태 3종을 모두 낼 수 있어야 한다** — 그러지 않으면 D5 의 분기를 화면으로 확인할
방법이 없다. multipart 업로드도 mock 이 받아야 한다 (파일을 저장하지 않고 고정 URL 반환).

### 구현하며 굳힌 것 (#83)

- **프로필 사진은 `next/image` 가 아니라 `<img>` 다.** 근거는 공통명세 S3 의 이미지 호스트
  문단 — 공개 주소가 환경변수라 `remotePatterns` 고정 목록에 넣을 수 없다.
- **업로드는 화면이 5MB 를 먼저 막는다.** 서버 검증(`STORAGE_002`·매직 바이트)을 대신하는
  것이 아니라, BFF 가 재시도를 위해 본문을 통째로 메모리에 올리므로 거기까지 보내지 않는
  첫 방어선이다. 형식은 서버만 판정할 수 있어 `accept` 는 편의로만 둔다.
- **파일 입력은 보이는 `<label>` 안에 두고 `sr-only` 로 감춘다.** `Button` 으로 감싸고
  입력을 숨기는 방식은 쓰지 않는다 — `<button>` 안의 label 클릭은 파일 선택기를 못 연다.
- **같은 파일을 다시 골라도 업로드되게 `input.value` 를 비운다.** 안 그러면 실패 후
  재시도가 조용히 막힌다 (`change` 가 발생하지 않는다).
- **수정 모달은 `<form>` 을 두지 않는다.** `Modal` 의 footer 가 패널 바깥이라 submit
  버튼이 폼에 속하지 않고, Enter 제출과 버튼 클릭이 다른 경로가 된다. Enter 는 입력의
  `onKeyDown` 이 맡는다.
- **모달을 열 때마다 서버의 현재 닉네임으로 되돌린다.** 저장하지 않고 닫은 값이 남으면
  "현재 내 정보" 를 잘못 보여준다.
