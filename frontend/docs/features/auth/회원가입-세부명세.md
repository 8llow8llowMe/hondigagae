## D0. 화면 정의

- **경로**: `/signup` (`app/(auth)/signup/page.tsx`)
- **인증**: **불필요.**
- **진입 경로**: `/login` 의 "회원가입" 링크 (`returnTo` 를 물고 온다), 직접 진입
- **이탈 경로**: 가입 완료 → `/login?returnTo=…` (자동 로그인되지 않는다), "로그인" 링크

**가입 응답은 `dataBody: null` 이다.** 토큰을 주지 않으므로 가입 직후 자동 로그인은
불가능하다. 완료 후 로그인 화면으로 보내고 이메일을 미리 채워 준다.

## D1. 레이아웃

로그인과 같은 `(auth)` 셸. 단계 표시를 상단에 둔다.

- 모바일 (375): 한 컬럼, 단계 표시는 텍스트 (`2 / 3`)
- 태블릿 / 데스크톱: `max-w-sm` 중앙 정렬

긴 한국어 실데이터로 확인할 항목:

- `MEMBER_105` 문구가 길다 — `"비밀번호는 공백 없이 영문자, 숫자, 특수문자를 각각 1자 이상 포함해야 합니다."`
  가 필드 아래에서 2~3줄이 될 때 다음 필드를 밀어내는 정도
- `MEMBER_001` — `"이미 가입된 이메일 (verylongaddress@example.com)입니다."` 의 줄바꿈

## D3. 데이터 흐름

```text
1단계  이메일 입력 → POST /auth/email/send-code
                     → 성공 → 2단계 + 60초 쿨다운 시작
2단계  코드 입력   → POST /auth/email/verify-code
                     → 성공 → 3단계  (인증 상태는 서버에 30분 유지)
3단계  프로필 입력 → POST /members/signup
                     → 성공 → /login?returnTo=…&email=…
```

| 항목                   | 내용                                                     |
| ---------------------- | -------------------------------------------------------- |
| API                    | `send-code`, `verify-code`, `signup` (3개 모두 mutation) |
| React Query key        | **없음** (mutation 전용)                                 |
| staleTime / retry      | `retry: false`                                           |
| mutation 후 invalidate | 없음 (로그인 전이라 캐시 없음)                           |
| 폴링 여부              | 없음. 쿨다운은 `setInterval` 카운트다운 (요청 아님)      |

**인증 상태는 프론트가 아니라 서버가 들고 있다.** `verify-code` 는 토큰을 반환하지 않고
서버에 "이 이메일은 인증됨(30분)"을 남긴다. 프론트는 단계 UI 만 관리한다.

**따라서 새로고침하면 1단계로 돌아간다.** 서버 인증은 살아 있으므로 같은 이메일로
코드를 다시 받아 진행하면 된다. 이 동작을 D8-1 에 미결로 남긴다.

## D4. 상호작용

| 트리거                         | 동작                                  | 결과                                 |
| ------------------------------ | ------------------------------------- | ------------------------------------ |
| 1단계 제출                     | 이메일 검증 → `send-code`             | 성공 → 2단계 + 쿨다운 60초 시작      |
| 2단계 "재전송"                 | 쿨다운 0 일 때만 활성 → `send-code`   | 쿨다운 재시작                        |
| 2단계 제출                     | `verify-code`                         | 성공 → 3단계                         |
| 2단계 "이메일 다시 입력"       | 1단계로 복귀                          | 코드 입력값·쿨다운 초기화            |
| 3단계 제출                     | 클라이언트 검증 → `signup`            | 성공 → `/login` 이동                 |
| `AUTH_003` (429)               | `FormAlert` + 재전송 버튼 비활성 유지 | 쿨다운이 끝나면 다시 활성            |
| `AUTH_004` 코드 불일치 (400)   | 코드 필드 에러                        | 코드만 비우고 포커스                 |
| `AUTH_005` 코드 만료 (400)     | `FormAlert` + **1단계로 되돌림**      | 코드를 다시 받아야 한다              |
| `MEMBER_001` 중복 (409)        | **폼 전체 오류** + "로그인하기" 링크  | **3단계에서야 드러난다** (아래 참고) |
| `MEMBER_006` 인증 미완료 (400) | `FormAlert` + **1단계로 되돌림**      | 30분이 지났다                        |
| 5xx / 무응답                   | `ErrorState` + 재시도                 | 단계·입력값 유지                     |

### 이메일 중복은 3단계에서야 드러난다

`send-code` 는 **가입 여부와 무관하게 항상 성공**한다 (계정 열거 방지 설계).
그래서 이미 가입된 이메일도 1·2단계를 통과하고, `signup` 에서 409 `MEMBER_001` 로 막힌다.

**이 흐름을 없앨 수 없다.** 백엔드 설계가 의도한 것이다. 화면이 할 일:

- 409 를 받으면 이메일 필드에 서버 문구를 붙이고 **"로그인하기" 링크를 함께 준다.**
  링크는 `/login?returnTo=…&email=<입력한 이메일>` 로 이메일을 넘겨 재입력을 없앤다.
- 3단계까지 입력한 비밀번호·이름·닉네임은 버린다. 다른 계정 정보이므로 유지할 이유가 없다.

> **필드 에러가 아니라 폼 전체 오류로 낸다** (2026-08-27 구현 시 정정).
> 초안은 "이메일 필드 에러"로 적었지만 **3단계 화면에는 이메일 입력이 없다** — 비밀번호·이름·닉네임만
> 있다. 붙일 필드가 없으므로 `FormAlert`(`role="alert"`) + 로그인 링크로 낸다. 링크가 이메일을
> 실어 보내므로 사용자는 재입력 없이 로그인으로 넘어간다.

문구 어미는 **해요체로 통일**한다 (`messages/common.ts` 의 기존 문구와 일치). 이슈 #15 의
"문구 어미 혼용"을 여기서 되풀이하지 않는다.

### 클라이언트 검증 문구 (`src/lib/messages/form.ts`)

백엔드 `MemberValidationMessage` / `AuthValidationMessage` 와 **같은 문구**를 쓴다.

| 필드     | 조건           | 문구                                                                         | 대응 코드    |
| -------- | -------------- | ---------------------------------------------------------------------------- | ------------ |
| email    | 비어 있음      | 이메일은 필수입니다.                                                         | `MEMBER_101` |
| email    | 형식 오류      | 이메일 형식이 올바르지 않습니다.                                             | `MEMBER_102` |
| code     | 비어 있음      | 인증코드는 필수입니다.                                                       | `AUTH_104`   |
| password | 비어 있음      | 비밀번호는 필수입니다.                                                       | `MEMBER_103` |
| password | 길이 위반      | 비밀번호는 8자 이상 20자 이하여야 합니다.                                    | `MEMBER_104` |
| password | 문자 구성 위반 | 비밀번호는 공백 없이 영문자, 숫자, 특수문자를 각각 1자 이상 포함해야 합니다. | `MEMBER_105` |
| name     | 비어 있음      | 이름은 필수입니다.                                                           | `MEMBER_106` |
| name     | 길이 위반      | 이름은 10자 이하만 가능합니다.                                               | `MEMBER_107` |
| nickname | 비어 있음      | 닉네임은 필수입니다.                                                         | `MEMBER_108` |
| nickname | 길이 위반      | 닉네임은 10자 이하만 가능합니다.                                             | `MEMBER_109` |

**비밀번호는 길이 → 문자 구성 순으로 검사하고 첫 오류만 보인다.** 백엔드 정렬 순서
(`@Size` 우선순위 1 → `@Pattern` 우선순위 3)와 같아야 클라이언트/서버 결과가 어긋나지 않는다.

패턴 정규식은 백엔드와 동일하게 옮긴다:

```text
^(?=.*[A-Za-z])(?=.*\d)(?=.*[!@#$%^&*()\-_=+\[\]{};:'",.<>/?\\|])\S+$
```

## D6. 접근성

- 단계 전환 시 **새 단계의 첫 입력으로 포커스를 옮긴다.** 옮기지 않으면 키보드 사용자가
  단계가 바뀐 것을 모른다.
- 단계 표시는 텍스트로도 읽힌다 (`3단계 중 2단계`). 색·아이콘만으로 표현하지 않는다.
- `autoComplete`: 이메일 `username`, 코드 `one-time-code`, 비밀번호 `new-password`,
  이름 `name`, 닉네임 `nickname`
- 코드 입력은 `inputMode="text"` — 백엔드 예시가 `A3K7MP2X` 로 **영숫자 혼합**이다.
  `numeric` 으로 두면 영문자를 못 넣는다.
- 쿨다운 카운트다운은 `aria-live="polite"`. 매 초 읽히지 않도록 **10초 단위로만** 갱신 알림.
- 오류 시 `aria-invalid` + `aria-describedby`, 폼 전체 오류는 `role="alert"`
- 터치 영역 44px 이상

## D7. 테스트 케이스

- **순수 로직**
  - 비밀번호 zod 스키마: 7자 → 길이 오류만, 8자 영문만 → 패턴 오류만, 공백 포함 → 패턴 오류
  - `toFieldErrors()`: `password` 에 `MEMBER_104`·`MEMBER_105` 가 함께 올 때 **`MEMBER_104` 만** 채택
  - 쿨다운 계산 순수 함수: 시작 시각 + 60초 → 남은 초
  - `classify(409) === 'conflict'`
- **렌더 분기**
  - 각 단계 컴포넌트에 `FormErrors` 주입 → 오류 마크업
  - 409 → 이메일 필드 오류 + "로그인하기" 링크가 마크업에 존재
  - 쿨다운 중 → 재전송 버튼 `disabled`
  - 5xx → `ErrorState` + 재시도
- **접근성 계약**
  - 각 입력의 `label` `htmlFor` ↔ `id` 일치
  - `autoComplete` 값이 위 표와 일치
