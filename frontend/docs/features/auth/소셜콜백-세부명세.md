## D0. 화면 정의

- **경로**: `/(auth)/oauth/[provider]/callback` — route group `(auth)`
- **인증**: 불필요. `PROTECTED_PATHS` 에 넣지 않는다
- **진입 경로**: 소셜 제공자의 리다이렉트 (**우리 화면에서 링크로 오지 않는다**)
- **이탈 경로**: `returnTo` 또는 `/` (성공) · `/login` (실패)

**로그인 화면에 소셜 버튼을 다는 것도 이 이슈다.** 콜백만 만들면 진입점이 없다.

## D1. 계약 — 서버가 리다이렉트를 대신 해주지 않는다

```text
1) GET /auth/{provider}/authorize      → { authorizationUrl }   ※ state 10분 유효
2) 사용자를 authorizationUrl 로 이동   ※ 우리가 location 을 바꾼다
3) 제공자가 /oauth/{provider}/callback?code=&state= 로 돌려보낸다
4) GET /auth/{provider}/login?code=&state=  → 일반 로그인과 동일한 응답 + Set-Cookie
```

`provider`: **`kakao` · `naver`** (`OAuthProvider` enum, 소문자 경로).

- **4단계를 반드시 `/api/bff` 로 부른다.** BFF 가 응답 body 의 `accessToken` 을 벗겨 세션
  쿠키에 봉인하고 게이트웨이의 refresh 쿠키를 함께 담는다 (`architecture-guide.md` §5).
  게이트웨이를 직접 부르면 **토큰이 브라우저 JS 에 노출되고 세션이 만들어지지 않는다.**
- 미가입 이메일이면 **자동 회원가입 후 로그인**한다 (컨트롤러 설명). 화면에 가입 단계가 없다.

### 오류 — 전부 4단계에서 나온다

| 코드       | HTTP | 뜻                                | 화면                                                   |
| ---------- | ---- | --------------------------------- | ------------------------------------------------------ |
| `AUTH_007` | 400  | 지원하지 않는 provider            | 처음부터 다시                                          |
| `AUTH_008` | 409  | **이미 다른 소셜로 가입된 계정**  | 서버 문구가 어느 provider 인지 말해 준다 → 그대로 노출 |
| `AUTH_009` | 400  | 이메일 제공 **동의 필요**         | 동의 안내 + 다시 시도                                  |
| `AUTH_010` | 401  | **state 무효** (10분 만료 · 위조) | 처음부터 다시                                          |
| `AUTH_011` | 400  | 프로필(닉네임) 제공 **동의 필요** | 동의 안내 + 다시 시도                                  |
| `AUTH_012` | 400  | 소셜 계정 이메일 **미인증**       | 제공자에서 인증 후 다시                                |
| `AUTH_013` | 400  | 인증 실패                         | 처음부터 다시                                          |
| `AUTH_014` | 502  | **제공자와 통신 불가**            | 잠시 후 다시 (우리 잘못이 아니다)                      |

**문구를 우리가 짓지 않는다.** 여덟 개 전부 `resultMessage` 가 이미 행동을 안내한다
(예: `AUTH_008` 은 어느 소셜로 가입됐는지까지 알려준다). `errorCode` 로는 **다음 행동만**
가른다 — "다시 시도" 인지 "제공자에서 조치" 인지.

## D3. 데이터 흐름

```text
[로그인 화면]  소셜 버튼 → GET /auth/{provider}/authorize
               → sessionStorage 에 returnTo 저장
               → window.location.assign(authorizationUrl)

[콜백 화면]    searchParams 에서 code · state
               → GET /api/bff/auth/{provider}/login?code=&state=
               → 성공: router.replace(returnTo ?? '/')
               → 실패: 오류 화면
```

| 항목        | 내용                                                               |
| ----------- | ------------------------------------------------------------------ |
| API         | `authorize` (버튼) · `login` (콜백)                                |
| React Query | **쓰지 않는다** — 캐시하면 안 되는 1회용 교환이다                  |
| 성공 후     | `queryClient.clear()` 후 이동 — 이전 사용자의 캐시를 남기지 않는다 |
| `returnTo`  | `sessionStorage`. **URL 에 싣지 않는다** (open redirect 표면)      |

### 반드시 지킬 것 셋

1. **교환은 정확히 한 번만 실행한다.** `code` 는 1회용이라 두 번 부르면 두 번째가 실패한다.
   React 18 StrictMode 는 개발 모드에서 effect 를 두 번 돌리고, 그러면 **성공한 뒤 곧바로
   실패 화면이 뜬다.** `useRef` 가드로 막는다 — 이 화면에서 가장 흔한 버그다.

2. **성공 후 `code`·`state` 를 주소에서 지운다.** `router.replace` 로 이동하면 히스토리에도
   남지 않는다. 남겨 두면 뒤로가기로 같은 코드를 다시 쓰려다 실패 화면을 본다.

3. **`returnTo` 는 같은 오리진의 경로만 허용한다.** `sessionStorage` 에서 읽은 값이라도
   `/` 로 시작하고 `//` 로 시작하지 않는 문자열만 쓴다. 아니면 `/` 로 보낸다.
   `proxy.ts` 가 이미 `?returnTo=` 로 보호 경로를 돌려보내므로 그 값을 이어받는다.

## D4. 상호작용

| 트리거                | 동작                        | 결과                                                     |
| --------------------- | --------------------------- | -------------------------------------------------------- |
| 소셜 버튼             | `authorize` → 제공자로 이동 | 실패하면 로그인 화면에 `FormAlert`                       |
| 콜백 진입             | 교환 1회                    | 성공 → 이동 / 실패 → 오류 화면                           |
| `code`·`state` 없음   | 교환하지 않는다             | 잘못된 진입 안내 + `/login`                              |
| 오류 화면 `다시 시도` | `/login` 으로               | **콜백에서 재시도하지 않는다** — `code` 가 이미 소모됐다 |

## D5. 상태별 화면

| 상태                                         | 표시               | 문구 (확정)                                                        |
| -------------------------------------------- | ------------------ | ------------------------------------------------------------------ |
| 교환 중                                      | 로딩               | `로그인하고 있어요`                                                |
| 성공                                         | (즉시 이동)        | —                                                                  |
| 파라미터 없음                                | `EmptyState`       | `잘못된 접근이에요` / `로그인 화면에서 다시 시도해 주세요.`        |
| 지원하지 않는 provider                       | `EmptyState`       | 서버 `resultMessage` 그대로                                        |
| 동의 필요 (`AUTH_009`/`AUTH_011`/`AUTH_012`) | 안내 + 다시        | 서버 `resultMessage` 그대로 + `{provider} 다시 시도`               |
| 이미 다른 소셜 (`AUTH_008`)                  | 안내               | 서버 `resultMessage` 그대로 (**어느 provider 인지 서버가 말한다**) |
| state 무효 (`AUTH_010`)                      | 안내 + 다시        | 서버 `resultMessage` 그대로                                        |
| 제공자 장애 (`AUTH_014`)                     | 안내 + 다시        | 서버 `resultMessage` 그대로                                        |
| 그 외 5xx                                    | `FormAlert` + 다시 | `잠시 후 다시 시도해 주세요.`                                      |

**성공 화면을 만들지 않는다.** 성공하면 곧바로 원래 가려던 곳으로 보낸다.

## D6. 접근성

- 교환 중 상태를 `aria-live="polite"` 로 알린다 — 화면이 저절로 바뀌는 유일한 화면이다
- 소셜 버튼은 제공자 이름을 텍스트로 담는다. **로고만 두지 않는다**
- 오류 화면의 다음 행동은 링크가 아니라 `Button` — `/login` 으로의 이동이지만 재시도의 의미다
  (→ **이동이므로 `<a>` 가 맞다.** `place-back-link.tsx` 와 같은 판단을 따른다)

## D7. 테스트 케이스

**순수 로직**

- `returnTo` 검증 — `/plans` 통과 / `//evil.com` 거부 / `https://evil.com` 거부 / `null`→`/`
- 오류 코드 → 다음 행동 매핑 (다시 시도 / 제공자에서 조치 / 잘못된 접근)

**렌더 분기**

- `code` 없음 → 교환하지 않고 안내
- `AUTH_008` → 서버 문구가 그대로 나온다
- **교환이 두 번 실행되지 않는다** (가드 회귀 테스트)
- 성공 시 성공 화면을 렌더하지 않는다

**mock**

`auth-data.ts` 에 `authorize` 와 `{provider}/login` 을 추가한다. `code` 값으로
`AUTH_008`/`AUTH_010`/`AUTH_014` 를 낼 수 있게 하고, **같은 `code` 를 두 번 쓰면 실패**하게
만든다 — 그러지 않으면 중복 실행 가드를 화면으로 확인할 수 없다.
