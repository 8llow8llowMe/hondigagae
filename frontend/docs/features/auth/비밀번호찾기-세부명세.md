# 비밀번호 찾기 세부 명세

> 상위 공통명세: `docs/features/auth/공통명세.md`
> **화면 정본**: `혼디가개 로그인·회원가입·약관.dc.html` (회원가입 인증코드 절의 문법을 따른다)
> 작성일: 2026-08-31
> **계약 확인 근거**: backend auth-service **소스 실측** — `AuthWebController` ·
> `AuthPasswordResetCodeSendRequest` · `AuthPasswordResetRequest` · `AuthErrorCode` ·
> `AuthValidationMessage` (백엔드 `origin/develop` `8e44ddc` 기준, 2026-08-31).
> 관련 BE 이슈: [#41](https://github.com/8llow8llowMe/hondigagae/issues/41)

## D0. 화면 정의

- **경로**: `/(auth)/password/reset` — route group `(auth)`
- **인증**: **불필요.** `proxy.ts` `PROTECTED_PATHS` 에 넣지 않는다 — 로그인하지 못한
  사람이 쓰는 화면이다
- **진입 경로**: 로그인 화면의 `비밀번호를 잊으셨나요?` (**이 이슈에서 추가한다**)
- **이탈 경로**: `/login`

한 라우트에서 **2단계를 진행한다.** 코드 발송과 재설정을 다른 화면으로 쪼개면 이메일을
다시 입력받거나 화면 간에 들고 다녀야 한다. 회원가입의 인증코드 단계와 같은 구조다.

## D1. 계약

### `POST /api/v1/auth/password/reset/send-code`

`{ email }` — `@NotBlank` + `@Email`.

> **계정 존재 여부와 무관하게 항상 성공으로 응답한다.** 미가입 이메일과 소셜 전용 계정에는
> 각각 **안내 메일**이 나간다 (컨트롤러 설명).

→ **화면이 "가입되지 않은 이메일이에요" 라고 말하면 안 된다.** 서버가 일부러 감추는 것을
화면이 흘리면 계정 열거(account enumeration)가 된다. 성공 문구는 **항상 같다**:
`메일을 보냈어요. 받은 편지함을 확인해 주세요.`

| 오류          | 코드       | HTTP | 화면                        |
| ------------- | ---------- | ---- | --------------------------- |
| 이메일 쿨다운 | `AUTH_003` | 429  | 서버 `resultMessage` 그대로 |
| IP 발송 상한  | `AUTH_016` | 429  | 서버 `resultMessage` 그대로 |

**둘 다 429 지만 원인이 다르다** — `AUTH_003` 은 이메일당 60초, `AUTH_016` 은 IP당 시간당
상한이다. 문구를 우리가 지어내지 말고 서버 것을 쓰면 저절로 갈린다.

### `POST /api/v1/auth/password/reset`

`{ email, code, newPassword }`.

`newPassword` 제약: **8~20자, 영문자·숫자·특수문자 각 1개 이상, 공백 불가.**
회원가입·비밀번호 변경과 **같은 정규식**이라 기존 검증을 재사용한다
(`docs/features/member/공통명세.md` S1).

| 오류             | 코드       | HTTP | 뜻                                      |
| ---------------- | ---------- | ---- | --------------------------------------- |
| 코드 불일치      | `AUTH_004` | 400  | 다시 입력하면 된다                      |
| 코드 만료·미발급 | `AUTH_005` | 400  | **코드를 다시 받아야 한다**             |
| 시도 5회 초과    | `AUTH_017` | 400  | **코드가 무효화됐다. 다시 받아야 한다** |
| 검증 실패        | `AUTH_100` | 400  | 필드 오류                               |

> **성공하면 전 기기 세션이 무효화된다** (컨트롤러 설명). 재로그인이 필요하다 →
> 성공 화면에서 그 사실을 말하고 `/login` 으로 보낸다.

## D2. 컴포넌트 구성

| 컴포넌트                 | 신규/기존 | 위치                                          | 비고               |
| ------------------------ | --------- | --------------------------------------------- | ------------------ |
| `PasswordResetView`      | 신규      | `features/auth/password-reset-view.tsx`       | 2단계 상태 소유    |
| `PasswordResetEmailStep` | 신규      | `features/auth/password-reset-email-step.tsx` | 이메일 + 발송      |
| `PasswordResetCodeStep`  | 신규      | `features/auth/password-reset-code-step.tsx`  | 코드 + 새 비밀번호 |

**재사용**: `Field`/`Input` · `Button` · `FormAlert` · `FormNotice` ·
**회원가입의 비밀번호 검증 스키마** (`features/auth/schemas.ts`) · 기존 쿨다운 타이머가
회원가입에 있으면 그것을 쓴다 — 없으면 이 이슈에서 만들고 회원가입도 함께 옮긴다.

새 공통 컴포넌트는 만들지 않는다.

## D3. 데이터 흐름

```text
[1단계] 이메일 입력 → POST /auth/password/reset/send-code
        → 성공(항상) → 2단계로 전환 + 60초 재발송 타이머
[2단계] 코드 + 새 비밀번호 → POST /auth/password/reset
        → 성공 → 완료 안내 → /login
```

| 항목          | 내용                                            |
| ------------- | ----------------------------------------------- |
| API           | 위 둘                                           |
| React Query   | **쓰지 않는다** — 조회가 없다. `useMutation` 만 |
| 상태          | 컴포넌트 로컬. **URL 에 이메일을 싣지 않는다**  |
| 재발송 쿨다운 | 60초 클라이언트 타이머 (`AUTH_003` 선반영)      |

**이메일을 URL 쿼리에 넣지 않는다.** 개인정보가 주소창·기록·공유 링크에 남는다.
새로고침하면 1단계로 돌아가는 편이 낫다.

## D4. 상호작용

| 트리거                | 동작        | 결과                                |
| --------------------- | ----------- | ----------------------------------- |
| `코드 받기`           | `send-code` | 항상 2단계로. 성공 문구는 늘 같다   |
| `다시 보내기`         | `send-code` | 60초 동안 `disabled` + 남은 초 표시 |
| `비밀번호 재설정`     | `reset`     | 성공 → 완료 안내                    |
| `AUTH_005`/`AUTH_017` | —           | **1단계로 되돌린다** + 이유 안내    |
| `AUTH_004`            | —           | 2단계 유지, 코드 필드만 오류        |
| `로그인으로`          | `/login`    |                                     |

`AUTH_005`(만료·미발급)와 `AUTH_017`(5회 초과)은 **같은 처리**다 — 코드가 더는 유효하지
않으니 다시 받아야 한다. `AUTH_004`(불일치)만 그 자리에서 다시 입력한다.

## D5. 상태별 화면

| 상태                        | 표시                 | 문구 (확정)                                                                                             |
| --------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------- |
| 1단계                       | 이메일 폼            | `가입한 이메일을 알려주세요` / `비밀번호를 새로 만들 수 있는 코드를 보내드려요.`                        |
| 발송 성공                   | 2단계 + 안내         | `메일을 보냈어요. 받은 편지함을 확인해 주세요.`                                                         |
| 429 (`AUTH_003`/`AUTH_016`) | `FormAlert`          | 서버 `resultMessage` 그대로                                                                             |
| 2단계                       | 코드 + 새 비밀번호   | `메일로 받은 코드를 입력해 주세요`                                                                      |
| 코드 불일치                 | 필드 오류            | 서버 `resultMessage` 그대로                                                                             |
| 코드 만료·초과              | 1단계 복귀 + 안내    | 서버 `resultMessage` 그대로 + `코드를 다시 받아 주세요.`                                                |
| 완료                        | 안내 + 이동          | `비밀번호를 바꿨어요` / `보안을 위해 모든 기기에서 로그아웃했어요. 새 비밀번호로 다시 로그인해 주세요.` |
| 5xx                         | `FormAlert` + 재시도 | `잠시 후 다시 시도해 주세요.`                                                                           |

**"가입되지 않은 이메일" 문구를 어디에도 만들지 않는다** (D1).

## D6. 접근성

- 단계 전환을 `aria-live="polite"` 로 알린다 — 시각적으로만 바뀌면 스크린리더는 모른다
- 코드 입력은 `inputMode="text"` + `autoComplete="one-time-code"`
- 새 비밀번호는 `autoComplete="new-password"`, 표시/숨김 토글에 `aria-pressed`
- 재발송 버튼이 `disabled` 인 동안 **남은 시간을 텍스트로도** 준다
- 오류는 필드와 `aria-describedby` 로 연결

## D7. 테스트 케이스

**순수 로직**

- 오류 코드 분기 — `AUTH_004`→필드 / `AUTH_005`·`AUTH_017`→1단계 복귀 / 그 외→`FormAlert`
- 비밀번호 정규식이 회원가입과 같은 규칙임을 고정
- 쿨다운 타이머 60 → 0

**렌더 분기**

- 발송 성공 문구가 **이메일 존재 여부와 무관하게 동일**하다 (열거 방지 회귀 테스트)
- `AUTH_017` → 1단계로 돌아가고 안내가 나온다
- 완료 화면에 전 기기 로그아웃 안내가 있다

**mock**

`auth-data.ts` 에 두 엔드포인트를 추가한다. **미가입 이메일도 성공으로 응답해야 한다** —
mock 이 404 를 내면 화면이 열거 방지를 어겼는지 확인할 수 없다.
`AUTH_004`/`AUTH_005`/`AUTH_017` 을 낼 수 있는 고정 코드를 둔다.
