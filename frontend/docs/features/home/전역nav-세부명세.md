# 전역 내비게이션 세부 명세

> 작성자 / 작성일: seonghoho / 2026-08-27
> 공통 명세: [공통명세.md](공통명세.md) — 계약·문구·상태 정본

## D0. 화면 정의

- **위치**: 전역. `app/(main)/layout.tsx` 에 둔다
- **한 줄 정의**: 만든 화면들 사이를 이동하게 하고, 판정의 기준이 되는 반려견을 항상 보이게 한다
- **범위에 포함**: 데스크톱 헤더, 모바일 헤더, 모바일 하단 탭바, 반려견 스위처, 긴급 진입
- **범위에서 제외**
  - `(auth)` 그룹 — 로그인·회원가입에는 nav 를 두지 않는다. 이탈 경로가 되면 `returnTo` 흐름이 깨진다
  - 알림 — **백엔드에 API 가 없다**
  - 검색 입력 — 장소 화면 소관. 헤더에 두면 모든 화면에서 장소 검색을 기대하게 된다

## D1. 레이아웃

### 데스크톱 (1024+)

높이 **64px** 고정 헤더. `max-width` 를 두지 않고 좌우 `40px` 패딩만 둔다 — 헤더는 화면 폭을 쓴다.

```text
[로고]  [장소 찾기] [여행 일정] [AI 일정 생성 (AI)] [내 반려견]   ...   [반려견 스위처] [긴급] [프로필]
```

### 모바일 (~767)

상단 헤더 + **하단 탭바** 2단이다.

- 헤더: 로고 좌측, 반려견 스위처 + 프로필 우측. 높이 `56px`
- 탭바: 4칸 grid, 각 칸 최소 `44px`, 하단 safe-area 여백
- **탭바는 `position: fixed`** 다. 본문에 탭바 높이만큼 `padding-bottom` 을 준다

### 태블릿 (768~1023)

데스크톱 헤더를 쓴다. **탭바를 두지 않는다** — 두 패턴이 같이 보이면 어디를 눌러야 할지 모른다.

긴 한국어 실데이터로 확인할 항목:

- 반려견 이름 **20자**(최대)일 때 스위처가 헤더를 밀지 않는지 → `max-width` + `truncate`
- 메뉴 4개 + 스위처가 1024px 에서 겹치지 않는지

## D2. 컴포넌트 구성

| 컴포넌트            | 신규/기존 | 위치                                  | 비고                          |
| ------------------- | --------- | ------------------------------------- | ----------------------------- |

| `GlobalHeader`      | 신규      | `src/features/nav/global-header.tsx`  | 서버 컴포넌트 (세션으로 분기) |
| `NavLinks`          | 신규      | `src/features/nav/nav-links.tsx`      | `'use client'` — 활성 판정    |
| `MobileTabBar`      | 신규      | `src/features/nav/mobile-tab-bar.tsx` | `'use client'` — 활성 판정    |
| `PetSwitcher`       | 신규      | `src/features/nav/pet-switcher.tsx`   | `'use client'` — 드롭다운     |
| `Icon` 세트         | 신규      | `src/components/icons/`               | D6 참조                       |
| `Badge`             | 기존      | `src/components/badge.tsx`            | AI 표시에 `tone="accent"`     |

**`NavLinks` 와 `MobileTabBar` 를 하나로 합치지 않는다.** 활성 판정 로직은 같지만
메뉴 구성이 다르다 (D4-1). 합치면 조건 분기가 컴포넌트를 지배한다.

`usePathname()` 을 쓰므로 둘 다 client 다. 헤더 셸(로고·레이아웃)은 서버에 남긴다.

## D3. 데이터 흐름

```text
(main)/layout.tsx (서버) → readSession()
  ├─ 세션 없음 → GlobalHeader(authed=false)  … 스위처·보호 메뉴 없음, 조회 0회
  └─ 세션 있음 → serverFetch GET /members/me/pets (retry: false)
                  → dehydrate → HydrationBoundary → PetSwitcher (client, 같은 key)
```

| 항목                   | 내용                                                                         |
| ---------------------- | ---------------------------------------------------------------------------- |
| API                    | `GET /members/me/pets` (미로그인은 호출하지 않는다)                          |
| React Query key        | `petKeys.list()` — **반려견 목록 화면과 공유한다**                           |
| staleTime / gcTime     | 1분 / 10분 (`api-integration-guide.md` §7)                                   |
| retry                  | `isRetriable` 기반 1회 (`PET_QUERY_OPTIONS`)                                 |
| mutation 후 invalidate | 반려견 등록·수정·삭제가 `petKeys.all` 을 무효화 → **스위처가 자동 갱신된다** |

**키를 공유하는 것이 중요하다.** `/pets` 에서 반려견을 등록하면 `petKeys.all` 무효화로
헤더 스위처도 함께 갱신된다. 별도 키를 쓰면 헤더가 낡는다.

### D3-1. 선택된 반려견은 어디에 두나

**Zustand.** `architecture-guide.md` §10 의 판단 질문 — "여러 라우트에 걸친 클라이언트 전용
상태인가" 에 해당한다.

- URL `searchParams` 가 **아니다**: 모든 화면의 URL 에 `petId` 를 붙이면 공유 링크가 지저분해지고,
  링크를 받은 사람의 반려견이 아니다
- React Query 가 **아니다**: 서버가 "선택된 반려견" 을 모른다. 서버 데이터의 복사가 아니다
- `useState` 가 **아니다**: 헤더와 홈·장소 상세가 같은 선택을 공유해야 한다

**초기값**: 목록의 첫 번째. 사용자가 고르면 `localStorage` 에 `petId` 를 남겨 재방문 시 복원한다
(토큰이 아니므로 허용 — `auth-guide.md` 는 토큰만 금지한다). 목록에 없는 `petId` 면 첫 번째로 떨어진다.

## D4. 상호작용

### D4-1. 메뉴 구성 — 데스크톱과 모바일이 다르다

| 항목         | 데스크톱 헤더    | 모바일 탭바 | 근거                                                         |
| ------------ | ---------------- | ----------- | ------------------------------------------------------------ |
| 홈           | 로고가 대신      | **탭**      | 데스크톱은 로고 클릭이 관례다                                |
| 장소 찾기    | 메뉴             | **탭**      |                                                              |
| 여행 일정    | 메뉴             | **탭**      |                                                              |
| AI 일정 생성 | 메뉴 + `AI` 배지 | **없음**    | 진입 빈도가 낮고, 일정 화면 안에서 시작하는 것이 맥락에 맞다 |
| 내 반려견    | 메뉴             | 내 정보 안  | 탭 5개는 모바일에서 좁다                                     |
| 내 정보      | 프로필 아이콘    | **탭**      |                                                              |
| 긴급 시설    | 아이콘 상시      | **없음**    | 탭에 두면 평상시에 계속 붉은 신호가 보인다 (D4-4)            |

**탭은 4개로 고정한다.** 5개가 되면 375px 에서 라벨이 줄바꿈된다.

### D4-2. 미로그인 처리 — 데스크톱과 모바일이 다르다

| 플랫폼   | 처리                                                | 근거                                                                |
| -------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| 데스크톱 | 메뉴 3개를 **유지**하고 누르면 `returnTo` 로 로그인 | 아래 — 숨기면 AI 일정 생성의 존재가 드러나지 않는다 (#116)          |
| 모바일   | 탭 4개를 **유지**하고 누르면 `returnTo` 로 로그인   | 탭은 위치가 근육기억이다. 숨기면 남은 탭이 이동해 오조작이 늘어난다 |

**두 폭이 같은 처리를 쓴다.** `protected` 는 *숨김 여부*가 아니라 *로그인으로 우회시킬지*의 표시다.

### ⚠️ 아트보드를 의도적으로 벗어난 곳 (이슈 #116)

**아트보드는 숨기기를 지정했다.** `혼디가개 홈·내비게이션.dc.html` → `03 전역 nav`:

| 아트보드                                       | 헤더 내용                                               |
| ---------------------------------------------- | ------------------------------------------------------- |
| `A · 데스크톱 — 미로그인 (보호 메뉴 3개 숨김)` | `혼디가개` · `장소 찾기` · `로그인` · `회원가입`        |
| `B · 데스크톱 — 로그인 후`                     | `혼디가개` · `장소 찾기` · `여행 일정` · `AI 일정 생성` |

그대로 두면 **미로그인 데스크톱 헤더에 `장소 찾기` 하나만 남는다.** `/ai-plans/new` 로 가는
링크는 이 헤더 항목과 `/plans` 안의 "직접 만들기" 시트(이것도 로그인 필요) 둘이었다. 모바일 탭에는
AI 항목이 애초에 없고(D4-1), 홈은 미로그인이면 일정 섹션 자체를 렌더하지 않았다.

→ **처음 방문한 사람이 AI 여행 설계의 존재를 알 방법이 없다.** 아트보드는 nav 배치를 그린 것이고,
기능의 발견 가능성은 그 화면 하나로 판단할 문제가 아니라고 보아 벗어났다.

**discoverability 문제는 nav 가 아니라 홈이 메웠다** (#905 R1). 홈 좌측 레일에 게스트에게도 보이는
AI 배너(`Banner`, 골든타임 아래·올레 배너 위, `toLoginHref` 로 로그인을 거친다)가 생기면서
`/ai-plans/new` 링크는 **셋**이 됐다 — 위 둘에 이 배너가 더해졌다. **모바일 탭에 AI 항목을 넣지
않는다는 D4-1 의 결정 자체는 그대로다** — 배너가 진입점을 대신할 뿐 탭 구성은 바뀌지 않았다.

되돌리려면 이 절과 `visibleDesktopItems` 를 함께 되살린다. **768 폭 실측**: 미로그인 헤더는 항목 3개

- `로그인`·`회원가입` 이 한 줄에 들어가고 넘치지 않는다 (`scrollWidth == clientWidth == 768`,
  AI 항목 끝 445 / 긴급 아이콘 시작 511 — 여유 66px). 항목을 더 늘리면 이 여유부터 확인한다.

`내 반려견` · `마이페이지` 는 계속 nav 밖이다 — 아바타 팝오버가 맡는다 (아트보드 03-B).

```text
미로그인 + [일정] 탭 → /login?returnTo=%2Fplans → 로그인 → /plans 복귀
```

`safeReturnTo()` 를 쓴다 (`src/lib/http/redirect.ts`, 이슈 #24 산출물).

### D4-3. 반려견 스위처

| 트리거             | 동작                                    | 결과                                |
| ------------------ | --------------------------------------- | ----------------------------------- |
| 스위처 클릭        | 드롭다운 열림                           | `aria-expanded="true"`              |
| 반려견 선택        | Zustand 갱신 + `localStorage` 기록      | **판정이 붙은 화면이 재조회된다**   |
| "반려견 등록" 클릭 | `/pets/new` 이동                        | 드롭다운 닫힘                       |
| 상한(5마리) 도달   | "반려견 등록" 을 **비활성 + 이유 표시** | `/pets` 목록과 같은 규칙 (공통명세) |
| `Esc` / 외부 클릭  | 닫힘                                    | 포커스가 트리거로 복귀              |
| 반려견 0마리       | 스위처 대신 **"반려견 등록" 버튼**      | 빈 드롭다운을 보여주지 않는다       |

**선택을 바꾸면 적합도·산책 위험도가 다시 조회된다.** 그래서 스위처의 위치가 헤더 상시 노출이다 —
판정의 기준을 바꾸는 컨트롤이 화면 밖에 숨어 있으면 사용자가 왜 값이 바뀌었는지 모른다.

### D4-4. 긴급 진입

| 플랫폼   | 위치                     | 톤                                              |
| -------- | ------------------------ | ----------------------------------------------- |
| 데스크톱 | 헤더 아이콘 상시         | `--danger-500` 아이콘. **배경을 채우지 않는다** |
| 모바일   | 홈의 얇은 바 + 장소 화면 | 같음                                            |

**평상시에 경고처럼 보이지 않게 한다.** 아이콘만 danger 색이고 배경·테두리는 중립이다.
`--danger-*` 는 5xx 전용이라는 `DESIGN.md` 규칙과 충돌하지 않는다 — 이건 상태 표시가 아니라
**아이콘의 의미색**이다. 그 예외를 명세에 남긴다.

**1024 이상에서는 아이콘 옆에 글자를 붙인다** ([#913](https://github.com/8llow8llowMe/hondigagae/issues/913)).
아이콘 하나로는 처음 온 사람에게 "병원·약국" 이 읽히지 않았다 — 구급상자 모양이 약국인지
응급실인지 갈린다. 계정 트리거도 같은 이유로 `내 정보` 를 붙인다. 두 글자 모두 `--fg` 다
(붉은 글자는 경보로 읽힌다). 높이 44 는 그대로이고 폭만 글자만큼 자란다.

| 요소        | 1024 미만    | 1024 이상                       | 실측 (1024 · 1280 · 1440)                |
| ----------- | ------------ | ------------------------------- | ---------------------------------------- |
| 응급 링크   | 아이콘 44×44 | 아이콘 + `병원 · 약국` · 113×44 | 로그인·게스트 모두 헤더 넘침 없음        |
| 계정 트리거 | 아이콘 44×44 | 아이콘 + `내 정보` · 96×44      | 로그인 1024 에서도 스위처와 한 줄에 든다 |

- `aria-label` 은 보이는 글자를 포함한다(`병원 · 약국` · `내 정보 메뉴 열기`, WCAG 2.5.3).
- 계정 트리거에 이름 첫 글자를 쓰지 않는다 — `AccountMenu` 는 회원 정보를 조회하지 않고,
  헤더 한 칸을 위해 모든 화면에 조회를 하나 늘리지 않는다.

## D5. 상태별 화면

| 상태                   | 헤더                     | 탭바        |
| ---------------------- | ------------------------ | ----------- |
| 미로그인               | 로그인·회원가입 버튼     | 탭 4개 유지 |
| 로그인 + 반려견 0마리  | "반려견 등록" 버튼       | 그대로      |
| 로그인 + 반려견 1마리+ | 스위처                   | 그대로      |
| 반려견 조회 loading    | 스위처 자리에 `Skeleton` | 그대로      |
| 반려견 조회 5xx        | **스위처를 숨긴다**      | 그대로      |
| `(auth)` 그룹          | **nav 없음**             | **없음**    |

**반려견 조회가 실패하면 스위처를 숨기고 nav 는 유지한다.** 헤더에 `ErrorState` 를 넣지 않는다 —
nav 가 에러 화면이 되면 어디로도 갈 수 없다. 홈의 판정 섹션이 그 실패를 대신 알린다.

## D6. 접근성

- 헤더는 `<header>`, 메뉴는 `<nav aria-label="주요">`, 탭바는 `<nav aria-label="하단">`
  — **랜드마크가 문서 전체에 0개**인 현재 상태를 여기서 해결한다 (이슈 #15)
- 활성 항목에 `aria-current="page"`. **색만으로 표시하지 않는다** — weight 도 함께 올린다
- 스위처는 `aria-expanded` / `aria-controls`. 열리면 첫 항목에 포커스, `Esc` 로 닫고 트리거 복귀
- 긴급 아이콘은 icon-only 라 **`aria-label` 이 타입으로 강제된다** (`component-guide.md` §7)
- 탭 라벨을 아이콘만으로 두지 않는다. **아이콘 + 텍스트**를 함께 (12px caption)
- 모바일 탭 각 칸 최소 `44×44`
- 스킵 링크(`본문으로 바로가기`)를 헤더 앞에 둔다 — 탭바까지 있으면 탭 이동이 길다
