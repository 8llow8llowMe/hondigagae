# 홈 첫 방문 판정 · 온보딩 밴드 세부 명세

> 진단 근거: [`docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md`](../../superpowers/specs/2026-09-15-ui-ux-audit-design.md) **H-1 (P0) · H-4 (P1)**, 시안 §1 · §9.
> 이 문서는 `홈-세부명세.md` 의 **좌측 맥락 패널 첫 카드**만 바꾼다. 나머지 홈 규칙은 그 문서가 정본이다.
> 한 레인(한 이슈 · 한 브랜치)이다 — 둘 다 `home-view.tsx` 의 같은 카드를 고치기 때문이다.

## D0. 화면 정의

- **경로**: `/` (변경 없음). 미로그인도 열린다 (공통명세 S1).
- **바꾸는 것**
  1. **H-1** 기준 장소가 없어도 `오늘 산책 {등급}` 판정을 그린다. FE 고정 **대표 지점** 으로 조회하고, 기준 줄이 그 사실을 말한다.
  2. **H-4** 미로그인 · 반려견 0마리의 프로필 자리를 링크 톤 행에서 **주 버튼이 있는 온보딩 행** 으로 바꾼다. 모바일 헤더에 미로그인 진입점(`로그인` 텍스트 링크)을 둔다.
- **바꾸지 않는 것**: 카드 경계(`[누구 · 지금 안전한가 · 언제 나가나]` 한 카드 · `[위급하면]` 한 카드, `DESIGN.md` §7-1) · 골든타임 · 우측 열 전부.
- **왜 지금**: 첫 방문 · 새 기기 · 시크릿 모드 · 공모전 심사용 브라우저 전부 `localStorage` 가 비어 있어, 서비스의 첫 문장("지금 가도 되나")이 홈에 없다. `use-home-insight.ts` 의 `useWalkSafety` 머리주석이 그 상태를 "섹션 미렌더" 로 정해 두었고, 공통명세 S4-1 · S5-1 이 그 결정의 정본이다. **이 문서가 그 두 절을 갱신한다** (D3-3).

## D1. 레이아웃

폭 분기 없음. 좌측 맥락 패널 첫 카드의 **블록 순서**만 바뀐다.

```text
[카드 1]                              현재                     →  변경
  ProfileCard (프로필 / 등록 유도)     링크 행 "반려견 등록 ›"      온보딩 행: 제목 + 설명 + [반려견 등록] primary
  WalkVerdict                          기준 없으면 미렌더           기준 없으면 대표 지점으로 렌더 · 기준 줄 2줄
  WalkTimesSection                     (변경 없음)
[카드 2] 병원 배너                     (변경 없음)
```

- 온보딩 행은 **프로필 자리 그대로**다 (`RegisterPrompt`). 반려견이 1마리 이상이면 지금처럼 프로필 행이 선다. 밴드를 카드 밖에 새로 두지 않는다 — §0 카드 판정("혼자 떼어놔도 말이 되는가") 에 걸리고, 판정의 화자(프로필)와 갈라진다.
- 주 버튼은 `ButtonLink variant="primary" size="md"`, 행 오른쪽 끝. 390px 에서 제목 · 설명이 두 줄로 접히고 버튼은 세로 중앙.
- 헤더(모바일 `<768`): 응급 아이콘 왼쪽에 `로그인` 텍스트 링크(`text-body-2 text-link font-semibold`, 44px 탭 영역). 데스크톱은 이미 `로그인 · 회원가입` 이 있어 변경 없음. 로그인 상태에서는 렌더하지 않는다.
- 판정 기준 줄은 **2줄**이 된다 (기존 1줄 `{장소} 기준` 유지 + 대표 지점일 때만 안내 캡션 1줄 추가). 시안 §1 ②.

## D3. 데이터 흐름

### D3-1. 기준 장소 결정 (변경)

```text
resolveBasisPlaceId(recentPlaceId, planFirstPlaceId = null, defaultPlaceId)
  1. 최근 본 장소 (localStorage)      ← 있으면 그대로 (현행)
  2. (일정 첫 장소 — 현행대로 null)
  3. DEFAULT_BASIS_PLACE_ID            ← 신규. 1·2 가 없을 때
```

- `useWalkSafety(placeId, condition)` 는 그대로다 — placeId 가 항상 있으니 `enabled` 가 항상 true 가 된다. **`enabled: placeId !== null` 은 지우지 않는다** (D5-3 의 404 폴백이 null 을 다시 만든다).
- 기준 줄은 서버 `data.placeTitle` 을 그대로 쓴다 (현행). 대표 지점이면 그 아래 캡션 `messages.home.basisDefaultNote` 를 붙인다. **대표 지점의 이름을 FE 가 하드코딩하지 않는다** — 서버가 준 `placeTitle` 만 쓴다.

### D3-2. 대표 지점 값

- `DEFAULT_BASIS_PLACE_ID = '126454'` (**사라봉공원**, 제주시 건입동 · 33.5160, 126.5462). 근거: dev `GET /places` 실측(2026-09-15). 제주시 도심 안, `JEJU_QUERY_CENTER`(제주시청 33.4996, 126.5312)에서 약 2.3km, 시민 산책지라 "산책 판정" 의 기준으로 뜻이 맞는다. `placeId` 는 TourAPI `contentId` 축이라 dev · 운영이 같다고 본다 — 갈리면 D5-3 이 받는다.
- `NEXT_PUBLIC_DEFAULT_BASIS_PLACE_ID` 로 덮어쓸 수 있게 둔다 (`.env.example` 에 주석과 함께 추가). 값이 없으면 상수.

### D3-3. 문서 갱신 (같은 PR)

- `공통명세.md` S4-1 표 `오늘 판정` 행: `조건부 · 기준 장소가 없으면 섹션 자체를 렌더하지 않는다` → **`항상 · 기준이 없으면 대표 지점(사라봉공원) 기준으로 그리고 캡션이 그 사실을 말한다`**.
- `공통명세.md` S5-1 "A 의 약점(첫 방문자에게는 기준이 없다)" 아래에 `→ 대표 지점 폴백으로 해소 (홈-첫방문-판정-세부명세.md)` 한 줄.
- `use-home-insight.ts` 의 `useWalkSafety` 머리주석 · `recent-place.ts` 머리주석의 "섹션 자체를 렌더하지 않는다" 문장을 바꾼다. 코드 주석과 문서가 같은 말을 해야 한다.

## D4. 상호작용 · 문구 (확정)

| 키                                     | 문구                                                         | 어디                                                   |
| -------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| `home.basisDefaultNote`                | `제주시 대표 지점이에요. 장소를 보면 그곳 기준으로 바뀌어요` | 판정 기준 줄 아래 caption, 대표 지점일 때만            |
| `home.guestProfileTitle`               | `우리 아이 기준으로 보려면`                                  | 온보딩 행 제목 (기존 키 값 교체)                       |
| `home.guestProfileDesc`                | `크기·더위 민감도까지 넣은 판정을 볼 수 있어요`              | 온보딩 행 설명 (기존 키 값 교체)                       |
| `home.registerPet`                     | `반려견 등록`                                                | 버튼 라벨 (변경 없음)                                  |
| `nav.login` (또는 헤더가 쓰는 기존 키) | `로그인`                                                     | 모바일 헤더 링크 — 기존 데스크톱 라벨 키를 그대로 쓴다 |

- 온보딩 행의 버튼은 `/pets/new` 로 간다 (현행 `RegisterPrompt` href 그대로). 미로그인은 `proxy.ts` 가 `/login?returnTo=%2Fpets%2Fnew` 로 보낸다 — 여기서 분기하지 않는다.
- 장소 상세를 열면 `writeRecentPlaceId` 가 저장하고(현행), 홈에 돌아오면 그 장소 기준이 되며 캡션이 사라진다. 이것이 캡션 문장의 약속이다.
- 행 전체가 링크였던 현행과 달리 **버튼만** 링크다. 제목·설명은 텍스트. (행 전체 탭은 버튼과 이중 포커스가 된다.)

## D5. 상태별 화면

| 상태                        | 화면                                                                                |
| --------------------------- | ----------------------------------------------------------------------------------- |
| 최근 본 장소 있음           | 현행 그대로. 캡션 없음                                                              |
| 최근 본 장소 없음 (첫 방문) | 대표 지점 판정 + 캡션 1줄. **판정 섹션이 렌더된다**                                 |
| 대표 지점 조회 로딩         | 현행 `WalkVerdict` 스켈레톤                                                         |
| 대표 지점 404 (D5-3)        | 판정 섹션 미렌더 (현행 첫 방문 화면으로 떨어진다). 콘솔 경고 1회                    |
| 대표 지점 5xx · 무응답      | 현행 오류 상태(`오늘 판정을 불러오지 못했어요` + 재시도). 대표 지점을 버리지 않는다 |
| 미로그인                    | 온보딩 행 + 헤더 `로그인`. 판정은 반려견 조건 없이(현행 `guestVerdictNotice` 유지)  |
| 로그인 · 0마리              | 온보딩 행(같은 문구). 헤더 `로그인` 없음                                            |
| 로그인 · 1마리 이상         | 프로필 행 (변경 없음)                                                               |

### D5-3. 저장된 기준 404 → 대표 지점, 대표 지점 404 → 미렌더

현행 `basisGone` 은 저장된 id 가 404 면 `clearRecentPlaceId()` 후 `null` 로 떨어져 **미렌더**였다. 변경 후에는 `null` 이 대표 지점으로 다시 해소되므로 **자연히 대표 지점 판정으로 넘어간다** — 추가 코드 없이 한 단계 더 좋아진다. 대표 지점 자체가 404 면(운영 DB 에 없음) `basisPlaceId` 를 `null` 로 굳혀 미렌더한다. 두 번째 404 에 대표 지점을 다시 시도하지 않는다 — 영원히 같은 404 다.

## D6. 접근성

- 캡션은 판정 `section` 안의 텍스트라 스크린리더가 등급 · 체감온도 · 기준 · 캡션 순으로 읽는다. `aria-live` 를 붙이지 않는다 (초기 렌더다).
- 온보딩 행 버튼의 이름은 `반려견 등록` 하나다. 제목을 `aria-labelledby` 로 잇지 않는다 — "우리 아이 기준으로 보려면 반려견 등록" 이 한 문장으로 읽히는 것이 오히려 자연스러워 검토했으나, 버튼 이름이 길어져 `Button` 규약(동사구 한 개)과 어긋난다.
- 모바일 헤더 `로그인` 링크는 44px 탭 영역, 아이콘 없이 텍스트.

## D7. 테스트 케이스

- 순수 로직 (TDD, `reasons.test.ts`):
  - `resolveBasisPlaceId(null, null, '126454')` → `'126454'`
  - `resolveBasisPlaceId('111', null, '126454')` → `'111'`
  - `resolveBasisPlaceId('', null, '126454')` → `'126454'` (빈 문자열은 값이 아니다 — 기존 규칙)
  - `resolveBasisPlaceId(null, null, null)` → `null` (셋째 인자 생략 호환)
  - `isDefaultBasis('126454')` → true, `isDefaultBasis('111')` → false
- 렌더 분기 (`walk-verdict.test.ts` · `profile-card.test.ts`, `renderToStaticMarkup` 문자열 단언):
  - `basisIsDefault` true → 마크업에 `basisDefaultNote` 문구 포함, false → 미포함
  - `RegisterPrompt` 마크업에 `href="/pets/new"` 인 `a` 가 **1개**, 클래스에 primary 변형 포함, 제목 · 설명 텍스트 포함
- e2e (`e2e/surface.spec.ts` 패턴, 새 컨텍스트 · 스토리지 없음 · 390px): `main` 첫 화면(`scrollY=0`)에 `오늘 산책` 텍스트와 등급어가 보인다. `basisDefaultNote` 가 보인다.
- 문구: `message-tone.test.ts` 통과 (새 문구 모두 해요체).

## D8. 미결 사항

- **D8-1. 위치 권한이 있으면 가까운 장소로 승격할까** — 선택지 A: 이번 범위 밖(대표 지점만). 선택지 B: `getCurrentPosition()` 이 `granted` 면 `GET /places?lat&lng&radius` 첫 장소를 기준으로. **추천 A.** B 는 왕복 1회가 늘고 "왜 이 장소인가" 를 화면이 또 설명해야 한다. 후속 이슈로 남긴다.
- **D8-2. 대표 지점을 권역별로 둘까** — 미로그인은 위치도 모르니 하나로 충분하다. **하나로 확정.**
