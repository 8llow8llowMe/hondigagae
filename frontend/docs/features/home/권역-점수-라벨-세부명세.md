# 권역 비교 점수 라벨 · 동점 문구 세부 명세

> 진단 근거: [`docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md`](../../superpowers/specs/2026-09-15-ui-ux-audit-design.md) **H-3 (P1)**, 시안 §1 ④.
> `홈-세부명세.md` 의 권역 섹션(`RegionalWeatherSection`, #158 · #342 · #352) 위에서 **라벨과 헤드라인 문장**만 바꾼다.
>
> **#1065 (2026-09-30) 가 라벨 두 곳을 다시 바꿨다** — D8-1 참고. 제목 아래 캡션(`regionScoreCaption`)은 제목 옆 ⓘ(`regionScoreInfo`)로 들어갔고, 배지는 `{score}점` → `{score}/100` 이다. 아래 D1 · D2 · D4 · D7 의 캡션·`점` 표기는 #638 당시의 기록이다. 동점 문구(D3 · D5)는 그대로다.
>
> **#1068 (2026-10-01) 이 칸 전체를 다시 그렸다** — D9 참고. 점수 배지가 걷히고 22/900 숫자 + `/100` + 3px 막대가 됐고, 날씨 값은 `24–31℃` · `강수 10%` 두 줄이다. D1 의 칸 레이아웃과 D8-3 의 배지 여백은 그 이전의 기록이다.

## D0. 화면 정의

- **경로**: `/` 우측 열 첫 카드 `오늘 나가기 좋은 권역`.
- **현상 (2026-09-15 실측)**: 5권역 점수 배지가 모두 `100` 이고 무엇의 100인지 라벨이 없다. 헤드라인은 `오늘은 제주시권이 가장 나아요` — 동점인데 1위를 단정한다. `regionScoreNote`(`날씨만 본 점수예요`)는 #342 에서 걷었고, 그 주석이 "되살릴 때는 자리가 바뀌었는지 먼저 본다" 고 적어 두었다. **자리가 바뀌었다** — 레일 카드 안에서 점수가 날씨 값 아래 홀로 서 있어 자리가 말을 못 한다.
- **바꾸는 것**
  1. 카드 제목 아래 `description` 한 줄로 점수의 뜻과 만점을 밝힌다.
  2. 점수 배지 텍스트를 `100` → `100점`.
  3. 최고점 동점(2곳 이상)일 때 헤드라인 문장을 동점 문장으로 갈아 낸다.
- **바꾸지 않는 것**: `recommendedRegion` · `recommendationReasons`(서버 완성형 문장) 렌더, 배지 톤(`suitabilityTone(levelOf(score))`), 레일 · 비교표 구조, `regionNone` 갈래.

## D1. 레이아웃

```text
오늘 나가기 좋은 권역                                    (Surface title)
반려견 활동 적합도 · 100점 만점                          (Surface description, caption — 신규)
오늘은 제주시권 · 서귀포권 · 동부권 · 서부권이 똑같이 좋아요   (동점 문장 — 신규 갈래)
  최고기온 26도, 강수확률 20% 로 … (서버 recommendationReasons — 변경 없음)
[제주시권] 구름많음 최고 26℃ 최저 22℃ 강수 20%  [100점]  (배지 텍스트만 변경)
```

- `description` 은 `Surface` 가 이미 받는 prop 이다 (`surface.tsx` 의 `Surface`). 새 자리를 만들지 않는다.
- 배지 `size="score"` 의 폭이 `100` → `100점` 으로 한 글자(10.4px) 늘어난다. **늘어난 몫은 칸 밖이 아니라 숫자 자리에서 빠진다** — 칸은 고정 폭이고(`w-44` 176 / `lg:w-46` 184. 초안이 적은 "150" 은 #395 시절의 낡은 값이다), `w-20`/`lg:w-22` 는 하한이 아니라 상한이라 남는 폭이 모자라면 조용히 눌린다.
  - 390 실측: `100점` + `px-3` 이면 숫자 자리에 **63.6px** 만 남아 가장 넓은 줄 `최고 31.0℃`(62.9)에 **0.6px** 이었다. 겨울의 `최저 -3.0℃` 처럼 부호 한 글자가 붙는 순간 접힌다.
  - 그래서 **`score` 배지의 좌우 여백을 12 → 8 로 내린다** (D8-3). 숫자 자리가 71.5px(여유 8.6)로 돌아온다. 칸 폭 상향은 `lg` 상한 187.4(1440 에서 화살표가 남지 않는 값)와 충돌해 쓰지 않는다.
  - 390px 레일 실측을 D7 에 둔다.

| ------------------------ | ---------------- | ------------------------------------------------ | ------------------------------------------------------------------------ |

## D3. 데이터 흐름

입력은 `RegionalWeatherResponse` 만이다. 추가 조회 없음.

```text
findTiedTop(regions)
  → weatherScore !== null 인 권역만
  → 최대값과 같은 권역들 (순서는 regions 순서 그대로 — 서버 정렬 존중)
  → []  (전부 null)  |  [one]  |  [two or more]
```

- 동점 판정은 **점수 값의 동일성**이다. 서버 `recommendedRegion` 이 무엇을 골랐는지와 무관하게, 화면이 같은 숫자를 보여 주면서 "가장 나아요" 라고 말하는 것을 막는 규칙이다.
- `recommendedRegion` 이 동점 집합 안에 있으면 동점 문장에서 **그 권역을 첫 자리**에 둔다. 서버의 선택을 지우지 않고 앞세운다.

## D4. 상호작용 · 문구 (확정)

| 키                        | 문구                              | 조건                                                               |
| ------------------------- | --------------------------------- | ------------------------------------------------------------------ |
| `home.regionScoreCaption` | `반려견 활동 적합도 · 100점 만점` | 카드 description, 항상                                             |
| `home.regionScoreUnit`    | `{score}점`                       | 배지                                                               |
| `home.regionTied`         | `오늘은 {names}이 똑같이 좋아요`  | 동점 2~4곳. `{names}` = `제주시권 · 서귀포권` (구분자 `·`)         |
| `home.regionTiedAll`      | `오늘은 어느 권역이든 좋아요`     | 동점이 **점수 있는 권역 전부**일 때 (예보 없음 권역은 셈에서 뺀다) |
| `home.regionRecommended`  | `오늘은 {name}이 가장 나아요`     | 단독 1위 (변경 없음)                                               |

- 동점 문장 아래에도 `recommendationReasons` 를 그대로 붙인다 — 서버가 준 근거 문장은 "왜 좋은가" 를 말하고, 동점 문장은 "어디가" 만 바꾼다.
- 조사 `이/가` 는 `{names}` 뒤에 항상 `이` 로 둔다 (권역 이름이 전부 `권` 으로 끝난다 — `제주시권이`, `서부권이`). 이름 규칙이 바뀌면 D8-2.
- **판정 낮은 권역을 따로 짚지 않는다** (진단 시안의 `한라산권만 18℃로 쌀쌀해요` 는 채택하지 않는다). "쌀쌀" 은 FE 의 판단이고, 그 권역은 표에서 점수와 기온으로 이미 보인다.

## D5. 상태별 화면

| 상태                         | 헤드라인                                                       |
| ---------------------------- | -------------------------------------------------------------- |
| 단독 1위                     | `오늘은 {name}이 가장 나아요` (현행)                           |
| 2~4곳 동점                   | `오늘은 {names}이 똑같이 좋아요`                               |

| 어떤 권역 점수가 null        | 그 권역은 동점 셈에서 빠지고 배지는 `예보 없음` (현행)         |

## D6. 접근성

- description 은 `Surface` 가 제목과 같은 헤더 영역에 두므로 스크린리더가 `제목 → 캡션 → 문장` 순으로 읽는다.
- 배지 `100점` 은 `tabular-nums` 유지. `점` 이 붙어도 열 정렬은 숫자 자리 수가 같아 어긋나지 않는다 (2자리·3자리 혼재 시는 현행과 같은 문제라 이 문서 범위 밖).

## D7. 테스트 케이스

- 순수 함수 (`region-tie.test.ts`, TDD):
  - `[100, 100, 100, 100, 100]` → 5곳, `isAll === true`
  - `[100, 100, 90, null, 80]` → 2곳, `isAll === false`
  - `[90, 80, 70]` → 1곳
  - `[null, null]` → 0곳
  - `recommendedRegion` 이 동점 집합에 있으면 결과 첫 요소
- 렌더 분기 (`regional-weather-section.test.ts`): 전부 100 fixture → `어느 권역이든 좋아요` 포함, `가장 나아요` 미포함, `100점` 포함, `반려견 활동 적합도 · 100점 만점` 포함. 단독 1위 fixture → `가장 나아요` 유지.
- 레이아웃 (`e2e/surface.spec.ts` 패턴, 390px): 권역 레일 카드 안 배지가 카드 오른쪽 경계를 넘지 않는다 (`getBoundingClientRect().right <= card.right`).
- 문구: `message-tone.test.ts`.

## D8. 미결 사항

- **D8-1. `점` 대신 `/100` 표기** — 장소 적합도는 `90 /100` 으로 쓴다 (`MetricValue`). 권역 배지는 `size="score"` 한 덩어리라 `/100` 을 작은 글자로 넣을 자리가 없다. **`점` + description 만점 표기로 확정.** 같은 카드 안에 만점이 적혀 있으면 `/100` 을 반복할 이유가 없다.
  - **#1065 에서 뒤집었다 (2026-09-30).** 홈 첫 화면의 상시 글줄을 줄이려고 캡션을 제목 옆 ⓘ 로 옮기면서, 만점을 상시로 말할 자리가 배지뿐이 됐다. 그래서 배지가 `56/100` 으로 만점까지 말하고(#638 의 목적 — "무엇의 100인지 화면에 있다" — 을 배지가 대신한다), 점수의 뜻(`날씨만 보고 매긴 반려견 활동 적합도`)은 ⓘ 안에서 원할 때 읽는다. `/100` 은 작은 글자로 나누지 않고 한 덩어리 그대로다.
  - **#1068 에서 배지를 걷었다 (2026-10-01).** 점수가 칸의 주인공(22/900)이 되면서 `/100` 이 `MetricValue` 의 단위 자리(12 · `--fg-muted`)로 내려갔다 — 이 항목이 처음 짚은 "장소 적합도는 `90 /100`" 과 이제 모양까지 같다. D9 참고.
- **D8-2. 권역 이름의 조사** — 서버 `name` 이 `권` 으로 끝나지 않는 값을 내면 `이/가` 가 틀릴 수 있다. 그때 `messages` 에 조사 헬퍼를 두는 대신 문장을 `{names} 모두 좋아요` 로 바꾼다 (조사 없음).
- **D8-3. `score` 배지 여백 12 → 8** — **확정 (2026-09-15).** D1 의 390 실측이 `px-3` 에서 숫자 자리 여유를 0.6px 까지 밀어붙인다는 것을 보였다. 8 은 spacing 스케일 안이고, #412 가 12 를 고른 근거(_"숫자만 담는 배지라 8 에서는 조여 보인다"_)는 `100` → `100점` 으로 글자가 하나 늘어난 지금 약해졌다. 대안인 칸 폭 상향은 `lg` 상한 187.4 와 충돌해 쓰지 않는다.

## D9. 칸 시각화 — 점수를 주인공으로 (#1068, 2026-10-01)

> 이슈 [#1068](https://github.com/8llow8llowMe/hondigagae/issues/1068) 이 정본이다. 참고 목업(UI 정리 2차)과 다르면 이슈가 맞다 — 목업의 `예보를 받지 못했어요` 보조 줄은 이슈에 없어 넣지 않았다.

- **D9-1. 무엇이 바뀌었나.** 칸이 `아이콘 | 최고·최저·강수 세 줄 | 점수 배지` 가로 배치에서 세로 줄 넷이 됐다. 정보는 줄이지 않고 형태로 바꾼다.

  ```text
  서귀포권        [추천]    이름 14/600 · 서버 추천 날의 단독 1위만 Badge tone="brand"
  86 /100                   MetricValue row — 22/900 등급 색 -500 · 단위 12 --fg-muted
  ━━━━━━━━━━━━━━━░░░        3px 막대 — 길이 = 점수, 색 = METRIC_FILL_TONE(-500), 트랙 --band
  ☀ 24–31℃                  날씨 아이콘 24 · 14/600
  ☂ 강수 10%                UmbrellaIcon 16 · 12 --fg-muted
  ```

- **D9-2. 등급 경계는 `SuitabilityLevel.from` 과 같다** — 80 이상 높음 · 60 이상 보통 · 그 아래 낮음. 서버가 칸에 등급 metadata 를 주지 않아 FE 는 색만 매핑하고 등급 이름을 짓지 않는다 (`levelOf`).
- **D9-3. `추천` 표시는 헤드라인이 `가장 나아요` 라고 말하는 날에만 선다** (`lib/insight/region-cell.ts` 의 `soleRecommendedCode`). 서버 추천이 없는 날(경보 · 예보 없음)과 최고점 동점 날에는 어느 칸에도 없다. 점수가 가장 높은 칸이 아니라 **서버가 고른 권역**에 붙는다 — 헤드라인이 이미 서버의 선택을 말하고 있다.
- **D9-4. 기온은 한 줄 범위다** (`regionTemperatureText`). 표기는 #1067 의 `formatStandaloneCelsius` 라 정수의 `.0` 을 떼고 의미 있는 소수는 남긴다. 두 값이 같으면 한 값(`31℃`), 한쪽만 오면 그 값의 이름을 붙인다(`최고 31℃`) — 접두 없이 한 값만 두면 #206 이 되살아난다.
- **D9-5. 예보 없는 권역은 점선 막대 + `예보 없음`** 이다 (§2-3 `UNKNOWN`). 0점은 빈 실선 트랙이라 **모양으로** 갈린다. 점선은 `--metric-unknown-500`(점선 전용) — 바로 위 낱말이 뜻을 함께 말해 선이 유일한 채널이 아니다. 숫자 줄과 같은 높이(30)에 배지를 앉혀 다섯 칸의 막대·날씨 줄이 열을 이룬다.
- **D9-6. 막대는 `aria-hidden` 이다.** 바로 위 숫자의 그림이라 보조기기에 점수가 두 번 읽히지 않게 한다. DESIGN.md §10 의 "진행률 링·게이지" 가 아니다 — 링은 숫자를 대신하고, 이 막대는 숫자 옆에서 §2-3 의 "색 + 텍스트 + 지표 바" 중 한 채널이다.
- **D9-7. 칸 폭은 그대로다** (`w-44` 176 / `lg:w-46` 184). 줄마다 칸 폭을 혼자 쓰므로 #412 · #638 · #1065 의 가로 폭 경쟁(숫자 자리 ↔ 배지 여백)이 없어졌다. 가장 넓은 줄은 `☀ 27.5–31.5℃`(116px, 390 실측 글자 84.0) — 둘째 칸 글자 자리 163 에 47px 여유다. 산식은 `styles/overlay-and-region-cell.test.ts`, 줄 수는 `e2e/region-score-badge.spec.ts` 가 `Range.getClientRects` 로 잰다.
- **D9-8. 실측 (2026-10-01, mock)** — 390 · 768 · 1440 모두 다섯 칸의 모든 글자 노드가 1줄, 칸 넘침 0, 칸 높이 121. 섹션 높이 268(390) · 280(768 · 1440). 골격 마지막 칸을 `h-40` → `h-42` 로 맞춰 데이터 도착 때 밀림이 2 · −2px 다.
- **D9-9. `MetricBadge size="score"` 를 쓰는 곳이 없어졌다.** 유일한 사용처가 이 칸이었다. #1069(같은 묶음, 다른 레인)가 같은 컴포넌트를 쓸 수 있어 이 PR 에서는 `metric.tsx` 를 건드리지 않았다 — 두 레인이 머지된 뒤에도 쓰는 곳이 없으면 그때 걷는다.
  - **#1076 에서 걷었다 (2026-10-01).** #1069 도 쓰지 않는 것을 확인해 `metric.tsx` 의 `score` 크기·타입·주석을 제거했다. `overlay-and-region-cell.test.ts` 의 `size="score"` 문자열 회귀 검사도 함께 걷었다 — 타입이 `size="score"` 자체를 컴파일 단계에서 막으므로 문자열 검사가 하던 일을 더 이른 시점에 더 넓게 대신한다.
