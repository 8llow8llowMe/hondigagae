# 골든타임 헤드라인 문구 세부 명세

> 진단 근거: [`docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md`](../../superpowers/specs/2026-09-15-ui-ux-audit-design.md) **H-2 (P1)**, 시안 §1 ③.
> 이 문서는 **헤드라인 줄의 등급 배지**를 다룬다. 곡선 면은 `홈-세부명세.md` **D4-1-c** 가 정본이다.
>
> **1차(#637)에서는 곡선을 그대로 뒀는데, 그것이 잔여로 남았다** — 아래 D9 · 이슈 [#656](https://github.com/8llow8llowMe/hondigagae/issues/656).

## D0. 화면 정의

- **경로**: `/` 좌측 카드 1 의 `WalkTimesSection` (`AVAILABLE` 갈래).
- **현상**: `11:00 – 23:00` 옆에 `goldenLevel.name`(예: `주의`) 배지가 서서 "좋은 시간인데 주의?" 로 읽힌다. 실제로 주의는 창 안의 14 · 15시 두 칸이다 (2026-09-15 실측).
- **바꾸는 것**: 헤드라인에서 배지를 떼고, 창 안의 등급 분포를 **문장 1줄**로 말한다. 문장의 등급어는 서버 `walkSafetyLevel.name` 을 그대로 쓴다.
- **바꾸지 않는 것**: 시각 색(`METRIC_WORD_TONE[tone]`, `goldenLevel` 톤) · `goldenSingleHour` · `SUPPRESSED_BY_WARNING` · `ALL_HOURS_RISKY` · `NoForecast` 갈래 · 곡선.
  - **시각 색은 이후 D10 에서 걷혔다** (#671 A-3). 1차가 남긴 잔여였고, 곡선은 D9(#656)에서 갈렸다.

## D1. 레이아웃

```text
오늘 산책하기 좋은 시간                      (h2, 변경 없음)
11:00 – 23:00                                (title-1, 배지 제거. 등급 톤 색은 D10 에서 걷힘)
14–15시는 노면이 46℃까지 올라 주의 등급이에요. 11–13시 · 16–23시가 좋아요.   (body-1, 신규)
[곡선]                                        (변경 없음)
제주시 기준 · 노면(아스팔트) 온도는 추정치예요  (변경 없음)
```

- 문장은 `text-body-1` 한 단락. 등급어 부분(`주의 등급`)만 `MetricWord` 톤을 준다 — 색만으로 말하지 않는다(§2-3), 그러나 어디가 등급어인지 눈이 잡아야 한다.
- 390px 에서 두 문장이 두 줄로 접혀도 된다. 세 줄이 되면 둘째 문장을 뺀다 (D4-2).

## D3. 데이터 흐름

입력은 `WalkTimesResponse` 만이다 (`hourly[]` · `goldenStart` · `goldenEnd` · `goldenLevel`). 추가 조회 없음.

```text
describeGoldenWindow(hourly, goldenStart, goldenEnd)
  → 창 안(isWithinGoldenWindow) 시각만 고른다 (양끝 포함 — 기존 규칙)
  → 각 시각의 walkSafetyLevel.code 로 연속 구간(run)을 만든다
  → { runs: [{ code, name, hours: [14,15], maxPavement: 46.3 }, ...],
      worst: run with the highest severity (SAFE < CAUTION < DANGER, 모르는 코드는 CAUTION 취급),
      allSafe: boolean }
```

- 시각 숫자는 `at`(`2026-09-15T14:00:00`) 의 시(hour) 를 **문자열 슬라이스**로 뽑는다. `Date` 파싱 금지 — `hourMinute` · `isWithinGoldenWindow` 와 같은 이유(브라우저 타임존).
- 등급 심각도 순서는 서버 코드 `SAFE` · `CAUTION` · `DANGER` 셋만 안다. 모르는 코드는 `CAUTION` 자리에 둔다 — 화면이 새 값을 모른 채도 렌더해야 한다 (루트 `CLAUDE.md` enum 규칙).
- `maxPavement` 는 `estimatedPavementCelsius` 최대값을 **정수로 반올림**한다 (진단 G-2: 문장 속 소수는 데이터 냄새). 곡선 셀의 소수 1자리는 그대로다 — 셀은 표, 문장은 말이다.

## D4. 상호작용 · 문구 (확정)

| 키                       | 문구                                                       | 조건                                                                                           |
| ------------------------ | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `home.goldenAllSafe`     | `이 시간대는 내내 {level} 등급이에요`                      | 창 안 등급이 하나뿐일 때. `{level}` = 그 등급의 서버 `name`                                    |
| `home.goldenCautionRuns` | `{runs}는 노면이 {pavement}℃까지 올라 {level} 등급이에요.` | 창 안에 SAFE 가 아닌 구간이 있을 때. `{runs}` = 그 구간들, `{level}` = 가장 심한 등급의 `name` |
| `home.goldenBetterRuns`  | ` {runs}가 좋아요.`                                        | 위 문장 뒤에 이어 붙인다. `{runs}` = 창 안 SAFE 구간들. SAFE 구간이 없으면 붙이지 않는다       |
| `home.goldenHourRange`   | `{from}–{to}시`                                            | 구간 표기. 한 시각이면 `{from}시` (`home.goldenHourSingle`)                                    |
| `home.goldenRunsJoin`    | `·`                                                        | 구간 사이 구분자                                                                               |

- **`{level}` 은 절대 FE 가 쓰지 않는다** — `walkSafetyLevel.name` 그대로. `주의` 라는 글자가 messages 에 들어가면 안 된다.
- 노면이 오르는 것이 아닌 등급(예: 추위 · 비 때문의 CAUTION 이 나중에 생기면)에 `노면이 ...℃까지 올라` 는 틀린 말이 된다. **D8-1 참고.** 1차는 노면온도가 유일한 등급 근거라는 현재 서버 규칙(`HourlyWalkSafetyItem` 주석)을 따른다.
- **D4-2. 길이 제한**: 두 문장 합이 390px 에서 세 줄을 넘으면(문자 수 60 초과로 근사) `goldenBetterRuns` 를 뺀다. 곡선이 어차피 좋은 구간을 면으로 보여 준다(D4-1-c).

| ---------------------------------------------------------- | ---------------------------------------------------------------------------- |

| `hourly` 가 창 안 시각을 하나도 안 담음 (응답 불일치)      | 문장 없음. 헤드라인만. 콘솔 경고 없이 조용히                                 |
| `SUPPRESSED_BY_WARNING` · `ALL_HOURS_RISKY` · `NoForecast` | 변경 없음                                                                    |

## D6. 접근성

- 문장이 배지를 대신하므로 스크린리더 읽기 순서가 `시각 → 등급 문장 → 곡선` 으로 자연스러워진다. 곡선 셀의 `sr-only` 라벨은 그대로.
- 등급어 `MetricWord` 색은 `-700` 층 (기존 `GoldenWindow` 주석의 대비 규칙).

  - 전부 SAFE → `allSafe === true`, `runs.length === 1`

## D8. 미결 사항

- **D8-1. 등급 근거가 노면온도가 아닐 때의 문장** — 지금 서버는 노면온도 하나로 등급을 매긴다. 서버가 `reasons` 를 시각 단위로 주기 시작하면 `노면이 ...℃까지 올라` 를 그 근거 문장으로 바꾼다. **1차는 노면온도 문장으로 확정**, 서버 변화 시 이 절을 갱신.
- **D8-2. 창을 둘로 쪼개 표기(`11–13시 · 16–23시`)할까** — 헤드라인을 쪼개면 서버가 준 `goldenStart/End` 와 화면이 다른 값을 말하게 된다. **헤드라인은 서버 창 그대로, 쪼갠 표기는 문장 안에서만.** 확정.

## D9. 곡선 면도 같은 사실을 말한다 (#656) — 해소

1차(#637)는 헤드라인 배지만 걷고 **곡선은 그대로 뒀다**. 그 결과 같은 카드 안에서 두 채널이
갈렸다 — 문장은 `14–15시는 … 주의 등급이에요` 라고 적는데 **면은 창 전체를 한 톤으로** 칠했다.
진단 H-2 가 남은 것으로 꼽은 부분이고, 이 문서가 _"곡선은 바꾸지 않는다"_ 라고 적은 자리다.

**면의 색을 칸마다의 `walkSafetyLevel` 로 바꿨다.** 규칙·표·미지 표현·견본 정합성은
`홈-세부명세.md` **D4-1-c** 의 「면의 색을 시각별 등급으로 바꾼다 (#656)」 절이 정본이다.

이 문서 쪽 영향:

- **D4-2(길이 제한)의 근거가 세진다.** 뒤 문장을 뺄 때 _"곡선이 어차피 좋은 구간을 면으로
  보여 준다"_ 고 적었는데, 한 톤이던 시절에는 그 말이 절반만 맞았다 — 면은 창을 보여 줬지
  **창 안 어디가 좋은지**는 보여 주지 못했다. 이제 맞는 말이다.
- **D5 상태표는 그대로다.** 문장 갈래는 하나도 바뀌지 않는다.
- **D6 접근성도 그대로다.** 면은 색 채널이고, 등급 분포는 문장이, 칸의 등급은 `sr-only` 가
  계속 낱말로 말한다.

## D10. 헤드라인 색과 등급어가 덮는 범위 ([#671](https://github.com/8llow8llowMe/hondigagae/issues/671) **A-2 · A-3**) — 해소

D0 이 _"바꾸지 않는 것"_ 에 적은 **시각 색**이 1차의 잔여였다. 배지의 글자는 지웠는데
**같은 주장을 하던 색**은 남아 있었다.

### D10-1. 헤드라인은 창 전체를 한 등급으로 칠하지 않는다 (A-3)

`goldenLevel` 은 창 하나에 등급 하나를 붙인 값이다 — 서버 `GoldenWalkWindow.level` 이
창 안 칸들을 `worseOf` 로 접는다. 22px 굵은 시각을 그 색으로 칠하면 **창 전체가 그
등급**이라고 말하는 셈이고, 그것이 #637 이 배지를 걷은 바로 그 이유였다.

**dev 실측 2026-09-21**: 창 `15:00 – 23:00` 에 `CAUTION` 한 칸 + `SAFE` 여덟 칸인데
`goldenLevel=CAUTION` 이라 헤드라인이 통째로 `metric-mid-700` 이었다. D9(#656)로 면이
칸마다 갈린 뒤로는 **이 색이 섹션에서 유일하게 "창 하나에 등급 하나" 를 말하고 있었다.**

| 후보                              | 판정                                                 |
| --------------------------------- | ---------------------------------------------------- |
| ① 색을 걷고 본문 색으로 둔다      | **채택**. 이 줄이 말하는 것은 등급이 아니라 시각이다 |
| ② 분포를 헤드라인 밖에서만 말한다 | 이미 D4 문장이 하고 있다 — 새로 할 일이 없다         |
| ③ `worst` 로 칠한다               | 기각. 지금과 실질 같다 (창 등급이 곧 창 안 최악이다) |

색이 유일한 채널이 아니어야 한다는 규칙(DESIGN.md §2-3)은 아래 문장의 등급어와 곡선 면이
칸 단위로 지킨다. 본문 색 `text-fg` 는 바로 위 `h2` 와 같은 토큰이다.

**`goldenLevel` 이 `WalkTimesSection` 의 렌더에서 사라진다.** 응답 필드는 그대로 받는다 —
곡선 면(D9)도 문장(D4)도 `hourly` 를 근거로 쓰므로 **소비처가 없어진 것이지 계약이 바뀐 것이
아니다.** 소비처가 다시 생기지 않는 것은 소스 단언으로 잠근다
(`walk-times-section.test.ts` 「goldenLevel 을 렌더에 쓰지 않는다」).

> **출발 전 브리핑(`plan-briefing-section.tsx`)은 아직 같은 색을 쓴다.** 그 화면의 골든타임
> 줄도 `walkSafetyTone(walkTimes.goldenLevel?.code)` 로 칠한다 — 같은 결함이고 같은 판정이
> 적용되어야 하지만, 이번 범위 밖이라(다른 레인이 그 파일을 잡고 있다) **후속으로 남긴다.**

### D10-2. 등급어는 자기가 덮는 구간만 부른다 (A-2)

`mixedLevelsText` 가 SAFE 아닌 구간을 **전부** `{runs}` 에 몰아넣고 등급어는 `worst.name`
하나만 썼다. 창 안에 서로 다른 등급이 둘 이상이면 문장이 면과 다른 말을 한다:

```text
문장: 14–16시 · 17시는 노면이 59℃까지 올라 위험 등급이에요. 18–21시가 좋아요.
면  : 14–16시 위험 / 17시 주의 / 18–21시 안전
```

**먼저 도달 가능성을 BE 소스로 판정했다.**

| 근거                              | 내용                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `HourlyWalkSafety.isAcceptable()` | `SAFE` 또는 `CAUTION` 에만 참                                                                           |
| `GoldenWalkWindow.acceptableRuns` | 그 칸만 이어 붙이고 **아닌 칸에서 구간을 끊는다** — `DANGER` 는 창 안에 들 수 없다                      |
| `WalkSafetyEvaluator.quickLevel`  | `SAFE` 에서 시작해 `CAUTION`/`DANGER` 로만 내려간다 — **`UNKNOWN` 을 내지 않는다**(기온 없는 행은 제외) |
| `WalkTimesPresenter`              | `hourly` 와 `goldenStart`/`goldenEnd` 가 **같은 곡선**에서 나온다                                       |
| dev 실호출 2026-09-21             | 창 `15:00–23:00` = `CAUTION` 1 + `SAFE` 8                                                               |

⇒ **창 안은 `SAFE`·`CAUTION` 두 값뿐이고, SAFE 아닌 구간은 전부 `CAUTION` 이다.** 위 어긋남은
오늘의 계약에서 **도달하지 않는다.**

**그래서 문장을 등급별 절로 쪼개지 않았다.** 쪼개면 D4-2 의 60자 예산을 다시 짜야 하는데,
오지 않는 경우 때문에 **실제로 보이는 문장이 짧아진다.** 대신 두 가지만 바꾼다:

1. `{runs}` 에 **`worst.code` 를 가진 구간만** 넣는다. 계약이 흔들려 다른 등급이 섞여 오더라도
   문장이 그 구간을 **잘못 부르는 대신 말하지 않는다** — 그 구간은 곡선 면과 `sr-only` 가 말한다.
2. **`UNKNOWN` 은 `worst` 후보가 아니다.** 서버 `WalkSafetyLevel.UNKNOWN` 은 등급이 아니라
   "판단하지 않았다" 이고, BE `worseOf` 도 _"실제 판정이 있으면 그쪽을 택한다"_ 로 적혀 있다.
   예전에는 FE `severityOf` 가 이 코드를 `CAUTION` 과 같은 심각도로 두어, 노면이 더 높으면
   `노면이 50℃까지 올라 판단 근거 부족 등급이에요` 가 나갔다.

   **모르는 코드(서버가 등급을 하나 더 냄)와는 갈라 둔다** — 그쪽은 여전히 `CAUTION` 자리에서
   판정에 든다. 접으면 새 등급이 조용히 "안전" 으로 읽힌다.

`worst` 가 없거나(창 안이 전부 `UNKNOWN`) 등급어가 덮는 구간이 없으면 **문장을 조용히 걷는다** —
D5 의 「응답 불일치」 행과 같은 처리다.

### D10-3. 혼합 등급 갈래를 목에서 볼 수 있다 (E-1)

기본 mock 의 창(18–21시)이 전부 SAFE 라 **D9 의 시각별 면도 D4 의 혼합 등급 문장도 로컬에서
볼 수 없었다.** 두 레인이 그때마다 mock 을 임시로 고쳤다 되돌렸고, D10-2 가 그래서 지금까지
안 잡혔다.

`mockWalkTimes` 에 갈래를 정식으로 뒀다 — **초코 조합에 `소리 민감` 을 더하면** 창이
`15–21시` 이고 그 안이 `주의(15–16) · 안전(17) · 주의(18) · 안전(19–21)` 이다. 창 **앞**의
14시는 `DANGER` 다: 서버 규칙상 그 칸이 창을 끊으므로, 창 안에 `DANGER` 를 넣은 목은 서버가
절대 주지 않는 응답이 된다.
