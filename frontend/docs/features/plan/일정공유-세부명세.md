## D0. 화면 정의

### 열람 화면

- **경로**: `/shared-plans/[token]` — route group `(main)`
- **인증**: **불필요.** `proxy.ts` `PROTECTED_PATHS` 에 **넣지 않는다.**

  > `/plans` 하위에 두면 proxy 가 미로그인을 `/login` 으로 튕겨 **공유가 성립하지 않는다.**
  > 백엔드가 `/api/v1/shared-plans` 로 접두어를 가른 것과 같은 이유이고, 경로만 보고
  > "이것은 공개" 가 읽혀야 한다.

- **진입 경로**: 외부(메신저·문자에 붙여 넣은 링크)뿐이다. 앱 안에 이 화면으로 가는 링크는 없다
- **이탈 경로**: 헤더 로고 → 홈. **항목에서 `/places/{placeId}` 로 나가는 링크는 건다** — 공개 화면이라 로그인 벽이 없다

### 발급·폐기 모달

- **경로 없음.** `/plans/[planId]` 안의 모달이다
- **인증**: 필요 (부모 화면이 보호 경로)
- **진입 경로**: `PlanManageMenu` → `공유 링크`
- **게이트**: `plan.status.code` 가 `CONFIRMED` · `COMPLETED` 일 때만 **메뉴 항목이 존재한다**

  > 초안에서 항목을 보여 주고 누르면 `PLAN_022` 400 을 띄우는 방식을 쓰지 않는다.
  > 눌러서 배우게 하는 자리가 아니다. `reverseStatusActions(plan.status.code)` 가
  > 이미 같은 메뉴에서 상태로 항목을 가르고 있어 **패턴이 그 자리에 있다.**

## D3. 데이터 흐름

### 열람 — React Query 를 쓰지 않는다

```text
page.tsx (서버) → serverFetch<SharedPlan>(paths.plans.shared(token))   ← accessToken 없음
                → 성공: SharedPlanSection 에 그대로 넘긴다
                → 404: notFound()
                → 410: <SharedPlanExpired />
                → 그 외: <ErrorState onRetry>  (client 경계 하나)
```

**`QueryClient` · `HydrationBoundary` 를 두지 않는다.** 이 화면에는 뮤테이션 · 필터 · 폴링 · 재조회가 하나도 없다. 쓰지 않을 캐시를 직렬화해 HTML 에 실어 내려보내는 값이 된다. 일정 상세가 그것을 두는 이유(클라이언트가 방문 체크 · 일자 편집으로 같은 key 를 갱신한다)가 여기에는 없다.

`retry` 는 서버 렌더를 재시도 백오프만큼 블로킹하므로 걸지 않는다 — 5xx 재시도는 화면의 버튼이 담당한다(`router.refresh()`).

### 발급·폐기 — React Query

| key                          | `staleTime` | `gcTime` | `retry` |
| ---------------------------- | ----------- | -------- | ------- |
| `planKeys.shareLink(planId)` | 30초        | 10분     | 1       |

`api-integration-guide.md` §7 의 **일정** 행 그대로다 — 같은 도메인이고 뮤테이션이 붙는다.

| 동작        | 호출                             | invalidate                   |
| ----------- | -------------------------------- | ---------------------------- |
| 모달 열기   | `GET /plans/{planId}/share-link` | —                            |
| 링크 만들기 | `POST`                           | `planKeys.shareLink(planId)` |
| 링크 폐기   | `DELETE`                         | `planKeys.shareLink(planId)` |

- **모달을 열 때 `GET` 이 404(`PLAN_023`)면 오류가 아니다.** "아직 공유 중이 아니다" 라는 정상 상태다. `retry: false` 로 두고 `null` 로 접는다
- **`POST` 는 멱등이다.** 유효한 링크가 있으면 새로 만들지 않고 그것을 돌려준다 — 화면이 `GET` 결과를 보고 버튼을 가르지만, 경합으로 두 번 눌려도 링크가 바뀌지 않는다
- **`DELETE` 도 멱등이다.** 폐기할 것이 없어도 200 이라 404 분기를 만들지 않는다

### 공유 URL 은 클라이언트가 만든다

```ts
// src/lib/plan/share-link.ts
export function shareUrlOf(token: string, origin: string): string
```

`origin` 은 브라우저의 `window.location.origin` 을 넘긴다. **`NEXT_PUBLIC_*` 환경변수를 새로 만들지 않는다** — 값이 하나 더 늘면 프리뷰·dev·프로덕션에서 어긋날 자리가 하나 더 생기고, 이 값은 사용자가 지금 보고 있는 주소가 정답이다.

## D4. 상호작용

### 발급 모달

| 상태           | 화면                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| 공유 중이 아님 | 설명 한 줄 + `링크 만들기` (primary)                                       |
| 공유 중        | 링크 텍스트(읽기 전용 · 전체 선택 가능) + `복사` + `링크 폐기` + 만료 안내 |

- **`복사` 는 `navigator.clipboard.writeText`.** 실패하거나 없으면(비 HTTPS · 구형) **입력 요소를 선택 상태로 두고** "복사하지 못했어요. 직접 복사해 주세요." 를 띄운다. 조용히 실패하지 않는다
- 복사 성공은 버튼 라벨을 `복사됨` 으로 2초 바꾼다. 토스트를 새로 만들지 않는다
- **폐기는 `ConfirmModal` 을 쓴다.** 되돌릴 수 없다 — 다시 `POST` 하면 **다른 토큰**이 나오고 이미 보낸 링크는 죽는다. 삭제와 같은 무게다
- 폐기는 `destructive` 톤이지만 **모달 안 버튼**이라 `PlanManageMenu` 의 선 아래 자리와 겹치지 않는다

### 열람 화면

읽기 전용이라 상호작용이 **장소 링크 하나**다. 항목이 장소를 가리키면(`targetId !== null` 이고 유형이 `PLACE`·`MEAL`·`LODGING`) `/places/{targetId}` 로 건다 — `isPlaceTarget` 을 그대로 쓴다.

## D8. 미결 사항

### D8-1. `ErrorKind` 에 `'gone'` 을 더한다 — **결정됨**

`src/lib/api/error.ts` `classify()` 에 410 자리가 없어 지금은 `'forbidden'` 으로 떨어진다. 재시도 버튼은 안 뜨니 동작은 맞지만 **문구가 일반 4xx 것**이 된다.

- `ErrorKind` 주석이 스스로를 _"UI 분기의 단일 기준"_ 으로 정의한다 → 여기가 정본이다
- 저장소 전체가 `kind` 를 `===` 로만 비교하고 exhaustive `switch` 가 없다 → 항목 추가로 깨지는 곳이 없다
- `isRetriable` 은 `'temporary'` 만 true 라 `'gone'` 은 자동으로 재시도 없음이다

### D8-2. 만료 화면의 HTTP 상태가 200 이다

`notFound()` 는 404 하나만 낼 수 있고, 서버 컴포넌트에는 상태 코드를 정할 수단이 없다. `proxy.ts` 의 rewrite 수법은 **토큰 유효성을 proxy 가 알 수 없어** 쓸 수 없다(백엔드를 불러야 안다).

**받아들인다.** 이 페이지는 `noindex` 라 크롤러가 soft-200 을 잘못 읽을 여지가 없다. `/places/[placeId]` 에서 soft 404 를 막은 이유(공개 색인 대상)가 여기에는 없다.

### D8-3. 만료 임박 경고를 두지 않는다

`expiresAt` 을 모달에 문장으로만 적는다(`2026-10-17까지 볼 수 있어요`). D-3 같은 임박 배지를 넣지 않는 이유 — 일정 상세에 들어와야 보이는데, **링크를 준 사람은 그때 이미 그 화면에 없다.** 알림 수단이 생기면 다시 본다.

## D9. BE 후속 요청

없다. 응답이 화면에 필요한 것을 전부 준다.

기록만 남긴다 — `SharedPlanResponse.status` 는 `CodeNameDescriptionMetadata`(3필드)인데 소유자 `PlanDetailResponse.status` 는 `CodeNameMetadata`(2필드)다. FE 는 공유용 타입을 따로 두고 `description` 을 받되 쓰지 않는다. **타입을 합치지 않는다** — 합치면 소유자 쪽에 없는 필드가 optional 로 새어 들어간다.

## 보안 메모

- **토큰은 열람 권한 그 자체다.** `console.log` · 분석 도구 · 쿼리스트링에 싣지 않는다. 백엔드도 게이트웨이 로그에서 가린다
- **열람 페이지는 `robots: { index: false, follow: false }`.** 색인되면 링크가 공개된다. 저장소에 `robots.ts` · `sitemap.ts` 가 없어 **페이지 메타데이터가 유일한 수단**이다
- `generateMetadata` 의 `title` 에 **일정 제목을 넣지 않는다.** 브라우저 히스토리·탭 제목으로 새는 것을 줄인다 — `공유된 여행 일정 · 혼디가개` 고정
