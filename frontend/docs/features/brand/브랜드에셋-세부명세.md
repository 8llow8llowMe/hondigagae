## 이 문서의 범위

화면이 아니라 **저장소가 브라우저·OS 에 내보내는 아이덴티티**를 다룬다. 파비콘 · 앱
아이콘 · 공유 카드 · PWA 매니페스트 · 헤더 락업(심볼 + 워드마크).

**세부명세 템플릿(D0~D9)을 그대로 쓰지 않는다.** 그 구조는 라우트를 가진 화면용이고,
여기에는 레이아웃·데이터 흐름·상태별 화면이 없다. 대신 같은 정신으로 절을 나눴다 —
계약(파일) · 배선 · 문구 · 테스트 · 미결 · BE 후속.

## B0. 원칙 — 이 문서 전체를 결정하는 한 줄

> **인터페이스 안은 무채색, 인터페이스 밖은 브랜드 컬러.**

`DESIGN.md` 0절이 "인터페이스는 무채색 · 장식 목적의 색은 없다" 고 못박았다. 이 규칙은
**헤더 로고에는 더 이상 적용되지 않는다** — 2026-09-04 에 뒤집었다 (#240).

헤더는 **심볼 + 워드마크 락업**을 쓴다. 조건은 `DESIGN.md` §1 의 표에 있다: 크기 24px ·
색은 `--brand-500` 하나 · 로고 자리에만. 그 셋을 어기면 브랜드가 판정 신호와 경쟁하기
시작하므로, 예외를 넓히지 않는 것이 이 결정의 전제다. **헤더 밖의 인터페이스는 그대로
무채색이다.**

반대로 파비콘·앱 아이콘·공유 카드가 사는 곳은 우리 UI 가 아니라 **브라우저 탭 · iOS 홈
화면 · 남의 타임라인**이고, 네이버·유튜브 아이콘과 나란히 놓인다. 거기서 무채색은 그냥
사라진다. **따라서 그 자리에 한해 브랜드 컬러를 쓴다 — 예외가 아니라 규칙이다.**

두 규칙은 모순이 아니라 같은 규칙의 양면이다. 어떤 에셋을 어디에 쓸지 헷갈리면 "이게
우리 화면 안인가 밖인가" 를 먼저 묻는다.

## B1. 색 — 새 색을 뽑지 않았다

값이 갈리는 것은 테스트가 막는다 (`src/lib/brand/chrome-colors.test.ts`).

## B3. 파일 계약 — 무엇이 어디에 있는가

`docs/hondi_img/hondigagae-brand.zip` 이 원본 24개를 담고 있고, 그중 런타임에 필요한
것만 아래 자리로 복사했다. **원본과 런타임 사본이 이중으로 존재한다** — 원본은 아트보드
export 기록이고 런타임 사본이 실제로 서비스된다.

### Next App Router 파일 규약 — 이름만으로 연결된다

**이 넷은 `<head>` 에 직접 쓰지 않는다.** 아트보드 5절이 이 사실을 명시했고, 손으로 다시
걸면 중복 태그가 나간다.

| 저장소 경로               | 원본                   | 방출되는 것                              |
| ------------------------- | ---------------------- | ---------------------------------------- |
| `app/favicon.ico`         | `favicon.ico`          | `<link rel="icon" sizes="32x32">` (먼저) |
| `app/icon.svg`            | `favicon.svg`          | `<link rel="icon" type="image/svg+xml">` |
| `app/apple-icon.png`      | `apple-touch-icon.png` | `<link rel="apple-touch-icon">` (180)    |
| `app/opengraph-image.png` | `og-image.png`         | `og:image` (1200 × 630)                  |

**`.ico` 가 `.svg` 보다 먼저 나가야 한다** — 구형 브라우저가 `.svg` 를 만나 깨지지 않게
하려는 것이고, Next 의 방출 순서가 이미 그렇다.

### 규약이 없는 것 — metadata / manifest 가 경로로 가리킨다

| 저장소 경로                    | 가리키는 곳                                       |
| ------------------------------ | ------------------------------------------------- |
| `public/safari-pinned-tab.svg` | `metadata.icons.other` → `<link rel="mask-icon">` |
| `public/site.webmanifest`      | `metadata.manifest`                               |
| `public/icon-192.png`          | 매니페스트 `icons[]`                              |
| `public/icon-512.png`          | 매니페스트 `icons[]`                              |
| `public/maskable-icon-512.png` | 매니페스트 `icons[]` `purpose: "maskable"`        |

- **`safari-pinned-tab.svg` 는 단색 실루엣만 허용된다** — 색이나 라운드 사각을 넣으면
  사파리가 통째로 검게 칠한다.
- **`apple-icon` 은 여백을 안에 넣고 라운드를 넣지 않는다** — iOS 가 직접 깎는다.
- **`maskable` 은 안전영역 안쪽 배치다** — 안드로이드가 원형으로 잘라도 발바닥이 살아남는다.

### 런타임에 쓰지 않는 원본

`logo-lockup*.svg`(스플래시·외부 노출) · `icon-mono.svg` · `logo-wordmark-white.svg`(어두운
배경) · `og-image.svg` · `PREVIEW.html`(에셋 시안) 는 `docs/hondi_img/` 에만 둔다.
**쓰는 자리가 생기기 전에 `public/` 으로 옮기지 않는다** — 서비스되는 정적 파일이 늘면
무엇이 실제로 쓰이는지 알 수 없어진다.

## B4. 워드마크 — 라이브 텍스트가 아니다

`src/components/brand/wordmark.tsx` — 인라인 SVG 컴포넌트.

**아웃라인이어야 한다.** Pretendard ExtraBold 를 패스로 뜬 것이고, 아트보드 6절이 이유를
못박았다: 폰트 로딩이 실패하면 **헤더만** 시스템 폰트로 튀어 로고가 로고처럼 안 보인다.
이 저장소는 dynamic subset 을 쓰므로(`tooling-guide.md` §12) 그 실패가 조각 단위로
일어날 수 있어 더 그렇다.

**`<img>` 나 `next/image` 가 아니라 인라인이다.** 이유 셋:

1. 로고는 첫 페인트에 있어야 한다 — 별도 요청이면 헤더가 한 프레임 비어 보인다
2. `next/image` 로 SVG 를 쓰려면 `dangerouslyAllowSVG` 를 켜야 하고, 그건 이 파일 하나를
   위해 프로젝트 전역의 이미지 정책을 여는 일이다
3. `fill="currentColor"` 를 쓸 수 있다 — 원본은 `#15181D` 로 고정돼 있는데 그 값이 `--fg`
   와 정확히 같다. 색을 박아 두면 토큰과 값이 두 곳으로 갈린다

| 규칙                                 | 값 / 근거                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------- |
| 높이 20 · 폭 74 (기본)               | 기존 로고 텍스트와 같은 크기 (`--text-emphasis` 20/800)                   |
| 높이 40 · 폭 148 (`(auth)` 셸 전용)  | 헤더 없는 화면의 유일한 신원 단서 — 정확히 2배 (`DESIGN.md` §1 개정)      |
| `viewBox="2.34 -80.57 333.72 90.14"` | 원본이 이미 잉크 경계에 맞게 잘려 있다 (비율 3.702). 여백을 더하지 않는다 |
| `fill="currentColor"`                | 호출부의 `text-fg` 가 색을 정한다. 다크 테마가 생기면 따라온다            |
| `role="img"` + `aria-label`          | 링크에 `aria-label` 을 다시 붙이지 않는다 — 이름을 두 번 읽는다           |

**헤더에 심볼을 붙이지 않는다.** 초록 사각형 하나가 헤더에 들어가면 화면에서 채도를 가진
유일한 장식이 된다 — 채도는 데이터에만 남긴다. 심볼이 붙는 락업은 스플래시·공유 카드
전용이다.

**락업 비율은 고정이다** — 심볼 44, 워드마크 좌측 여백 12.96(심볼 폭의 29.5%), 전체
206.09 × 44. 쓸 자리가 생기면 이 값을 눈으로 조정하지 않는다.

## B5. 공유 카드 — 1200 × 630

공유 카드는 남의 타임라인에서 **폭 300px 안팎으로 줄어든다.** 그 크기에서 살아남는 것은
락업과 한 줄뿐이라 화면 미리보기·사진을 넣지 않았다.

**여기서는 심볼이 들어간다** — 공유 카드는 인터페이스 밖이다. B0 의 헤더 규칙과 모순이
아니라 같은 규칙의 다른 쪽이다.

- **`twitter:image` 를 따로 두지 않는다.** 트위터는 `twitter:image` 가 없으면 `og:image`
  를 읽으므로 같은 1200 × 630 을 두 번 실을 이유가 없다. `twitter.card` 만 알린다.
- **`metadataBase` 가 필요하다.** 없으면 Next 가 `og:image` 를 상대 경로로 내보내고
  카카오톡·트위터 크롤러가 못 읽는다. 도메인은 `NEXT_PUBLIC_SITE_URL` 로 주입한다 —
  dev = `https://dev.hondigagae.com` / prod = `https://www.hondigagae.com` (B10 1번 참고).

## B6. 문구 — 매니페스트와 공유 카드가 같은 한 줄을 쓴다

| 자리                                | 문구                                                                |
| ----------------------------------- | ------------------------------------------------------------------- |
| `<title>` · `og:title` · 매니페스트 | `혼디가개`                                                          |
| `<meta name="description">`         | `반려견과 함께하는 제주 여행을 설계합니다.`                         |
| `og:description` · 매니페스트       | `제주 반려견 동반 여행 — 날씨와 노면 온도로 오늘 산책을 판정합니다` |

**공유 카드 문구가 페이지 description 과 다르다.** 카드 이미지 안에 이미 그 문장이
그려져 있어(아트보드 4절) 다른 문장을 쓰면 그림과 글이 어긋난다. 매니페스트와 같은 값을
쓰는 것도 같은 이유다.

## B7. 색 상수 — 왜 raw hex 가 있는가

`src/lib/brand/chrome-colors.ts` 는 **저장소에서 유일하게 raw hex 를 쓰는 소스 파일이다.**
`no-restricted-syntax` 를 그 두 줄에서만 끈다.

이유: `theme-color` 와 `mask-icon` 의 `color` 가 가는 곳은 CSS 가 아니라 **`<meta>` /
`<link>` 속성**이다. 안드로이드 크롬이 상태바를 칠할 때, 사파리가 고정 탭 실루엣에 색을
입힐 때 읽는 값이고, **둘 다 CSS 변수를 해석하지 않는다** — `var(--brand-500)` 을 넘기면
무시된다.

**손으로 맞추기로 한 값은 반드시 갈라진다** (이슈 #50: `tokens.css` 가 `DESIGN.md` 보다
한 세대 뒤처진 채로 지나갔다). 그래서 `chrome-colors.test.ts` 가 세 파일을 대조한다:

- `MASK_ICON_COLOR` == `tokens.css` 의 `--brand-500`
- `THEME_COLOR` == `tokens.css` 의 `--bg`
- `site.webmanifest` 의 `theme_color` == `THEME_COLOR`
- `site.webmanifest` 의 `background_color` == `--bg`

세 번째가 특히 중요하다 — 매니페스트가 있는 설치형에서는 매니페스트의 `theme_color` 가
`<meta>` 를 이기므로, 두 값이 갈리면 **설치 전후로 상태바 색이 바뀐다.**

## B8. `theme-color` 는 초록이 아니라 흰색이다

가장 틀리기 쉬운 지점이라 절을 따로 뒀다.

PWA 상태바가 헤더와 이어져야 하는데 **헤더 배경이 흰색(`--bg`)이다.** 초록을 넣으면
상태바만 색 띠로 떠 보인다. 브랜드 컬러가 있으니 거기에 넣고 싶어지는 자리인데,
상태바는 "인터페이스 밖" 이 아니라 **헤더의 연장**이다.

## B9. 테스트

**렌더 테스트를 만들지 않는다.** 파비콘·og 는 Next 가 파일 이름으로 방출하는 것이라
우리 코드에 검증할 분기가 없다 — 테스트를 쓰면 Next 의 구현을 테스트하게 된다.

대신 **갈라질 수 있는 것만** 지킨다 (`chrome-colors.test.ts`, 4케이스): B7 의 대조 4종.

수동 확인이 남는 것 (B11 참고):

- 브라우저 탭에서 파비콘이 16px 로 뭉개지지 않는가
- iOS 홈 화면 추가 시 `apple-icon` 이 잘리지 않는가
- 카카오톡·트위터 공유 미리보기 — **도메인 확정 후에만 가능하다**
- 헤더 락업(심볼 24 + gap 8 + 워드마크 74)이 375 / 768 / desktop 에서 nav 를 밀지 않는가

## B12. 아트보드 동기 결과 — #124 방문 체크는 없다

아트보드 13개를 훑어 확인한 결과다.

**새로 들어온 것**: `혼디가개 브랜드 자산.dc.html` (이 문서의 정본).

**들어오지 않은 것**: **`PUT …/visited`(방문 체크)의 아트보드는 아직 없다.**
`다녀옴` / `visited` 문자열이 13개 아트보드 어디에도 없고, 아트보드 작업공간의
`CLAUDE.md` 가 지금도 그 API 를 **"아직 화면이 없다"** 로 적어 두고 있다.

즉 [#124](https://github.com/8llow8llowMe/hondigagae/issues/124) 의 토글 배치·톤은
**여전히 아트보드 정본 없이 구현된 상태다.** 근거로 삼은 것은 두 가지뿐이다:

- `혼디가개 여행 일정` 01 주석의 "선행 3열 금지" (그래서 후행 열로 갔다)
- `DESIGN.md` §7 (44 는 이제 지도 타깃만 · #883) · §2-3 (색만으로 전달 금지)

**후속으로 아트보드가 그려지면 재검토가 필요한 지점**:

| 지점             | 현재 구현                           | 아트보드가 정할 수 있는 것              |
| ---------------- | ----------------------------------- | --------------------------------------- |
| 토글 자리        | 행 후행 44px 아이콘 열              | 선행 체크박스 열 / 메타 줄 안 / 별도 바 |
| 체크된 행의 표현 | `다녀옴` 배지 + 제목·썸네일 톤 약화 | 취소선 / 배경 tint / 순번 칩 변형       |
| 초기화 경고 자리 | 일자 헤더 아래 한 줄 (조건부)       | 저장 확인 모달 안 / 편집기 안           |
| 방문 진행률      | **없음** (범위 밖)                  | 좌 레일 개요에 `다녀온 곳 3/8`          |

`docs/features/plan/일정상세-세부명세.md` D9-3 이 "아트보드 정본이 없다" 고 적어 둔 것이
아직 유효하다.
