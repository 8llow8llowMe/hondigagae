## D0. 화면 정의

- **경로**: `/pets/new` (라우트 그룹 `(main)`)
- **인증**: 필요
- **한 줄 정의**: 반려견의 크기·민감도·성향을 입력해 등록한다
- **범위에 포함**: 필드 10개, 클라이언트 검증, 서버 400 필드 매핑, 상한 경합 처리, 이탈 경고
- **범위에서 제외**: 사진(백엔드 필드 없음), 여러 마리 일괄 등록

`/pets/new` 가 `/pets/[petId]` 보다 먼저 매칭된다 (Next 는 정적 세그먼트 우선). `new` 를 `petId` 로 오인해 조회하는 경로는 생기지 않는다.

## D1. 레이아웃

한 컬럼. 필드가 10개라 섹션으로 묶는다.

- 모바일 (375): `px-4`, 전체 폭
- 태블릿 이상: `max-w-lg` 중앙 정렬. 로그인 폼(`max-w-sm`)보다 넓게 잡는다 — `RadioGroup` 항목이 `description` 을 포함해 2줄이 되므로 좁으면 3줄로 접힌다

### 섹션 구성

| 섹션      | 필드                                                 | 근거                                     |
| --------- | ---------------------------------------------------- | ---------------------------------------- |
| 기본 정보 | `name` · `breed` · `birthYm`                         | 신원. 필수 1개 + 선택 2개                |
| 크기      | `sizeType`                                           | 입장 가능 여부를 가르는 값이라 독립 섹션 |
| 성향      | `activityLevel` · `sociality` · `walkPreferred`      | AI 일정 설계에 쓰이는 값                 |
| 민감도    | `heatSensitive` · `coldSensitive` · `noiseSensitive` | 날씨·장소 필터에 쓰이는 값               |

**제출 버튼은 하단 고정으로 두지 않는다.** 폼이 길어 스크롤되지만, 고정 CTA 는 `RadioGroup` 마지막 항목을 가린다.

긴 한국어 실데이터로 확인할 항목:

- `sociality.LOW.description`("다른 개나 낯선 사람을 불편해합니다.")이 375px 라디오 항목에서 2줄을 넘기지 않는지
- 서버 검증 문구("반려견 이름은 20자 이하만 가능합니다.")가 필드 아래에서 줄바꿈될 때 다음 필드가 밀리지 않는지

**새 공통 컴포넌트를 만들지 않는다.** #43 이 선택 계열을 이미 만들었다.

`PetForm` 은 `submitting` prop 을 받아 `Button` 의 `loading` 에 배선한다 — 인증 폼(`login-form`)이 이미 쓰는 이름이라 폼 계층의 prop 명을 통일한다 ([#24](https://github.com/8llow8llowMe/hondigagae/issues/24) 리뷰 반영분).

**`PetForm` 을 등록·수정이 공용한다.** 백엔드가 `PetSaveRequest` 를 등록·수정에 공유하므로(공통명세 S2) 폼도 하나여야 계약과 어긋나지 않는다. 차이는 props 로 받는다 — 수정-세부명세 D2 참조.

## D3. 데이터 흐름

```text
/pets/new 진입 (서버) → 조립만. 프리페치 없음 (초기 데이터가 없는 폼 화면)
  → PetForm (client, initialValues = EMPTY_PET_FORM_VALUES)
       제출 → validate(petFormSchema, values)
            → 통과 → toPetSavePayload(values)   ← 빈 값을 null 로, enum 을 code 로
                  → clientFetch POST /members/me/pets
                  → 성공 → invalidateQueries(petKeys.all) → router.replace('/pets')
```

| 항목                   | 내용                                                          |
| ---------------------- | ------------------------------------------------------------- |
| API                    | `POST /members/me/pets`                                       |
| React Query key        | **없음** (mutation 전용)                                      |
| retry                  | `0` — 중복 생성 위험. 전역 mutation 기본값 (`§7`)             |
| mutation 후 invalidate | **`petKeys.all`** — 목록의 `totalCount` 가 상한 판정에 쓰인다 |
| 폴링 여부              | 없음                                                          |

이동은 `router.replace()` 다. `push` 를 쓰면 뒤로가기로 등록 폼에 돌아와 같은 반려견을 두 번 등록할 수 있다.

**`architecture-guide.md` §9 확정표에 "반려견 목록/상세" 는 서버 프리페치지만 이 화면은 프리페치가 없다.** 초기 데이터가 없는 폼이라 결정 트리 1번("초기 화면에 보이는 데이터인가?")에서 아니오로 빠진다 — 로그인·회원가입과 같다.

## D4. 상호작용

| 트리거                    | 동작                                            | 결과                                                 |
| ------------------------- | ----------------------------------------------- | ---------------------------------------------------- |
| 텍스트 입력               | `setValue` + **해당 필드 오류만** 제거          | 오류 메시지 사라짐                                   |
| 라디오 선택               | `setValue`                                      | 선택 항목 강조 + `checked` 이동                      |
| 체크박스 토글             | `setValue`                                      | —                                                    |
| 제출 (버튼 / Enter)       | 클라이언트 검증 → 통과 시 요청                  | 실패 시 요청을 보내지 않고 **첫 오류 필드로 포커스** |
| 제출 중 재제출            | 재진입 가드로 무시                              | 요청 1회만 나감                                      |
| 400 필드 오류 (`PET_1xx`) | `toFormErrors()` 로 필드에 매핑                 | 해당 필드 아래 서버 문구 + 첫 오류로 포커스          |
| **400 `PET_002`**         | `FormAlert` + 상한 문구. **필드 오류가 아니다** | 목록으로 돌아가는 링크를 함께 낸다                   |
| 5xx / 무응답              | `ErrorState` + 재시도. **폼은 그대로 유지**     | 입력값 보존                                          |
| 401                       | BFF 재발급 1회 → 실패 시 로그인                 | 이 화면은 아무것도 하지 않는다                       |
| 입력 후 이탈 시도         | `beforeunload` 경고 (`isDirty`)                 | `form-guide.md` §7                                   |
| "목록으로" 클릭           | `/pets` 이동                                    | 입력 중이면 경고를 거친다                            |

**`PET_002` 를 필드 오류로 만들지 않는다.** 붙일 필드가 없다 — 상한은 요청 전체의 성질이다. 그리고 목록에서 이미 막고 있으므로, 여기까지 온 것은 **다른 탭에서 동시에 등록한 경합**이다. 따라서 문구에 "목록을 새로고침해 확인해주세요" 를 함께 낸다 (공통명세 S4-2).

**`birthYm` 을 비우고 제출해도 통과해야 한다.** 클라이언트 스키마가 `''` 를 허용하고, `toPetSavePayload()` 가 `null` 로 바꿔 보낸다. `''` 를 그대로 보내면 서버가 `PET_104` 로 거부한다 — 이 화면에서 가장 쉽게 재발하는 함정이다.

## D5. 상태별 화면

| 상태          | 표현                                        | 폼             | 재시도   |
| ------------- | ------------------------------------------- | -------------- | -------- |
| 초기          | 빈 폼 (`EMPTY_PET_FORM_VALUES`)             | —              | —        |
| 제출 중       | 버튼 `loading` (→ `disabled` + `aria-busy`) | 입력 잠금 없음 | —        |
| 400 필드 오류 | 필드별 서버 문구 + `aria-invalid`           | **유지**       | 없음     |
| 400 `PET_002` | `FormAlert` + 목록 링크                     | **유지**       | 없음     |
| 5xx / 무응답  | `ErrorState` **폼 위에 얹힘**               | **유지**       | **있음** |

**5xx 에서 `ErrorState` 가 폼을 대체하지 않는다.** 대체하면 입력값을 고칠 수단이 사라져 새로고침밖에 남지 않는다 — [#24](https://github.com/8llow8llowMe/hondigagae/issues/24) 최종 리뷰 I1 이 잡은 실수다.

### 초기값 (`EMPTY_PET_FORM_VALUES`)

| 필드                         | 초기값     | 근거                                                                |
| ---------------------------- | ---------- | ------------------------------------------------------------------- |
| `name` / `breed` / `birthYm` | `''`       | controlled input 은 null 을 못 받는다                               |
| `sizeType`                   | `'SMALL'`  | 제주 반려견 동반 장소가 소형견 기준이 가장 많다                     |
| `activityLevel`              | `'MEDIUM'` | 중앙값. 사용자가 안 만지면 극단으로 편향되지 않는다                 |
| `sociality`                  | `'MEDIUM'` | 위와 동일                                                           |
| boolean 4개                  | `false`    | **서버 기본값과 같게 맞춘다.** primitive 라 누락 시 서버도 false 다 |

boolean 을 `false` 로 두는 것은 "민감하지 않다" 는 주장이 아니라 "사용자가 켜지 않았다" 의 표현이다. 서버가 primitive `boolean` 이라 이 값을 구분할 수 없으므로(공통명세 S3-4), 폼에 보이는 것과 저장되는 것을 일치시키는 것이 최선이다.

### 클라이언트 검증 문구 (`src/lib/messages/pet.ts`)

백엔드 `PetValidationMessage` 복제본이다. 대응 코드는 주석으로 추적한다.

| 필드      | 조건        | 문구                                  | 서버 코드 |
| --------- | ----------- | ------------------------------------- | --------- |
| `name`    | 비어 있음   | 반려견 이름은 필수입니다.             | `PET_101` |
| `name`    | 20자 초과   | 반려견 이름은 20자 이하만 가능합니다. | `PET_102` |
| `breed`   | 50자 초과   | 품종은 50자 이하만 가능합니다.        | `PET_103` |
| `birthYm` | 형식 불일치 | 생년월은 yyyy-MM 형식이어야 합니다.   | `PET_104` |

`sizeType`/`activityLevel`/`sociality` 의 필수 문구(`PET_105`~`107`)는 정의만 해 두고 화면에서 도달하지 않는다 — `RadioGroup` 이 항상 유효한 값 하나를 들고 있다. **도달 불가를 근거로 스키마에서 빼지 않는다.** 초기값을 바꾸거나 "선택 안 함" 을 도입하면 즉시 필요해진다.

## D6. 접근성

- 각 섹션 제목은 heading(`h2`). 폼 제목은 `h1`
- 텍스트 필드는 `Field` + `Input` 조합으로 `label`/`error`/`aria` 가 자동 배선된다
- `RadioGroup` 은 `<fieldset>`+`<legend>`, `Checkbox` 는 자체 `<label>` — `Field` 로 감싸지 않는다 (`component-guide.md` §7)
- 필수 필드는 `required` prop 으로 별표를 붙인다. 별표는 `aria-hidden` 이고 **의미는 문구가 전달한다**
- 제출 실패 시 첫 오류 필드로 포커스를 옮긴다. 트리거는 **`submitCount`** 다 — `errors` 에 의존하면 두 필드가 동시 오류일 때 한 필드를 타이핑하다 포커스를 빼앗긴다 ([#24](https://github.com/8llow8llowMe/hondigagae/issues/24) 발견 7)
- `FormAlert` 는 `role="alert"`, 성공·안내는 `role="status"`

## D8. 미결 사항

### D8-1. 등록 성공 후 이동 — 목록으로 간다

- **선택지 A (채택)**: `/pets` 목록으로 `replace`
- 선택지 B: 방금 등록한 `/pets/{petId}` 로 이동
- **근거**: 등록 직후 사용자의 관심은 "등록됐나" 이고 목록이 그 답을 준다. B 는 방금 채운 폼과 거의 같은 화면을 다시 보여준다
- **되돌리는 비용**: 없다. 응답이 `PetResponse` 라 `petId` 를 이미 알고 있어 B 로 바꾸는 것은 한 줄이다

### D8-2. 등록 완료 안내를 목록에서 낼지

지금은 내지 않는다. 목록에 새 카드가 나타나는 것이 확인 자체다. 회원가입([#24](https://github.com/8llow8llowMe/hondigagae/issues/24))처럼 `?registered=1` 배너를 붙이는 것은 **화면이 바뀌지 않는 경우**(로그인 화면 → 로그인 화면)에 필요했던 것이고, 여기는 화면이 바뀐다.

## D9. BE 후속 요청

공통명세 S6 의 3건이 걸린다. 특히 **S6-1(enum 열거 수단 없음)** 이 이 화면의 선택지 3개를 하드코딩하게 만든다. 백엔드 enum 에 값이 추가되면 이 화면이 조용히 낡는다.
