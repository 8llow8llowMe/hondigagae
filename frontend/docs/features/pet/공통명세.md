## S0. 개요

- **한 줄 정의**: 반려견의 크기·민감도·성향을 등록해 여행 설계의 입력으로 쓴다.
- **사용자가 달성하려는 것**: 내 개에게 맞는 장소·일정을 추천받기 위한 프로필 확보.
  컨트롤러 주석이 이 화면의 목적을 못박아 둔다 — _"AI 여행 설계의 핵심 입력"_.
- **범위에 포함**
  - `/pets` — 목록. 카드에 전체 프로필을 렌더한다 (S3-2 참고)
  - `/pets/new` — 등록
  - `/pets/[petId]` — **수정 폼 + 삭제.** 읽기 전용 상세 화면을 두지 않는다 (S5-1)
  - 선택 계열 공통 컴포넌트 `RadioGroup` / `Checkbox` 신규
  - pet 타입 · API 계층 · mock
- **범위에서 제외**
  - 반려견 사진 업로드 — **백엔드 DTO 에 이미지 필드가 없다.** `PetSaveRequest` 10개 필드가 전부다
  - 여행 일정에서의 반려견 선택 — 일정 화면 소관
  - 전역 nav / 헤더 — 이슈 #15
  - `GET /internal/pets/{petId}/condition` — **내부 API 다.** 서비스 간 호출용이며 게이트웨이가 라우팅하지 않는다

## S1. 화면 목록

| 화면      | 경로            | 인증 | 상태 |
| --------- | --------------- | ---- | ---- |
| 목록      | `/pets`         | 필요 | 기획 |
| 등록      | `/pets/new`     | 필요 | 기획 |
| 수정·삭제 | `/pets/[petId]` | 필요 | 기획 |

- 라우트 그룹은 `(main)`. `(auth)` 가 아니다 — 로그인한 사용자의 화면이다.
- **`PROTECTED_PATHS` 에 `/pets` 는 이미 등록돼 있다** (`proxy.ts:18`). 추가 작업이 없다.
  미로그인 진입 시 `/login?returnTo=%2Fpets` 로 보내지고, 그 화면은 #24 에서 만들었다.
- `/pets/new` 가 `/pets/[petId]` 보다 먼저 매칭된다 (Next 는 정적 세그먼트 우선).
  `new` 를 `petId` 로 오인해 조회하는 경로는 생기지 않는다.

## S2. 사용 API

기본 경로 `/api/v1/members/me/pets`. FE 코드에서는 BFF 규약대로 `/members/me/pets` 로 쓴다
(`architecture-guide.md` §7).

| #   | METHOD 경로                       | 용도 | 응답                                   |
| --- | --------------------------------- | ---- | -------------------------------------- |
| 1   | `GET /members/me/pets`            | 목록 | `{ pets: PetItem[], totalCount: int }` |
| 2   | `GET /members/me/pets/{petId}`    | 상세 | `PetResponse`                          |
| 3   | `POST /members/me/pets`           | 등록 | `PetResponse`                          |
| 4   | `PUT /members/me/pets/{petId}`    | 수정 | `PetResponse`                          |
| 5   | `DELETE /members/me/pets/{petId}` | 삭제 | `dataBody: null` → `unwrapVoid()`      |

- 5개 모두 `@PreAuthorize("isAuthenticated()")` 다. 401 은 BFF 재발급 흐름이 처리한다.
- 5개 모두 `@Valid` 가 정상적으로 붙어 있다 — `POST /auth/login` 의 누락(#40)과 같은 문제는 없다.
- **DELETE 는 소프트 삭제다.** 컨트롤러 주석: _"기존 여행 일정이 참조하고 있어 소프트 삭제로 처리"_.
  삭제 후 목록을 다시 조회하면 사라지지만, 일정이 참조하던 반려견은 서버에 남아 있다.
- `SliceResponse` 가 아니다. **커서·무한 스크롤이 없다.** 회원당 최대 5마리라 항상 전량이 온다.

### `PUT` 은 부분 수정이 아니다

`PetSaveRequest` 를 등록과 수정이 **공유한다.** 수정에서 필드를 빼면 `PetCommandProcessor.update()`
가 그 값으로 통째로 덮어쓴다. 즉 **PATCH 의미가 아니다.** 수정 폼은 항상 10개 필드를 다 보낸다.

### S3-2. 목록 항목이 상세와 같다

`PetItem` 과 `PetResponse` 는 **필드 단위로 완전히 동일하다.** `PetItem` 의 주석이 의도를 밝힌다 —
_"회원당 최대 5마리라 목록에서도 전체 프로필을 내려, 프론트가 카드에 성향 배지를 바로 렌더링할 수 있게 한다"_.

두 가지가 따라온다.

1. **읽기 전용 상세 화면은 정보를 하나도 더하지 못한다.** 그래서 `/pets/[petId]` 를 수정 폼으로 둔다 (S5-1).
2. `/pets/[petId]` 직접 진입(북마크·새로고침)에는 API #2 가 필요하다. 목록에서 이동한 경우는
   캐시가 있으므로 `petKeys.detail` 을 목록 데이터로 시드할 수 있다 — 다만 **1차 구현에서는 하지 않는다.**
   두 경로의 동작이 갈리면 디버깅이 어려워지고, 최대 5건 조회는 비용이 낮다.

### S3-3. `birthYm` 빈 문자열은 400 이다 — 이 명세의 최대 함정

```java
// PetSaveRequest.java:27
@Pattern(regexp = "^\\d{4}-(0[1-9]|1[0-2])$", message = PetValidationMessage.BIRTH_YM_FORMAT_INVALID)
String birthYm
```

Jakarta `@Pattern` 은 **`null` 을 유효로 본다.** 그러나 `""` 는 null 이 아니므로 정규식에 걸려
`PET_104` 가 된다. 선택 입력인데 "비워둠"을 `""` 로 보내면 거부된다.

**규칙: 빈 값은 `null` 로 직렬화한다.** `toPetSavePayload()` 한 곳에서만 처리한다.

`breed` 는 정반대다. `@Size(max = 50)` 뿐이라 `""` 가 통과하고 그대로 저장돼 응답에 `""` 로 돌아온다.
**같은 "선택 입력" 두 개가 서로 다르게 동작한다.** 그래서 정규화를 필드별로 흩지 않고 한 함수에 모은다.

| 입력값 | `breed`          | `birthYm`         |
| ------ | ---------------- | ----------------- |
| `""`   | 통과 → `""` 저장 | **400 `PET_104`** |
| `null` | 통과             | 통과              |
| 공백만 | 통과 → 공백 저장 | **400 `PET_104`** |

둘 다 `trim()` 후 빈 문자열이면 `null` 로 보낸다. `breed` 는 서버가 받아주더라도 `""` 를 저장할
이유가 없다 — 목록 카드에서 빈 배지를 그리게 된다.

### S3-4. boolean 4개는 primitive 다

`boolean` 이고 `Boolean` 이 아니다. 필드를 누락하면 Jackson 이 **조용히 `false` 로 채운다.**
검증 오류가 나지 않는다. 즉 **"미입력"과 "아니오"를 서버가 구분할 수 없다.**

- 폼은 4개를 **항상 명시적으로** 보낸다.
- 등록 화면의 초기값을 의도적으로 정한다 — **전부 `false`** 로 둔다. "민감하지 않음 / 산책 선호 안 함"이
  아니라 "사용자가 켜지 않았음"의 표현이며, 서버 기본값과 일치시켜 폼과 저장 결과가 어긋나지 않게 한다.
- `walkPreferred` 만 의미가 반대 방향(긍정 속성)이라 문구로 구분한다 (S4-4).

### S3-5. 요청과 응답의 enum 표현이 다르다

```text
요청:  "sizeType": "SMALL"
응답:  "sizeType": { "code": "SMALL", "name": "소형견", "description": "체중 10kg 미만" }
```

수정 폼은 `response.sizeType.code` 를 꺼내 요청의 `sizeType` 으로 되돌려야 한다.
**이 매핑을 놓치면 수정 저장이 조용히 깨진다** (`[object Object]` 가 enum 으로 전송되거나
`PET_105` 가 난다). `toPetFormValues()` 한 곳에서만 처리한다.

`name` / `description` 은 **서버 문구를 그대로 렌더한다.** 한국어 매핑 테이블을 만들지 않는다
(`api-integration-guide.md` §6).

### S3-6. enum 값과 화면 문구 (`shared-travel` 실측)

| enum             | code     | name   | description                                      |
| ---------------- | -------- | ------ | ------------------------------------------------ |
| `PetSizeType`    | `SMALL`  | 소형견 | 체중 10kg 미만                                   |
|                  | `MEDIUM` | 중형견 | 체중 10kg 이상 25kg 미만                         |
|                  | `LARGE`  | 대형견 | 체중 25kg 이상                                   |
| `ActivityLevel`  | `LOW`    | 낮음   | 짧은 산책을 선호하며 장시간 활동을 힘들어합니다. |
|                  | `MEDIUM` | 보통   | 일반적인 산책과 관광 일정을 소화합니다.          |
|                  | `HIGH`   | 높음   | 긴 산책과 활동적인 일정을 선호합니다.            |
| `SocialityLevel` | `LOW`    | 낮음   | 다른 개나 낯선 사람을 불편해합니다.              |
|                  | `MEDIUM` | 보통   | 상황에 따라 적응합니다.                          |
|                  | `HIGH`   | 높음   | 다른 개나 사람과 잘 어울립니다.                  |

**`description` 이 실용적이다.** "낮음 / 보통 / 높음"만 보여주면 사용자가 무엇을 고르는지 모른다.
그래서 선택 UI 를 `select` 가 아니라 **`RadioGroup` 으로 만들고 description 을 함께 노출한다** (S5-2).

**단, 등록 폼에서는 세 값을 하드코딩할 수밖에 없다.** enum 목록을 내려주는 API 가 없다
(응답 metadata 는 이미 선택된 값 하나뿐이다). code 는 `src/types/pet.ts` 에 상수로 두고,
`name`/`description` 은 위 표를 근거로 `src/lib/messages/pet.ts` 에 둔다 — S6-1 에 BE 요청으로 남긴다.

## S4. 상태 / 에러

### S4-1. 네 상태

| 상태            | 컴포넌트     | 재시도   | 문구                                                                   |
| --------------- | ------------ | -------- | ---------------------------------------------------------------------- |
| loading         | `Skeleton`   | —        | —                                                                      |
| 목록이 빈 배열  | `EmptyState` | 없음     | "등록된 반려견이 없습니다" / "반려견을 등록해 맞춤 여행을 받아보세요." |
| 404 (`PET_001`) | `EmptyState` | **없음** | "존재하지 않는 반려견입니다" / "목록으로 돌아가 다시 선택해주세요."    |
| 5xx             | `ErrorState` | **있음** | "정보를 불러오지 못했습니다" / "잠시 후 다시 시도해주세요."            |

- `birthYm` / `breed` / `age` 가 `null` 인 필드는 **숨긴다.** "정보 없음" 을 그리지 않는다.
- 폴링 없음.
- **5xx 에서 폼을 유지한다.** `ErrorState` 를 폼 위에 얹고 대체하지 않는다 — #24 최종 리뷰 I1 이
  같은 실수를 잡았다 (`ErrorState` 가 폼을 대체하면 입력값을 고칠 수단이 사라진다).

### S4-2. 400 분기 — `resultCode` 를 봐야 한다

`PET_002`(등록 상한) 와 필드 검증(`PET_1xx`) 이 **둘 다 400** 이다. `classify()` 는 둘을
`'bad-request'` 로 뭉갠다. `resultCode` 로 분기한다.

| 코드                | 표시 위치    | 문구                                                         |
| ------------------- | ------------ | ------------------------------------------------------------ |
| `PET_002`           | 폼 전체 오류 | 서버 문구 + "최대 5마리까지 등록할 수 있어요." (상한값 노출) |
| `PET_101`~`PET_107` | 해당 필드    | `toFormErrors()` 가 매핑 (`form-guide.md`)                   |
| `PET_113`           | 폼 전체 오류 | 잘못된 경로. 정상 흐름에서 발생하지 않는다 (S4-3)            |

**`PET_002` 는 등록 화면에 들어오기 전에 막는 것이 우선이다.** 목록의 `totalCount` 가 5면
등록 버튼을 비활성화하고 이유를 적는다. 서버 오류는 **경합(다른 탭에서 등록) 대비 2차 방어**다.

### S4-3. `/pets/abc` 는 404 가 아니라 400 이다

```java
// PetWebController.java:50
@PathVariable long petId
```

숫자가 아닌 `petId` 는 `MethodArgumentTypeMismatchException` → `PET_113`, **400** 이다.
`notFound()` 가 걸리지 않는다. 장소 상세의 `PLACE_113` 과 같은 함정이다.

`petId` 자체는 응답에서 **문자열**이다 (Snowflake ID — JS 안전 정수 범위를 넘는다).
`number` 로 파싱하지 않는다.

| ---------------- | --------------- | -------------------------- |

| `sizeType`       | 크기            | — (필수)                   |
| `activityLevel`  | 활동량          | — (필수)                   |
| `sociality`      | 사회성          | — (필수)                   |

## S5. 미결 사항

### S5-1. `/pets/[petId]` 를 수정 폼으로 둔다 — 확정

- **선택지 A (채택)**: `/pets/[petId]` = 수정 폼 + 삭제. 읽기 전용 상세 없음
- 선택지 B: 상세(`/pets/[petId]`) + 수정(`/pets/[petId]/edit`) 분리
- **근거**: `PetItem` == `PetResponse` (S3-2) 라 상세가 목록 카드보다 더 보여줄 것이 없다.
  읽기 전용 페이지는 "수정" 버튼 하나만 있는 막다른 화면이 된다.
- **되돌리는 비용**: 낮다. 상세에 일정 이력·AI 추천이 붙는 시점에 `/pets/[petId]` 를 상세로 바꾸고
  폼을 `/edit` 으로 옮긴다. 폼 컴포넌트는 그대로 재사용된다.

### S5-2. 선택 UI 를 `RadioGroup` 으로 한다 — 확정

- **선택지 A (채택)**: `RadioGroup` — 3개 선택지와 `description` 을 모두 노출
- 선택지 B: `select` — 공간을 덜 쓰지만 description 을 숨긴다
- **근거**: S3-6 의 description 이 선택의 근거 자체다(“체중 10kg 미만”). 숨기면 사용자가
  소형/중형을 체중 기준으로 고를 수 없다. 선택지가 3개뿐이라 공간 비용도 작다.
- **되돌리는 비용**: 낮다. `Field` 조립 규약이 같으므로 컴포넌트만 교체된다.

### S5-3. 반려견 사진 — 백엔드에 필드가 없다

`PetSaveRequest` 에 이미지 필드가 없고 `PetResponse` 에도 없다. 회원 프로필 이미지
(`POST /members/me/profile-image`) 는 있는데 반려견은 없다. 카드 시각 요소는 **이름 첫 글자 아바타**로
대체한다. BE 요청은 S6-2.

## S6. BE 후속 요청

### S6-1. enum 목록 조회 API 또는 Swagger 열거

`PetSizeType` / `ActivityLevel` / `SocialityLevel` 의 **선택지 목록을 내려주는 API 가 없다.**
응답 metadata 는 이미 선택된 값 하나뿐이라, 등록 폼의 선택지 3개는 FE 가 하드코딩해야 한다.
`api-integration-guide.md` §6 이 "한국어 매핑 테이블을 만들지 않는다"고 규정하는데,
**선택지를 그릴 때만은 어길 수밖에 없다.**

enum 에 값이 추가되면 FE 가 조용히 낡는다. 열거 API(`GET /pets/enums`)나 최소한
Swagger `@Schema(allowableValues=...)` 를 요청한다.

### S6-2. 반려견 사진 업로드

회원에는 있고(`POST /members/me/profile-image`) 반려견에는 없다. 카드가 시각적으로 구분되지 않는다.

### S6-3. `HttpMessageNotReadableException` 핸들러가 없다

`PetExceptionHandler` 와 catch-all(`MemberExceptionHandler`) 모두 이 예외를 다루지 않는다.
유효하지 않은 enum 값(`sizeType: "HUGE"`)이나 깨진 JSON 을 보내면 Jackson 이 역직렬화 단계에서
실패하고, **`Response` 래퍼가 없는 맨 400** 이 나간다. FE 의 `unwrap()` 이 파싱할 수 없다.

**이 화면은 선택지를 고정 목록으로 제한하므로 실제로 유발하지 않는다.** 다만 다른 클라이언트나
계약 변경 시 드러나는 잠재 결함이라 남긴다. 우선도 낮음.
