# 반려견 목록 세부 명세

> 계약 확인 근거: Swagger 미호출 (백엔드 미기동). 소스 실측 — 공통명세 상단 참조

## D0. 화면 정의

- **경로**: `/pets` (라우트 그룹 `(main)`)
- **인증**: 필요. `proxy.ts:18` `PROTECTED_PATHS` 에 등록돼 있어 미로그인은 `/login?returnTo=%2Fpets` 로 간다
- **한 줄 정의**: 등록한 반려견을 한눈에 보고, 수정·삭제·추가 등록으로 들어간다
- **범위에 포함**: 카드 목록, 빈 상태, 등록 진입(상한 판정 포함), 카드 → 수정 이동
- **범위에서 제외**: 반려견 사진(백엔드 필드 없음 — 공통명세 S5-3), 정렬·필터(최대 5마리라 불필요), 일정 이력

## D1. 레이아웃

한 컬럼. 최대 5장이라 그리드를 넓게 쓸 이유가 없다.

- 모바일 (375): `px-4`, 카드 전체 폭, 세로 스택
- 태블릿 (768) 이상: `max-w-2xl` 중앙 정렬. 2열 그리드로 가지 않는다 — 카드에 성향 배지가 7개까지 들어가 좁은 열에서 배지가 3줄로 접힌다
- 등록 버튼은 목록 **상단**에 둔다. 하단 고정 CTA 는 5장뿐인 목록에 과하다

긴 한국어 실데이터로 확인할 항목:

- `description` 이 가장 긴 `ActivityLevel.LOW`("짧은 산책을 선호하며 장시간 활동을 힘들어합니다.") — 카드에는 `name` 만 쓰지만 배지 폭 계산에 참고한다
- 이름 20자 + 품종 50자가 동시에 최대일 때 카드 헤더가 밀리지 않는지
- 상한 도달 시 안내 문구("최대 5마리까지 등록할 수 있어요.")가 버튼 옆에서 줄바꿈되는지

## D3. 데이터 흐름

```text
/pets 진입 (서버) → readSession() → serverFetch GET /members/me/pets (retry: false)
                     → dehydrate → HydrationBoundary
                                     → PetListSection (client, useQuery 같은 key)
```

| 항목                   | 내용                                                                            |
| ---------------------- | ------------------------------------------------------------------------------- |
| API                    | `GET /members/me/pets`                                                          |
| React Query key        | `petKeys.list()`                                                                |
| staleTime / gcTime     | 1분 / 10분 (`api-integration-guide.md` §7)                                      |
| retry                  | 1 (클라이언트). **서버 프리페치는 `retry: false`** (`architecture-guide.md` §9) |
| mutation 후 invalidate | 이 화면에 mutation 없음. 등록·수정·삭제 화면이 `petKeys.all` 을 무효화한다      |
| 폴링 여부              | 없음                                                                            |

**서버 프리페치 실패를 화면 전체 실패로 만들지 않는다.** 실패하면 클라이언트가 재조회한다.

**`petKeys.detail` 을 목록 데이터로 시드하지 않는다.** `PetItem` == `PetResponse` 라 기술적으로 가능하지만, 목록 경유 진입과 직접 진입(북마크·새로고침)의 동작이 갈리면 디버깅이 어려워진다. 최대 5건 조회는 비용이 낮다 (공통명세 판정 8).

## D4. 상호작용

| 트리거                     | 동작                               | 결과                                                      |
| -------------------------- | ---------------------------------- | --------------------------------------------------------- |
| 카드 클릭                  | `/pets/{petId}` 이동               | 수정 폼. `petId` 는 **문자열** — 파싱하지 않는다          |
| "반려견 등록" (5마리 미만) | `/pets/new` 이동                   | 등록 폼                                                   |
| "반려견 등록" (5마리)      | **버튼 `disabled` + 이유 표시**    | 이동하지 않는다. 문구: "최대 5마리까지 등록할 수 있어요." |
| 5xx 재시도                 | `refetch()`                        | 목록 다시 조회                                            |
| 401                        | BFF 가 재발급 1회 → 실패 시 로그인 | 이 화면은 아무것도 하지 않는다 (`auth-guide.md` §3)       |

**상한을 서버 오류로 알게 하지 않는다.** `totalCount >= MAX_PET_COUNT` 면 진입 자체를 막는다. 등록 화면까지 들어가 필드 10개를 채운 뒤 `PET_002` 를 받는 것은 낭비다. 서버 오류는 **다른 탭에서 동시 등록한 경합** 대비 2차 방어로 등록 화면이 처리한다 (공통명세 S4-2).

## D5. 상태별 화면

| 상태           | 표현                                                | 재시도   |
| -------------- | --------------------------------------------------- | -------- |
| loading        | `Skeleton` 카드 2장 + 헤더                          | —        |
| 목록이 빈 배열 | `EmptyState` "등록된 반려견이 없습니다" + 등록 버튼 | **없음** |
| 5xx / 무응답   | `ErrorState` "정보를 불러오지 못했습니다"           | **있음** |
| 상한 도달      | 목록은 정상. 등록 버튼만 `disabled` + 안내          | —        |

카드 안에서 숨기는 것 (**"정보 없음" 을 그리지 않는다**):

| 필드      | null 일 때                                    |
| --------- | --------------------------------------------- |
| `breed`   | 품종 줄을 렌더하지 않는다                     |
| `birthYm` | 생년월을 렌더하지 않는다                      |
| `age`     | `birthYm` 이 없으면 항상 null → 나이를 숨긴다 |

성향 배지는 **true 인 것만** 표시한다. "더위에 민감하지 않음" 을 배지로 그리면 배지가 항상 4개가 되어 정보량이 0 이 된다. `sizeType` / `activityLevel` / `sociality` 는 항상 값이 있으므로 **서버 metadata 의 `name` 을 그대로** 배지에 쓴다.

## D6. 접근성

- 카드 제목은 heading 요소(`h2`). `EmptyState`/`ErrorState` 의 제목도 heading (`component-guide.md` §7)
- 카드 전체를 클릭 대상으로 만든다. `Card` 에는 `onClick` 이 없으므로 **`next/link` 의 `Link` 로 감싸고** `variant="interactive"` 로 hover 를 준다. `div` + `onClick` 을 쓰지 않는다 — 키보드로 도달할 수 없다
- **중첩 링크를 만들지 않는다.** 카드 안에 별도 링크·버튼을 두지 않는다 (수정·삭제는 카드 안이 아니라 이동한 화면에서 한다)
- 배지는 장식이 아니라 정보다. `aria-hidden` 을 붙이지 않는다
- 상한 도달 시 `disabled` 버튼만 두지 않고 **이유를 텍스트로** 함께 낸다. `disabled` 는 스크린리더에 "왜" 를 전달하지 못한다
- `Skeleton` 은 `aria-hidden`

## D8. 미결 사항

### D8-1. 카드 시각 구분 — 이름 첫 글자 아바타로 간다

- **선택지 A (채택)**: 이름 첫 글자 아바타 + 배경색을 `petId` 해시로 결정
- 선택지 B: 크기별 실루엣 아이콘
- **근거**: 백엔드에 사진 필드가 없다(공통명세 S5-3). A 는 이름이 다르면 반드시 구분되고, B 는 소형견 3마리를 구분하지 못한다
- **되돌리는 비용**: 낮다. 사진 API 가 생기면 아바타 자리를 이미지로 바꾼다
