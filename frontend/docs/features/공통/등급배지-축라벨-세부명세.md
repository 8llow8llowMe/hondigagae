# 등급 배지 축 라벨 세부 명세

- 이슈: #652 (진단 **G-1 [P1]** · **D-2 [P1]**)
- 진단 정본: `docs/superpowers/specs/2026-09-15-ui-ux-audit-design.md` §2-3 D-2 · §2-12 G-1 · §6
- 대상: `src/components/metric.tsx` 의 `MetricBadge` 와 그 호출부 전부

## D0. 화면 정의

`MetricBadge` 는 홈·장소 목록·장소 상세·일정·저장한 장소·소개에서 쓰는 **등급 배지 하나**다.
이 문서는 그 배지가 **어느 축의 등급인지 말하게** 만든다.

### 현상 (2026-09-15 실측, 390×844, dev API `MOCK_API=false`)

**① 장소 상세 `/places/126434` (수월봉) — 한 화면에 `보통` 배지가 둘이다.**

| 위치                          | 축     | 문구   | 폭       | tint 클래스         | 배경               | 글자색           |
| ----------------------------- | ------ | ------ | -------- | ------------------- | ------------------ | ---------------- |
| `y=376` 이름 줄 오른쪽        | 적합도 | `보통` | 38.74 px | `bg-metric-mid-100` | `rgb(254,244,224)` | `rgb(138,95,15)` |
| `y=704` `언제 가면 덜 붐빌까` | 혼잡도 | `보통` | 38.74 px | `bg-metric-mid-100` | `rgb(254,244,224)` | `rgb(138,95,15)` |

**문구·폭·배경·글자색이 전부 같다.** 두 배지를 가르는 단서는 화면상 y 좌표(328px 떨어져
있다)뿐이고, 이름 옆 배지는 자기 축을 말하는 이웃 텍스트가 없다 — 이것이 D-2 다.

**② 홈 `/` 천제연폭포 행 — 한 행 안에서 두 축이 나란히 선다.**

| 위치                        | 축     | 문구   | 폭       | 톤           |
| --------------------------- | ------ | ------ | -------- | ------------ |
| `y=1066` (`order-first` 줄) | 혼잡도 | `혼잡` | 38.74 px | `low` (회색) |
| `y=1101` (제목 줄 오른쪽)   | 적합도 | `보통` | 38.74 px | `mid` (앰버) |

35px 떨어진 두 배지가 **서로 다른 축의 등급**이다. 색이 다르지만 색은 축이 아니라 등급을
말하므로, 무엇의 `혼잡` 이고 무엇의 `보통` 인지 알려 주지 않는다.

**③ 규칙이 아니라 예외로 이미 접두어가 붙어 있다.**

같은 홈 화면 `성판악` 행의 혼잡도 `UNKNOWN` 배지는 **`혼잡도 정보 없음`(96.3 px)** 이다
(`messages.home.congestionUnknown`). `place-insight-row.tsx` 의 주석이 그 이유를 갖고 있다 —
_"서버 `name` 이 '정보 없음' 인데 배지 하나로 서면 무엇의 정보가 없는지 알 수 없다"_.
**같은 이유가 `보통` 에도 그대로 적용되는데 거기에만 붙여 두었다.**

**④ 디자인 정본은 이미 축 접두어를 전제하고 있다.**

`DESIGN.md` §2-3 등급 표의 **"대표 문구"** 열이 `적합도 높음` · `적합도 보통` · `적합도 낮음`
이다. 정본이 가정한 어휘에서 화면이 축만 떨어뜨린 것이다.

### 바꾸는 것

- **충돌하는 두 축 — 적합도 · 혼잡도 — 의 등급 배지 앞에 축 라벨을 붙인다.** `적합도 보통` ·
  `혼잡도 보통`.
- 축 라벨은 **값과 무관하게 항상** 붙는다. `보통` 일 때만 붙이면 배지 모양이 값마다 달라져
  사용자가 "앞 낱말이 축" 이라는 규칙을 배울 수 없고, 서버가 새 충돌 어휘를 보내면 조용히
  깨진다.
- `messages.home.congestionUnknown` 을 `정보 없음` 으로 줄인다 — 접두어가 컴포넌트에서
  붙으므로 문구에 남겨 두면 `혼잡도 혼잡도 정보 없음` 이 된다.

### 바꾸지 않는 것 — 그리고 그 이유

- **서버 enum `name` 을 그대로 렌더하는 규칙** (`api-integration-guide.md` §6). 어휘 자체를
  `한산·보통·붐빔` / `적합·무난·부적합` 으로 다시 짓자는 진단 1안은 **쓰지 않는다** — 진단
  §6 결정표가 이미 _"1차는 축 라벨, 어휘 변경은 BE 이슈로"_ 로 갈라 두었다. D9 로 넘긴다.
- **`DESIGN.md` §2-3 등급 토큰.** 색·tint·`-700` 층 전부 그대로다. 접두어는 배지 안에서
  같은 색으로 렌더되므로 대비 값이 바뀌지 않는다.
- **배지 크기 토큰** (`sm` `md` `score`). `#638` 이 정한 `px-2` 를 건드리지 않는다.
- **산책 안전(`안전·주의·위험`) · 기상특보(`폭염 경보`) · 일정 상태(`확정·초안·완료`) ·
  속성 배지(`실내 여부 미확인`).** 축이 충돌하지 않거나 문구가 이미 축을 말한다 — D5 참고.

## D1. 레이아웃 — 390 폭 예산

배지 폭 = **텍스트 폭 + 18px** (`px-2` 좌우 16 + 투명 테두리 2). 실측으로 확인했다
(`보통` 20.74 + 18 = 38.74).

접두어 비용 (`text-caption` 12px/600 Pretendard 실측):

| 접두어    | 비용         |
| --------- | ------------ |
| `적합도 ` | **+33.97px** |
| `혼잡도 ` | **+33.97px** |

주요 자리의 여유:

| 자리                                      | 칸 폭 | 배지 현재 → 후       | 남는 폭                  | 판정                     |
| ----------------------------------------- | ----- | -------------------- | ------------------------ | ------------------------ |
| 장소 상세 이름 줄 (`h1` flex-1 + 배지)    | 358   | 38.74 → 72.71        | h1 311.26 → **277.29**   | 여유 (아래 참고)         |
| 혼잡도 카드 `가장 덜 붐비는 날` 줄        | 358   | 38.74 → 72.71        | 날짜~배지 사이 101.71    | 여유                     |
| 홈 행 혼잡도 줄 (`order-first`, 단독)     | 266   | 38.74 → 72.71        | 193.29                   | 여유                     |
| 홈 행 제목 줄 (제목 flex-1 + 배지 + 점수) | 266   | 그룹 103.09 → 137.06 | 제목 154.91 → **120.94** | **접힘 문턱이 내려간다** |

`제주올레길 7코스` 가 150.84px 다 — 277.29 안에 든다.

**홈 행 제목 줄만 비용을 낸다.** 제목은 18px/600 이라:

| 제목               | 폭     | 현재(154.91) | `적합도 보통`(120.94) | `적합도 여행 적합`(97.35) |
| ------------------ | ------ | ------------ | --------------------- | ------------------------- |
| `천제연폭포`       | 77.79  | 한 줄        | 한 줄                 | 한 줄                     |
| `성산일출봉`       | 95.07  | 한 줄        | 한 줄                 | 한 줄                     |
| `한라산국립공원`   | 108.90 | 한 줄        | 한 줄                 | **두 줄**                 |

제목은 `break-words` + `flex-1` 이라 **넘치지 않고 접힌다.** 접힘 문턱이 9자 → 7자(적합도

**1280 에서는 여유가 더 크다** (홈 행이 `@2xl` 레이아웃으로 갈라져 배지가 제목 줄을 떠난다).

## D2. 컴포넌트 구성

### D2-1. `MetricBadge` 에 `axis` 슬롯을 더한다

```tsx
<MetricBadge tone={suitabilityTone(code)} axis="suitability">
  {level.name}
</MetricBadge>
```

- `axis?: MetricAxis` — `'suitability' | 'congestion'` 유니온이다. **자유 문자열로 받지
  않는다.** 유니온이면 축이 하나 늘 때 타입이 전 호출부를 가리키고, `grep` 로 전수 확인이
  된다.
- 생략하면 접두어가 없다 — 지금 라벨을 붙이지 않기로 한 자리(D5)가 기본값으로 남는다.
- 접두어 문구는 **`messages` 에서 읽는다.** 컴포넌트 안에 한국어 리터럴을 두지 않는다.

### D2-2. 접두어는 **자기 `<span>`** 으로 렌더한다

```tsx
{
  axis !== undefined && <span className="me-1 font-medium">{METRIC_AXIS_LABEL[axis]}</span>
}
{
  children
}
```

- **텍스트 노드를 이어 붙이지 않는다.** `{label} {children}` 로 쓰면 React 가 하이드레이션
  경계에 주석 노드를 끼워 실제 DOM 과 `renderToStaticMarkup` 문자열이 갈린다 —
  `toContain('적합도 보통')` 이 테스트에서만 통과하는 false-green 이 된다
  (`testing-guide.md` §5, 인계 문서의 반복 함정).
- 간격은 `me-1`(4px). 12px 공백 실측이 3.1px 이라 눈에 같다.
- `font-medium` 으로 **한 단계 낮춘다.** 배지 본문은 `font-semibold` 다. 색은 그대로라
  대비가 바뀌지 않고(§2-3 `-700` 층 유지), `적합도` 가 라벨, `여행 적합` 이 값으로 읽힌다.
  **크기·색으로 낮추지 않는다** — 크기를 줄이면 12px 밑으로 내려가고, 색을 흐리면 MID tint
  위 5.16:1 이 무너진다.

### D2-3. 톤 계산은 그대로 호출부가 한다

`metric.tsx` 는 여전히 code 를 해석하지 않는다. `axis` 는 **어휘 표**이지 code→tone 매핑이
아니다 — `suitabilityTone` / `congestionTone` 은 `lib/insight/tone.ts` 에 그대로 있다.

## D3. 데이터 흐름

**서버 계약 변화가 없다.** 접두어는 전부 FE 문구이고, 배지 본문은 지금처럼 서버 `name` 이다.
새 API·새 필드·새 타입이 없다.

## D6. 접근성

- 접두어와 등급이 **한 배지(`<span>`) 안**에 있으므로 스크린리더가 `적합도 보통` 을 한
  덩어리로 읽는다. `aria-label` 을 따로 두지 않는다 — 두면 보이는 글자와 읽히는 글자가
  갈릴 자리가 생긴다.
- 접두어 `<span>` 에 `aria-hidden` 을 **주지 않는다.** 축을 못 듣는 사용자가 생긴다.
- 대비는 그대로다. 접두어는 본문과 같은 `-700` 층 색이고 굵기만 600 → 500 이다.
- 색으로만 축을 가르지 않는다는 `DESIGN.md` §2-3 규칙을 이 변경이 **더 지킨다** —
  지금까지 두 축을 가르는 유일한 단서가 위치였다.

## D7. 테스트 케이스

`renderToStaticMarkup` 문자열 단언이다 (`testing-guide.md` §5). **범위를 좁힌다** — 마크업
전체에 `toContain('적합도')` 를 걸면 같은 화면의 다른 요소가 통과시킨다.

| #   | 대상                                   | 단언                                                                                             |
| --- | -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1   | `MetricBadge` `axis` 없음              | 접두어 `<span>` 이 **없다**. 기존 호출부의 마크업이 그대로다                                     |
| 2   | `MetricBadge axis="suitability"`       | 배지 여는 태그 안쪽에 `<span class="me-1 font-medium">적합도</span>` 가 있고 그 뒤가 서버 `name` |
| 3   | `MetricBadge axis="congestion"`        | 위와 같고 문구가 `혼잡도`                                                                        |
| 4   | 접두어가 **텍스트 노드로 붙지 않는다** | 배지 안에 `적합도 보통` 이라는 **연속 문자열이 없다** (D2-2 의 근거를 고정한다)                  |
| 5   | 장소 상세 이름 줄                      | `h1` **다음 형제** 배지에 `적합도` 가 있다 (화면 전체가 아니라 그 배지 범위에서)                 |
| 6   | 혼잡도 카드 배지                       | `혼잡도` 가 붙고, 같은 카드의 막대 `sr-only` 는 **바뀌지 않았다**                                |
| 7   | 홈 행 혼잡도 `UNKNOWN`                 | `혼잡도 정보 없음` 이 **한 번만** 나온다 (`congestionUnknown` 중복 회귀)                         |
| 8   | 라벨을 붙이지 않기로 한 배지           | `실내 여부 미확인` · `폭염 경보` 배지에 접두어 `<span>` 이 없다                                  |
| 9   | 메시지 상수                            | `messages.home.congestionUnknown` 이 `혼잡도` 로 시작하지 않는다                                 |

**새 단언마다 뮤테이션을 한 번 넣어 실제로 빨간불이 되는지 확인한다.**

## D8. 미결 사항

### D8-1. 홈 행 제목 접힘 문턱이 9자 → 7자로 내려가는 것을 받아들인다

| 선택지                           | 결과                                                              |
| -------------------------------- | ----------------------------------------------------------------- |

**dev API 실측에서 홈에 서는 제목은 `성판악`(46.67) · `천제연폭포`(77.79) 둘이고 둘 다 한
줄을 유지한다.** 문턱이 내려가는 것은 사실이고, 실제로 접히는 제목이 오늘 화면에는 없다.
BE 가 D9-1 을 받아 주면 문턱이 다시 올라간다.

### D8-2. 반려견 동반 `정보 없음` 배지는 이 이슈에서 건드리지 않는다

`place-pet-info.tsx:123` 의 `정보 없음` 도 축을 말하지 않는다. 다만 **이 이슈가 푸는 문제는
"같은 낱말이 두 축에 쓰인다"** 이고 동반 축에는 충돌 상대가 없다. 또 이 배지는 `반려견 동반
정보` 제목 바로 아래에 서고, `#650` 의 판정 요약이 같은 값을 `동반 · 정보 없음` 으로 이미
축과 함께 말한다. 붙인다면 별도 이슈다.

### D8-3. `/about` 예시의 어휘를 실화면과 맞춘다

`about.specimen.suitabilityGrade` 는 `적합도 높음` 인데 실제 서버 `name` 은 `여행 적합` 이라
소개 페이지가 **실제로 없는 화면**을 보여 주고 있었다. 이 이슈로 실화면이 `적합도 여행 적합`
이 되므로 예시도 그 문구로 맞춘다. 예시의 일은 실화면을 보여 주는 것이다.

## D9. BE 후속 요청

### D9-1. 적합도 `HIGH` 의 `name` 을 짧게

`여행 적합` → `적합`. 축 라벨이 앞에 서면 `적합도 여행 적합` 은 `여행` 이 군더더기다.
줄이면 `적합도 적합`(72.71px)이 되어 홈 행 제목이 **23.6px** 을 되찾고 접힘 문턱이 7자에서
다시 9자로 올라간다. **FE 는 이 값을 창작하지 않는다** — 서버가 바꾸면 화면이 따라간다.

### D9-2. 진단 1안(축별 어휘 분리)은 BE 결정이다

혼잡도 `한산·보통·붐빔` / 적합도 `적합·무난·부적합` 로 어휘 자체를 가르는 안은 enum `name`
변경이라 BE 이슈다. 그 안이 채택되면 축 라벨은 **덜 필요해지지만 없애지는 않는다** — 축을
밝히는 것과 어휘를 겹치지 않게 하는 것은 다른 일이다.
