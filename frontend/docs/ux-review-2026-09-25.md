# 혼디가개 화면 사용성 · UI 검토 (2026-09-25)

> 기준: **실제 렌더 화면과 전체 사용 흐름**. `DESIGN.md`·아트보드 준수 여부는 보지 않았다.
> 방법: `MOCK_API=true` dev 서버(5174)에 fixture 계정으로 들어가 **32개 라우트 × 3 뷰포트**
> (데스크톱 1440 · 태블릿 768 · 모바일 390)를 전체 캡처하고, DOM 실측(탭 타깃 < 40px ·
> 12px 미만 글자 · 가로 오버플로 · 콘솔 오류)과 상호작용(로그인 오류 · 폼 검증 · AI 일정
> 생성 전 과정 · 시트 · 메뉴)을 같이 봤다. 카카오 지도는 5174 에서 실제로 뜬다.
>
> 점수는 100점 만점 세 축이다. **완성도**(상태·빈 화면·오류·문구가 다 갖춰졌는가),
> **사용성**(목표까지의 단계·발견 가능성·오해 소지·터치 타깃), **UI**(위계·밀도·정렬·일관성).
> 뷰포트별 차이가 있으면 `D/T/M` 으로 적었다.

## 0. 총평

- 전체 평균 **완성도 91 · 사용성 87 · UI 89**. 상태 화면(로딩·빈·404·5xx)과 문구가 거의
  모든 화면에 갖춰져 있고 반응형 파손·가로 오버플로·콘솔 오류가 **0건**이다. 공모전 출품작
  기준으로 상위권 완성도다.
- 남은 문제는 **구조적 큰 결함이 아니라 밀도·발견 가능성·터치 타깃** 세 갈래에 모인다.
  1. **AI 일정 생성의 진입점이 약하다.** 데스크톱 상단 nav 에만 있고, **홈과 모바일에는 없다.**
     모바일은 `일정 탭 → + → 시트 → AI 일정` 세 단계다. 서비스의 차별점이 가장 깊이 묻혀 있다.
  2. **작은 컨트롤이 모바일에서 44px 아래다.** 일정 상세의 행 액션(`장소 추가`·`순서 편집`·
     `담기`·`다녀옴`) 32px, 긴급 시설 필터 칩 36px, 헤더 계정 메뉴 36px, 푸터 법적 링크 14px.
  3. **판정 근거가 같은 무게의 문단 7개로 흐른다.** 홈·장소 상세의 산책 판정이 "요약 한 줄 +
     근거들" 인데 시각 위계가 없어 훑어 읽기 어렵다.
  4. **모순처럼 읽히는 문장.** 홈 권역 카드가 "추천할 권역이 없어요" 라면서 바로 아래 56점·
     48점 배지를 보여 준다. 이유(경보·예보 없음)가 없어서 표를 잘못 읽은 것처럼 느껴진다.
