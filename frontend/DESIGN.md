# 혼디가개 Design System

> **이 문서가 코드가 따르는 디자인 토큰의 정본이다.** 색상·타이포·spacing·radius·shadow는 여기에만 정의한다.
> 상태: **3차 토큰 세트 — 디자인 가이드(아트보드) 실측 반영** (2026-08-28, 이슈 #50).
>
> **상위 정본은 `혼디가개 디자인 가이드.dc.html`(Claude Design 산출물)이다.** 이 문서는 그 값을
> 코드용으로 옮겨 적는 쪽이다. 값이 갈리면 가이드가 이긴다. 가이드에 없는 값을 여기서 만들지 않는다.
> 코드는 `src/styles/` 의 CSS 변수만 따라간다.
> **모든 대비비는 실측값이다.** 색을 바꿀 때는 다시 계산해 이 문서를 갱신한다.
> 적용 규칙과 공통 컴포넌트 목록은 `docs/styling-guide.md`.

## 0. 표면 원칙 (2a — 확정)

이 절이 나머지 전부를 지배한다. **색·간격을 고르기 전에 표면부터 정한다.**

- **페이지는 흰색이다.** 회색은 배경이 아니다.
- 묶음의 경계는 **8px 밴드(`--band`)** 로만 끊는다. 같은 묶음 안은 **1px 구분선**으로 잇는다.
  밴드가 "여기서 다른 이야기가 시작된다"는 **유일한 신호**다.
- 목록은 **카드가 아니라 전폭 행**이다. 테두리·라운드·그림자 없이 놓고 구분선으로 나눈다.
  구분선 좌우 인셋 16(모바일) / 40(데스크톱).
- **회색 배경 위에 둥근 흰 카드를 띄우지 않는다** — 대시보드처럼 읽힌다.
- **둥근 것은 사진뿐이다.** 목록·섹션에 라운드가 없다.
- 그림자는 **실제로 떠 있는 것**(팝오버·모달·바텀시트·드래그 중인 항목)에만.

> 이 방향 때문에 `Card` 컴포넌트를 폐기했다. `Row` / `Section` / `Band` 를 쓴다
> (`docs/styling-guide.md` §2).

## 1. 제품 톤

반려견과 함께하는 제주 여행. **따뜻하되 과장하지 않는다.**

시각 컨셉은 **데이터 신뢰형**이다 — **인터페이스의 채도를 낮추고 채도를 데이터에만 남긴다.**
표면(배경·테두리·회색)은 계측면처럼 중립적이고, 색이 붙는 곳은 측정값·등급·근거다.

- 사용자는 **여행 중 이동하면서** 본다 → 모바일 1순위, 큰 터치 영역, 짧은 문장.
- 정보 서비스가 아니라 **의사결정 지원** 서비스다 → 추천에는 항상 근거(XAI `reasons`)를 함께 보여준다.
- **위계는 크기와 순서로 만든다.** P1 안전 → P2 오늘 행동 → P3 예정·상시.
  **우선순위를 색으로 만들지 않는다.** 낮은 우선순위는 접는다.
- **색은 유일한 채널이 아니다.** 등급은 항상 문구로 먼저 전달한다("적합도 높음"). 색은 보조.
- 마케팅 톤 금지. "최고의", "완벽한" 같은 표현을 쓰지 않는다.

### 용어 (고정)

| 사용             | 금지                 |
| ---------------- | -------------------- |
| 반려견           | 강아지, 애견, 멍멍이 |
| 여행 일정        | 여행 계획, 플랜      |
| 장소             | 스팟, 포인트         |
| 여행 적합도      | 여행 점수, 궁합      |
| 반려견 동반 가능 | 펫 프렌들리          |

용어 "판정"은 **안전 판단(산책 위험도)에만** 쓴다. 장소 제안은 **"추천"**이다.

## 2. 색상

### 2-1. 표면 · 테두리

| 토큰              | 값        | 용도                                            |
| ----------------- | --------- | ----------------------------------------------- |
| `--bg`            | `#FFFFFF` | 페이지 · 행                                     |
| `--band`          | `#EEF0F3` | **8px 밴드 · 태그 · 스켈레톤**                  |
| `--bg-sunken`     | `#F5F6F8` | **모형 밖 자료 전용. 화면 안에서 쓰지 않는다.** |
| `--border`        | `#E3E5EA` | 구분선 · 테두리                                 |
| `--border-strong` | `#C4C8D0` | 입력 필드 · 그래버 · unknown 점선               |
| `--row-selected`  | `#F0F7F3` | 선택된 행 tint                                  |

> **`--bg-sunken` 을 섹션 배경으로 쓰지 않는다.** 아트보드 9종에서 화면 안 사용이 0회다.
> 화면 안에서 묶음을 끊는 유일한 회색은 `--band` 다. 스켈레톤·태그 배경도 `--band` 다.

### 2-2. 텍스트 — 3단

| 토큰           | 값        | 용도                                | 흰 배경 | `--band` 위 |
| -------------- | --------- | ----------------------------------- | ------- | ----------- |
| `--fg`         | `#15181D` | 본문 · 제목                         | 17.79:1 | 15.58:1     |
| `--fg-muted`   | `#596069` | 보조 설명 · 메타 · **단위**         | 6.36:1  | 5.57:1      |
| `--fg-subtle`  | `#878D96` | placeholder · 비활성 · 장식 전용    | 3.34:1  | —           |
| `--fg-inverse` | `#FFFFFF` | 진한 배경 위 텍스트 (Toast 17.79:1) | —       | —           |

> **`--fg-subtle` 은 어떤 크기에서도 읽는 텍스트에 쓰지 않는다.** 단위(`/100`, `℃`)에도
> `--fg-muted` 를 쓴다. 읽는 회색 텍스트는 `--fg` · `--fg-muted` **두 단계뿐**이다.
> 클릭 가능한 값(필터 개수 0 등)은 흐리게 하지 않고 `--fg-muted` 를 유지한다.

### 2-3. 등급 `--metric-*` — 5톤 × 3층

적합도·산책 위험도 **등급 전용** 스케일이다. 상호작용 색(브랜드·링크)에서 분리한다.

세 층은 역할이 고정이다 — `-100` tint 배경 / `-500` 흰 배경 위 마크·테두리·큰 숫자 / `-700` 텍스트.

| 단계       | 토큰                   | `-100` (tint) | `-500` (마크)         | `-700` (텍스트)         | 대표 문구   |
| ---------- | ---------------------- | ------------- | --------------------- | ----------------------- | ----------- |
| `CRITICAL` | `--metric-critical-*`  | `#FDECEC`     | `#D54040` (흰 4.53:1) | `#CE2D2D` (tint 4.55:1) | 위험        |
| `HIGH`     | `--metric-high-*`      | `#E4F0EA`     | `#1F7A55` (흰 5.29:1) | `#16563C` (tint 7.39:1) | 적합도 높음 |
| `MID`      | `--metric-mid-*`       | `#FEF4E0`     | `#B0761A` (흰 3.85:1) | `#8A5F0F` (tint 5.16:1) | 적합도 보통 |
| `LOW`      | `--metric-low-*`       | `#EEF0F3`     | `#6B7280` (흰 4.83:1) | `#4B5563` (tint 6.62:1) | 적합도 낮음 |
| `UNKNOWN`  | `--metric-unknown-500` | **없음**      | `#A8AEB8` (점선 전용) | `--fg-muted` 를 쓴다    | 정보 없음   |

`-700` 의 흰 배경 대비: CRITICAL **6.47:1**(`#B91C1C`) · HIGH **8.64:1** · MID **5.64:1** · LOW **7.56:1**.

**규칙**

- **`--metric-mid-500`(`#B0761A`) 을 12px 텍스트에 절대 쓰지 않는다.** 흰 배경 3.85:1 이다.
  3px 지표 바와 stroke 아이콘(비텍스트 3:1)에만 쓴다.
- **등급 색을 숫자에 쓸 때는 22px 이상 + weight 900 에만** 허용한다(대형 텍스트 3:1 기준).
  중립 수치(거리·개수)에는 등급 색을 쓰지 않고 `--fg` 를 쓴다.
- **`--metric-unknown-500`(`#A8AEB8`) 은 어떤 텍스트에도 쓰지 않는다.** 점선 테두리 전용이고
  문구는 `--fg-muted` 로 쓴다. `UNKNOWN` 에는 tint 를 주지 않는다.
- **`LOW` 에 danger 를 쓰지 않는다.** 적합도가 낮은 것은 오류가 아니다.
- **색만으로 정보를 전달하지 않는다.** 등급은 색 + 텍스트(서버 `name`) + 지표 바를 함께 쓴다.
  **FE는 색만 매핑하고 문구는 서버 값을 쓴다.** 모르는 code 는 `UNKNOWN` 으로 떨어진다.
- **등급 색을 우선순위·장식·브랜드·지도 마커·일정 상태(초안/확정/완료)로 전용하지 않는다.**

> **`--metric-critical-*` 은 `--danger-*` 와 값이 같지만 토큰을 분리했다** (이슈 #50 결정).
> 장애(5xx)와 산책 위험 판정이 같은 붉은색이면 사용자가 둘을 구분할 수 없다.
> 붉은 톤을 갈라야 할 때 이 토큰의 값만 바꾸면 화면 코드는 건드리지 않는다.

### 2-4. 액션 · 링크

| 토큰           | 값        | 용도                      | 대비                             |
| -------------- | --------- | ------------------------- | -------------------------------- |
| `--brand-500`  | `#2E9B6B` | **주요 액션** (채운 버튼) | 흰 글자 **3.49:1 — 아래 미해결** |
| `--brand-600`  | `#237A54` | 주요 버튼 hover / pressed | 흰 글자 5.27:1                   |
| `--link`       | `#1F7A55` | **링크 · 인라인 액션**    | 흰 배경 5.29:1                   |
| `--link-hover` | `#16563C` | 링크 hover                | 흰 배경 8.64:1                   |

> **미해결 — 주요 버튼의 흰 글자가 AA 에 미달한다.**
> `--brand-500` 위 흰 글자는 **3.49:1** 이고 버튼 라벨은 16px/600 이다.
> 디자인 가이드는 이것을 "16px/600 = AA 대형" 으로 적었지만 **WCAG 기준으로는 대형이 아니다** —
> 대형 텍스트는 24px 이상(일반) 또는 **18.66px 이상 + bold** 다. 16px 은 bold 여도 본문이라
> 4.5:1 이 필요하다. 실렌더 감사에서 모든 화면의 주요 버튼이 이 조합으로 나왔다 (이슈 #50).
>
> 세 갈래 중 하나를 골라야 한다. **브랜드 색 결정이라 임의로 바꾸지 않고 남겨 둔다.**
>
> 1. 버튼 채움을 `--brand-600`(`#237A54`, 흰 글자 **5.27:1**)으로 내린다 — 코드 한 줄, 대비 해결.
>    대신 주요 버튼이 지금보다 어두워진다.
> 2. 버튼 라벨을 18.66px 이상 + bold 로 올린다 — 타입 스케일(§3-1)에 없는 크기가 필요하다.
> 3. 알려진 예외로 남긴다 — **권장하지 않는다.** 주요 행동이 모든 화면에 있다.
>
> 회귀 감시는 `src/styles/contrast.test.ts` 가 한다. 그 테스트는 이 값이 3:1 이상 4.5:1 미만임을
> 단언하므로, 값을 바꾸면 테스트가 먼저 알려준다.

> **`--link` 는 `--metric-high-500` 과 값이 같다**(`#1F7A55`). 아트보드 실측이 그렇다.
> 토큰명을 분리해 둔 것은 **나중에 갈라야 할 때 한 줄만 고치기 위해서**다 (이슈 #50 결정).
> 링크에 `--metric-high-*` 을, 등급에 `--link` 를 쓰지 않는다 — 값이 같아도 이름을 지킨다.
> **주요 버튼(`--brand-500`)과 링크(`--link`)는 값이 다르다.** "누를 것"의 두 단계다.

### 2-5. AI 표시

| 토큰           | 값        | 용도                             | 대비           |
| -------------- | --------- | -------------------------------- | -------------- |
| `--accent-100` | `#FDEEE0` | **AI 생성 표시** 배경            | —              |
| `--accent-700` | `#A75921` | **AI 생성 표시** 텍스트 · 아이콘 | tint 위 4.51:1 |

> **accent 는 "AI 가 생성·판단한 것" 표시 전용이다.** 장식 배지에 쓰지 않는다.
> 장식으로 쓰면 사용자가 AI 표시를 알아볼 근거가 사라진다.

### 2-6. 시스템 상태 `--danger-*`

**일시 장애(5xx) 전용**이다. 등급(`--metric-critical-*`)과 토큰을 분리한다.

| 토큰           | 값        | 용도                                      | 대비           |
| -------------- | --------- | ----------------------------------------- | -------------- |
| `--danger-100` | `#FDECEC` | 오류 tint 배경                            | —              |
| `--danger-500` | `#D54040` | 오류 아이콘 · 보더 (흰 배경)              | 흰 배경 4.53:1 |
| `--danger-700` | `#CE2D2D` | `--danger-100` 위 텍스트 · 파괴 버튼 채움 | tint 위 4.55:1 |
| `--danger-900` | `#B91C1C` | **메뉴 안 파괴적 항목 텍스트**            | 흰 배경 6.47:1 |

**중요**: `--danger-*` 를 **데이터 부재(404)에 쓰지 않는다.** 404는 `--fg-muted` + 중립 톤이다
(`docs/api-integration-guide.md` §3).

### 2-7. 폐기한 토큰

| 폐기                                       | 대체                                  | 이유                                          |
| ------------------------------------------ | ------------------------------------- | --------------------------------------------- |
| `--warn-*`                                 | `--metric-mid-*`                      | 아트보드 사용 0회. **측정값은 경고가 아니다** |
| `--info-*`                                 | `--band` + `--fg-muted`               | 아트보드 사용 0회. 파랑은 팔레트에 없다       |
| `--success-500`                            | `--brand-500`                         | 값이 동일했다. 성공은 상호작용의 결과다       |
| `--bg-subtle`                              | `--band`(화면 안) / `--bg-sunken`(밖) | 한 토큰이 두 역할을 겸해 오용됐다             |
| `--brand-50`, `--brand-100`, `--brand-300` | `--metric-high-100` 또는 `--band`     | 아트보드 사용 0회                             |
| `--accent-500`, `--accent-600`             | `--accent-700`                        | 아트보드 사용 0회                             |
| `--radius-lg`(카드)                        | 라운드 없음                           | 목록·섹션에 라운드가 없다 (§0)                |

### 2-8. 브랜드 예외 (소셜 로그인 버튼에만)

| 토큰           | 값        | 용도                       |
| -------------- | --------- | -------------------------- |
| `--kakao-bg`   | `#FEE500` | 카카오 버튼 배경           |
| `--kakao-fg`   | `#191600` | 카카오 버튼 글자 (14.20:1) |
| `--naver-mark` | `#03C75A` | 네이버 마크                |

> **소셜 브랜드 색은 로그인 버튼의 마크·배경에만 예외로 허용한다.** 다른 곳에 쓰지 않는다.
> 네이버 초록 채움 + 흰 글자는 **2.25:1 로 미달**이므로 **흰 배경 변형**을 쓴다.

## 3. 타이포그래피

- 본문 폰트: **Pretendard Variable** (가변 축 `45~920`).
- 배포 방식: **dynamic subset** (`unicode-range` 분할, 조각 평균 31KB). 근거는 `docs/tooling-guide.md` §12.
- 폴백: `-apple-system, BlinkMacSystemFont, "Malgun Gothic", "Apple SD Gothic Neo", sans-serif`

### 3-1. 타이포 스케일 — 7단

| 토큰      | size / line-height | weight    | 용도                                          |
| --------- | ------------------ | --------- | --------------------------------------------- |
| `page`    | 34 / 44            | 800       | 페이지 타이틀 (드묾)                          |
| `display` | 28 / 36            | 800 · 900 | 화면 제목 / **큰 지표 숫자**(900)             |
| `title-1` | 22 / 30            | 700 · 900 | 섹션 제목 · 반려견 이름 / **행 안 점수**(900) |
| `title-2` | 18 / 26            | 600       | 행 제목 · 모바일 섹션 제목                    |
| `body-1`  | 16 / 24            | 600       | 버튼 · 배너 제목 · 판정 요약                  |
| `body-2`  | 14 / 22            | 400 · 600 | **본문** · 근거 문장 · 인라인 링크(600)       |
| `caption` | 12 / 18            | 500 · 600 | 메타 · 태그 · 배지 · 단위                     |

**본문 기본은 `body-2`(14/22/400)다.** `body-1`(16/24)은 weight 600 고정이며 버튼·요약용이다.

**허용된 스케일 밖 예외 2개** — 이것 말고는 없다.

| 값          | 어디에서만                             | 근거                                             |
| ----------- | -------------------------------------- | ------------------------------------------------ |
| **20/800**  | `ProfileCard` 등급어("주의") **한 곳** | 18은 라벨(16/600)과 안 갈리고 22는 이름과 겹친다 |
| **11·13px** | 아바타 **이니셜 글자**(원형 안)        | 텍스트가 아니라 도형 내부 요소다                 |

### 3-2. Weight — 실제로 쓰는 6단

| weight | 용도                                | 최소 크기                   |
| ------ | ----------------------------------- | --------------------------- |
| 400    | **본문 기본**                       | 제한 없음                   |
| 500    | 메타 · 단위 · 태그                  | 제한 없음                   |
| 600    | 행 제목 · 버튼 · 라벨 · 인라인 링크 | 제한 없음                   |
| 700    | 섹션 제목 · 반려견 이름             | 제한 없음                   |
| 800    | 화면 · 페이지 제목                  | **20px 이상**               |
| 900    | 지표 숫자                           | **22px 이상, 1~2단어 이내** |

**규칙**

- **100 / 200 / 300 은 쓰지 않는다.** 한글은 얇은 쪽 식별력이 급격히 떨어진다.
- **800 · 900 을 20px 미만에 쓰지 않는다.** 작은 크기에서 굵은 획이 뭉개진다.
- **700 과 800 을 같은 화면의 위계로 쓰지 않는다.** 한글에서 구분이 거의 안 된다 — **크기**로 나눈다.
- 중간값(450, 550 등)을 쓰지 않는다.

### 3-3. 숫자 규칙

- **숫자가 들어가는 모든 요소에 `font-variant-numeric: tabular-nums`** — 날짜·온도·점수·거리·시각·개수.
  "필요한 곳"이 아니라 규칙이다. 목록에서 자릿수가 흔들리면 값을 비교할 수 없다.
- **단위는 값보다 작고 흐리게** (`caption` + `--fg-muted`). 값이 먼저 읽혀야 한다.
  **단위를 생략하지 않는다** — ℃ / km / % / 점 은 항상 표기한다.
- **큰 지표는 28/900, 행 안의 점수는 22/900. 그 사이 크기를 쓰지 않는다.**
- 긴 한국어 텍스트는 `word-break: keep-all` 로 어절 단위 줄바꿈한다.

## 4. Spacing 스케일

```text
4, 6, 8, 12, 16, 20, 24, 32, 40, 48, 64
```

**스케일 밖 값을 쓰지 않는다.** Tailwind arbitrary value(`p-[13px]`)도 금지.

| 값      | 용도                                                   |
| ------- | ------------------------------------------------------ |
| 4       | 인라인 아이콘 보정                                     |
| **6**   | **태그 사이** (2차 세트에서 신설)                      |
| 8       | 근거 문장 사이 · 버튼 그룹 · **밴드 높이**             |
| 12      | 행 내부 문장 사이 · 판정 요약 상하 padding             |
| 16      | 모바일 행 padding · 모바일 좌우 여백 · **구분선 인셋** |
| 20      | 데스크톱 레일 padding · 섹션 제목 아래                 |
| 24      | 모바일 섹션 사이                                       |
| 32      | 데스크톱 섹션 사이                                     |
| 40      | 데스크톱 좌우 여백 · **구분선 인셋**                   |
| 48 · 64 | 그 이상이 필요할 때만                                  |

> **섹션 사이를 더 벌리는 대신 8px 밴드를 쓴다.** 여백으로 끊으려 하면 밴드의 신호가 약해진다.

## 5. Radius — 5개뿐

| 토큰            | 값     | 용도                                     |
| --------------- | ------ | ---------------------------------------- |
| `--radius-sm`   | 4px    | 배지 · 태그 · 지표 바                    |
| `--radius-md`   | 8px    | 버튼 · 입력 · 썸네일 · tint 블록 · Toast |
| `--radius-lg`   | 12px   | **팝오버 · 메뉴** (카드가 아니다)        |
| `--radius-xl`   | 16px   | 모달 · 바텀시트 상단                     |
| `--radius-full` | 9999px | 사진 · 아바타 (유일한 곡선 강조)         |

> **목록 · 섹션 · 행에는 라운드가 없다.** 새 라운드 값을 만들지 않는다.

## 6. Shadow

**행·섹션의 기본 표현은 라운드 없는 1px 구분선이다.** shadow 는 **실제로 떠 있는 것**에만 쓴다.

| 토큰          | 값                               | 용도                                                   |
| ------------- | -------------------------------- | ------------------------------------------------------ |
| `--shadow-md` | `0 4px 12px rgba(21,24,29,.08)`  | 팝오버 · 메뉴 · 모달 · 드래그 중인 항목 · 지도 위 카드 |
| `--shadow-lg` | `0 12px 32px rgba(21,24,29,.12)` | 바텀시트 · Toast                                       |

> **`--shadow-sm` 을 폐기했다.** "평면 카드를 살짝 띄우는" 용도였는데 §0 에서 평면 카드 자체를 없앴다.
> 목록 행에 그림자를 쓰지 않는다.

## 7. 레이아웃 · 브레이크포인트

| 이름    | 폭       | 헤더 | 탭바 | 구조                                              |
| ------- | -------- | ---- | ---- | ------------------------------------------------- |
| mobile  | ~767     | 56   | 64   | 1단. 좌우 여백 16. **기준 375**, 접힘선 844       |
| tablet  | 768~1023 | 64   | —    | 1단 유지. 적합도만 2열                            |
| desktop | 1024~    | 64   | —    | 좌 400(맥락) 또는 280(필터 레일) sticky / 우 가변 |
| max     | 1584~    | 64   | —    | 좌측만 480까지. 우측은 늘어난다                   |

**레이아웃 토큰** — 화면이 이 값을 직접 쓰지 않고 토큰을 참조한다.

| 토큰                | 값               | 용도                          |
| ------------------- | ---------------- | ----------------------------- |
| `--header-h`        | 56 → 64(768~)    | 헤더 높이 (검색 필드 없음)    |
| `--header-h-search` | 64               | 검색 필드가 있는 헤더         |
| `--tabbar-h`        | 64               | 모바일 하단 탭바              |
| `--rail-context`    | 400 → 480(1584~) | 좌측 맥락 패널 (홈·일정 상세) |
| `--rail-filter`     | 280              | 좌측 필터 레일 (목록 화면)    |
| `--band-h`          | 8                | 밴드 높이                     |

- 검색 필드가 있는 헤더는 **64**, 없으면 **56**.
- **모바일 우선으로 작성한다.** 데스크톱 스타일을 미디어 쿼리로 덧붙인다.
- 모바일 최소 터치 영역 **44×44px**.
- **375px 에서 가로 스크롤이 생기면 버그다.** 넓은 콘텐츠는 자체 `overflow-x` 컨테이너로 감싼다.

### 7-1. 좌우 역할

- **좌 400 = 맥락 패널**(홈·일정 상세) — 누구와(프로필) · 지금 안전한가(판정) · 위급하면(병원).
- **좌 280 = 필터 레일**(목록 화면). 역할이 다르므로 폭도 다르다. 둘 다 sticky.
- **우(가변) = 지금 할 일.**
- **세로축이 곧 우선순위다.** 같은 우선순위가 아닌 것을 가로로 배치하지 않는다.
- **순서가 의미인 자료(일정 일자)를 2열로 쪼개지 않는다** — 읽는 순서가 꺾인다.

### 7-2. 열 구분선

**열 구분선은 그리드 컨테이너에 깐다.** sticky 열에 `border-right` 를 주면 그 열 높이에서 선이 끊긴다.

```css
background: linear-gradient(var(--border), var(--border)) 280px 0 / 1px 100% no-repeat;
```

- 열 사이는 세로선 1px 이고 **회색 배경을 깔지 않는다.**

### 7-3. PhotoGallery 표시 크기

**전폭 히어로를 쓰지 않는다.** TourAPI 이미지는 해상도가 고르지 않아(가로 500–800px 가
흔함) 1040·390 전폭으로 늘리면 업스케일이 드러난다. **높이는 항상 고정**이다.

| 토큰                     | 값    | 용도                   |
| ------------------------ | ----- | ---------------------- |
| `--gallery-w-mobile`     | 342px | 모바일 캐러셀 항목 폭  |
| `--gallery-h-mobile`     | 214px | 모바일 고정 높이       |
| `--gallery-w-lead`       | 590px | 데스크톱 대표 폭 상한  |
| `--gallery-h-desktop`    | 300px | 데스크톱 고정 높이     |
| `--gallery-w-thumb`      | 362px | 데스크톱 썸네일 폭     |
| `--gallery-h-thumb`      | 146px | 데스크톱 썸네일 높이   |
| `--gallery-w-single-max` | 660px | **1장일 때 멈추는 폭** |

장수별 배치 — `0장 = 섹션 미렌더` / `1장 = 660 에서 멈춤` / `2장 = 균등 2분할` /
`3장 이상 = 대표 + 썸네일 2 + +N`.

- **사진은 한 곳에서만 말한다.** 상단 갤러리가 있으면 본문 아래 "사진" 섹션을 두지 않는다.
- **0장이면 섹션을 렌더하지 않는다** — 회색 "이미지 없음" 면이 첫 화면을 덮지 않는다.
  **목록 썸네일은 반대다**: 거기서는 행 높이를 지켜야 하므로 같은 크기 타일을 남긴다.
- 모바일은 `scroll-snap` + 옆 사진 물림, 점 인디케이터 대신 **`1/8` 카운터**.
- **사진 출처는 갤러리 바로 아래, 정보 출처는 본문 끝** — 각각 자기 자료 옆에서 읽힌다.

## 8. 모션

- 기본 transition: `150ms ease-out` (색·투명도), `200ms ease-out` (변형·레이아웃)
- 바텀시트·모달: `250ms cubic-bezier(.2,.8,.2,1)`
- `prefers-reduced-motion: reduce` 를 존중해 변형 애니메이션을 끈다.
- **AI 일정 생성 대기**는 수초~수십초다. 무한 스피너 대신 진행 단계 표시를 쓴다.

## 9. 아이콘

- 선(line) 스타일, 굵기 1.5px, 24px 기본 / 20px 조밀 / 16px 인라인.
- **icon-only 버튼에는 반드시 `aria-label`.** 장식 아이콘은 `aria-hidden`.
- 반려견 관련 아이콘은 과하게 귀엽게 가지 않는다 (§1).
- **문구를 아이콘으로 대체하지 않는다.** 등급은 문구가 말한다.

## 10. 쓰지 않는 것

- 그라디언트 · 이모지 · 느낌표
- **평평한 행의 그림자**
- **12px 미만 글자** (예외: 아바타 이니셜, §3-1)
- **새 라운드 값**
- **weight 800·900 을 20px 미만에** 쓰는 것
- **700 과 800 을 같은 화면의 위계로** 쓰는 것
- **배지·판정 옆의 장식성 세로 바** — 3px 바는 `ReasonList` 근거 부호에만
- **등급 색을 우선순위·장식·브랜드로 전용**하는 것
- **진행률 링·게이지 같은 점수 시각화** — 숫자와 문장으로 충분하다
- **장소 사진을 판단 근거로 쓰는 것** — 썸네일은 행을 잡아주는 장치이고 근거는 문장이다
