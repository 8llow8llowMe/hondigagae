# Cursor 어댑터

Cursor CLI와 Cursor 에이전트에서 `dev-orchestrator`를 실행할 때의 모드 선택이다. 작업 유형과 `T0`–`T3` 판정은 [SKILL.md](../SKILL.md)를 따른다.

Cursor는 `.agents/skills/dev-orchestrator/SKILL.md`를 프로젝트 스킬로 읽고, `/dev-orchestrator`로 호출할 수 있다. 루트 `AGENTS.md`도 규칙으로 읽는다. Codex용 모델 표를 이 호스트의 모델 ID로 복사하지 않는다.

## 모드

| 모드 | 쓰는 일 |
|------|---------|
| Agent | 파일 수정, 검색, 터미널, 구현과 검증 |
| Plan | 구현 전에 범위, 순서, 검증, 위험 신호를 고정 |
| Ask | 파일을 바꾸지 않는 탐색·원인 조사 |

CLI에서는 `agent`, `agent --mode=plan`, `agent --mode=ask`에 해당한다. 세션 안에서는 호스트가 제공하는 모드 전환을 쓴다. 이미 그 모드에 있으면 같은 모드를 다시 열지 않는다.

## 복잡도별 실행

| 등급 | 실행 |
|------|------|
| `T0` | 현재 Agent가 직접 처리한다. 하위 에이전트, Plan, 별도 검토를 두지 않는다 |
| `T1` | Agent가 구현한다. 위치가 불명확할 때만 Ask 또는 읽기 전용 탐색을 한 번 둔다. 쓰기는 한 실행자다 |
| `T2` | Plan으로 범위와 검증을 고정한 뒤 Agent가 구현한다. 구현 후 읽기 전용 검토를 별도로 수행한다 |
| `T3` | Plan으로 설계·원인·위험 신호를 먼저 고정한다. 계획이 저장소 증거와 맞기 전에 파일을 수정하지 않는다. 구현은 Agent 한 명이 맡고, 검토를 분리한다. 인증·결제·개인정보·분산 상태가 있으면 보안 검토를 한 번 더 둔다 |

`T3`의 추가 검토가 Cursor의 승격이다. Codex의 `xhigh` 모델 지정을 대신한다.

## 하위 에이전트

세션에 하위 에이전트 도구가 있을 때만 역할을 나눈다. 없으면 메인 실행자가 EXPLORE → PLAN → IMPLEMENT → VERIFY → REVIEW 순서로 직접 수행한다.

모델을 지정해야 하면 **그 세션의 사용 가능 목록**에서 고른다.

| 역할 | 선택 |
|------|------|
| 탐색 | 목록에서 가장 가볍고 빠른 모델 |
| 구현 | 세션의 구현용 기본 모델 |
| `T2` 원인 분석·검토 | 목록에서 더 깊은 추론이 가능한 모델 |
| `T3` 원인 분석·검토·설계 | 목록의 최상위 추론 모델 |

목록에 최상위 모델이 없으면 Plan과 분리된 검토 패스로 같은 절차를 수행하고, 보고에 모델 부재를 적는다. `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra`가 세션 목록에 있을 때만 Codex 어댑터의 칸을 그대로 쓸 수 있다. 없다고 그 ID를 만들어 지정하지 않는다.

## 예시

회원 닉네임 수정 API:

- `TYPE: FEATURE`
- `COMPLEXITY: T0`
- Agent가 해당 API와 테스트만 수정한다

운영 멀티 인스턴스에서만 동일 이벤트가 두 번 처리될 때:

- `TYPE: BUG`
- `COMPLEXITY: T3`
- Ask 또는 읽기 전용 탐색으로 재처리·락·트랜잭션·커밋 시점을 모은다
- Plan으로 원인 후보와 최소 수정 범위를 고정한다
- Agent가 확정된 원인만 수정하고 회귀 테스트를 실행한다
- 별도 읽기 전용 검토를 수행한다
