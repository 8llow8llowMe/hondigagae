# Development Orchestrator

메인 실행자가 작업을 분류하고 필요한 역할만 선택한다. 호스트별 역할 파일·모델·권한의 정본은 아래 두 문서다.

- Codex — [Codex 에이전트 운영 가이드](../../../docs/codex-agents.md) (`.codex/agents/*.toml`)
- Claude Code — [Claude Code 에이전트 운영 가이드](../../../docs/claude-agents.md) (`.claude/agents/*.md`)

**분류와 라우팅 판단은 호스트가 같고, 실행 수단만 다르다.** agent 기능이 없는 호스트에서는 메인 실행자가 같은 역할을 순서대로 수행한다.

## 역할 이름

역할은 동일하고 이름 표기만 호스트 관례를 따른다.

| 역할 | Codex | Claude Code | 모델 등급 |
|------|-------|-------------|-----------|
| 탐색 | `explorer` | `explorer` | 저비용 |
| 단순 구현 | `crud_implementer` | `crud-implementer` | 저비용 |
| 일반 구현 | `implementer` | `implementer` | 고성능 |
| 버그 분석 | `bug_investigator` | `bug-investigator` | 고성능 |
| 최종 검토 | `reviewer` | `reviewer` | 고성능 |
| 리팩토링 | `refactorer` | `refactorer` | 고성능 |
| 설계 | `architect` | `architect` | 최상위 추론 |

워크스페이스 전용 역할은 Claude Code 에만 파일이 있다. BE 는 `be-executor` / `be-hexagonal-reviewer` / `be-db-reviewer` / `be-security-reviewer`, FE 는 `fe-*` 7종이다. 다른 호스트에서는 해당 역할 프롬프트를 순차로 적용한다.

## 기본 원칙

- 먼저 루트 `AGENTS.md`(Claude Code 는 `CLAUDE.md`)와 대상 워크스페이스의 엔트리 문서를 읽는다.
- 에이전트 수보다 작업 경계와 증거를 우선한다. 명확한 작업에 조사 역할을 형식적으로 추가하지 않는다.
- 병렬 실행은 서로 독립적인 **읽기 전용** 조사·검토에만 사용한다.
- 공유 파일, 공개 계약, DB 스키마, 도메인 객체를 수정하는 쓰기 역할은 한 번에 하나만 실행한다.
- 하위 에이전트가 다시 에이전트를 낳게 하지 않는다. 역할 선택과 결과 통합은 메인 실행자의 책임이다.
- 사용자가 명시적으로 병렬화·특정 역할·특정 모델을 요청하면 안전한 범위에서 우선한다.

## 작업 분류와 흐름

### SIMPLE

대상: 명확한 CRUD, DTO, 매핑, 단순 검증·설정, 작은 테스트.

1. 위치가 명확하면 탐색 역할을 생략한다.
2. 애플리케이션 코드 변경은 단순 구현 역할에 맡긴다.
3. 문구나 한 줄 메타데이터처럼 위임 비용이 더 큰 변경은 메인 실행자가 직접 처리할 수 있다.
4. 대상 범위 검증만 실행한다. 설계 역할과 병렬 팀을 호출하지 않는다.

### FEATURE

대상: 일반적인 단일 서비스·화면 기능.

1. 코드 위치나 호출 흐름이 불명확할 때만 탐색 역할을 먼저 실행한다.
2. 구현 역할이 순차적으로 구현하고 테스트한다. 워크스페이스 전용 역할이 있으면 그쪽을 쓴다 (BE `be-executor`, FE `fe-implementer`).
3. 공개 API, 보안, 트랜잭션, 복수 계층에 영향이 있거나 변경량이 큰 경우 검토 역할이 최종 diff 를 검토한다.
4. HIGH 이상 지적은 구현 역할이 수정한 뒤 다시 검증한다.

### BUG

대상: 원인이 불명확하거나 재현·상태·트랜잭션·동시성 분석이 필요한 버그.

1. 독립적인 증거 수집이 유효할 때 버그 분석 역할과 탐색 역할을 병렬 실행한다.
2. 메인 실행자가 두 결과를 실제 코드와 대조해 근본 원인을 확정한다.
3. 원인이 확정된 뒤에만 구현 역할이 최소 수정한다.
4. 검토와 회귀 테스트를 실행한다.

명확하고 국소적인 버그는 두 조사 역할을 모두 호출하지 않는다.

### REFACTOR

대상: 동작을 보존하면서 구조를 바꾸는 변경.

1. 탐색 역할과 검토 역할이 현재 의존성·냄새·회귀 위험을 독립적으로 읽기 전용 분석할 수 있다.
2. 중요한 계층이나 모듈 경계를 넘으면 구현 전에 설계 역할을 추가한다.
3. 메인 실행자가 범위와 보존할 동작을 고정한다.
4. 리팩토링 역할 한 명이 순차적으로 수정하고 테스트한다.
5. 검토 역할이 최종 diff 를 다시 검토한다.

### ARCHITECTURE

대상: MSA·보안·트랜잭션·메시징·동시성·대형 교차 모듈 설계.

1. 설계 역할과 탐색 역할을 병렬 실행한다.
2. 메인 실행자가 설계 제안을 실제 저장소 증거와 대조하고 설계를 확정한다.
3. 구현 요청이 포함된 경우 확정된 계획을 구현 역할 또는 리팩토링 역할 한 명에게 전달한다.
4. 마지막에 검토와 관련 검증을 실행한다.

### LARGE_FEATURE

읽기 전용 발견 작업만 최대 2~3개로 병렬화한다. 백엔드 대형 작업은 `backend-multi-agent`, 프론트엔드 대형 작업은 `fe-multi-agent`의 프로젝트 역할 구성을 함께 적용한다. 발견 결과를 하나의 계획으로 통합한 뒤 쓰기는 순차 수행한다.

## 완료 조건

다음을 모두 충족해야 완료로 보고한다.

1. 요청한 동작이 구현되었다.
2. 영향 범위가 컴파일되고 관련 테스트가 통과했다.
3. 필요한 수준의 최종 검토가 끝났다.
4. CRITICAL/HIGH 지적이 해결되었다.
5. 불필요한 변경과 겹치는 동시 편집이 없다.
6. 실제 실행한 검증과 남은 위험을 메인 실행자가 보고한다.

**하위 에이전트의 "통과했다" 를 그대로 옮기지 않는다.** 메인 실행자가 검증 명령을 한 번 더 돌린 결과로 보고한다.
